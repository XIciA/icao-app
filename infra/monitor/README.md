# 生产基础监控

用户选择只在服务器保留告警，不配置消息推送或公开监控端口。

- 每五分钟检查磁盘、可用内存、CPU load、核心容器、API 本机/公网 readiness、最近数据库备份与 API 日志。
- 状态：`/var/lib/icao-monitor/status.json`；七天聚合历史：同目录 `history-*.ndjson`。
- 查看告警：`journalctl -u icao-monitor.service --since today`；仅告警新增和恢复时输出对应事件。
- 磁盘 80% 预警，90% 或不足 3 GiB 严重；数据库备份超过 30 小时严重。
- API 413、5xx 和非 AI 接口 P95 超过两秒触发预警。慢接口至少需要 20 条样本。
- 请求日志每次最多读取两万行；状态注明可能截断。只记录固定服务前缀和聚合指标，不保存身份、IP、查询参数或请求正文。
- 监控不会清理镜像、修改数据或自动重启服务。没有配置异机探针，整机失联时本机无法自行发出外部告警。

## 后台看板数据

`monitor.py` 与 `dashboard_export.py` 必须一起安装到同一 release 目录。采集新增 CPU 两次采样间
平均使用率、总内存及每路由 HTTP 状态计数；旧历史没有的字段保留空值。每小时最多成功读取一次
DeepSeek 官方余额，密钥只在现有 API 容器内部使用，失败保留上次余额及其原始采集时间。

监控将固定白名单的聚合数据写到 `dashboard/dashboard.json`。父目录仍是 `0700`；该子目录 `0755`、
文件 `0644`，Ops API 通过只读 bind mount 读取这个子目录，不读取根权限的原始状态，也不挂载 Docker
socket。看板接口仅注册在独立 Ops API，沿用管理员角色、会话和审计；接口响应禁止缓存。
监控文件最多保留七天、2200 个采样点，读取大小有上限。没有采样的时段不补零、不断言正常。

现有本地后台通过已有 SSH 身份复制同一份白名单投影到本机私有目录，不新增云端监听端口。
线上和本地均通过 `/v1/admin/stability` 读取聚合，不向浏览器提供数据库连接或服务商密钥。

看板的 AI 调用 / 用量估算和自然日点击账户由现有表只读聚合，最多七个上海自然日，60 秒缓存，
数据库事务只读、语句超时五秒。AI 成功率按已结束调用加权；接口 P95 按原始五分钟窗口展示，
不合并或平均 P95。费用缺失保留未知，不冒充官方账单。真实并发、客户端端到端体验、带宽上限、
云套餐余量、续费日期、异地备份与恢复演练尚无采集源时明确显示未接入，不使用草图示例值。

从已合入 `origin/main` 的干净源码安装到 `/opt/icao/runtime/monitor/releases/<commit>/`，将 `current` 原子切换至该目录，并安装本目录的 systemd unit。保留前一版目录可回滚。首次安装运行 `systemctl start icao-monitor.service`，检查状态文件、日志和 timer 后交付。
