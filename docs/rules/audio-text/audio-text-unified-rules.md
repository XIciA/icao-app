# 音频文本统一规范（听力、故事复诵、陆空通话）

## 1. 用途与当前策略

本文档是听力、故事复诵和陆空通话三类题库的共同文本规范入口。共性规则只在本文档列出；各题型独有规则见第 4 至第 6 节，完整历史细则仍保留在原规则文档中。

- **暂停 Whisper**：当前不运行 Whisper、不生成新的 Whisper 候选，也不依据既有 Whisper 结果修改题库；音频疑点改由人工复听确认。（例：`1.5 seconds` 与 `15 seconds` 有分歧时，必须人工确认。）
- **保留历史记录**：已有转写、快照和报告不删除、不覆盖，只作为历史材料。（例：旧候选写 `wind come`，人工确认后正式题库写 `wind calm`。）
- **重新启用条件**：以后只有得到明确授权，才恢复 Whisper 识别或以新的 ASR 流程生成候选。（例：只有明确提出“重新启用 Whisper 识别”后才可恢复。）

## 2. 三类题库共性规则

1. **音频事实优先**：文本应忠实于音频，不为语法自然或表达流畅而自由改写。（例：音频确认是 `at 15 / at 46`，不得改成 `1.5 / 4.6`。）
2. **不确定就保留**：听不清的地点、数字、单位或后续回复保留现值并记录，不用常识猜补。（例：无法确认放油数量时，暂不改写 `4,000 pounds`。）
3. **数字必须有证据**：航班号、跑道、高度、航向、频率、时间和应答机编码，只能按音频或确定性规则修改。（例：`heading 330` 不得根据场景标题改成其他航向。）
4. **只在授权范围内修改**：内容校对和格式治理必须遵守各题型边界，不借机扩大处理范围。（例：故事复诵只清理格式，不修正疑似语法错误。）
5. **中英文分别核对**：已授权的英文事实发生修改时，中文必须同步复核，但不得根据一方猜写另一方。（例：人工确认 `wind calm` 后，中文同步为“静风”。）
6. **格式只做确定性清理**：统一标点、空格、换行和说话人标签，不借格式清理改变正文内容。（例：`PIL:` 可规范为 `P: `，但后面的发话内容不改。）
7. **源数据与 App 同步**：先修改正式题库源，再同步 App 内嵌题库，禁止只改一份。（例：源数据与 App 内嵌数据中的同一卡片必须一致。）
8. **保护非目标内容**：卡片 ID、标题、顺序、分类、音频路径和未授权字段不得变化。（例：修正文本时不得顺手更换音频文件。）
9. **修改必须可追溯、可重复**：保留前后差异和人工决定；同一规则重复执行不能产生新修改。（例：第二次执行后修改数应为 0。）
10. **统一验收**：修改后检查题目数量、字段完整性、音频映射、源与内嵌数据一致性，并运行内容及项目检查。（例：听力题仍保持 631 题且音频路径全部有效。）

## 3. 听力与陆空通话共用航空格式

1. **呼号使用规范格式**：无线电呼号写作“三字代码 + 一个半角空格 + 原数字”，但普通叙述中的航司名称保留自然表达。（例：`Qantas 432 → QFA 432`；`A British Airways Boeing 737` 保持原写法。）
2. **民航字母紧凑书写**：明确属于代号的 ICAO 字母词转为大写字母并与所属数字连写，普通英语同形词不转换。（例：`Lima Kilo Oscar → LKO`、`Alpha 3 → A3`；酒店语境中的 `hotel` 不改。）
3. **进离场代号加短线**：写作“代码-原数字及后缀”，不补零、不删零，并保留进场或离场含义。（例：`IKUBA01A arrival → IKUBA-01A arrival`。）
4. **Runway 按位置定大小写**：直接连接跑道号时使用 `Runway`，其他位置使用 `runway`，数字及 `L/R/C` 后缀不变。（例：`runway in use runway 26 → runway in use Runway 26`。）

## 4. 听力题独有规则

1. **处理完整答题链路**：范围包括英文原文、中文翻译、四个选项、正确索引和参考答案。（例：正确答案从 B 改为 C 时，`correctChoiceIndex` 与 `referenceText` 必须一起更新。）
2. **问题固定另起一行**：英文使用 `Question:`，中文使用 `问题：`，不得把选项或答案混入音频原文。（例：正文结束后写 `Question: What happened?`。）
3. **答案由正确索引生成**：参考答案不单独随意维护，格式统一为 `正确答案：B. <选项内容>`。（例：索引为 1 时生成 B 项文本。）
4. **普通叙述不强制代码化**：客舱广播、新闻和事故叙述中的航司名称按实际表达保留。（例：`Transworld Airlines Flight 455` 不机械改成无线电呼号。）
5. **重复题逐题判断**：文本相似不代表应删除；先核对音频、问题、选项和答案。（例：两题正文相同但问题不同，可以同时保留。）
6. **听不清的候选保持原值**：人工仍无法唯一判断时记录“已复核并保留”，不继续扩写。（例：`20s航空英语-94` 暂时保留现有返航和放油描述。）

## 5. 故事复诵独有规则

1. **当前只做格式治理**：只处理 `audioText` 和 `audioTextZh` 的排版、空格及明确正文外标签，不修改故事事实、语法或用词。（例：不能因句子不自然就重写整句。）
2. **正文保存为单段**：删除排版换行、空行、制表符和首尾空白，中文与英文各保持一个自然段。（例：两行连续故事合并为一段，但单词之间保留空格。）
3. **粘词必须来自确认词表**：只拆分能够明确判断的单词，不使用无约束自动分词。（例：`thecontroller → the controller`，但 `AirAsia` 不拆。）
4. **航空标识不得误拆**：机型、跑道、飞行高度层和呼号保持完整。（例：`B747`、`36R`、`FL340` 不拆分。）
5. **首尾标签逐卡删除**：篇号、来源备注或重复航班号只有进入人工确认清单后才能删除。（例：结尾独立重复的 `AFR123` 可删，正文首句中的 `AFR123` 必须保留。）
6. **正文字符序列受保护**：除批准的空格、标点和首尾标签外，不增加、删除或替换字母、数字和汉字。（例：疑似错误年份仍保留并进入复核报告。）

## 6. 陆空通话独有规则

1. **允许修正确认的专业转写错误**：明显拼写、术语和固定通话表达可以修正，语义不明确时只报告。（例：`call sigh → call sign`、`breaking action → braking action`。）
2. **固定表达只做局部修正**：不得因为整句不自然就全面润色。（例：`ready to takeoff → ready for takeoff`，其余发话保持不变。）
3. **规范文本可使用航空书面形式**：无需机械展开为音频逐字读法。（例：音频读作 `flight level three nine zero`，文本可写 `FL390`。）
4. **保留对话分段和角色标签**：`B:`、`C:`、`P:` 等标签及 `<br>` 表达的发言边界不得随意合并。（例：飞行员复诵不能并入管制员指令。）
5. **四字段航空格式同步**：新增的呼号、民航字母、进离场代号和 Runway 规则同时覆盖原文、翻译、参考答案及答案翻译。（例：四个字段中的 `Qantas 432` 均统一为 `QFA 432`。）
6. **音频差异先分类再处理**：先判断是文本错误、音频映射错误、等价口语表达还是展示信息混入，只有确定的文本错误才改正文。（例：音频读 `zero four`、文本写 `04` 属于等价表达，无需改回单词。）

## 7. 统一执行流程

1. 保存目标字段修改前快照和非目标字段摘要。（例：先记录卡片 ID 与音频路径哈希。）
2. 使用确定性规则生成候选，不运行 Whisper。（例：扫描 `IKUBA01A`，生成 `IKUBA-01A` 候选。）
3. 人工复核涉及音频事实或语义的候选。（例：人工确认是 `wind calm` 后再批准。）
4. 将批准差异写入正式源并同步 App 内嵌题库。（例：源数据和内嵌数据同时更新。）
5. 重复执行规则，确认结果幂等且没有越界变化。（例：再次运行时修改数为 0。）
6. 运行音频映射、内容构建、完整内容检查和项目检查。（例：执行 `pnpm content:audio:verify`、`pnpm content:build`、`pnpm content:check:full`、`pnpm check`。）
