# D8 内部运营后台结构决策

状态：已确认；具体产品与权限设计在后台建设阶段另行完成
确认日期：2026-08-12
关联需求：[Native App 正式商业上线总需求](../requirements.md)

## 已确认结构

- 建设一个与用户 App 隔离、独立部署的内部运营后台，不把管理能力放入用户 App。
- 首发工作人员角色只有管理员和客服；二者使用独立工作人员账号登录同一后台，通过角色区分可见
  页面和允许操作，不能复用普通用户手机号账号。
- 后台通过专用服务端管理接口读取和操作现有用户、订单、权益、AI 风控及后续运营数据。
- 后台页面和客户端不得直接连接或修改生产数据库。
- 当前用户 Web 产品及 Vercel 部署继续冻结；内部运营后台不是面向用户的 Web 商业化，也不得复用、
  修改或顺带发布现有 Web/Vercel。

## 首发安全底线

- 工作人员账号必须支持停用、强验证和最小权限；正式环境不得共享账号。
- 客服默认只看完成工单所必需的脱敏数据，不得查看 AI 正文、录音、完整支付凭证或其他无关信息。
- 退款、补偿、赠送、封禁、注销协助和数据导出属于高风险操作，至少记录操作者、对象、原因、前后
  状态和时间；具体授权与复核规则在后台大流程设计时确定。
- 所有查询和变更都通过受鉴权的管理接口完成并留下不可由普通后台账号删除的审计记录。

## 后续边界

本决策只确认后台的存在形式、首发角色和安全边界。页面、工作人员登录方式、细粒度权限、退款、
补偿、赠送、风控处理、审计和高风险操作流程，等进入后台建设阶段时再具体设计，不在当前决策阶段
展开。
