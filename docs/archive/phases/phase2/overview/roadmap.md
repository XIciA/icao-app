## 3. 阶段 0：前置条件与高风险验证

### 目标

在大规模实现前确认外部环境和微信登录路线能够成立。

### 主要工作

- 列出 ECS、域名、HTTPS、自托管 Supabase、短信、邮件、微信开放平台和 AI 的所需账号与凭证。
- 确认正式 iOS Bundle ID、回调域名、Universal Link 和内部测试设备。
- 验证微信登录能否接入自托管 Supabase Auth，并保持 Supabase 为会话权威。
- 确认题库、音频、图片和用户数据的内部测试访问边界。
- 固定 `docs/ai/` 中的 AI 能力规范版本基线。

### 允许范围

- 只读盘点、最小可行性代码、开发环境配置和阶段记录。

### 禁止范围

- 不建立平行账号系统，不批量迁移数据，不开始完整页面接入。

### 验收标准

- 微信 Auth 有可维护、可验证的方案；否则形成明确阻塞并回到架构决策。
- 所需外部资源、负责人、获取方式和缺失项清楚。
- 当前用户未提交改动不会被覆盖。

## 4. 阶段 1：后端与 Supabase 基础

### 目标

建立真实服务共同依赖的后端、数据库、认证和对象存储基础。

### 主要工作

- 建立 TypeScript 模块化单体、统一配置、错误、日志、健康检查和测试结构。
- 配置开发/内测自托管 Supabase Auth、PostgreSQL 和 Storage。
- 建立 Drizzle schema、版本化 SQL Migration 和权限/RLS 补充 SQL。
- 建立 RN 统一 API client、认证头、超时、取消和错误映射。
- 配置密钥隔离、备份、基础监控和恢复检查。

### 禁止范围

- 不在 RN 中保存服务端密钥，不直接开放业务表，不接真实业务页面。

### 验收标准

- 新环境可从空库按 Migration 建立并重复验证。
- 健康检查、鉴权失败、日志和配置缺失能稳定返回。
- 客户端可安全连接内测 API，不暴露私密配置。

## 5. 阶段 2：真实题库与资源

### 目标

把题库和文件从开发期快照迁移为服务端权威资源，同时保留页面与稳定 ID。

### 主要工作

- 先建立统一内容工程：维护源按题库/话题拆分，统一 schema、稳定 ID 和资源命名，再生成版本化发布产物；不复制页面、Repository 或后端模块。
- 编写可重复执行的题库导入、资源上传、manifest 和校验流程。
- 导入 5 套题库、4947 张卡片和资源元数据。
- 校验 3678 张音频卡片与 3894 条音频索引，处理多余、缺失和重复引用。
- 建立远程 `QuestionBankRepository`、资源 adapter、版本、缓存、签名地址和重试。
- 保留嵌入式 repository 作为迁移期间的受控回退。

### 禁止范围

- 不改题目内容、稳定 ID、页面结构或学习交互；不打包完整音频库。

### 验收标准

- 数据数量、字段、ID 和 object key 可对账，导入重复执行不产生重复数据。
- iOS 从真实服务完成“题库 -> 目录 -> 学习卡 -> 音频”。
- 断网、过期地址、缺失资源和服务失败均有明确恢复路径。

## 6. 阶段 3：真实登录与账号

### 目标

完成强制邮箱登录和会话、邮件测试、注销删除的真实闭环。

### 主要工作

- 接入 Supabase Auth adapter 和 `expo-secure-store` 会话存储。
- 建立 App 全局登录门禁，题库、资源、同步和 AI 服务端强制鉴权。
- 实现邮箱注册/登录、会话恢复、自动刷新、当前设备退出和全部设备立即退出。
- 实现修改密码、Mailpit 换绑/找回测试、账号注销和活跃数据删除。
- 旧版未归属数据必须显式合并或归档后从空账号开始。

### 禁止范围

- 不接匿名游客、手机号、微信、Apple 或正式 SMTP；不让页面直接依赖 Supabase SDK。

### 验收标准

- 邮箱账号与治理能力在 iOS 内部环境可用。
- App 重启后会话恢复，失效后提示并安全退出。
- 未归属数据选择、跨账号隔离和同步不会丢失或复制学习数据。
- 换绑、找回、过期链接、注销和全部设备退出均有明确反馈。

## 7. 阶段 4：学习数据同步

### 目标

把本机学习数据升级为登录账号可恢复的在线优先同步。

### 主要工作

- 建立服务端学习状态、学习记录和报告数据结构。
- 为本地数据增加迁移版本、稳定记录 ID、更新时间和待同步状态。
- 实现上传、拉取、确认、自动重试、去重和版本冲突处理。
- 覆盖进度、作答、标签、高亮、笔记和报告。
- 在账户同步页展示真实状态、最后成功时间、失败原因和重试。

### 禁止范围

- 不清空现有 SQLite 数据，不建设完整离线模式或复杂双向冲突编辑器。

### 验收标准

- 同账号在重新安装或第二个 iOS 会话中恢复核心数据。
- 重复提交不产生重复记录，旧版本不覆盖新版本。
- 弱网、超时、部分成功和重新登录不造成静默数据丢失。

## 8. 阶段 5：AI 基础与真实查词

### 目标

先用 AI 查词验证同意、模型调用、schema、额度和成本的完整链路。

### 主要工作

- 建立 AI Gateway、provider adapter、统一 envelope、错误和调用记录。
- 建立 AI 数据同意、撤回和服务端强制检查。
- 实现每日额度、分钟频率、并发控制、用户成本和全局成本上限。
- 按标准库重建 AI 查词 Prompt、schema、上下文和 eval。
- 将现有查词弹层替换为真实加载、结果、失败、额度和重试状态。

### 禁止范围

- 不接语音和其他 AI，不用 Mock 结果兜底真实成功，不在客户端放模型密钥。

### 验收标准

- 五套题库均可从现有入口真实查词。
- 同意、拒绝、撤回、超时、供应商失败、额度耗尽和成本熔断全部通过。
- 标准 eval 输出结构和内容边界通过。

## 9. 阶段 6：全部 AI 学习能力

### 目标

完成 Web 标准库已有的全部真实 AI 学习能力。

### 主要工作

- 接入 900句、陆空通话、OPI、故事复诵的语音上传、转写和航空规范化。
- 实现 900句本地原文对比。
- 实现陆空通话、故事复诵语法检查。
- 实现 OPI 语法纠错与表达润色组合。
- 接入 Prompt/schema/domain/eval 版本和完整结果状态。
- 验证录音临时处理与服务端清理。

### 禁止范围

- 不新增真实 ICAO 评分、等级判定或 Web 标准库不存在的 AI 能力。

### 验收标准

- 五类 AI 能力在对应题库入口工作，模块映射无误。
- PCM/WAV 真机录音可稳定上传、转写和回放，原始录音不被长期保存。
- 语法检查和润色保留原意、不生成标准答案、不输出评分。
- 配额、成本和标准 eval 回归通过。

## 10. 阶段 7：权益与状态收口

### 目标

建立未来商业化边界，并清理真实能力与演示状态的混淆。

### 主要工作

- 建立免费权益、AI 额度、未来会员权益和用户 entitlement 快照。
- 预留购买恢复、退款、权益失效和服务维护状态。
- 更新账户、同步、AI 和设置页面的真实状态与内部测试标识。
- 保留 AI 模考评分为明确 Mock，不显示真实购买入口。

### 禁止范围

- 不接 StoreKit、Google Play Billing、订阅 SDK 或任何真实支付。

### 验收标准

- 页面只依赖统一 entitlement 结果。
- 测试权益、真实 AI、Mock 模考和未开放支付边界清楚。
- 不存在误导用户购买或声称真实评分的文案。

## 11. 阶段 8：iOS 内部验收与收口

### 目标

证明第二阶段在 iOS 上达到内部测试可用，并记录所有延后风险。

### 主要工作

- 运行 RN、后端、Migration、数据导入、权限和 AI eval 全部检查。
- 在 iOS 模拟器和物理 iPhone 完成资源、账号、同步、AI、额度和弱网全链路。
- 验证重装/第二会话恢复、微信回跳、录音、切后台和服务失败。
- 检查密钥、日志、数据清理、备份恢复和成本熔断。
- 更新 `phase-log.md`，生成 `closeout.md` 和剩余风险清单。

### 验证门禁

- RN：`pnpm check`、Expo Doctor、iOS Development Build 和物理 iPhone。
- 后端：类型、lint、测试、API 集成与 Migration 检查；具体命令在阶段 1 固定。
- 数据：5 套题库、4947 张卡片、3678 张音频卡片和 3894 条索引对账。
- AI：能力矩阵、标准 eval、同意、额度和成本边界。
- 不运行 Android 测试，收口报告必须明确 Android 未验收。

### 验收标准

- `requirements.md` 中全部 iOS 内部测试效果有证据对应。
- 无客户端密钥、静默数据丢失、未清理录音或额度绕过问题。
- 真实资源、四类登录、同步和五类 AI 能力可持续内部测试。
- 支付、账号注销、Apple 登录、Android 验收和正式上架仍明确留在后续阶段。

- `technical-plan.md` 和本路线图由用户确认。
- 阶段 0 所需外部账号与配置可以开始准备。
- 当前工作区未提交改动的归属清楚，不与执行写入范围冲突。
- 不存在需要改变总战略或架构决策的未解决问题。

路线图确认后，Codex 按小流程从阶段 0 自动推进；遇到缺少外部账号/凭证、微信 Auth 路线失败、成本或数据风险扩大时暂停并返回大流程。
