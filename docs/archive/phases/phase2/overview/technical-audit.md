已具备：

主要缺口：

- 题库仍是安装包内嵌快照，没有远程版本、更新、缓存失效或服务端权威源。
- 音频仍依赖开发期本地 HTTP 资源服务，没有 Storage object key、签名访问或 CDN。
- 当前学习数据按 topic 保存为 JSON，没有用户归属、记录版本、更新时间、同步状态或迁移版本。
- 没有远程 repository、同步 outbox、冲突处理或服务端学习数据表。

## 4. 登录与账号

当前 `AuthScreen` 只模拟邮箱密码和手机号验证码，未创建真实账户；账户、资料、安全和同步页面均为演示状态。

缺口：

- 未安装或配置 Supabase SDK、`expo-secure-store`、Auth adapter 或会话恢复。
- 没有匿名游客、真实短信、真实邮件、微信登录或游客升级。
- 当前登录页没有微信入口，需按现有设计语言补齐。
- 当前 Bundle ID/Package Name 为 `com.anonymous.*`，不适合作为微信开放平台和正式身份回调标识。
- 账号页仍有“注销账户”演示入口，与第二阶段不提供自行注销的要求不一致；执行时必须禁用、隐藏或明确标记为不可用。

外部前置条件：

- 自托管 Supabase Auth 可访问地址、JWT/密钥和回调域名。
- 短信 provider、签名、模板和测试号码。
- 邮件 SMTP/provider、发件域名和模板。
- 微信开放平台 AppID、应用审核材料、Bundle ID、Universal Link/回调配置和测试账号。

## 5. 后端与基础设施

当前仓库没有业务后端、Drizzle schema、SQL Migration、Supabase 客户端、部署配置或 API 环境变量。`EXPO_PUBLIC_ICAO_ASSET_BASE_URL` 是唯一真实资源环境入口。

根据已确认架构，需要补齐：

- TypeScript 模块化单体和统一产品 API。
- 自托管 Supabase Auth/PostgreSQL/Storage。
- Drizzle 数据访问与版本化 SQL Migration。
- HTTPS、域名、密钥管理、备份、日志、监控和恢复验证。
- 开发、内部测试和后续生产环境的明确隔离。

单 ECS 对约 300 DAU 的 MVP 方向成立，但当前没有机器规格、域名、备案、备份目标、监控或可接受停机/数据丢失指标，执行前仍需提供或确认环境。

## 6. AI 现状

RN 当前没有真实 AI client、API、Prompt 执行、schema 校验、同意记录、额度或成本统计：

- 查词弹层只显示后续接入说明。
- 录音只保存在本机临时目录，不上传、不转写。
- AI 模考和报告明确使用固定 Mock 数据。

可复用标准库：

- 当前项目以 `docs/ai/` 作为 AI 能力与基础资产的规范入口。
- Web 参考库有 6 个 AI Route Handler 和 63 个 `features/ai` 文件，覆盖查词、转写、原文对比、语法检查和 OPI 润色链路。
- Web 的 Prompt、schema、航空热词、数字读法、规范化、错误码和 eval 可作为行为证据，但代码不能照搬。

主要风险：

- 相同模型不等于相同效果，必须重建前处理、Prompt、schema、后处理和 eval，而不是只接模型 API。
- RN iOS 当前录音采用 16 kHz 单声道 PCM/WAV，需要确认外部 ASR 的格式、时长和上传限制。
- AI 同意、撤回、额度、成本和原始录音清理必须由服务端强制执行，不能只靠 UI。

## 7. UI 与产品边界

第一阶段页面足以承载真实能力，但需要受控调整：

- 登录页新增微信入口和真实状态。
- 账户页替换演示资料、同步和安全状态。
- 学习页查词弹层替换为真实 AI 内容。
- 口语区增加转写、原文对比、语法检查、OPI 分析和额度状态。
- 设置中增加 AI 数据同意与撤回。
- 注销入口按内部测试边界关闭。

这些调整属于真实能力接入，不授权重做导航、组件气质或学习流程。Mock AI 模考仍必须明确标记，不能与真实 AI 学习能力混淆。

## 8. 风险分级

### P0：执行前必须解决

- 微信与自托管 Supabase Auth 的兼容验证。
- 正式 iOS Bundle ID、回调域名和微信开放平台配置。
- ECS/Supabase/HTTPS、短信、邮件和 AI 测试凭证。
- 用户数据、题库、音频和图片的内部测试访问权限及资源发布方案。
- 确认当前未提交改动的归属，避免后续阶段覆盖用户改动。

### P1：垂直链路必须验证

- SecureStore 会话容量、刷新、失效和重装行为。
- 游客升级不丢失 SQLite 学习数据。
- 题库导入幂等、远程版本和资源签名 URL 失效恢复。
- 同步重复提交、弱网重试和版本冲突。
- PCM/WAV 上传、ASR 准确率和原始录音清理。
- AI 额度和成本上限在并发请求下保持一致。

### P2：内测持续处理

- 单 ECS 的资源争用、日志容量、备份恢复和模型供应商波动。
- iOS 真机上的微信回跳、会话恢复、音频中断和长文本结果展示。
- 第二阶段不测试 Android 带来的平台回归风险；不得据此声明 Android 可用。
- 不提供账号自行注销只能用于内部测试，正式上架前必须重新决策。

## 9. 总体判断

正确执行顺序是：外部前置与微信可行性 -> 后端/Supabase 基础 -> 真实资源 -> 登录账号 -> 学习同步 -> AI 基础与查词 -> 全部语音/文本 AI -> 权益预留 -> iOS 内部验收。

除微信 Auth 兼容性外，未发现需要改变已确认宏观架构的阻塞项。
