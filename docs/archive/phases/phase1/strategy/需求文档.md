# 历史归档：第一阶段需求文档——React Native App 1:1 对照复刻与基础能力

状态：已确认

更新时间：2026-07-11

## 1. 目标

交付可在 iOS / Android 真机运行的 React Native App，按当前 Web 对照基线完成页面、视觉、交互和已有功能效果的 1:1 复刻。

本阶段不是商业化上线，也不要求所有真实内容与服务能力已接入。

## 2. 对照与复刻原则

- 对照基线：`rn-web-baseline-2026-07-11`。
- 复刻范围：当前 Web 的全部既有页面、流程和已有交互。
- 复刻效果：UI、信息层级、页面跳转、操作反馈、动效和状态效果保持一致。
- 使用 React Native 的方式实现，不迁移 Web UI 代码，不使用 WebView。

## 3. 本阶段范围

- 总原则：当前 Web 已有的页面、流程、交互和状态，React Native 版均必须具备对应效果；不按模块删减范围。
- 认证、首页、发现、我的、题库学习、学习记录、标注、账户设置、信息页和状态页。
- 当前已有的单词、文章、资源、课程、随身听、OPI 热点、AI 模考等页面及其现有效果；mock、示例数据和占位可继续保留。
- “体系课程”只复刻 App 内部页面，不迁移独立桌面营销页 `/curriculum`。
- 题库列表、学习卡、翻卡、音频播放、学习进度、标注和笔记等已有学习行为。
- 学习进度、标注和笔记的本地保存与恢复。
- 缺失单词、图片或资源的占位、加载失败和基础异常表现。

## 4. 核心框架要求

- 本阶段不是只做视觉复刻；必须同步建立可承接后续资源、账号、同步、AI 和商业化能力的核心工程框架。
- 页面、导航、状态、资源、本地数据、接口与功能模块需要具备清晰边界，当前 mock 能力可在后续替换为真实能力。
- 后续新增真实功能应在此基础上扩展，避免推翻第 1 阶段的页面、数据或交互结构。
- 具体技术选型与实现方案由后续技术方案文档确定。

## 5. 协作与执行边界

- 用户负责确认需求文档、技术方案、技术盘点和路线图，并只在范围、成本或战略变化时做宏观决策。
- 四份大流程文档确认后，代码实现、验证、问题修复和阶段收口由 Codex 按小流程持续推进，不需要用户逐步接管。
- 技术方案优先选择便于 Codex 稳定实现、验证、维护和后续扩展的路线。

## 6. 本阶段不做

- 不新增当前 Web 尚不存在的真实业务功能。
- 不接入真实账号、云同步、跨设备恢复。
- 不补齐全部单词、图片、真实资源。
- 不接入完整真实 AI、会员、订阅、购买或退款。
- 不改变已冻结的 Web 页面结构、视觉语言或交互流程。
- 不迁移面向桌面浏览器的 `/curriculum` 营销落地页。
- 不进入正式上架、支付和商业化运营。

## 7. 验收效果

- 当前 Web 的既有页面和流程可在 React Native iOS / Android 双端逐页对照。
- 用户可完成“进入题库 → 学习卡 → 音频 → 本地保存学习记录”的完整链路。
- 主要页面不存在明显的字体、间距、滚动、安全区、底部导航或抽屉层级偏差。
- mock、示例与占位页面保持可用；未接入真实能力不得导致页面崩溃或流程中断。
- 核心工程框架可在不推翻当前复刻成果的前提下接入后续真实能力。
- 后续新增真实功能只在 React Native 中开发。
