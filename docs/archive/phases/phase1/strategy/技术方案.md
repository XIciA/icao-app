# 历史归档：第一阶段技术方案——React Native App 1:1 对照复刻与基础能力

状态：已确认

更新时间：2026-07-11

## 1. 方案结论

建立独立的 React Native + Expo + TypeScript 工程，使用 Development Build 在 iOS / Android 真机运行，以 `rn-web-baseline-2026-07-11` 和 `docs/design/ui-style-guide.md` 为共同对照，原生复刻当前 Web 的页面、交互、状态和已有功能效果。

当前 Web 只作为设计、内容、交互和业务规则参考，不迁移 Web UI 代码，不使用 WebView。

第一阶段优先完成可稳定运行的原生 App 和完整对照复刻；真实账号、云同步、完整 AI、支付和商业化能力继续留在后续阶段。

## 2. 技术执行原则

- 只固定会影响长期方向和返工风险的边界，不提前锁死具体库、版本、目录、数据表或算法。
- 具体导航、状态管理、本地存储、测试和组件实现由 Codex 根据兼容性、构建结果、维护成本和最终效果选择。
- 当前实现必须方便后续接入 Supabase Auth、业务后端、云同步、AI 和商业化能力，但第一阶段不提前实现这些真实服务。
- 页面和业务代码不得直接绑定临时数据源、浏览器 API 或未来云服务；通过可替换的数据与平台能力边界连接。
- 视觉和交互以当前设计稿为准，技术便利不能成为改变页面结构、视觉语言或学习流程的理由。

## 3. 工程与模块方向

React Native 工程与当前 Web 设计稿工程分开维护，避免把 Next.js、DOM、CSS 和浏览器依赖带入原生 App。

App 按职责保持清晰边界：

- 页面与导航：负责原生屏幕、跳转、弹层和状态展示。
- 共享视觉组件：负责颜色、字体、间距、圆角、卡片、按钮、导航和状态组件的一致性。
- 学习功能：负责题库目录、学习卡、音频、标注、笔记、学习记录和已有交互规则。
- 数据访问：负责读取当前题库、示例数据和必要本地记录，并为后续远程接口保留替换边界。
- 平台能力：负责音频、录音、权限、安全区、键盘、网络状态和应用生命周期。
- 基础设施：负责错误处理、日志、配置和测试支持。

具体目录结构和组件拆分由 Codex 在创建工程和实施垂直样例时确定。

## 4. 页面与视觉复刻

- 按需求范围内的全部既有页面、流程、弹层和状态逐项建立 RN 对照清单，不按模块删减需求范围；独立桌面营销页 `/curriculum` 不进入 RN 复刻范围。
- 先建立原生设计令牌和少量共享组件，再复刻页面，避免每个页面独立猜测颜色、间距和圆角。
- 以 375 × 812 为主要视觉基准，同时检查 360、390、430px 宽度和 iOS / Android 安全区。
- Web 动效使用原生等价方式实现；保留翻卡、按压反馈、加载和状态切换效果，不复制浏览器动画代码。
- 图标、字体和图片使用适合 React Native 的实现，但视觉结果必须符合现有风格文档。

## 5. 数据与后续接口边界

- 第一阶段使用当前题库 JSON、音频索引、示例数据和 mock 状态支撑页面及核心学习链路。
- 学习进度、标注、笔记和学习记录保留必要的轻量本地保存，防止 App 退出或临时失败造成数据丢失；这不代表建设离线学习功能。
- 页面只依赖统一的数据访问接口，不直接依赖具体本地存储或 Supabase 业务表。
- 后续账号与跨设备同步接入时，替换或扩展数据实现，不推翻页面、学习流程和核心数据语义。
- 第一阶段不建设完整双向离线同步、复杂冲突系统或真实云端业务数据库。

## 6. 题库、音频和图片资源

- 当前资源库是第一阶段复刻和验证的内容来源，但不将全部本地资源直接固化为长期 App 安装包方案。
- 资源读取通过统一边界完成，使开发期资源、后续 Supabase Storage 和未来其他对象存储可以替换。
- 题库、音频和图片以联网访问为最终方向；第一阶段可采用适合开发与真机验证的资源提供方式。
- 允许必要缓存改善加载，但不开发题库下载、音频包下载和离线资源管理。
- 资源缺失、网络失败、音频失败时必须显示明确状态和重试入口。

## 7. 音频、录音与设备能力

- 音频播放与录音优先使用 Expo 稳定能力，录音优先采用 `expo-audio`。
- 使用真实 Development Build 验证麦克风权限、录音开始与停止、音频播放、切后台、中断恢复和失败状态。
- Web 中的 `Audio`、`MediaRecorder`、`navigator` 和 Permissions API 只作为行为参考，不能直接迁移。
- 如果 Expo 能力不能达到现有功能效果，Codex 可以评估第三方原生库、Config Plugin 或自定义模块，并记录原因和影响。

## 8. 验证方案

第一阶段实施时至少包含：

- TypeScript、静态检查和必要自动化测试。
- iOS / Android Development Build 构建验证。
- 核心学习链路的双端真机验证。
- 主要页面与 Web 基线的逐页视觉对照。
- 360–430px 宽度、安全区、滚动、键盘、弹层和底部导航检查。
- 音频、录音、权限、网络失败、资源失败和 App 生命周期状态检查。
- 每个路线图阶段结束时检查 Git 差异和高层战略一致性。

具体测试工具、构建命令和设备矩阵在技术盘点与路线图中根据真实环境确定。

## 9. 主要风险与处理方向

- 当前设计稿包含大量页面、子流程和状态，需要先建立完整对照清单，防止遗漏。
- 当前题库资源约 560 MB，音频文件较多，不能未经评估全部直接打入 App 安装包。
- 现有实现使用 Next.js、DOM、localStorage、浏览器媒体 API、Tailwind 和 Web 动画，需要转换为原生等价能力。
- iOS 与 Android 在字体、权限、音频焦点、安全区和返回行为上存在差异，必须持续真机验证。
- 1:1 复刻范围较大，应先完成一个包含目录、学习卡、音频和本地记录的真实垂直样例，再扩展到全部页面。

## 10. 不采用的路线

- 不使用 WebView 封装当前 Web。
- 不直接迁移 React Web 组件、CSS 或浏览器 API。
- 不在第一阶段提前建设完整后端、真实账号、云同步、支付或商业化系统。
- 不为了未来可能需求提前建设复杂离线系统、微服务或重型客户端数据架构。
- 不另起一套视觉语言、导航模式或产品流程。
