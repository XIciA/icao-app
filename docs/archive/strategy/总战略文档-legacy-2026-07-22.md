# 历史归档：飞猪 ICAO 原生双端 App 与 Web 在线版商业化总战略

> 本版本已于 2026-07-30 被当前总战略替代，仅用于追溯。

状态：总战略基线

更新时间：2026-07-22

## 战略决策

- 正式移动端采用 **React Native + Expo + TypeScript**，交付 iOS / Android 原生 App。
- 正式产品同时支持 Web 在线版；Web 与原生 App 共用 React Native、Expo、TypeScript 主代码库、产品规则、内容和用户数据服务。
- Web 是同一产品的响应式在线版：手机浏览器接近移动 App，PC 浏览器使用桌面导航和宽屏重排；不发展为独立 Web 产品，不替代原生 App。
- Expo 是 React Native 的工程框架，不是 WebView 壳；首个项目从一开始使用 **Development Build**，不以 Expo Go 作为正式能力边界。
- 历史 Web / 高保真设计稿仍只作为设计、内容、交互、状态和业务规则的对照基线；新的 Web 在线版从当前 RN 工程扩展，不恢复或迁移历史 Web 实现。
- 优先使用 Expo 提供的稳定能力；只有录音、音频或其他设备能力确有缺口时，再以原生模块补齐。

## 三类资产的职责

| 资产 | 职责 | 不承担的职责 |
| --- | --- | --- |
| 高保真设计稿 / 历史 Web 项目 | 页面视觉、交互流程、状态规格、题库展示结构、资源与逻辑参考 | 直接迁移为 React Native UI 或正式 Web 在线版 |
| 内容与服务能力 | 题库、音频、词汇、AI、账号、学习记录、同步与接口规则 | 决定 App 的视觉与导航细节 |
| React Native 主工程 | iOS / Android 原生 App、Web 在线版、共享页面与业务、平台适配、发布与运营能力 | 重新定义已定版的产品和设计规则 |

## Web 在线版横向扩展

状态：需求、技术方案、技术盘点与路线图已确认，进入小流程

核心需求：

- 现有 App 面向用户开放的全部页面和功能进入 Web 最终范围。
- 手机浏览器以现有移动 App 为视觉与流程基准；PC 浏览器在同一页面、路由和产品规则上使用桌面导航、内容最大宽度和多栏重排。
- 页面、题库、业务规则、接口契约和同步逻辑优先三端共用；仅浏览器能力差异保留平台适配。
- 题库和词汇继续以云端版本为权威来源，用户数据继续通过同一账号和同步服务在 iOS、Android、Web 间恢复。
- 正式 Web 录音必须运行在受信任 HTTPS 环境；域名、备案、证书和公开发布仍按人工事项与部署规则单独满足。

## 第 0 阶段：Web 对照基线冻结 + RN 启动准备

状态：已收口，不再阻塞开发

核心需求：

- 当前 Web 版本作为 React Native 1:1 对照基线，保留页面、视觉、交互、状态、题库结构和已有资源规则。
- 当前 Web 项目不再承担新增真实功能开发；后续真实功能优先在 React Native 中实现。
- 未接入的单词、图片、账号同步和部分状态不再作为 RN 启动阻塞项，转入后续阶段完成。

完成标准：

- 已明确正式客户端采用 React Native + Expo。
- React Native 可直接启动独立工程，并以当前 Web / 设计稿为对照复刻依据。

## 第 1 阶段：React Native App 1:1 对照复刻与基础能力

核心需求：

- 在独立 React Native 工程中复刻当前 Web 的页面结构、视觉效果、交互流程和已有功能效果。
- 交付 iOS / Android 真机可运行的基础 App，不做 WebView 封装，也不直接迁移 Web UI 代码。
- 先建立稳定的本地学习体验，为后续真实资源、账号与 AI 接入提供基础。

要做什么：

- 建立 React Native + Expo + Development Build 工程，确定导航、状态、接口、缓存、错误处理和日志的基础结构。
- 按当前 Web 对照基线复刻题库、学习卡、发现、我的及已有独立页面的视觉与交互。
- 使用现有题库 JSON、音频和示例数据完成页面展示；缺失资源提供明确占位与失败回退。
- 实现本地学习进度、标注 / 笔记等已有学习行为的基础保存与恢复。
- 在 iOS / Android 真机持续验证不同屏幕尺寸、音频、权限弹窗、切后台和基础异常状态。

本阶段结束标准：

- 当前 Web 的既有页面和交互可在双端 React Native App 中完成 1:1 对照复刻。
- 用户可以完成本地题库学习、音频播放和学习记录保存 / 恢复。
- 页面和交互符合移动端学习 App 体验，不是 Web 页面简单搬运。

## 第 2 阶段：真实资源、账号同步、AI 与商业化能力完善

核心需求：

- 将第 1 阶段的对照 App 完善为可内测、可商业化演进的真实产品能力。

要做什么：

- 补齐单词、图片、真实音频和其他首版内容资源，并完善离线、缓存、更新与失败回退规则。
- 接入登录、账号、学习记录云同步与跨设备恢复，明确同步失败和数据冲突处理。
- 接入首版真实 AI 能力，明确调用失败、超时、额度、成本控制与用户提示。
- 完善加载、弱网、权限失败、同步失败、AI 失败等关键状态。
- 落实会员、订阅或 AI 增值能力所需的权益规则、购买、恢复购买和退款说明基础。
- 在 iOS / Android 真机验证核心学习链路、资源、账号、AI 与商业化能力。

### 第二阶段 C 账号决策

- App 取消匿名游客和免登录使用，邮箱密码账号是当前唯一登录方式；无有效会话不能进入题库、资源、同步或 AI。
- 当前封闭内测允许邮箱注册自动确认。Mailpit 只用于换绑邮箱和找回密码测试，不向公网邮箱发信。
- 手机号、微信、Apple、正式 SMTP、公司主体、域名、备案和公开运营继续延期。
- 账号支持当前设备退出、全部设备立即退出、修改密码、测试邮件换绑/找回、注销和活跃数据删除。

### 第二阶段 A：已完成的先行执行切片

- 先使用现有 ECS 完成题库/资源云端接入和学习数据同步。
- 邮箱密码只作为同步所需的最小用户归属；关闭邮箱确认，仅限受控测试。
- 云端是权威数据源，App 保留内嵌题库和本地数据作为缓存、失败保护和迁移回退。
- 首次登录由用户确认是否把本机未归属学习数据合并到当前账号，不自动跨账号合并。
- 域名、备案、HTTPS 公网联调、SMTP、短信、微信、AI、OSS/CDN、异机备份和商店能力延期，并保留可替换接口。
- 第二阶段 A 完成不代表完整第二阶段或微信 Auth P0 已完成。
- 本切片已于 2026-07-12 完成，后续回到完整第二阶段路线图继续。

本阶段结束标准：

- 题库、资源、账号、同步和首版 AI 能力在已定边界内可靠可用。
- 商业化能力具备进入上架准备的产品与技术基础。
- 内测反馈没有阻塞正式上架的核心技术问题。

## 第 3 阶段：正式上架准备

核心需求：

- 完成审核、合规、商店展示和上线运营所需材料准备。

要做什么：

- 准备商店资料：名称、图标、截图、简介、关键词、测试账号。
- 准备合规材料：隐私政策、用户协议、权限说明、账号注销和数据删除说明。
- 准备收费说明：会员、订阅、退款、恢复购买和权益说明。
- 按目标渠道要求完成提交前检查、版本构建和提审准备，避免因材料缺失返工。

## 第 4 阶段：正式上线与商业化收费运营

核心需求：

- 通过正式发布和收费运营扩大用户规模与市场影响力。

要做什么：

- 正式发布稳定版本，先保证用户能顺利开始学习。
- 观察真实使用数据和反馈，优先修复影响信任和转化的问题。
- 按既定收费方案开启会员、题库包或 AI 增值能力。
- 持续优化获客、留存、转化和内容更新效率。
