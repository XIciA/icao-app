# 学习保存与三端同步梳理

日期：2026-11-03。范围来自当前用户要求：全面梳理 iOS、Android、正式网页学习保存及同步，优先后台可靠保存和自动恢复，减少打扰。本页为本轮调查与修复方案，不新增项目长期规则。

状态：本页保留 11 月 3 日首轮调查与用户确认的验收标准。后续学习保存与同步已随 3596169 交付，下载／离线音频回归再由 PR #330 修复；当前实施、发布与待验状态以[执行记录](implementation.md)为准。下文的“当前问题／待修”指调查时状态，不代表现在仍未实施；真实三端体验仍待用户在对应候选验收。

## 用户体验目标

2026-11-03 用户确认：以下六项是本轮最终体验验收标准。

1. 正常学习自动保存，用户不用操心。
2. 断网也能保留学习结果，恢复联网后自动同步。
3. 三端同账号、同范围的进度最终一致，收到更新后页面自动刷新。
4. 两端同时学习不互相冲掉结果，重试不重复生成历史。
5. 切账号不串数据，删除的记录不被旧设备重新传回来。
6. 只有确实无法可靠保存、存在丢失风险时才作必要提示。

### 本轮改动安全边界（用户同日确认）

- 本次是对现有 App 的优化，保留已经正常的功能与用户数据。每项修改必须能对应确认的问题或必要依赖，不顺带重构、整理无关代码或更换技术栈。
- 优先复用现有存储、同步和账号隔离机制。必要的共享根因修复可以修改相关实现，但应限定影响范围；不能为了避免改共享代码而复制实现或只在页面掩盖错误。
- 修改前明确现有正常行为和受影响调用方；修改后同时验证正常流程及故障恢复，保护现有去重、删除墓碑、重置代次、账号隔离与历史数据兼容。
- 按可独立验证的改动推进，发现回归先解决，不叠加未经验证的扩大改动。现有测试通过只是基线，不能代替新增故障覆盖或实际三端核心体验验收。
- 最终按上述六项体验逐项记录证据和未验证边界；不承诺绝对无故障，不把代码检查通过等同于用户验收通过。

### 数据语义补充

- 同一账号、同一内容范围的累计学习进度，在联网同步完成后应一致；短暂延迟不得成为长期不一致。
- 用户正常学习时持续本地保存；上传失败自动恢复，不要求反复点击保存。只有确实无法可靠留存且有丢失风险时，给必要、克制的提示，不用静默吞错冒充成功。
- 历史、进度、续学位置分别具有明确语义：删除历史不清空累计进度；重做题目不降低累计完成状态；查看历史不产生新学习进度。
- 重试、重复响应与应用重启不能重复生成历史。切换账号不得串数据；明确删除或清空的数据不能被旧设备复活。

## 数据范围与现有责任链

| 数据 | 当前来源与路径 | 核对重点 |
| --- | --- | --- |
| 题目累计进度、续学位置、选项状态 | useStudySession.native → learning-store.native → 本地 topic 状态 → card_state 待上传队列 → sync API → 另一端本地状态 → 目录 | 持久化、漏入队、冲突、刷新；各字段不能一律覆盖 |
| 学习历史、模考报告、热点学习回顾 | saveReport → addRecord → learning-record-storage.native 的摘要与详情 → learning_record 队列 | 报告和累计进度一致；摘要详情原子保存已有保护；重试幂等 |
| 我的回答、转写与 AI 结果 | StudyWorkbench.native → 独立 ai_result 记录 → 学习历史按 session/item 组合 | 文本自动保存、结果关联、历史继承不重新写入、删除与清空 |
| 笔记与标注 | annotation-store.native → 当前账号工作区 → annotations 文档同步 | 已有失败保留/flush；仍需检查持久化和入队失败、跨端合并 |
| 关联词汇学习与收藏 | vocabulary progress/persistence → vocabulary 文档同步 | 共用同步引擎变更的回归范围；不是把词汇进度当题库进度 |
| 录音原文件 | recording repository/session 的独立职责 | 录音完成标记和时长不等于录音文件跨端同步；本方案不据此新增录音云存储 |

正式 Web 的 Metro 映射（tools/edgeone-shared-modules.cjs）使用共享原生业务模块，包括认证、同步、学习流程；浏览器存储走 storage.web。不能凭旧 AuthProvider.web 的登录模式分支判断正式网页不支持同步。iOS、Android 共用学习与同步业务，实际系统存储/生命周期仍需分别验证。

## 已确认实现与缺口

1. **N-02：进度失败与完成脱节。** useStudySession.native:238 起先更新页面内状态，再异步 saveCardState；失败只记录 saveFailure。finish/saveReport 不等待全部题目进度写入。完成页可能有历史而缺累计进度。已有前轮故障注入证据，本轮核对源码仍存在。
2. **本地数据与待上传队列分步写。** learning-store.native:151 起先写 topic，再 enqueueCardState；addRecord 也先写本地记录，再入队。后一步失败时存在本地已保存、待上传未登记的窗口。需在已有存储与同步所有者中实现原子提交或可恢复的持久化登记，不能只重试现有队列或在页面补提示。
3. **自动同步恢复不足。** scheduleLearningSync 800ms 单次调度失败后吞掉调用拒绝，没有在此安排后续退避重试。当前主要靠新写入、工作区切换、回前台等触发；未找到常驻前台远端变化的持续获取机制。需按前后台和联网状态设计自动恢复，不能无界请求或把队列错误反复弹窗。
4. **进度页面缺更新订阅。** applyChange 的 card_state 写入本地后没有进度变更通知；目录 useFocusEffect 按进入/依赖变化读取。已收到的远端进度可能未反映到当前目录。历史存储已有 listeners，不能一概说所有列表均无刷新。
5. **网页持久化失败可能被伪装为成功。** storage.web 的数据库打开失败/blocked 退回 memoryFallback，写方法返回成功；内存无法保证刷新后保留。数据库正常打开后的事务写失败会 reject，不是所有失败都被吞掉。读取失败也有返回 fallback/空值的路径，需要防止误判为空数据再覆盖。
6. **续学位置的冲突合并不足。** API applyCardState 中旧/相同实体版本分支，只合并新增 visited/completed，否则回传云端状态，不合并传入 lastVisitedAt；新版本分支保留缺省字段但不能单凭客户端版本判定跨端访问先后。需明确续学位置合并规则并验证时间偏差；不能认为所有进度字段已由累计布尔合并解决。
7. **并发与重启边界待故障验证。** topic 本地写队列、同步 applyChange 和浏览器多个标签页的读改写不是同一个跨端事务。存在需检查的交错窗口，当前尚无复现结论，不标作已确认丢数据。

已有保护必须保留：服务端按账号事务锁；mutationId 去重及载荷校验；累计 visited/completed 合并；删除墓碑；学习数据/AI 重置代次；客户端工作区账号隔离；历史摘要和详情 multiSet。修复应加强这些机制，不另建一套同步系统。

## 修复顺序

1. 定义保存成功边界：先可靠持久化本次变更及待同步责任，再让后台独立上传。既有失败不能因另一个题目的成功而被清掉；完成报告与应保存进度要可恢复一致。
2. 统一后台调度：重试退避、恢复联网/前台触发、前台远端更新获取、认证与永久错误分类、账号切换取消。保留待处理数据和故障证据，避免无限快速循环。
3. 完成下载到显示的闭环：远端提交到本地成功后通知相应页面；持续学习中的本地未上传变更不能被迟到响应覆盖。
4. 核对多端合并：累计进度、续学位置、独立会话、回答、笔记、删除分别制定字段级处理，保留现有用户数据；题目更新的稳定身份检查遵守长期规则。
5. 网页持久化与并发补齐：不能把内存态称为已持久化；检查禁用/阻塞数据库、存储配额、多标签页和刷新。
6. 校验历史存量：先只读比对本地/云端摘要和待上传信息。缺失项仅在能可靠归属且无删除/清空冲突时恢复，不能把所有历史回放成新进度；生产批量修复与部署仍按已有授权边界执行。

## 必须覆盖的验收场景

| 场景 | 结果要求 |
| --- | --- |
| iOS→Android、Android→Web、Web→iOS，及反向组合 | 相同账号/题库/范围的进度、历史与续学符合各自语义，页面自动更新 |
| 断网学习，恢复网络 | 本地可继续，恢复后自动上传下载，无重复历史 |
| 本地写成功但入队失败、上传成功但响应丢失 | 可恢复，不漏传、不重复、不中断其他正常数据 |
| 保存途中退出/杀进程/网页刷新，再进入 | 已确认持久化的数据不丢；未完成操作按持久化恢复依据续做 |
| 两端同时学不同题、同一题或不同会话 | 累计进度不倒退，会话不互相覆盖，续学位置符合明确规则 |
| 同步与本地作答同时发生 | 迟到云端响应不覆盖未提交的新编辑 |
| A账号同步中切到B，随后旧请求返回 | B不受A数据污染，A待同步数据保留在A工作区 |
| 删除历史/清空数据后旧设备联网 | 不复活被明确删除的数据；删除历史不清累计进度 |
| 题库更新/范围切换/历史回顾 | 稳定身份不串题；比较相同范围；回顾不增加进度 |
| 浏览器数据库不可用、配额不足、多标签页 | 不虚报持久化成功，不把读取错误当空数据覆盖 |
| 正常完成、提前退出、模考、热点、五库 | 按各入口实际 progressMode 验证，不能强行把 session-only 写入累计进度 |

真实跨端验收须记录安装包/网页构建、账号匿名标识、内容版本、网络状态、操作次序和结果。不用源码检查或 mock 通过冒充真机验收。截图用户的具体原因尚需对应网址、版本、账号及不同进度类型，当前不推断其数据已丢失。
