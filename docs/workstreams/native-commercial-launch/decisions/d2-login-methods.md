# D2 正式登录方案决策

状态：已确认；iOS 提交仍有前置条件
确认日期：2026-08-09
关联需求：[Native App 正式商业上线总需求](../requirements.md)

## 决策

- Native 正式账号采用 **手机号验证码 + 微信登录**。
- iOS 和国内 Android 共用同一正式账号体系。
- Apple 登录暂不接入；首发不提供邮箱或密码登录。
- 邀请码退出登录链路，只保留后续活动或权益用途。

## 账号规则

- Supabase `auth.users.id` 继续作为唯一业务用户 ID；手机号和微信只是登录身份。
- 微信用户可主动绑定手机号，但不强制绑定。
- 新身份只能在已登录并重新验证后绑定；不得按昵称等弱信息自动合并账号。
- 身份已属于另一账号时停止绑定并进入受控冲突处理；禁止静默覆盖数据或权益。
- 至少保留一种可用登录方式，不允许解绑最后一个身份。

## iOS 上线前置条件

Apple App Review Guideline 4.8 明确将微信登录列为第三方登录场景。当前“手机号 + 微信、无
Apple”的组合可以先开发，但不能直接视为已满足 iOS 最终提交条件。

iOS 提交前必须二选一并留下最终验收记录：

1. 增加 Apple 或其他已验证符合 4.8 的等效隐私登录；或
2. iOS 正式包隐藏微信登录，仅保留手机号验证码；Android 继续提供手机号 + 微信。

在该选择完成前，D2 不阻塞手机号和微信的内部实现，但属于 iOS 商店提交阻断项。

参考：<https://developer.apple.com/app-store/review/guidelines/#login-services>
