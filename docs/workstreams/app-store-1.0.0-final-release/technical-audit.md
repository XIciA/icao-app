## 一、审计说明

- 本审计以最新 `origin/main` 的代码、配置、测试和仓库内规则为技术事实，以负责人在本轮提供的
  Apple、TestFlight、备案和微信开放平台截图为外部平台事实。
- 当前工作区在审计开始时处于旧 detached HEAD；为了避免用旧代码写新规则，已只读确认差异并切换到
  `origin/main` 对应 detached HEAD。尚未创建任务分支、提交、构建或部署。
- “代码存在”不等于“生产可用”，“平台已创建”不等于“真机闭环通过”。以下状态严格区分：
  已实现、已配置、已部署、已上传、已真机验收、可提交和已提交。

- `app.json` 用户版本保持 `1.0.0`；App Store Connect 当前最高已上传 Build 为 `3493765`。

  OTP/密码/Apple/微信登录闭环（PR #86—#90，最终基线 `8e90bdd`）。

## 四、关键问题一审计：登录与账号闭环

### 4.1 已实现

- `src/components/auth/login-screen.tsx` 已提供 OTP/密码切换、忘记密码、Apple 登录、16+和协议勾选。
- `src/features/auth/phone-otp-challenge-store.ts` 已使用 SecureStore 保存手机号、用途和时间元数据，
  不保存验证码；未过期挑战可在页面重新进入后恢复。
- OTP 有服务端签发时间、5 分钟有效期和重发时间；验证码验证成功后会清理挑战。
- `AuthProvider` 及最近提交已经处理“迟到的启动会话恢复覆盖刚完成 OTP 登录”的已知竞态，并有相应
  测试。
- 账号安全页已有绑定手机号、设置/重置密码、近期认证和注销入口。

### 4.2 2026-09-04 收口状态

- 方案 A 登录 UI、同屏 OTP/密码切换、圆形 Apple/微信入口、统一 OTP 用途挑战和会话 generation 已通过
  PR #90 进入 `origin/main`；旧会话异步任务不能覆盖较新的交互式登录。
- 微信官方 NoPay OpenSDK、Native 桥、服务端 code 交换、身份冲突/近期认证/注销和“只允许微信登录、
  禁止微信支付及客户端秘密”的发布门禁已进入主线。
- 聚焦认证/API测试、完整 `pnpm check:ci`、iOS Release Simulator 构建及独立安全复审已通过，P0/P1
  已关闭。
- 真实微信移动应用 AppID、已审核 Universal Link、服务端 AppSecret、线上 AASA 和最终真机授权仍为
  `WAITING_HUMAN`；最终 Build 尚未完成 OTP/密码/Apple/微信真机总验收。

### 4.3 风险

- 如果在现有多个页面上分别补状态，会再次产生 OTP 生命周期、会话采纳和导航竞态。
- 微信第三方身份若直接等同业务账号，可能导致跨端串号、重复赠送或后续无法绑定手机号。
- 微信 SDK 可能引入新的 PrivacyInfo、URL Scheme、网络数据或审核披露；接入后不能沿用“无微信”的
  旧归档和商店隐私答案。

## 五、关键问题二审计：会员购买

### 5.1 已实现

- D4 已冻结五档非自动续期商品、Product ID、天数、价格原则、重复购买顺延、退款重算和中国大陆范围。

- StoreKit、本地商品合同、服务端账本、Notifications V2 和 Sandbox/Production 隔离已有大量自动化
  基础，不需要推倒重做。

### 5.2 2026-09-04 收口状态

- 商品发现错误分类、有限恢复生命周期、不确定交易、账号/环境代次和购买后统一权益刷新已通过 PR #86
  进入 `origin/main`；不使用假商品或本地硬编码价格。
- StoreKit 与热点权益集成聚焦门禁共 14 个套件、130 项测试通过，iOS TestFlight 静态发布合同通过。
- 五档 IAP 已创建、具有简体中文名称/说明和中国大陆价格，当前仍因缺少五张审核截图显示
  `MISSING_METADATA`；最终 CHN/自动新增地区关闭仍须在提交前读取平台实时值反查。
- Build `3493766` 尚未上传，五档真实本地化价格、购买、恢复、重购、退款和环境隔离仍缺最终
  TestFlight 真机证据。

### 5.3 风险

- 直接延长 loading 或增加无限重试会掩盖根因并造成重复付款风险。
- 使用本地假价格或审核专用商品会违反已确认的 StoreKit 单一价格源和真实审核要求。
- 如果 entitlement 刷新与内容缓存分离，购买成功后热点和题库仍可能显示锁定。

## 十、审计结论

- 项目不是“只剩手续”：Apple 付费手续前三项已经完成，但四个关键问题都包含真实代码、原生配置、
  服务端和真机验收工作，其中微信登录和商业闭环工作量最大。
- 现有架构已具备良好基础，无需重写 App；最稳妥路线是统一状态所有者、补齐微信身份、修复 StoreKit
  真机链路、建立唯一品牌派生链、类型化热点权限，再生成一个全新的最终候选 Build。
- 微信平台人工节点可能等待，但它只阻塞微信最终集成和提交门禁；热点、Logo/UI、商业、材料草案和
  自动化验证可持续并行，不得因负责人未即时响应而停止整体工作。
