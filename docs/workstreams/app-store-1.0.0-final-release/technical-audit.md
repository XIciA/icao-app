  `origin/main` 对应 detached HEAD。尚未创建任务分支、提交、构建或部署。
- “代码存在”不等于“生产可用”，“平台已创建”不等于“真机闭环通过”。以下状态严格区分：
  已实现、已配置、已部署、已上传、已真机验收、可提交和已提交。

## 四、关键问题一审计：登录与账号闭环

### 4.1 已实现

- `src/components/auth/login-screen.tsx` 已提供 OTP/密码切换、忘记密码、Apple 登录、16+和协议勾选。
- `src/features/auth/phone-otp-challenge-store.ts` 已使用 SecureStore 保存手机号、用途和时间元数据，
  不保存验证码；未过期挑战可在页面重新进入后恢复。
- OTP 有服务端签发时间、5 分钟有效期和重发时间；验证码验证成功后会清理挑战。
- `AuthProvider` 及最近提交已经处理“迟到的启动会话恢复覆盖刚完成 OTP 登录”的已知竞态，并有相应
  测试。
- 账号安全页已有绑定手机号、设置/重置密码、近期认证和注销入口。

### 4.2 当前缺口

- 当前登录 UI 仍是旧的分屏/大按钮结构，不是已选定的方案 A；验证码与手机号不在同一主表单，
  Apple 按钮层级过高，尚无圆形第三方快捷登录区。
- 当前 OTP Challenge 类型只直接覆盖 `login | recovery`；绑定、近期认证和注销需要纳入统一用途模型
  审计，避免不同页面并行维护不一致的验证码生命周期。
- 负责人真机曾多次复现“验证码正确但失败/过期”“成功后又回登录页”。主线已有针对性修复，但尚未在
  新的最终 TestFlight Build 上完成完整闭环验收，不能仅以单元测试判定结束。
- 当前没有微信 OpenSDK 依赖、Native 配置、登录入口或生产 code 交换。既有 `check-wechat-runtime-freeze`
  仍把“没有微信”当发布条件，和最新决定直接冲突。
- D2、D7、D9 的旧冻结正文已在本轮更新为“1.0.0 启用微信登录、继续禁用微信支付”；历史追溯行保留
  旧决定并由 2026-08-31 新决定明确覆盖。
- 微信移动应用审核、AppID、Universal Link、AASA、AppSecret 和隐私字段尚未核实，构成微信最终验收
  的外部依赖，但不应阻塞其他工作流。

### 4.3 风险

- 如果在现有多个页面上分别补状态，会再次产生 OTP 生命周期、会话采纳和导航竞态。
- 微信第三方身份若直接等同业务账号，可能导致跨端串号、重复赠送或后续无法绑定手机号。
- 微信 SDK 可能引入新的 PrivacyInfo、URL Scheme、网络数据或审核披露；接入后不能沿用“无微信”的
  旧归档和商店隐私答案。

## 五、关键问题二审计：会员购买

### 5.1 已实现

- D4 已冻结五档非自动续期商品、Product ID、天数、价格原则、重复购买顺延、退款重算和中国大陆范围。
- `MembershipPage.tsx` 已渲染会员状态、AI 点数、五档 offerings、刷新和恢复入口。
- `CommerceRuntimeProvider.native.tsx` 已校验服务端目录与本地/StoreKit 商品合同，处理购买、恢复、
  不确定交易、AppState 对账和账号切换代次。
- StoreKit、本地商品合同、服务端账本、Notifications V2 和 Sandbox/Production 隔离已有大量自动化
  基础，不需要推倒重做。

### 5.2 当前缺口

- 负责人在 TestFlight 真机截图中稳定看到“商品暂时不可用”，说明 App Store 商品发现的真实链路未
  闭合。当前 UI 把多种原因压缩为同一文案，无法区分平台元数据、StoreKit 查询、账号、环境、Bundle、
  商业目录或原生桥接问题。
- “恢复购买”曾进入持续“正在恢复购买…”状态，说明恢复操作缺少对真机异常路径有效的有限生命周期，
  或底层完成/错误回调没有可靠回到 ready。
- 现有主线是否已经包含后续 commerce 临时分支的全部修复需要以 PR/commit 重新核对；不能把未合入
  或已中断 Agent 的工作当成完成。
- 五档 IAP 的最新 App Store Connect 状态、审核截图、可提交状态和最终 CHN 供应范围尚未在本轮重新
  读取；旧记录中的 `MISSING_METADATA` 不能假定已经消失。
- 尚无最终候选 Build 上的五档真实本地化价格、购买、恢复、重购、退款和环境隔离真机证据。

### 5.3 风险

- 直接延长 loading 或增加无限重试会掩盖根因并造成重复付款风险。
- 使用本地假价格或审核专用商品会违反已确认的 StoreKit 单一价格源和真实审核要求。
- 如果 entitlement 刷新与内容缓存分离，购买成功后热点和题库仍可能显示锁定。

## 六、关键问题三审计：Logo 与全局 UI

### 6.1 已实现

- `assets/images/icon.png` 是负责人提供且已确认的蓝色“5 + 飞机 + 青色声波”正方形图；`app.json`
  的 Expo、iOS 和 Android App Icon 已引用该文件。
- Native 全局加载页已有直接引用该母版的实现和测试。
- 项目已有统一颜色、字体、间距、圆角和 Lucide 图标规则。

### 6.2 当前缺口

- `app.json` 的 Android splash 仍引用 `assets/images/splash-icon.png`，该文件是独立、残缺的白色图形，
  与“唯一母版”决策冲突。
- 仓库还存在 Android foreground/background/monochrome、favicon、官网和 promo 等品牌相关文件；
  尚无清单明确哪些是 Native 受控派生物、哪些是冻结网站资源、哪些应删除。
- 现有品牌展示没有统一 `AppBrandLogo` 组件，页面仍可能以不同 `resizeMode`、容器裁切或近似飞机图标
  展示品牌，造成用户指出的“飞机只有一半”问题。
- 尚未完成最终正式路由的全量视觉矩阵；已知需检查启动/加载、登录、发现、题库、录音、会员、热点、
  账号、安全、隐私和所有状态页。

### 6.3 风险

- 直接删除所有名含 icon/logo 的文件会误伤 iOS/Android 必需派生资源和被冻结的公开网站。
- 只替换某一张图片不能保证未来母版调整能全局生效；需要资源所有权、生成链和静态门禁共同完成。

## 七、关键问题四审计：OPI 热点

### 7.1 已实现

- 热点 brief、题目映射、构建脚本和校验脚本已经存在；页面可展示日期、考点、话题数和学习入口。
- `loadQuestionBank('opi')` 已使用正式题库内容访问能力，会员权限由服务端/仓库层判断。

### 7.2 当前缺口

- `HotspotDetailScreen.native.tsx` 当前直接捕获 `Error.message` 并作为用户描述显示；服务端返回
  `membership_required` 时就原样出现在正式 UI。
- 页面把会员锁定、网络失败、内容不存在和数据异常统一成红色“读取失败 + 重新加载”，没有正确引导
  用户查看会员，也没有防止无意义重复请求。
- 当前会员页购买/恢复后是否会使热点缓存失效并立即重取授权没有完整端到端证据。
- 热点摘要与完整会员题目的 API/缓存边界需要确认，避免无权限用户已经拿到完整题目、仅由 UI 隐藏。

### 7.3 风险

- 只把 `membership_required` 翻译成中文仍是补丁；必须让访问层返回类型化状态并统一权限刷新。
- 热点缓存如果不含账号和环境，会在账号切换或 Sandbox/Production 间串用授权。

## 十、审计结论

- 项目不是“只剩手续”：Apple 付费手续前三项已经完成，但四个关键问题都包含真实代码、原生配置、
  服务端和真机验收工作，其中微信登录和商业闭环工作量最大。
- 现有架构已具备良好基础，无需重写 App；最稳妥路线是统一状态所有者、补齐微信身份、修复 StoreKit
  真机链路、建立唯一品牌派生链、类型化热点权限，再生成一个全新的最终候选 Build。
- 微信平台人工节点可能等待，但它只阻塞微信最终集成和提交门禁；热点、Logo/UI、商业、材料草案和
  自动化验证可持续并行，不得因负责人未即时响应而停止整体工作。
