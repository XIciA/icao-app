## 一、执行组织

- 协调 Agent 是唯一入口，负责范围、阶段门禁、Agent 分派、代码复查、PR 合入、生产发布、Apple/微信
  平台操作和人工提示。
- 每个写入任务从最新 `origin/main` 建立短期 `codex/` 分支和独立 worktree；限定文件范围，完成小流程
  后经 PR 合入 `main` 并删除临时分支/worktree。
- 正式 TestFlight、App Store、生产 API、数据库迁移和公开材料只来自干净 `origin/main`。
- 专职角色按阶段启用：
  - 登录与微信 Agent；
  - 商业与 StoreKit Agent；
  - UI、唯一 Logo 与热点 Agent；
  - 独立审计 Agent（只读，不修复自己的发现）。
- 灵活细节任务只在文件范围不冲突时并行；协调 Agent 统一共享接口，禁止为赶进度建立第二套账号、
  权益、Logo 或内容权限实现。
- 子 Agent 数量和角色按真实依赖动态调整；每个任务必须有范围、接口、验收、证据和回滚合同。Agent
  停滞、越界、反复失败或与主线漂移时，由协调 Agent保存检查点、停止写入并重新分配，不让单个 Agent
  的异常拖垮长任务。
- 阶段状态、提交、测试、风险和下一步持续落盘到阶段记录，保证上下文压缩、任务接管或 Agent 轮换后
  可以从证据继续，而不是重新猜测。

## 二、非阻塞人工队列

所有任务按三类队列维护：

- `READY`：无需负责人输入，可立即执行；
- `WAITING_HUMAN`：等待密码、验证码、扫码、法律/事实确认或真机操作；
- `DONE`：已有可复核证据。

执行规则：

- 一个任务进入 `WAITING_HUMAN` 只冻结它和它的直接后继，不冻结同阶段其他 Agent，也不冻结后续不依赖
  它的材料、代码、测试和审计。
- 例如微信移动应用认证等待扫码时，继续完成 OTP/密码状态机、热点、唯一 Logo、商业闭环、UI 审计、
  测试和商店材料草案；只有“微信生产真机通过”和“最终提交”保持等待。
- 负责人长期未响应时，协调 Agent 继续消耗所有 `READY` 项，集中维护一个最小人工清单，不重复催促
  同一事项，也不把外部平台等待误报为整体停止。
- 只有到最终候选集成、TestFlight 验收和正式提交这些汇合门禁时，尚未完成的直接依赖才允许阻塞。

## 三、阶段 0：基线、规则与工作区冻结

### 工作

- 以最新 `origin/main`、App Store Connect、微信开放平台和生产服务重新读取当前事实。
- 固化本目录四份大流程文档；D2、D4、D7、D9 已更新为微信现行口径，执行开始时再次复核；历史
  追溯保留但不再约束当前任务。
- 列出已上传 Build、现有商品状态、平台字段、生产版本、数据库迁移和所有待人工事项。
- 创建阶段记录和证据目录；平台截图、归档证据和凭据放仓库外或受保护/忽略目录。

### 禁止

- 不从旧 detached HEAD 开发；不使用未合并分支或旧 Build 作为正式来源。
- 不把手机号、密码、验证码、银行、税务、Apple/微信密钥写入仓库。

### 完成标准

- 规则无微信口径冲突；工作区从最新主线建立；四个问题和上架主线各有明确状态与负责人。

## 四、阶段 1：四个关键问题并行收口

本阶段允许三个写入 Agent 并行，独立审计在阶段末统一进入。

### 1A 登录与微信闭环

#### 工作

- 实现方案 A 登录 UI、唯一 Logo、OTP/密码切换、协议勾选和圆形 Apple/微信入口。
- 将 OTP 登录、绑定、找回、近期认证和注销纳入统一挑战合同；完成会话代次和根级认证门。
- 全量回归手机号 OTP/密码、Apple、绑定、解绑、找回、退出和注销。
- 选择并锁定兼容 Expo 55/RN 0.83 的微信 OpenSDK 方案，完成客户端、Config Plugin、服务端 code
  交换、identity 映射、冲突处理、注销和防重复赠送。
- 更新发布门禁，从“禁止任何微信”改为“允许微信登录、禁止微信支付和客户端秘密”。
- 同步隐私政策、第三方清单、商店标签草案和审核说明。

#### 人工节点

- 微信移动应用创建/审核、企业确认、扫码、验证码、AppID/AppSecret 查看和 Universal Link 验证。
- 这些节点进入 `WAITING_HUMAN` 后，Agent 转去完成可离线实现和自动化测试，不等待空转。

#### 验收

- 四种登录入口及异常路径通过；有效 OTP 状态可恢复；登录成功不回弹；账号安全/注销无冲突；
  微信真机授权、取消、重放和账号映射通过；归档无微信支付。

### 1B 商业与 StoreKit 闭环

#### 工作

- 读取 App Store Connect 五档商品、协议、地区和元数据，定位 TestFlight 商品发现失败的事实根因。
- 修复商品目录加载、错误分类、恢复生命周期和不确定交易对账；不引入假商品或假价格。
- 验证服务端 JWS、Notifications V2、幂等、退款、环境隔离和权益刷新。
- 建立商业状态机测试、StoreKit 本地测试和 TestFlight 真机测试清单。

#### 人工节点

- Apple 双重认证或平台重新登录；沙盒购买时在 iPhone 确认。
- 等待人工期间继续服务端、客户端、商品元数据、测试和截图模板工作。

#### 验收

- 五档本地化商品可见；购买、取消、pending、恢复、重购、退款和环境隔离通过；无无限恢复、无重复
  扣款风险；购买后题库/热点立即刷新权益。

### 1C 唯一 Logo、全局 UI 与热点

#### 工作

- 建立 `assets/images/icon.png` 唯一母版、共享 `AppBrandLogo`、受控派生清单和静态检查。
- 移除 Native splash 对残缺 `splash-icon.png` 的运行时依赖；不修改冻结的官网/Vercel资源。
- 对全部正式路由执行小/大屏、状态、键盘、安全区、动态字体、图标和原始错误码审计。
- 将热点访问改为类型化状态；实现会员锁定、网络、下线、离线授权和内容异常的独立体验。
- 实现会员购买/恢复后的统一 entitlement 事件和热点即时刷新。

#### 验收

- Native 品牌只有一个母版和确定性派生链；所有品牌图完整无裁切；全局 UI 无已知明显缺陷；
  热点不显示 `membership_required`，权限变化即时生效且不泄露会员题目。

### 1D 独立审计与集成

- 独立审计 Agent 在干净集成提交上检查三个 Agent 的变更、接口边界、竞态/幂等、安全隐私、迁移回滚、
  原生配置、性能资源、真实设备边界、测试和材料一致性；不得修改被审计代码或审计自己的改动。
- 审计发现必须包含 P0/P1/P2/P3 等级、代码位置、复现步骤、影响和复验方法。P0/P1 未关闭不得进入下一
  阶段；修复后由同一独立审计角色在新提交上复验，不能由修复者自行宣布关闭。
- 协调 Agent 按审计项分派修复、复验并依次合入 `main`；运行聚焦检查后再运行完整 `pnpm check`。
- 若三个分支修改共享接口，先在协调分支确定接口再重放各分支，禁止直接拼接冲突代码。

### 阶段完成标准

- 四个关键问题自动化、集成和可用外部环境验证通过；没有必须重新设计的 P0/P1 缺陷。
- 等待微信平台的外部动作可以尚在队列；其余代码必须完成并独立审计。微信保持隐藏时不阻塞最终
  Build；只有准备在用户界面启用微信入口时，生产配置和真机授权才是前置条件。

## 五、阶段 2：生产服务与最终候选包

### 工作

- 数据库迁移在副本演练，确认备份和回滚后应用 Production；部署从 `origin/main` 构建的生产 API。
- 配置 Apple、腾讯云和 DeepSeek 受保护生产参数；微信参数仅在开放平台审核通过并准备启用入口时
  配置。验证公开法律、支持、隐私和注销页面。
- 从 App Store Connect 读取最高 Build，更新为严格递增值，经 PR 合入 `main`。
- 执行聚焦测试、`pnpm check`、生产烟雾测试和最终归档反查。
- 从干净 `origin/main` 归档并上传 TestFlight；只用这个 Build 生成最终截图和提交证据。

### 人工节点

- 生产平台密码/2FA、微信或 Apple 验证码。未响应时继续所有不依赖该凭据的检查和材料。

### 完成标准

- 生产 API、数据库、首发可见登录方式、Apple 登录/IAP、AI、内容权限和隐私页面一致；新 Build `VALID`，
  Git SHA、签名、原生配置和隐私清单可追溯。

## 六、阶段 3：审核账号、TestFlight 与截图

### 审核账号

- 使用负责人已指定、公司长期控制的真实手机号，通过一次正常 OTP 创建 Production 账号并设置高强度
  密码；具体手机号和密码只进入受保护凭据，不进入仓库文档。
- 审核员使用手机号+密码登录，不需要公司接收短信；账号不使用白名单、万能 OTP、假手机号或后门。
- 同一账号依次验收免费体验、会员内容、AI、购买、恢复，注销最后执行。

### TestFlight 真机矩阵

- 方案 A 登录页、OTP 状态恢复、密码、Apple、绑定、后台恢复和注销；微信入口隐藏态及防误开启门禁；
- 题库、音频、录音、AI、点数、同步、热点免费/会员状态；
- 五档商品读取、代表档购买、重购、恢复、App 被杀后核对、退款/撤销和环境隔离；
- 启动、加载、全局 Logo、重点 UI 和隐私/支持入口。

### 截图

- 生成并上传 6 张 `1320 x 2868` 简中产品截图：题库目录、音频逐题练习、录音完成、AI 辅助、
  收藏/笔记/记录、登录同步。
- 五档 IAP 各上传一张最终候选包真实商品截图；不得含真实手机号、验证码、错误页或假价格。

### 人工节点

- 负责人接收审核账号首次 OTP、在 iPhone 确认沙盒购买并完成最终真机验收。
- 负责人未响应时，先完成可自动化矩阵、截图生成、像素/隐私审计和平台草稿，不阻塞其他工作。

### 完成标准

- 负责人明确回复最终 TestFlight 通过；审核账号可独立登录；11 张截图与最终 Build 一致。

## 七、阶段 4：App Store Connect 最终材料

### 工作

- 反查 Paid Apps Agreement、银行、税务仍有效；不重复已完成手续。
- App 和五档 IAP 只供应中国大陆，自动新地区关闭；备案、分类、16+、名称、副标题、关键词和描述一致。
- 补齐隐私标签、Privacy Choices、支持/隐私 URL、审核联系人、一个审核账号和中英文 Notes。
- Notes 覆盖手机号密码、Apple、免费/会员边界、五档商品、购买/恢复、录音、ASR、文本 AI、
  麦克风、热点和注销；不描述微信支付、课程或学习报告。
- 将最终 Build 关联 1.0.0，把五档首次 IAP 加入同一 submission，保持审核通过后自动发布。

### 完成标准

- App Store Connect 无缺失元数据、无地区/隐私/截图冲突；所有字段从最终归档和生产能力反向核对通过。

## 八、阶段 5：提交、拒审闭环与发布

### 提交

- 负责人真机验收通过后，协调 Agent执行最后反查并提交 App 1.0.0 + 五档 IAP。
- 提交不是“工作结束”；持续等待 Apple 结果并记录审核通信。

### 拒审

- 材料问题：修正文案、截图、审核说明或平台字段，不无意义重建。
- 代码/资源/原生配置问题：在新短期分支修复，合入主线，上传更高 Build，重新真机验收和提交。
- 本人身份、法律、税务、权利或新验证码：进入 `WAITING_HUMAN`；其他可执行修复继续。

### 上线

- 审核通过后自动发布；验证中国大陆商店页面、下载、登录、购买、恢复、会员、热点、AI、注销和支持。
- 建立 annotated release tag、发布记录、回滚目标和上架收口文档；TestFlight继续作为后续补丁通道。

### 最终完成标准

- App Store 状态已提交并最终通过；中国大陆商店可下载 1.0.0；五档 IAP 可购买；核心生产流程通过；
  正式产物可追溯到 `origin/main` 精确提交和发布标签。

## 九、阶段 6：上架后事项

- 单独启动可视化 Ops 后台设计、部署、管理员/TOTP 和权限审计，不回写为1.0.0上架前缺口。
- 根据真实运营数据决定 Android 商店、微信支付、更多地区、后台重设计和后续 App 版本。
- 未经新决策，不扩大销售地区、不启用微信支付、不恢复体系课程或学习报告。

## 十、验证命令与证据基线

- 聚焦：认证/OTP/会话/微信、StoreKit/商业、Logo/UI、热点/内容权限测试。
- 全量：`pnpm check`；干净 GitHub runner 使用 `pnpm check:ci`，不能替代具备完整媒体源的本地发布检查。
- iOS：`pnpm check:ios:storekit`、`pnpm check:ios:testflight`、`pnpm check:legal`、最终归档审计。
- 生产：迁移演练、API 健康、Apple Notifications V2、微信 code 交换、隐私/支持页面和内容权限烟雾测试。
- 平台：App Store Connect 写入前读取，写入后反查；截图和平台证据保存仓库外或忽略目录。
- 审计：每个关键域完成后做阶段审计；最终 TestFlight Build 和正式提交前分别执行一次独立发布审计，
  以新归档包、生产服务和 App Store Connect 反查为准。
