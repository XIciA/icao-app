# 图片题功能与资源迁移需求

状态：已完成并通过小流程验收

更新时间：2026-07-13

工作目录：`docs/workstreams/image-question-migration/`

## 1. 核心问题

当前 `icao-app` 的 OPI 题库只有文本型问题卡，没有图片题分类、图片卡数据语义和原生图片学习状态。`feizhuicu` 已整理出一组图片题功能与资源，但它只作为本任务的资源和行为参考，不是设计稿、代码模板或可整体导入的题库。

本任务要在 `icao-app` 当前 React Native、统一题库内容工程、远程资源和学习数据框架内，建立图片题能力，并只取用该功能实际需要的图片题子集。

## 2. 目标

- 在 OPI 题库中增加“图片题”分类，不新增一级题库或主导航入口。
- 迁移 23 个图片题话题；每个话题先展示一张图片卡，再学习该图片对应的问题卡。
- 迁移并接入 23 张最终图片、64 道问题及其 64 个问题音频。
- 图片题继续使用当前 App 的目录、进度、答题卡、学习记录和账号同步框架。
- 使用本项目自己的数据结构、资源清单和原生组件实现，不照搬 `feizhuicu` 的 Web 代码、路由或完整题库 JSON。

## 3. 参考与归属边界

- 图片题资源参考：`/Users/zhouyide/Desktop/icao项目/feizhuicu` 中当前已完成的图片题子集。
- 产品结构、UI、导航与交互归属：以 `icao-app` 当前 React Native 实现、设计令牌和学习流程为准。
- 设计仓库仍只作为项目战略与视觉规范来源，不从中获取本次图片题资源，也不向其中写入任何文件。
- 只取用 23 个图片题话题所需的最终图片、问题文本、翻译、参考答案和问题音频；不复制来源项目的生产字段、页面代码、脚本、中间产物或其它题库内容。
- 本任务不包含独立单词学习功能或词书资源迁移。

## 4. 功能范围

### 4.1 OPI 图片题分类与话题

- 在 OPI 目录中新增“图片题”分类，与现有气象、特情、运行等分类同级。
- 分类下包含 23 个图片题话题，标题、顺序、话题数量和卡片数量可追溯、可对账。
- 每个话题的第一张为图片卡，后续为该图片对应的问题卡；不得丢题、串题或改变图片与问题的对应关系。
- 新增稳定且不与现有题库冲突的分类、话题和卡片 ID，后续发布不得重编号或复用。

### 4.2 图片卡

- 图片卡只承担观察图片的学习步骤，在当前学习卡收起、展开和前后题切换过程中都以同一张图片为主体。
- 图片使用适应式完整展示，不能为了填满卡片裁掉飞机姿态、跑道、天气、设备、事故状态或相对位置等关键信息。
- 图片卡不播放音频，不显示问题、译文、参考答案、录音、AI 查词或文字标注工具。
- 图片加载中、加载失败、超时和重试必须有明确状态；失败不得导致页面崩溃，也不得阻止用户退出或切换题目。
- 图片上的“本图片由AI生成”标识必须保持可见，不重新生成、去除或遮挡该标识。

### 4.3 问题卡

- 64 道问题保持与对应图片和原问题一致，不擅自改变题意。
- 每张问题卡应具备英文问题、中文题意、英文参考答案、中文参考内容和问题音频。
- 来源中缺失的少量中文题意可以补齐，但必须单独记录，不借迁移批量改写或润色其它内容。
- 问题卡继续使用当前 OPI 的音频播放、口语录音、参考答案、笔记、标签、高亮、AI 查词和学习操作。
- 单张问题音频不可用时仍可阅读文字、录音和继续学习，并提供明确重试入口。

### 4.4 学习状态与同步

- 图片卡和问题卡都纳入当前话题进度、答题卡、学习记录和完成统计。
- 新增稳定 ID 必须与现有本地学习存储和云同步定位方式兼容。
- 远程题库或资源失败时继续遵守当前缓存与内嵌回退规则；网络不可用时不承诺图片离线可用，但必须显示可理解的失败状态。
- 不改变现有 OPI 普通题目的学习数据、同步语义或用户体验。

## 5. 资源范围

本任务只迁移以下资源：

| 资源 | 数量 | 用途 |
| --- | ---: | --- |
| 最终图片 | 23 张 | 每个话题的图片卡 |
| 问题文本 | 64 道 | 图片后的 OPI 问题卡 |
| 问题音频 | 64 个 | 问题卡音频播放 |
| 话题标题与中英参考内容 | 23 组 / 64 题 | 目录和学习内容 |

资源要求：

- 图片和音频进入 `icao-app` 自有内容维护、发布和对象存储链路，不在运行数据中保存来源项目绝对路径。
- 正式题库数据只保留当前 App 需要的字段；来源追溯放在任务清单或迁移报告，不把来源项目的整套 metadata 带入运行层。
- 不取用原始 Word、原始照片、AI 生成中间图、联系表、生成脚本、其它 OPI 题目或其它题库资源。
- 不把图片或音频直接硬编码为带域名的永久 URL，也不把资源打入新的离线下载包。

## 6. 明确不做

- 不迁移 `feizhuicu` 的 Web 组件、Next.js 路由、CSS、DOM、浏览器 API 或学习页实现。
- 不复制 `feizhuicu` 的完整 OPI JSON、其它 OPI 分类或其它题库。
- 不迁移独立单词学习功能、三本词书或 838 条词汇资源。
- 不重新生成或重新设计 23 张图片，不移除现有 AI 标识。
- 不重做当前 App 的全局导航、题库目录、学习页视觉语言或普通 OPI 卡片。
- 不新增完整离线学习、资源下载、会员、支付或新的 AI 能力。
- 不新增图片处理、播放器或存储生产依赖，除非真实实现证明现有能力无法满足并重新回到大流程确认。
- 不修改数据库 Schema；如果执行中发现必须迁移数据库，必须暂停并单独完成备份与迁移审查。
- 大流程文档确认前不进入代码、正式数据、素材复制或 ECS 部署。

## 7. 验收效果

- OPI 从当前 7 个分类、121 个话题、1269 张卡，正确增加为 8 个分类、144 个话题、1356 张卡。
- 23 个话题均可从 OPI 目录进入，每个话题第一张为对应图片卡，后续问题数量与来源分组一致。
- 23 张图片和 64 个问题音频均可通过当前资源链路解析；资源数量、MIME、checksum、引用和对象存储记录可对账。
- 图片完整显示且 AI 标识可见；加载、失败、超时和重试状态在真实渲染中可用。
- 图片卡不出现音频、录音、查词和文字工具；问题卡保留当前 OPI 学习能力。
- 64 张问题卡的英文问题、中文题意、参考内容和音频完整，缺失补充项有审计记录。
- 本地缓存、内嵌回退、学习进度、记录和账号同步没有因新增卡片类型发生回归。
- `pnpm check`、内容全量校验、相关 iOS Development Build 和模拟器真实链路通过。
- ECS 上的正式 OPI 发布和资源导入完成后，`/health/ready`、OPI 题库接口、图片/音频资源接口和 App 远程读取均通过代表性验证。
- 未修改设计仓库、独立单词模块、来源项目代码或本任务之外的功能。
