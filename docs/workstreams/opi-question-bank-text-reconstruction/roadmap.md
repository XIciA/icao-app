# OPI 题库文本梳理与重建路线图

状态：已确认；文本内容阶段交由同事执行，环境依赖阶段由项目负责人接续

更新时间：2026-07-17

## 1. 文档定位

本路线图承接已经确认的 `requirements.md`、现状盘点 `technical-audit.md` 和实施设计 `technical-plan.md`。

路线图已经确认。文本内容小流程按 `handoff.md` 交由同事执行；统一 release 构建、旧 OPI 学习数据清理、App 渲染和线上发布由项目负责人在具备完整环境的电脑上接续。

## 2. 执行原则

- 严格遵守“英文问题—中文问题—英文答案—中文答案”的锁定顺序。
- 正式扩展前先完成 30 至 50 张代表性校准卡，确认问题边界、答案风格和结构动作标准。
- 以话题为语义去重边界，以 40 至 60 张原始卡为常规处理批次。
- 先在工作项中定稿，四阶段全部完成后再统一写回维护源。
- 任何拆分、合并、移动、删除和图片答案延期都留下原因与审计映射。
- 不按问号数自动拆题，不按相似度分数自动删题。
- 保留题使用稳定 ID；新拆分题使用新 ID；已发布 ID 永不复用。
- 同一话题最终连续重排 `taskTitle`，并按已确认规则保持或调整题目顺序。
- 不保留旧 OPI 学习数据，不开发进度、笔记或高亮迁移。
- 每个阶段都要有可验证产物，不能仅以“已经人工看过”作为完成依据。
- 未通过本阶段验收时不进入下一阶段。

## 4. 阶段 0：基线冻结与执行工具

### 目标

在改动任何 OPI 正式文本前，建立本次重建唯一可追溯的输入、工作项和质量基线。

### 允许范围

- 新增 OPI 专用处理工具、测试和 workstream 报告。
- 读取 OPI 维护源和现有内容构建规则。
- 在 `.generated/opi-question-bank-text-reconstruction/` 生成快照和中间文件。

### 禁止范围

- 不修改正式 OPI topic JSON。
- 不调整 release version。
- 不调用未经确认的外部付费 API。
- 不修改图片、UI、音频和其他题库。

### 核心产出

- 144 个话题文件的文件校验和和结构快照。
- 1356 张卡片的身份清单，明确 1333 张文本卡与 23 张纯图片卡。
- 1333 个逐卡工作项。
- 完全重复、词法高相似、多问号、斜杠、中英混排、翻译缺失和图片依赖候选报告。
- OPI 专用严格校验和回滚命令。
- 批次清单和每批所属完整话题范围。

### 验收标准

- 冻结、准备和审计命令可重复运行且输出一致。
- 1333 张文本卡全部入账，23 张纯图片卡全部排除且未丢失。
- 现状统计至少能够重现技术盘点中的关键基线。
- 任一卡片能从工作项追溯到原 category、topic、card 和原始四字段。
- 回滚在候选副本上验证有效。

### 建议验证

```text
audit
freeze
prepare
verify-stage baseline
pnpm content:check:full
```

## 5. 阶段 1：英文问题重建与结构定稿

### 目标

完成全部英文问题的纠错、重写、拆分、同话题去重、明显归属调整和最终定稿，同时冻结卡片结构决策。

### 处理顺序

1. 按话题读取原问题和语义参考。
2. 处理基础语言和格式错误。
3. 判断问题单元，决定保留或拆分。
4. 在完整话题范围内处理完全重复和高相似问题。
5. 检查明显错位，必要时移动并重新检查目标话题。
6. 确定 canonical ID、新拆分 ID、删除项和图片答案依赖候选。
7. 批次审查后锁定英文问题与结构决策。

### 允许范围

- 大幅重写英文问题。
- 按独立回答任务拆分。
- 选择或重写同话题最佳版本。
- 移动明显错位问题。
- 删除确无独立价值的问题。
- 标记需要具体图片才能定稿的答案候选；英文问题仍必须在本阶段定稿。

### 禁止范围

- 不翻译中文问题。
- 不正式生成答案。
- 不做跨话题机械去重。
- 不整体重构话题体系。
- 不直接写回 OPI 正式源。

### 核心产出

- 每个最终卡片的英文问题。
- `keep/rewrite/split/merge/move/delete` 结构决策。
- `complete/deferred-image-answer` 答案处理候选。
- 旧目标到最终目标的初步审计映射。
- 同话题高相似候选逐项结论。
- 新增、保留、合并、移动、删除和待定数量报告。

### 验收标准

- 所有原始文本卡都有唯一、明确的结构决策。
- 每张最终文本卡只有一个独立回答任务，或记录为合理的不可拆依赖追问。
- 同一话题完全重复为 0。
- 所有高相似候选都有语义结论，不存在未决自动删除。
- 英文问题不存在明显语法、拼写、标点、大小写、粘连、异常换行或未决斜杠表达。
- 移动后已完成目标话题二次去重。
- 保留卡 ID 稳定，`taskTitle` 与顺序方案完整。
- 全部英文问题和结构决策状态为 `locked`。

## 6. 阶段 2：中文问题重新翻译

### 目标

只依据阶段 1 锁定的英文问题，为全部最终文本卡建立新的中文问题。

### 允许范围

- 根据英文含义进行自然、准确的中文表达优化。
- 统一合理的航空术语和通用缩写表达。

### 禁止范围

- 不沿用旧中文作为翻译底稿。
- 不增减英文问题中的事实、范围或追问。
- 不修改已锁定英文问题、结构动作、ID 或归属。
- 不开始参考答案重建。

### 核心产出

- 每张最终文本卡的 `audioTextZh`。
- 术语一致性表和翻译异常报告。

### 验收标准

- 中文问题覆盖率为 100%，包括所有图片话题文本问题。
- 中文和英文问题单元完全一致。
- 中文自然、简洁，不含机械直译和额外信息。
- 英文问题字段中无中文，中文字段中无穿插式英文句子；必要航空缩写除外。
- 英文问题阶段校验和不变。
- 全部中文问题状态为 `locked`。

## 7. 阶段 3：英文参考答案重建

### 目标

依据最终双语问题，为每张可完成文本卡建立一份自然、准确、可学习的英文参考答案。

### 允许范围

- 选择、融合或完全舍弃旧答案内容。
- 补充回答问题所需的必要信息。
- 简单题通常使用 3 至 5 句，复杂题使用 2 至 3 个短段落，不设置机械字数。
- 以 ICAO 4 级容易学习、5 级自然度为目标，优先口语化、准确和可复述。
- 核对 ICAO、CAAC、FAA、EASA、制造商等官方资料；体系有差异时使用通用安全表述并标记。

### 禁止范围

- 不保留多版本答案、编号答案或项目符号答案。
- 不回答已经拆走、合并或删除的旧问题。
- 不编造具体公司、机型、个人经历或事故事实。
- 不猜测未确认的图片细节。
- 不修改已经锁定的问题和中文问题。
- 不把个人经历或公司程序示范答案伪装成真实经历或真实公司规定。

### 核心产出

- 每张可完成文本卡的一份 `referenceText`。
- 航空内容风险项和 `deferred-image-answer` 清单。
- 问答匹配抽样报告。

### 验收标准

- 除明确 `deferred-image-answer` 的答案外，英文答案覆盖率为 100%。
- 每道题只有一份最终英文答案。
- 答案直接覆盖问题要求，没有旧题残留内容。
- 编号版本、中英混排、无关拼接和明显模板化内容为 0。
- 答案符合已确认的 ICAO 等级、篇幅、口语化和官方资料标准。
- 航空术语、风险描述和处置逻辑通过语义复核。
- 问题和中文问题阶段校验和不变。
- 全部可完成英文答案状态为 `locked`。

## 8. 阶段 4：中文参考答案重新翻译

### 目标

只依据已锁定英文答案建立准确、自然并保持段落对应的中文参考答案。

### 允许范围

- 在不改变实质内容的前提下优化中文句式。
- 保留必要航空缩写并使用一致术语。

### 禁止范围

- 不沿用旧中文答案作为翻译底稿。
- 不增加、删减或改变英文答案观点。
- 不修改任何已锁定英文问题、中文问题或英文答案。

### 核心产出

- 每张可完成文本卡的 `referenceTextZh`。
- 中英段落和术语一致性检查报告。

### 验收标准

- 除明确 `deferred-image-answer` 的答案外，中文答案覆盖率为 100%。
- 中英文观点、信息范围、顺序和自然段逐项对应。
- 中文自然、专业，不存在中英交替穿插。
- 前三个阶段校验和不变。
- 全部可完成中文答案状态为 `locked`。

## 9. 阶段 5：稳定 ID、审计映射与正式写回

### 目标

把已锁定工作项安全转换为正式 OPI 维护源，保留稳定 ID，并形成完整结构动作审计；不迁移旧学习数据。

### 处理顺序

1. 固化旧目标到 canonical 目标或 retired 状态的版本化映射。
2. 为拆分、合并、移动和删除生成完整对账。
3. 连续整理最终 `taskTitle`，并落实已确认的题目顺序。
4. 在临时候选中生成全部 OPI 文件并执行严格校验。
5. 校验通过后一次性写回正式维护源。

### 允许范围

- OPI bank、category、topic 维护源。
- workstream 正式审计映射与变更报告。

### 禁止范围

- 不更改数据库 schema。
- 不开发学习状态、同步、笔记或高亮迁移。
- 不在同事的文本交接环境中清理本地或云端学习数据。
- 不递增 release version，不导入 ECS。
- 不修改其他题库内容。

### 核心产出

- 正式版本化目标审计映射。
- 重建后的 144 个 OPI 话题及同步后的数量声明。
- 原始卡、最终卡和所有结构动作对账报告。
- `taskTitle`、顺序和图片答案延期报告。

### 验收标准

- 保留卡稳定 ID 不变，新增 ID 唯一，退役 ID 未被复用。
- 审计映射覆盖全部拆分、合并、移动和删除。
- `taskTitle` 连续，最终顺序符合确认规则。
- 没有新增运行时学习数据兼容代码。
- OPI 专用严格校验通过。
- `pnpm content:check:full` 在写回后通过。
- diff 只包含路线范围内的预期文件。

## 10. 阶段 6：发布构建、渲染验收与收口

### 目标

形成可回滚、可发布的本地正式候选，并以真实 App 展示和完整报告证明需求已满足。

### 处理顺序

1. 更新 registry 的 release version 和 releasedAt。
2. 运行统一构建，生成 App 内嵌题库和完整 release。
3. 执行结构、内容和全项目验证；如存在旧 OPI 学习数据则按范围清理。
4. 在 iOS 与 Android 检查代表性 OPI 学习卡。
5. 形成最终变更、验收、未决图片项和回滚报告。

### 允许范围

- `content/question-banks/registry.json`。
- 统一构建生成的正式产物。
- 本路线验收和收口文档。
- 仅在真实渲染证明现有统一组件存在缺陷时，另行评审最小 UI 修复。

### 禁止范围

- 不在本阶段继续改写内容以绕过质量门；内容问题应退回对应阶段重新锁定。
- 不自动导入 ECS。
- 不处理图片资源和图片展示。
- 不借机修复无关工作区问题。

### 核心产出

- 新的完整题库 release 和 App 内嵌题库。
- 最终 OPI 数量与字段覆盖统计。
- 重写、拆分、合并、移动、删除、图片答案延期的完整摘要。
- iOS、Android 代表性页面验收记录。
- 本地回滚材料和正式收口报告。

### 验收标准

- `pnpm content:build` 通过。
- `pnpm content:check:full` 通过。
- OPI 专用 `verify-formal` 通过且无未解释例外。
- `pnpm check` 不出现本任务新增失败；既有无关错误单独记录。
- 普通短题、复杂题短段落、拆分题、合并题、移动题和图片话题文本题完成代表性渲染检查。
- 普通卡的问题和答案均呈现为英文、分隔线、中文，且没有字段内双语混排；图片答案延期卡的问题双语完整且不显示猜测性参考答案。
- 其他题库、图片资源、音频机制、导航和学习页整体设计保持不变。
- 所有图片答案延期项都有 ID、原因和后续入口。
- 如存在旧 OPI 学习数据，已清理或形成明确清理记录；不要求迁移。

## 11. 阶段 7：可选线上发布

### 进入条件

阶段 6 已完成，且用户明确确认把本地正式候选发布到 ECS。

### 核心步骤

- 从已验收的确定版本构建发布材料。
- 备份线上当前 release、数据库相关数据和源材料。
- 通过既有导入脚本导入新的题库 release。
- 完成容器或服务刷新，并确认 `/health/ready`。
- 使用代表性登录请求验证题库列表、OPI version、数量和关键卡片。
- 如云端存在旧 OPI 学习数据，按已确认范围清理并验证不会重新写回。
- 保留可立即恢复旧 active release 的回滚路径。

### 验收标准

- 线上只激活预期 release。
- App 本地内嵌数据与 API 返回版本和关键内容一致。
- 没有导入无关工作区变更。
- 健康检查、代表性请求和回滚检查全部通过。

## 12. 阶段回退规则

- 英文问题改变：退回阶段 1，并使对应中文问题和中英文答案全部失效。
- 中文问题改变但英文不变：退回阶段 2，答案可保留但必须重新执行问答匹配检查。
- 英文答案改变：退回阶段 3，并使对应中文答案失效。
- 结构动作或目标 ID 改变：退回阶段 1，同时重做阶段 5 审计映射和对账。
- 正式源写回后发现内容错误：不得手工修改生成产物，应修改工作项、重新锁定并重新 `apply`。
- 线上发布后发现阻断性问题：先恢复旧 active release，再回到相应本地阶段修正。

## 13. 路线图确认点

确认本路线图即代表同意：

- 按 0 至 6 阶段依次执行，不并行混做四类内容。
- 先建立工具和工作项，再处理 1333 张文本卡。
- 保留稳定 ID 和审计映射，但不保留或迁移已有 OPI 学习数据。
- 普通内容按批次自动推进，人工审核集中于校准抽样和少量真正无法安全判断的结构问题。
- 内容全部锁定后才统一写回和递增 release version。
- 阶段 6 以本地正式候选为默认终点。
- 阶段 7 线上发布需要再次明确确认，不因路线图确认而自动执行。

本项目可以按 `handoff.md` 进入文本内容小流程。交接范围外的环境依赖工作不得由同事在全新电脑上提前执行，也不能因文本候选已经提交而将整个工作流标记为完成。
