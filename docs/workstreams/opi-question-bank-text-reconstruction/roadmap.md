# OPI 题库文本重建路线图

状态：已确认

更新时间：2026-07-18

## 1. 执行基线

本路线图承接已确认的：

- `requirements.md`
- `technical-audit.md`
- `technical-plan.md`

旧 `handoff.md` 已失效并删除。本工作流不再采用全新电脑、同事分支、项目负责人接续或外部/本地模型路线。

全部阶段由 Codex 在当前仓库的 main 分支连续执行。主 Codex 可以启用 Codex 子 Agent 和 Codex 辅助脚本，但不得调用 Ollama、Qwen、外部 API 模型或其他本地模型。

辅助脚本只能生成或整理候选，不能自行将文本、结构动作、图片答案延期或阶段状态标记为 `locked`。阶段 0 至 7 的最终锁定权只属于主 Codex 或受其任务边界约束的 Codex 子 Agent，并且必须在工作项中留下锁值、理由和检查记录。

## 2. 阶段总览

| 阶段 | 目标 | 核心产出 | 进入下一阶段标准 |
| --- | --- | --- | --- |
| 0 | 清除两次失败资产并重建基线 | 干净工具、空白工作项、新快照、真实阶段记录 | 失败资产为 0，正式源重新冻结且可回滚 |
| 1 | 英文问题重建 | 最终英文问题、结构动作、ID、归属和顺序 | 全部英文问题与结构决策锁定 |
| 2 | 中文问题重译 | 依据锁定英文问题的新中文问题 | 中文问题覆盖完整并锁定，英文锁值不变 |
| 3 | 英文参考答案重建 | 最终英文答案、事实来源和图片延期决定 | 可完成答案全部锁定，问题锁值不变 |
| 4 | 中文参考答案重译 | 最终中文答案 | 可完成中文答案全部锁定，前三阶段锁值不变 |
| 5 | Codex 终审 | 去重、归属、排序、风格、事实和映射终审报告 | 无未决高风险项，可应用正式源 |
| 6 | 正式应用与本地候选 | OPI 维护源、完整审计、release、检查和双端验收 | 本地正式候选通过全部质量门 |
| 7 | Git 与生产上线 | main 提交推送、备份、导入、线上验证和回滚证据 | 线上版本、数量、内容、缓存和双端展示通过 |

阶段必须按顺序执行。内容阶段只能通过回退规则返工，不能并行混做或跳过锁定。

## 2.1 内容阶段通用质量控制

- 每批指定独立的 Codex 内容生产者与 Codex 复核者；复核者不得复用生产者的上下文、候选结论或理由，主 Codex 执行最终锁定。
- 生产者边生产边完成必要校对，不在批次完成后额外执行一次同上下文全文重读；独立 Codex 只执行一次全量文本复核。
- 独立复核对普通通过项只紧凑记录卡片 ID 和状态，只有返工、高风险或争议项记录详细依据与完整替换文本；报告精简不得减少全量阅读覆盖。
- 主 Codex 每批只逐项处理复核争议、机器报警和高风险项，代表性普通样本改在每累计 200 至 300 张的检查点统一抽检，不再逐批抽检，也不对普通通过项做第三次等量全文复核；最终锁定权与重复全量审核分开。
- 普通语言题执行全量结构校验和每 200 至 300 张检查点抽检；拆分、合并、移动、删除、图片延期、个人/公司程序题、航空程序题、具体数值/限制题和事实不确定项必须逐项重点复核并记录依据。
- 每个检查点统计答案句数、段落数、常见开头和结尾、高频句式、同话题相似度、中英文段落对应和异常长度分布；脚本只报告候选，Codex 决定是否返工。
- 每批锁定后生成不可变 hash 清单，记录输入校验和、输出锁值、结构动作、生产者、复核者和规则版本。后续问题按受影响规则和批次整体返工，禁止无法追溯的零散手改。
- 批次先锁定文本、结构动作、canonical ID 和目标话题；跨批移动引起的最终连续编号在阶段 1 全局关闭时统一对账并进入 closure hash。批次可暂不填写纯数字 `targetOrder`，摄入工具仅为局部结构校验分配确定性临时序号；临时序号不进入批次 seal。纯数字顺序调整不使已锁批次 seal 失效，也不触发无增益的全文重审。
- 一对一合并以被合并工作项的 `canonicalCardId` 和源卡映射为权威记录，不因早期 canonical 缺少冗余反向 source ID 而单独重开旧批；只有多意图源的次级映射，或 canonical 文本、结构、归属发生变化时，才要求回写并重封相关旧批。
- 普通 `keep` / `rewrite` 项的 `reason` 和 `reviewBasis` 使用规则代码或一句短理由；拆分、合并、移动、高风险和争议项继续记录完整依据。主 Codex 的批次裁决与检查点报告使用确定性紧凑摘要，不重复抄写生产文本或独立复核全文。

## 3. 阶段 0：失败资产清理与重新冻结

### 目标

完全舍弃同事失败资产和 Ollama/Qwen 失败资产，从未被污染的 OPI 正式维护源重新建立唯一基线。

### 主要工作

1. 停止所有 Ollama、Qwen、旧 OPI 模型批处理和相关 runner。
2. 确认没有残留模型进程或后台生成任务。
3. 删除整个 `.generated/opi-rebuild/` 旧目录。
4. 删除 `tools/opi-model-batches.mjs`。
5. 清理 `tools/opi-rebuild.mjs`：
   - 删除 Ollama/Qwen endpoint、Prompt、模型状态和检查点。
   - 删除同事旧候选文本、自动锁定、旧硬编码重写、拆分、合并和润色结果。
   - 保留或重建读取、审计、冻结、空白工作项、锁值、验证、映射、apply 和 rollback 能力。
6. 把 `phase-log.md` 中旧阶段 0、1、2 声明标为废弃，恢复为“小流程尚未开始”。
7. 审查正式 OPI 维护源相对基线和 `origin/main` 的差异，确认没有失败文本写入。
8. 重新执行 audit、freeze、prepare 和 baseline verification。
9. 验证回滚在候选副本上有效。

### 允许范围

- `tools/opi-rebuild.mjs` 和专用测试。
- 删除旧模型脚本和 ignored 生成目录。
- workstream phase-log 和阶段 0 审计记录。
- 新 `.generated/opi-rebuild/` 基线和空白工作项。

### 禁止范围

- 不修改正式 OPI 文本。
- 不开始英文问题生产。
- 不修改 registry release version。
- 不修改图片、UI、音频、API、数据库或其他题库。
- 不继承任何失败工作项、候选文本、结构裁决或锁定状态。

### 验收标准

- 模型相关进程和脚本为 0。
- 旧生成目录已删除，新目录只含重新生成的基线、空白工作项和确定性候选索引。
- `tools/opi-rebuild.mjs` 不存在 Codex 之外的模型调用或旧候选常量。
- phase-log 真实显示阶段 0 重新开始。
- 新基线重现 8 分类、144 话题、1356 卡、1333 文本卡、23 纯图片卡和 64 张图片话题文本卡。
- 153 个维护源文件均有校验和，正式源无失败文本 diff。
- 回滚演练通过。

## 4. 阶段 1：英文问题重建

### 目标

由 Codex 完成全部英文问题纠错、重写、拆分、同话题去重、明显归属调整、稳定 ID 和顺序方案。

### 执行方式

1. 先完成 30 至 50 张代表性校准批次。
2. 固定问题边界、语言、拆分、合并、移动和删除标准。
3. 以完整话题为边界处理 40 至 60 张常规批次。
4. 每完成约 200 至 300 张执行跨批次抽检。
5. 对所有高相似候选、拆分、合并、移动和删除逐项裁决。
6. 抽检发现系统问题时返工全部受影响卡片。
7. 全量机器校验通过后锁定英文问题和结构动作。

### 核心产出

- 每张最终文本卡的英文问题。
- `keep/rewrite/split/merge/move/delete` 决策和理由。
- canonical ID、派生 ID、目标话题和顺序方案。
- 同话题重复与高相似候选裁决。
- 输入、输出和各动作数量报告。
- 检查点抽检记录。

### 禁止范围

- 不翻译中文问题。
- 不生成参考答案。
- 不做跨话题机械去重。
- 不整体重构话题体系。
- 不写回正式 OPI topic JSON。
- 不使用失败候选作为底稿。

### 验收标准

- 1333 张原始文本卡都有明确结构决定。
- 每张最终卡只有一个独立回答任务或合理的必要追问。
- 同话题完全重复为 0，全部高相似候选有语义裁决。
- 英文不存在明显语法、拼写、标点、粘连、异常换行和未决斜杠表达。
- 移动卡完成目标话题二次去重。
- 保留 ID 稳定、派生 ID 唯一、退役 ID 未复用。
- 英文问题和结构状态全部锁定。

## 5. 阶段 2：中文问题重译

### 目标

只依据阶段 1 锁定英文问题，为全部最终文本卡重新建立自然、准确的中文问题。

### 主要工作

- 按同一批次边界生成中文问题。
- 保持英文范围、语气、人称、条件和必要追问。
- 统一航空术语和通用缩写。
- 每 200 至 300 张执行跨批次抽检；发现系统问题时返工受影响范围。
- 全量验证英文锁值、中文覆盖、语言纯度和问题单元对应。

### 禁止范围

- 不使用旧中文或失败中文候选作为底稿。
- 不修改英文问题、结构动作、ID、归属和顺序。
- 不开始参考答案。

### 验收标准

- 中文问题覆盖全部最终文本卡，包括 64 张图片话题文本卡。
- 中英文问题单元、范围和语气一致。
- 中文自然、简洁、规范，没有额外解释或答案。
- 英文问题锁值不变。
- 中文问题全部锁定。

## 6. 阶段 3：英文参考答案重建

### 目标

依据最终问题，为每张可完成文本卡建立一份自然、准确、可学习的英文参考答案。

### 主要工作

- 简单题通常写 3 至 5 句，复杂题写 2 至 3 个短段落。
- 直接回答最终问题，不残留旧题内容。
- 个人经历、公司程序和机型题明确使用示范答案身份。
- 核对重要航空事实；记录官方来源、适用范围和不确定性。
- 逐项决定图片答案是否真正依赖具体画面。
- 每 200 至 300 张执行跨批次抽检，并重点覆盖航空高风险内容。
- 对图片延期、事实不确定和高风险程序题逐项复核。

### 禁止范围

- 不保留多个版本、编号或项目符号答案。
- 不编造个人经历、雇主、公司程序、机型数值或事故事实。
- 不猜测图片内容。
- 不修改问题、ID、归属和顺序。

### 验收标准

- 除正式图片延期项外，英文答案覆盖率为 100%。
- 每题只有一份最终答案，问答直接匹配。
- 没有编号版本、中英混排、无关拼接和系统性模板套话。
- 答案达到 ICAO 4 级易学、5 级自然度。
- 事实来源和不确定性记录完整。
- 问题阶段锁值不变，英文答案全部锁定或正式延期。

## 7. 阶段 4：中文参考答案重译

### 目标

只依据锁定英文答案建立准确、自然且段落对应的中文答案。

### 主要工作

- 保持英文观点、范围、语气、逻辑顺序和段落。
- 统一航空中文术语和必要缩写。
- 每 200 至 300 张执行跨批次抽检。
- 全量校验字段覆盖、语言纯度、段落对应和前三阶段锁值。

### 禁止范围

- 不使用旧中文答案或失败模型中文作为底稿。
- 不增加、删除或改变英文答案观点。
- 不修改英文问题、中文问题或英文答案。

### 验收标准

- 除正式图片延期项外，中文答案覆盖率为 100%。
- 中英文观点、范围、顺序和自然段一致。
- 中文自然、专业，不存在穿插式英文句子。
- 前三个阶段锁值不变。
- 中文答案全部锁定或正式延期。

## 8. 阶段 5：Codex 终审

### 目标

在正式写回前完成跨批次、跨阶段的最终质量裁决，确认内容、结构、归属、排序和审计材料可以形成正式题库。

### 主要工作

- 汇总全部检查点抽检结果和返工记录。
- 复核所有拆分、合并、移动、删除、图片延期、高相似候选和事实不确定项。
- 按分类和话题抽检四字段问答与翻译质量，覆盖不同生产批次和 Codex producer。
- 复查同话题去重、目标话题归属和最终顺序。
- 检查答案长度、口语自然度、示范身份和模板化倾向。
- 校验源卡到目标卡映射、退役 ID 和最终数量。
- 生成待应用预览和回滚计划。

### 禁止范围

- 不在终审中静默修改已锁定文本。
- 发现内容问题必须按回退规则退回对应阶段重新锁定。
- 不通过弱化校验规则消除异常。

### 验收标准

- 全部结构动作和高风险项有明确最终裁决。
- 抽检无系统性语言、翻译、问答或模板问题；已发现问题的影响范围完成返工。
- 四阶段全量结构校验和锁值通过。
- 最终数量、映射、各话题排序和审计材料完整。
- 审查结论允许进入正式应用。

## 9. 阶段 6：正式应用、本地构建和双端验收

### 目标

把锁定工作项安全应用到唯一维护源，形成可回滚的本地正式 release，并完成完整项目检查和双端代表性显示验收。

### 主要工作

1. 构建和验证 OPI 临时候选。
2. 验证 rollback 后重新构建候选结果一致。
3. 一次性 apply 到 OPI bank、category 和 topic 维护源。
4. 生成全部正式审计 artifacts。
5. 更新 registry release version 和 `releasedAt`。
6. 运行 `pnpm content:build`、`pnpm content:check:full`、OPI `verify-formal` 和 `pnpm check`。
7. 检查 diff，确认没有第二套题库、音频映射或资源解析来源。
8. 在 iOS 和 Android 验证代表性页面。
9. 完成最终质量、双端验收和本地回滚报告。

### 代表性页面范围

- 普通短问题和简单答案。
- 复杂问题和多段答案。
- 拆分题、合并题、移动题。
- 图片话题的一般航空知识题。
- 图片答案延期题。
- 中英文较长、缩写较多和术语较多的卡片。

### 验收标准

- 一个页面只有一个问题。
- 问题和答案均为英文、横线、中文，字段内不穿插双语。
- 图片答案延期不影响双语问题展示，也不显示猜测性答案。
- 最终卡片数量、各话题数量、ID、`taskTitle` 和映射对账通过。
- 维护源、生成 release 和 App 内嵌题库一致。
- 所有规定命令通过，或确认不存在本任务新增失败。
- iOS 和 Android 代表性显示无阻塞问题。

## 10. 阶段 7：Git、生产备份、上线与验证

### 目标

从已验收的确定 main 文件集完成提交、推送和生产内容发布，并保留可验证回滚路径。

### 主要工作

1. 审查最终 Git diff 和生成文件。
2. 更新 `src/config/app-version.ts` 为最终上海时间。
3. 运行最终检查并只暂存本次有效文件。
4. 提交并推送 main。
5. 在 ECS 查询当前 active release 和 OPI 学习数据范围。
6. 备份 PostgreSQL、当前内容 release、源材料和旧激活版本。
7. 校验备份 SHA-256，并验证恢复目录可读。
8. 如需清理旧 OPI 学习数据，只在确认范围后执行并验证不会重新同步。
9. 使用正式内容导入流程导入新 release，不部署无关 API 源码。
10. 验证 `/health/ready`。
11. 使用登录态请求验证线上 OPI version、最终卡片数量、代表性四字段、checksum、ETag 和 304。
12. 验证 App 内嵌题库与 API active release 一致。
13. 保留数据库 dump、旧发布目录、内容级回滚步骤和线上证据。
14. 完成 closeout。

### 验收标准

- main 提交和推送成功，提交范围干净。
- 最终报告明确显示版本。
- 数据库和旧内容版本备份存在且可读。
- 线上只激活预期 release。
- `/health/ready` 中 API 和 database 均为 `ok`。
- OPI 版本、数量、代表性卡片、ETag 和 304 全部符合预期。
- iOS 和 Android 使用的新内容显示正确。
- 回滚路径可以立即执行且证据完整。

## 11. 回退规则

- 英文问题改变：退回阶段 1，对应中文问题和中英文答案全部失效。
- 中文问题改变：退回阶段 2，并重新检查问答匹配。
- 英文答案改变：退回阶段 3，对应中文答案失效。
- ID、结构动作、目标话题或顺序改变：退回阶段 1，并重做阶段 5、6 的映射和对账。
- 正式源发现内容问题：从工作项返工后重新 apply，不手工修改构建产物。
- 生产验证失败：恢复旧 active release；必要时恢复数据库备份，再回到对应本地阶段。

## 12. 自动推进与暂停条件

路线图已经授权阶段 0 至 7 连续执行，不设置中间人工确认点。以下情况才暂停并请求用户决策：

- 必须改变本需求、话题体系、宏观架构或产品范围。
- 必须调用 Codex 之外的模型、付费资源或新的外部平台。
- 生产凭证、设备、数据库备份或回滚能力真实不可用，且安全替代方案不存在。
- 航空事实存在重大官方冲突，无法通过适用范围和保守表述解决。
- 继续执行需要数据库 schema migration、API 源码部署或不可逆的范围外数据操作。
- 用户或其他并行工作与当前写入范围发生无法安全绕开的冲突。
