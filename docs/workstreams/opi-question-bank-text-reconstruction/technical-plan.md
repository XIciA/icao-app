# OPI 题库文本梳理与重建技术方案

状态：已确认；按 `handoff.md` 的分工边界执行

更新时间：2026-07-17

## 1. 方案目标

在现有统一题库架构中完成 1333 张 OPI 文本问题卡的英文问题重建、中文问题重译、英文答案重建和中文答案重译，并保证：

- 所有语义决策可逐卡审查和追溯。
- 四个内容阶段严格按依赖顺序锁定。
- 保留稳定 card ID 和结构动作审计，不开发旧学习数据迁移。
- 正式维护源、App 内嵌题库和最终发布包保持一致。
- 不修改图片资源、学习页设计、音频生命周期和其他题库。

## 2. 总体技术路线

采用“冻结基线—生成工作项—分阶段定稿—审计映射—一次应用—严格验证—形成发布候选”的路线：

```text
OPI 正式维护源
-> 冻结基线和校验摘要
-> 生成逐卡重建工作项与重复候选
-> 英文问题定稿并锁定结构决策
-> 中文问题重译并锁定
-> 英文参考答案重建并锁定
-> 中文参考答案重译并锁定
-> 生成 ID/目标审计映射
-> 受控写回 OPI 维护源
-> content:build + 专用校验 + 展示验收
-> 本地正式候选
```

正式维护源只在四个文本阶段全部通过后统一写回。模型或人工编辑不能跳过工作项，直接批量覆盖 topic JSON。

## 3. 文件和所有权边界

### 3.1 允许新增或修改

- `docs/workstreams/opi-question-bank-text-reconstruction/`
- `tools/opi-text-reconstruction.mjs`
- OPI 专用测试或固定样例文件。
- `content/question-banks/banks/opi/bank.json`
- `content/question-banks/banks/opi/categories/*.json`
- `content/question-banks/banks/opi/topics/*.json`
- 最终发布时的 `content/question-banks/registry.json`
- 由 `pnpm content:build` 自动生成的正式产物。
- OPI 范围内旧学习数据的清理记录；实际环境清理由项目负责人执行。

### 3.2 禁止修改

- 图片文件、图片资源清单和纯图片卡展示。
- OPI 播放、录音、权限、音频会话和转写流程。
- 学习页整体 UI、导航和交互。
- 听力、900 句、陆空通话和故事复诵内容。
- 服务端数据库 schema。
- 当前工作区中与本路线无关的已有变更。

### 3.3 生成文件

临时快照、批次中间文件和自动报告统一放入：

```text
.generated/opi-question-bank-text-reconstruction/
```

该目录已经被 Git 忽略，只用于恢复、对账和批次执行。需要长期保留的规则、最终统计、决策摘要、目标审计映射与验收报告应写入 workstream 文档目录；不能只存在于 `.generated`。`verify-formal` 只能依赖已提交的最终维护源和正式审计产物，必须能在干净检出中复现；冻结快照只服务执行期回滚和阶段校验。

## 4. OPI 专用处理工具

新增单一入口 `tools/opi-text-reconstruction.mjs`，避免建立多个互相覆盖数据的脚本。建议命令如下：

```text
audit             只读扫描当前维护源，生成质量基线
freeze            冻结源文件校验和、数量和卡片身份
prepare           生成逐卡工作项和重复候选
verify-stage      校验指定内容阶段及锁定状态
build-review      生成变更预览、统计和待处理项
apply             仅从全部已锁定工作项写回正式维护源
verify-formal     在干净检出中验证正式维护源、逐卡映射、四字段校验和和质量产物
rollback          从本次冻结快照恢复本路线修改的 OPI 文件
```

工具必须满足：

- 默认只读；只有明确调用 `apply` 或 `rollback` 才能修改维护源。
- 每次应用前验证源文件校验和，发现基线外变更立即停止。
- 同一输入重复执行得到相同输出。
- 不调用付费外部 API，也不把题库上传到未经确认的外部服务。
- 所有失败都指出 card ID、topic ID、字段和规则，不能只输出总数。
- `apply` 先写临时候选并完整验证，再以受控方式替换目标文件。

## 5. 逐卡工作项合同

每张原始文本卡生成一个工作项；拆分时在同一决策中增加派生卡。建议核心字段为：

```ts
type OpiReconstructionItem = {
  source: {
    categoryId: string
    topicId: string
    cardId: string
    contentChecksum: string
  }
  decision: {
    action: 'keep' | 'rewrite' | 'split' | 'merge' | 'move' | 'delete'
    answerDisposition: 'complete' | 'deferred-image-answer'
    targetCategoryId: string
    targetTopicId: string
    canonicalCardId: string
    sourceCardIds: string[]
    reason: string
  }
  content: {
    questionEn: string
    questionZh: string
    answerEn: string | null
    answerZh: string | null
  }
  review: {
    questionEn: 'draft' | 'locked'
    questionZh: 'blocked' | 'draft' | 'locked'
    answerEn: 'blocked' | 'draft' | 'locked' | 'deferred-image-answer'
    answerZh: 'blocked' | 'draft' | 'locked' | 'deferred-image-answer'
    imageDependencyReason?: string
    factSources?: Array<{ title: string; url: string }>
    factUncertainty?: string
  }
}
```

真实格式可按脚本需要细化，但必须保留来源身份、最终身份、结构动作、答案处理状态、理由、四份文本和四阶段状态。任何删除、合并、移动和图片答案延期都必须有明确理由，不能用空文本表示。

## 6. 四阶段锁定机制

### 6.1 英文问题重建

处理语法、格式、缺词、多词、用词、斜杠表达、问题边界、拆分、同话题去重和明显归属错位。

本阶段完成后锁定：

- 最终英文问题。
- 卡片保留、拆分、合并、移动或删除决策。
- 最终话题归属。
- canonical card ID 与新增 card ID。
- 所有图片话题文本卡的英文问题都必须锁定，不能因答案依赖图片而延期问题阶段。

后续三个阶段不得修改这些内容。确需修改时必须退回英文问题阶段，解除相关项锁定，并使其中文问题和全部答案重新进入待处理状态。

### 6.2 中文问题重译

只读取已锁定的英文问题，全部重新翻译。旧中文可用于发现专有名词，但不能作为翻译底稿直接沿用。

校验重点：

- 问题边界一致。
- 不增减事实或追问。
- 中文自然、简洁。
- 英文和中文严格分字段。

### 6.3 英文参考答案重建

只依据已锁定问题重新建立一份最优英文答案。旧答案只用于识别原有考查意图和可能有价值的信息，必须重新判断正确性与适用性。

校验重点：

- 直接回答问题的每个必要部分。
- 没有继续回答已经被拆走或删除的问题。
- 没有多版本编号、项目符号答案或中英文混排。
- 航空术语和处置逻辑准确、稳妥。
- 不伪造个人经历、公司程序、机型数据或事故事实。
- 达到 ICAO 4 级容易学习、5 级自然度。
- 简单题通常为 3 至 5 句，复杂题为 2 至 3 个短段落，不设置机械字数。
- 优先口语化、准确和可复述，不追求高级词汇或论文式表达。
- 个人经历和公司程序类内容明确属于可调整的示范答案。
- 航空事实优先核对 ICAO、CAAC、FAA、EASA、制造商等官方资料；不同体系存在差异时使用通用安全表述并记录。
- 只有无法脱离具体图片确认的答案可以标记为 `deferred-image-answer`；对应英文问题和中文问题必须已经完成。
- 延期图片答案不保留旧答案，也不发布猜测性答案，英文与中文答案字段均留空并进入正式延期清单。

### 6.4 中文参考答案重译

只依据已锁定英文答案重新翻译，保持观点、信息范围、逻辑顺序和自然段一致。完成后四个字段同时进入最终候选。

## 7. 批次与质量控制

### 7.1 批次大小

- 正式扩展前先处理 30 至 50 张代表性校准卡，确认问题边界、答案风格和结构动作标准。
- 每个工作批次建议处理 40 至 60 张原始文本卡。
- 每完成约 200 至 300 张，执行一次跨批次规则校准和抽样复核。
- 同一话题不得被切到无法完成同话题去重判断的多个孤立批次；超大话题可以拆批，但最后必须合并复审。

批次边界是恢复和评审单位，不是发布单位。1333 张文本卡全部完成前不构建正式 release。

### 7.2 自动、语义判断与人工抽样分工

脚本负责确定性工作：

- 抽取、排序、校验和与数量统计。
- 语言字符、异常换行、斜杠、编号格式和字段完整性检测。
- 完全重复和词法高相似候选生成。
- 卡片 ID 分配与冲突检查。
- 变更预览、映射生成、写回与产物对账。

语言模型或执行者负责语义工作：

- 是否拆分及如何重写。
- 高相似问题是否真正重复。
- 最佳版本选择和话题归属。
- 问答匹配、航空知识可靠性和翻译质量。

相似度分数只能生成候选，不能单独作为删除依据。明确符合规则的内容可以按批次推进，不要求逐卡人工审批；人工审核集中在初始校准批次、每 200 至 300 张检查点抽样和少量真正无法安全判断的结构问题。

答案事实不确定时优先改为可靠的通用安全表述。结构仍不确定时优先保留独立问题，不冒险合并或删除。

## 8. 拆分、合并和 ID 策略

### 8.1 通用规则

- 保留卡继续使用原 card ID。
- 已发布 ID 永不重新编号、永不赋予无关新问题。
- 同一普通话题内最终连续重排 `taskTitle`，但显示编号不能代替稳定 ID。
- 原题相对顺序尽量保留；拆分题紧跟主问题；移动题放入目标话题最相关的位置。
- 图片话题中的纯图片卡和“图片观察”标题保持不变。

### 8.2 拆分

- 原 card ID 分配给与原卡主要考查意图最接近的主问题。
- 其他独立问题使用新建且全局唯一的确定性 ID。
- 如果无法确定主问题，加入少量人工复核清单，不按句子顺序机械选择。

### 8.3 合并或去重

- 从候选中选择质量和归属最合理的 canonical card ID。
- 其他旧 card ID 进入审计映射，不能被新问题复用。
- 最终文本可在最佳旧版本基础上继续重写，不要求逐字保留 canonical 卡的旧文本。

### 8.4 移动

- card ID 保持不变，目标 category/topic 更新。
- 记录完整旧目标和新目标，用于内容审计和防止 ID 复用。
- 移动后必须重新执行目标话题内去重。

### 8.5 删除与图片答案延期

- 删除仅用于语义无效、无独立价值且不能合理整合的问题。
- 无法脱离具体图片确认时，只把答案标记为 `deferred-image-answer`；英文问题和中文问题仍须完成。
- 删除和图片答案延期都必须进入最终报告，不能静默消失。

## 9. 学习数据处理决定

### 9.1 不保留旧学习数据

- 项目负责人已经确认不需要保留任何 OPI 学习进度、完成状态、标签、笔记或高亮。
- 本轮不实现 card ID 运行时别名、状态合并、云同步归一、笔记合并或高亮重定位。
- 内容重建和学习数据清理互相独立，不能为迁就旧进度降低题库文本质量。

### 9.2 稳定 ID 与审计映射

- 保留卡仍维持原 card ID，已退役 ID 永不复用。
- 生成旧目标到 canonical 新目标或 retired 状态的完整映射。
- 映射只用于逐卡审计、结构动作复核和后续问题追踪，不接入 App 或 API 运行时。

### 9.3 清理边界

- 如果 App 本地存在 OPI 学习数据，正式发布阶段可以直接清理 OPI 范围数据。
- 如果云端存在 OPI 学习数据，也可以按 OPI 范围清理，但必须由项目负责人在完整环境中执行备份、范围核对和清理后验证。
- 不修改数据库 schema，不在同事的纯文本交接阶段接触本地或云端学习数据。

## 10. OPI 专用严格校验

正式应用前后都要执行同一组规则。每张最终文本卡的问题字段必须满足：

- `audioText` 非空、自然且只含英文问题所需字符。
- `audioTextZh` 非空且为对应中文问题。
- 除正式记录的 `deferred-image-answer` 外，`referenceText` 非空、只含英文答案，不含答案版本编号。
- 除正式记录的 `deferred-image-answer` 外，`referenceTextZh` 非空且为对应中文答案。
- `deferred-image-answer` 卡的两个问题字段必须完整，两个答案字段必须为空，且延期原因必须存在。
- 四个字段不存在中英穿插和异常换行。
- 问题没有未决斜杠备选表达；合法航空写法使用小型白名单。
- 每张卡只有一个独立回答任务，或已记录为不可拆的依赖追问。
- 同一话题完全重复为 0。
- 每个高相似候选都有保留、合并或独立角度说明。
- 所有移动、拆分、合并、删除和图片答案延期都有审计映射与原因。
- category、topic、card 数量和声明值一致，全部 ID 唯一。
- 保留卡 ID 稳定，普通话题 `taskTitle` 连续，顺序符合已确认规则。
- 英文答案符合已确认的 ICAO 等级、篇幅、口语化和官方资料核对标准。
- 四阶段锁定链完整，后阶段没有越权修改前阶段校验和。

语法质量、问答匹配和翻译准确性不能只靠正则表达式，应结合逐批语义评审和最终抽样复核。

## 11. 写回、构建与正式候选

### 11.1 写回维护源

所有工作项锁定后，`apply` 根据最终目标重新生成受影响的 OPI topic 文件，并同步：

- 话题 `cardCount`。
- 分类 `topicCount` 和 `cardCount`。
- OPI bank 总数及摘要。
- 正式审计映射与最终变更报告。

写回前后保存文件级校验和和卡片级对账，确保没有修改其他题库。

### 11.2 构建

正式候选执行：

```bash
pnpm content:build
pnpm content:check:full
```

构建应自动刷新：

- `dist/question-bank-release`
- `src/features/question-bank/data/question-bank.json`

不得手工同步这两处产物。

### 11.3 release version

处理中间批次不递增 release version。只有本地正式候选通过全部内容和展示验收后，才更新 `content/question-banks/registry.json` 的 `releaseVersion` 与 `releasedAt`，重新构建最终 release。

### 11.4 线上发布

本路线默认交付本地正式候选，不自动导入 ECS。若用户确认上线，再单独执行：

- 只从已验收的确定版本构建发布包。
- 保留线上当前 release 和源数据回滚材料。
- 导入题库 release，不夹带无关工作区变更。
- 重启或刷新所需服务并检查 `/health/ready`。
- 使用登录态请求核对 OPI bank version、数量和代表性卡片。
- 如发现旧 OPI 学习数据，按已确认决定清理并验证不会重新同步回旧状态。

## 12. 验证策略

每个小批次执行：

- 工作项 schema 校验。
- 阶段锁定和依赖校验。
- 当前话题完整去重候选复核。
- 变更前后字段 diff。

每个大阶段执行：

- 全量 OPI 专用严格校验。
- 数量、ID 和动作对账。
- 规则漂移抽样。
- 从短题、长题、拆分题、合并题、移动题、图片话题文本题中抽样复审。

最终候选执行：

- `pnpm content:build`。
- `pnpm content:check:full`。
- OPI 专用 `verify-formal`。
- `pnpm check`，并区分既有无关失败与本任务新增失败。
- iOS 和 Android 至少各检查一组代表性学习卡，确认问题和答案都是英文、分隔线、中文的统一结构。
- 检查短答案、复杂题短段落、图片答案延期卡和新拆分卡的显示状态。
- 如执行了 OPI 学习数据清理，验证清理范围和结果。

本轮不改变原生依赖、Expo 插件或权限，因此不要求仅为文本内容重建新的 Development Build；若实际执行中越过此边界，则必须重新评估原生验证范围。

## 13. 完成定义

只有同时满足以下条件，技术实施才算完成：

- 1333 张原始文本卡均有可追溯最终决策。
- 所有保留或新增文本卡的问题字段完整；除图片答案延期项外，答案字段完整并通过质量门。
- 所有结构动作和 ID 变化有审计映射。
- 维护源、生成产物、统计和报告一致。
- 没有新增旧学习数据迁移或兼容层；如存在旧数据，已按确认范围清理或明确留给环境阶段清理。
- 代表性学习页完成真实渲染验收。
- 图片资源、音频生命周期、其他题库和 UI 边界保持不变。
- 所有图片答案延期项被完整列出并交给后续图片专项。
- 形成可回滚的本地正式候选；线上发布仅在单独确认后执行。
