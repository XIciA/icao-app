# 随身听播放系统技术方案

状态：已确认

更新时间：2026-07-16

## 1. 方案结论

> 2026-07-16 缺陷修复修订：Expo Audio 的锁屏 options 不能提供独立的上一首/下一首命令，且原实现以单 source 的 JS 结束回调驱动续播，无法满足锁屏自动下一题和单曲循环。本轮已获用户授权，将随身听唯一播放引擎改为 `react-native-track-player@4.1.2`；共享题库、资源解析、音频协调、Provider 状态和 UI contract 不变。本文后续与本修订冲突的 Expo-only 描述，以本修订和阶段 7 记录为准。
>
> 2026-07-16 音频生命周期勘误：第 5 节的 `AudioSessionCoordinator` 方案已被后续治本重构取代。
> 当前实现是带串行队列、超时、独占录音和 token lease 的 `AudioSessionOrchestrator`，完整规则见
> `docs/guides/audio-lifecycle-and-change-rules.md`；禁止恢复本文的旧接口或双轨兼容层。

在当前 React Native App 内建立一个长期挂载的随身听播放 Provider，由它持有唯一的 Track Player、播放队列、播放模式、当前曲目和持久化状态。全屏播放器、迷你播放器和系统媒体信息只订阅这一份状态，不各自创建播放器。

曲目继续来自统一题库 repository，音频地址继续由统一资源服务按当前曲目解析。时长元数据进入题库内容维护和发布 contract：复用设计仓库已有 1,827 条索引作为导入基线，补齐当前正式内容中新增的缺口，然后由内容构建产物提供给 App，不在随身听 feature 保留第二份索引。

题卡音频、随身听、录音和录音回放通过一个共享音频会话协调层互斥。题卡与录音继续使用 Expo Audio；随身听使用 Track Player 的原生队列、后台 service、RepeatMode 和系统媒体命令。

## 2. 共享内容与时长 contract

### 2.1 曲目来源

- 题库维护层继续是内容唯一来源。
- 模块范围由维护源中的 `capabilities.radioEligible` 声明派生；内容构建把该能力发布到共享运行时 contract，随身听页面不重复维护模块清单。
- 每条播放曲目从正式卡片映射出稳定 ID、bank、category、topic、标题、英文、中文、音频路径和时长。
- 曲目排序沿用题库发布顺序；搜索和筛选只生成视图，不改变原始稳定顺序。
- App 通过现有 `loadQuestionBank` 读取远程、cache 或 embedded 数据，不再用只读的 `getEmbeddedQuestionBanks()` 作为随身听专属入口。

### 2.2 时长归属

建议扩展现有资源维护 schema，为音频资源记录可选的正数 `durationSeconds`；内容构建时把对应值发布为卡片上的只读 `audioDurationSeconds`，供所有需要音频时长的 App 功能共用。

维护与生成关系：

1. 资源维护清单是时长元数据的维护源；
2. 设计仓库 1,827 条时长索引只做一次性、可审计导入；
3. 当前缺少的 732 条和未来新增音频从规范资源文件读取媒体时长；
4. 题库构建产物中的 `audioDurationSeconds` 是由维护源生成的运行时字段，不允许手工编辑；
5. 内容检查验证所有 `radioEligible` 且有音频的卡片都存在有效时长，卡片音频路径能对应唯一资源；
6. 随身听运行时不读取设计仓库文件，也不重新扫描音频。

这样既能让队列一次展示全部时长，也避免为每条曲目先加载远程音频才能知道时长。

### 2.3 与当前题库迁移的协调

当前 dirty worktree 中的题库迁移正在修改 bank、topic、资源清单、嵌入数据和发布工具。随身听小流程不得覆盖或平行重写这些文件。

实施前先执行协调门槛：

- 确认题库迁移的正式发布版本和文件归属；
- 在迁移后的正式曲目集合上重新计算曲目数、时长覆盖和缺失清单；
- 由现有内容工具承载时长 schema 与构建，不新建随身听内容工具；
- 若题库迁移尚未收口，只先做不重叠的队列/播放纯逻辑和文档，不修改冲突文件。

## 3. 播放队列模型

### 2026-07-16 UI 与播放间隔增量

- 本地快照升级为 schema 2，并新增 `intervalSeconds`；schema 1 和缺字段快照迁移为 0 秒，其余题库、曲目、位置、模式、字幕和倍速继续恢复。
- 0 秒继续使用原有“当前内容 → 下一内容”和原生 `RepeatMode.Track`，不插入占位轨道。
- 1–30 秒使用短原生队列“当前内容 → 30 秒静音占位 → 下一内容”；单曲循环的下一内容仍是当前题。
- playback service 在静音轨道激活时固定 1× 并 seek 到 `30 - intervalSeconds`，等待由原生媒体时钟完成，不依赖后台可能暂停的 JS timer。
- 静音轨道沿用当前题锁屏标题、artist 和 album，但以 `radioTrackKind: interval` 与内容轨道区分；Provider 在等待结束前不提交下一题状态。
- 手动上/下一题不等待；等待中暂停会暂停原生时钟，继续播放会恢复；改模式只替换后续内容，改间隔会重新定位静音轨道，设为 0 会跳过占位。
- 静音资源加载或播放失败时跳过等待；内容音频失败继续使用原有可重试错误态。

建立与 UI 无关、可单元测试的队列状态机，核心状态包括：

- 当前 bank ID、完整曲目列表和当前 track ID；
- 播放模式 `order | repeatOne | shuffle`；
- 随机播放历史与历史游标；
- 字幕模式 `english | bilingual | off`；
- 倍速、保存位置和最后一次用户操作；
- 元数据、资源解析、缓冲、可播放、播放、暂停、结束和错误状态。

规则：

- 顺序模式按稳定顺序前进，末条回到首条。
- 单曲循环在结束事件中 seek 到 0 并继续，不重建队列。
- 随机模式从除当前曲目外的候选中选择下一首；上一首从历史返回，前进后再选新曲目。
- 点击上一首始终立即切换上一题，不因当前播放位置改变含义。
- 切换 bank 时保存原 bank 位置，进入新 bank 时恢复其上次曲目；首次进入从首条开始。
- 点击队列曲目属于明确播放意图，切换后自动播放。
- 原生 active-track 事件只接受带共享 `radioTrackId`/`radioBankId` 的队列项，并忽略当前题重复事件。

## 4. 全局播放架构

### 4.1 Provider 与唯一状态

在受保护 App 根布局的长期生命周期内挂载随身听 Provider：

- Provider 使用一个 Track Player 原生实例，随 App 登录会话存在并在退出时清理队列。
- Provider 暴露只读状态和 `play`、`pause`、`seek`、`next`、`previous`、`selectTrack`、`selectBank`、`setMode`、`setSubtitle`、`setRate`、`retry`、`stopAndClear` 等命令。
- 全屏播放器只负责展示和发送命令，不再直接 `replace` 或配置音频模式。
- 迷你播放器与系统媒体元数据订阅同一 Provider。
- Provider 只在当前曲目即将播放时解析签名资源地址，不为数千条队列提前请求 URL。
- 切歌时取消或忽略旧曲目的异步解析结果，避免慢请求覆盖新曲目。

### 4.2 资源加载与重试

- 抽取现有资源服务的非 hook 调用路径，继续使用同一签名 URL cache 和过期策略。
- 首次解析失败时保留曲目信息并进入可重试错误态。
- 用户重试时使用 `forceRefresh` 获取新签名地址，再替换当前 source。
- 播放超时沿用共享超时语义；失败后不自动无限跳曲或重试。
- 只有当前 source 成功加载后才执行用户待处理的播放意图。

### 4.3 为什么不直接加载完整 `AudioPlaylist`

Expo SDK 55 的 `AudioPlaylist` 能提供 gapless 和三种循环档位，但本任务不直接把全部曲目作为 native playlist：

- 当前队列最多数千条，生产 URL 为有有效期的签名地址；一次解析并装入全部 source 会增加启动时间、请求量和过期风险。
- 产品随机模式需要历史返回和避免连续重复，不能只靠 playlist 的 loop 模式。
- 当前 App 还要在录音、题卡短音频和随身听之间切换音频会话，单一按需 source 更容易明确所有权。

因此采用 JavaScript 完整元数据队列 + Track Player 原生短队列：只解析并装入当前与下一首，原生切歌后再补下一首。这样不批量解析签名 URL，也能让锁屏状态的自然结束和单曲循环由原生层完成。

## 5. 共享音频会话协调

建立共享 `AudioSessionCoordinator`，把全局 `setAudioModeAsync` 从页面组件中收口为明确 profile：

| 角色 | 音频模式 | 与随身听关系 |
| --- | --- | --- |
| 随身听 | 后台播放、静音键可播、独占音频焦点 | 获得长期播放焦点 |
| 题卡音频 | 前台播放、静音键可播 | 开始时暂停随身听 |
| 录音 | 允许录音、禁止后台录音 | 开始前暂停所有播放 |
| 录音回放 | 前台播放 | 与题卡音频、随身听互斥 |

协调原则：

- 同一时刻只有一个角色实际出声。
- 角色切换由协调层先暂停旧 owner，再设置音频模式，最后启动新 owner。
- 录音或题卡音频结束后不自动恢复随身听，避免意外出声；用户可从迷你播放器恢复。
- 耳机断开和系统中断按 `expo-audio`/系统行为暂停，App 不强行续播。
- 锁屏 active player 只允许随身听注册；停止、退出和切换到录音时清理或暂停系统媒体状态。
- 现有 `StudyAudioPlayer` 和 `SpeakingPracticePanel` 保留各自满足功能所需的 player/recorder，但不再自行竞争全局音频模式。

## 6. 后台与锁屏

2026-07-16 增量：播放间隔复用 Track Player playback service 和原生 active-track 事件。静音轨道固定 1×，内容轨道恢复用户倍速；因此前台、后台、锁屏和控制中心共享同一媒体时钟与远程命令，不新增定时器、player 或 session owner。

- `index.js` 在 Expo Router 入口前注册 Track Player playback service；根 Provider 注册与页面按钮共用的 play/pause/seek/previous/next/stop 命令。
- CNG/Prebuild 生成 iOS audio background mode；Track Player 自身提供 Android media playback foreground service 和媒体通知。`expo-audio` 的后台播放保持关闭，避免第二个后台 service owner；后台录音同样关闭。
- 原生队列始终至少准备当前曲目与下一曲；顺序/随机自然结束由原生队列过渡，单曲循环使用 `RepeatMode.Track`。
- 系统上一首/下一首事件进入同一 Provider 命令；手动下一首不受单曲循环模式拦截，手动上一首始终切换上一题。
- 锁屏元数据标题使用曲目标题，artist/album 使用“飞猪 ICAO”和模块/题组，切歌时由 Track Player 自动更新。
- Android 必须验证媒体通知与持续后台播放；iOS 验证锁屏、控制中心和切后台。
- 不开启后台录音，不为本任务增加无关权限。

## 7. 本地持久化

复用 `expo-sqlite/kv-store` 保存一个带 schema 版本的设备本地播放快照：

- 各 bank 最后 track ID；
- 当前 track ID 和播放位置；
- 播放模式、字幕模式和倍速；
- 0–30 秒整数播放间隔；
- 最后内容 release/version，用于恢复校验。

保存策略：

- 模式、字幕、倍速和切歌立即保存；
- 播放位置按节流间隔保存，并在暂停、切后台、切歌和卸载时补写；
- 冷启动恢复元数据和位置，但 `playing` 固定为 false；
- track 不存在或时长变短时校正位置；无法恢复时回到该 bank 首条；
- 退出登录停止播放并清除当前会话；是否保留设备偏好按现有账号隔离规则执行，不新增云同步文档。

## 8. UI 实现方案

### 2026-07-16 方案 1 修订

- 题库目录、我的标注和随身听改用同一个 `QuestionBankSwitcherHeader` 与同一底部切换抽屉，只注入各自的题库项和切换动作。
- 随身听头部不显示页面标题和明显分割线；返回/队列为 40 点击区与 20 图标，题库图标底盒 38、图标 19、箭头 16。
- 主体只保留一行可点击题名、题号胶囊和进入箭头；点击先暂停，再携带精确 card ID 进入学习页。
- 删除大封面、三排重复元信息、文字式“学习本题”和答案卡片；字幕关闭显示不超过 96 宽的轻量波形，字幕开启显示无边框滚动文字。
- 主播放按钮为 56/24，上下一题为 44 点击区/22 图标；模式、倍速、间隔和字幕使用 18 图标与单行短标签。
- 新增 0–30 秒、步进 1 秒的播放间隔抽屉，包含 0/3/5/10/15/30 快捷值；复用非破坏扩展后的 `AudioTimeline`。
- 波形只在实际内容播放时轻微呼吸，暂停和等待时静止，并遵循系统“减少动态效果”。

### 8.1 全屏播放器

- 以只读 Web `radio-player-view.tsx` 和当前 RN 页面为交互/视觉参考，使用 React Native 原生组件重构，不复制 DOM/CSS。
- 保留 App 的 TopBar、AppText、主题令牌、字体角色、钴蓝主控制和轻量卡片语言。
- 实现前按 `docs/ui-style-guide.md` 列出将复用的颜色、字体、间距、圆角、阴影、按钮、弹层和状态配方；不得凭感觉另起视觉语言。
- 页面采用“可伸缩字幕区 + 固定底部控制区”，删除负 margin 定位。
- 复用 `AudioTimeline` 实现拖动，拖动期间暂停，结束后只在原本播放中时恢复。
- 模式、倍速和字幕使用清楚图标与文字；三态切换不能只靠颜色表达。
- 长字幕使用独立滚动区域；无字幕、缺译文、加载、缓冲和错误都有稳定布局。
- 高级感通过明确的信息层级、充足但不松散的留白、统一对齐、轻边框/轻阴影和克制动效实现，不通过新增颜色、强玻璃效果、厚重阴影或装饰堆叠实现。

### 8.2 队列 Sheet

- 用虚拟化列表替代 `ScrollView.map`。
- 列表数据来自完整元数据队列，直接显示索引时长。
- 搜索和分类/题组筛选在内存元数据上执行，不触发音频解析。
- 当前曲目自动滚动到可见位置，支持选中态、正在播放态和错误态。
- 保留 Bottom Sheet 的安全区、拖拽与关闭行为，不在 Sheet 内创建第二播放器。

### 8.3 迷你播放器

- 在受保护路由的共享宿主渲染，只有存在当前播放会话且不在全屏随身听时显示。
- 使用绝对布局宿主与页面底部 inset 协调，不侵入每个页面手写 padding。
- 在题库沉浸学习、录音或阻塞弹层场景根据统一策略折叠或隐藏；不能遮挡学习主操作。
- 点击主体回到 `/content/radio`，播放/暂停和下一首直接调用 Provider。

## 9. 测试与验证方案

### 9.1 内容与纯逻辑

- 校验 `radioEligible` 模块、稳定顺序、音频/英文/中文/时长 100% 覆盖。
- 校验设计索引导入、缺失时长补齐、重复 ID、重复音频映射和异常时长。
- 队列状态机覆盖顺序末尾回首、单曲循环、随机不连续重复、随机历史、手动上/下一题、快速切歌和内容更新恢复。

### 9.2 组件与集成

- mock Track Player 验证 capabilities、后台 remote event 路由、加载、待播放意图、active-track 去重、seek、倍速、失败和强制刷新。
- 验证全屏与迷你播放器读取同一状态，路由离开不释放播放实例。
- 验证题卡音频、录音、回放会暂停随身听，且不会自动恢复。
- 验证 KV 快照节流、冷启动暂停恢复、失效 track 回退和退出清理。

### 9.3 原生与视觉

- 运行 `pnpm check`、内容全量检查、Expo Doctor 和相关测试。
- 原生配置变更后执行 Prebuild/Development Build；检查生成文件 diff。
- iOS 与 Android 真机或等价设备验证后台、锁屏、系统媒体控制、耳机/蓝牙断开、来电/音频焦点、录音互斥和长时间续播。
- 375 × 812 对照设计基线，并检查 360、390、430 宽度、长字幕、最大队列和错误态。
- 对全屏播放器、队列 Sheet、迷你播放器建立默认、播放、暂停、缓冲、错误、三种字幕和长文本状态矩阵，逐项保存真实渲染证据并进行视觉复审。
- 构建通过不代替真实播放和视觉验收。

## 10. 部署与发布边界

- React Native UI 与播放逻辑通过 Metro 验证；原生 config plugin 变化必须重建 Development Build。
- 时长字段进入共享题库 contract 后，embedded、远程发布物和 cache 必须保持 schema 兼容。
- 若只修改内容发布物而不改 `services/api`，按当前内容发布流程验证线上数据；若实际修改 `services/api`，必须按运行规则部署 ECS、重启容器、验证 `/health/ready` 和代表性题库请求。
- 不部署当前工作树中未经复核的其它题库迁移差异；正式发布必须来自明确文件集或已确认提交，并保留回滚点。
- 本任务不包含数据库 Migration。

## 11. 不采用的方案

- 不继续扩展页面内 `useState + useAudioPlayer`：无法支持跨路由、迷你播放器和统一生命周期。
- 不把题库卡片复制为随身听 JSON：会形成内容、字幕和音频的第二来源。
- 不把设计仓库时长索引直接复制为长期运行时文件：当前已缺 732 条，且会随题库版本继续漂移。
- 不预先解析并装入所有签名音频 URL：请求量大、易过期，也不利于随机历史。
- 不让每个音频/录音组件继续独立调用全局音频模式。
- 不继续用 Expo Audio 单 source + JS `didJustFinish` 承担锁屏续播：它不能提供本任务要求的系统上一首/下一首命令，且 JS 生命周期不是锁屏自然结束的可靠边界。
