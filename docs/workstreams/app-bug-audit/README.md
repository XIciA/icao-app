## 核心目标

1. 排查 App 的异常输出及主要流程，尽量消除明显 bug。
2. 区分合理业务限制、表达不清和真实逻辑缺陷。
3. 合理空态可以保留，但应清楚说明原因和下一步，避免让用户误认为故障。
4. 对逻辑缺陷追查共用原因及所有受影响入口，解决一类问题，不只修一个页面。
5. 同时检查无错误提示的隐性问题，例如静默跳过同步、错误数量、保存失败却显示成功。
6. 不承诺绝对零 bug；以覆盖证据、已知问题收口和针对性回归验证判断完成。
