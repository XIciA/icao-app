# 排查与修复方案（已授权实施，2026-10-17）

## 范围与分类

目标范围是 iOS、Android、正式 Web 的异常输出和主要用户流程。冻结的 Vercel 项目只做必要的只读核对，修改范围须以用户后续授权及项目边界为准。

每个输出分类为：

- 合理且清楚：保留，例如四级复考随身听没有适用内容。
- 合理但含糊：优化原因解释及重试、调整范围、登录或会员入口。
- 逻辑错误：追查数据来源、完整性、版本、权限、筛选和并发问题，修复所有相关调用方。
- 证据不足：记录缺少的证据和最小验证方法，不计为通过。

## 工作顺序

1. **建立输出清单**：红字、错误弹窗、空态、不可用、已删除、无权限、加载失败、永久加载、禁用按钮、无响应、异常返回。不能仅搜索颜色或错误关键词。
2. **逐项反查条件**：用户操作 → 账号与范围 → 请求及数据来源 → 筛选和权限 → 页面。核实数据是真的不存在，还是未加载、被过滤、无权限、旧版本或请求失败。
3. **查共用根因**：检查同一服务、索引和缓存的全部调用方，避免页面级补丁。重点排查局部数据当全局、网络失败当空数据、旧请求覆盖新状态、账号隔离和静默丢弃。
4. **补查正常外观下的错误**：登录退出、账号切换、备考目标/范围、做题保存、播放、标注/高亮/笔记、学习记录、随身听、模拟考试、会员刷新、重启与跨设备同步。
5. **按当前授权实施修复**：按数据丢失/账号隔离/权限 → 主流程阻断与错误结果 → 恢复能力 → 文案体验排序。
6. **验证并收口**：按风险选用聚焦测试和实际操作；设备音频等能力用对应环境验证，不机械叠加全量构建或平台矩阵。

## 验证场景

| 场景 | 关注点 |
| --- | --- |
| 免费、有效会员、到期 | 权限和提示一致 |
| 不同考试目标与学习范围 | 筛选准确，不误判下架 |
| 首次启动、缓存、升级 | 加载及历史数据兼容 |
| 断网、慢网、失败恢复 | 不假报无内容，恢复有效 |
| 重启、切换账号、跨设备 | 数据保留、隔离与同步 |
| 题库更新 | ID、位置、版本及旧引用解析 |

## 题库索引专项拟议方案

以下是本轮技术方案；实际实施和验证结果见 `completion-2026-10-17.md`。本轮不部署或发布，不迁移持久化数据结构。

- 在现有题库仓库层统一身份解析、存在性判断、权限判断和内容加载；不创建平行题库。
- 利用未经过学习范围过滤的 `scopeCardIds.all` 建立完整目录索引；内置正文仅是部分内容，不能作为题目存在性的依据。
- 拟以 `bankId + cardId` 表达稳定身份，分类和主题作为位置；迁移前检查历史版本唯一性及 ID 重用情况，兼容旧四段式引用。
- 统一解析入口覆盖标注、学习跳转、同步归属、历史记录和随身听返回原题等调用方。
- 区分加载中、可用、需要会员、范围不符、离线未缓存、网络失败、版本不一致、确认下架和引用未解析。旧目录缺失不能直接判删除。
- 同步携带身份，不依赖正文；旧记录解析失败保留并重试，不静默跳过。恢复只基于仍存在的本机记录或快照，不承诺找回从未上传且已丢失的数据。
- 复用版本与 checksum、现有账号隔离和授权缓存；目录及主题一致读取。正文变化需校验高亮指纹，避免错误定位。
- 逐项替换错误用途，保留合理的内置启动与离线回退；随身听备考目标限制按用户认可的行为保留。
- 加入目录完整性、ID 唯一性、版本与引用兼容、同步不丢记录及用户流程回归检查；诊断不记录用户正文或凭据。
- 只改服务器不能解决当前客户端索引逻辑；后续修复需更新受影响客户端和正式 Web。是否需要配套服务端或目录元数据更新，以最终实现为准；不需要重录题库。

## 交付与完成标准

- 异常输出清单：位置、触发条件、数据依据、文案、恢复操作、分类、证据。
- 问题清单：严重度、根因、影响面、修复方案与状态。
- 验证记录：已检查范围、测试结果、交付与用户验收分别记录。
- 剩余风险：未复现、缺少环境或证据的事项不能写成已通过。
- 已覆盖主要流程无未解决严重问题；所有清单项有结论；共性缺陷有统一修复及回归保障。
