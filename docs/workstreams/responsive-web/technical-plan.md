# 响应式 Web 适配技术方案

状态：已确认  
更新时间：2026-07-22

## 1. 推荐方案

继续使用当前 Expo + React Native Web 工程，在同一路由和业务模块之上增加轻量 Web 宽度约束；不新建独立 Web 项目，不新增第二套业务实现。

布局模式保留移动优先的三档断点：手机 `<768px`、平板 `768–1023px`、桌面 `≥1024px`。手机和平板使用全部可用宽度；桌面内容宽度取浏览器宽度的 88% 与 1280px 中的较小值，并居中显示。

## 2. 实现边界

- 共享：`src/app` 路由、`src/features` 业务、`src/components/ui`、`src/theme`、API 与 contracts。
- Web 布局层：以真实浏览器尺寸判断布局模式；移动 Web 全宽渲染；PC Web 的根页面、背景与全屏层保持 100%，只在共享页面内容层增加居中的宽度上限。
- 导航：所有 Web 宽度均保留现有底部导航与当前学习流程，不增加桌面导航分支。
- 页面：现有页面、卡片和交互直接接入统一限宽容器。仅在视觉验收发现溢出或固定定位异常时做最小局部修正。
- 平台能力：继续复用现有 Web 存储、录音、音频和会话 adapter；不创建第二个音频或录音生命周期 owner。
- 本地验收：允许通过显式 Web 构建开关显示 UI 验收入口。验收模式只放开页面路由，不创建认证会话或访问令牌；正常 Web 导出强制关闭，原生平台始终不可用。

## 3. 关键取舍

- 不重新开发 Web UI：手机与 PC Web 都直接继承现有移动视觉，PC 只限制横向拉伸，避免三端规则分叉。
- 不保留固定手机画布：它只能用于预览，不能满足真实手机浏览器或桌面宽屏使用。
- 不强制所有页面三端像素一致：共享产品规则和组件语义，允许 PC 为鼠标、键盘和信息密度调整布局。
- 不新增 Web 框架或生产依赖：当前 Expo Web、React DOM 和 React Native Web 已具备所需基础；只有验证证明现有能力无法满足时才回到大流程评估。

## 4. 风险与控制

- 固定尺寸调用会影响抽屉、音频与学习页：先统一真实视口来源，再逐页验证。
- PC 宽屏直接拉伸会破坏阅读密度：主体内容统一采用 88% 比例与 1280px 最大宽度，背景与全屏层不参与限宽；当前阶段不增加页面栏位。
- Web 平台能力与原生不同：录音只在 HTTPS 环境验收；存储、音频和会话继续通过已有 Web adapter。
- 免登录验收可能被误当作真实业务验收：页面必须显示验收模式标识，联网、同步和账号链路仍要求真实登录，并以构建检查阻止正常 Web 导出开启入口。
- 原生回归：Web 差异代码使用 `.web` 文件或 Web 壳层隔离；每阶段保留 iOS / Android 关键入口冒烟检查。

## 5. 不采用方案

- 独立 Next.js / React Web 工程：会复制路由、组件和业务状态，违反共享主代码库目标。
- 两套手机 Web / PC Web：会形成重复页面和后续维护分叉。
- 固定手机画布或手机外框：无法适配真实浏览器尺寸。
- 当前不采用桌面侧边栏、顶部导航和页面多栏：收益尚不足以覆盖设计、实现和三端维护成本，可在未来独立评估。
