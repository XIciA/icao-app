# Native App 1.0.0 技术方案

状态：已确认，执行中

## 总体方案

- 延续 React Native、Expo、TypeScript、NestJS、PostgreSQL 与 CNG/Prebuild，不引入 WebView 或第二套
  Native 技术栈。Vercel 用户 Web 保持冻结。
- 业务账号以永久 `accountId` 为唯一归属；认证身份、订单、会员、AI点数和学习数据通过服务端事务
  关联。客户端状态不授予永久权益。
- 采用不可变订单/权益/点数账本和可重算汇总状态；支付、通知、重试、归并和退款均以稳定外部标识
  幂等。
- 生产安全状态使用 PostgreSQL 持久化，避免服务重启清空验证码、近期认证、防重放和限流状态；首发
  不新增 Redis 生产依赖。

## 支付与权益

- 保留 `NativeCommerceProvider` 作为客户端稳定边界。iOS 优先接入锁定版本的 StoreKit 2 兼容库；
  若 Expo 55/RN 0.83 兼容检查失败，改用薄层 Expo Native StoreKit 2 模块，业务接口不变。
- 服务端使用 Apple App Store Server Library 验证 JWS、查询交易并处理 Notifications V2；不使用旧
  `verifyReceipt`。`accountId` 作为购买时稳定 UUID 关联标识，归并后由服务端映射至主账号。
- 数据层包含渠道商品映射、订单、Apple交易、通知事件、权益段、点数批次/流水和调整审计；测试与
  生产环境分账，交易标识全局唯一。
- 五档非自动续期商品映射到统一内部商品键；重复购买串行顺延会员时间，点数按权益段分批发放，退款
  仅撤回对应订单未兑现权益。

## 内容、AI与账号

- 版本化免费ID清单随包内置；会员题库和资产由现有内容API增加权益校验，签发72小时离线授权。缓存
  到期只锁定内容，不删除个人数据。
- 正式文本AI路由只允许 DeepSeek；静态词典保持0点且不调用模型；ASR只使用腾讯云。DeepSeek训练/
  改进口径按可核实事实披露，风险登记但不阻塞1.0.0。
- 手机、Apple、微信身份均映射至 `accountId`。绑定、归并、注销、免费点防重复和权益重算在事务内
  完成；近期认证与防重放授权均为短时、单用途并持久化。
- 手机号敏感操作的近期认证支持“当前密码”与“短信验证码”两条正式路径；已设置密码的审核账号
  通过当前密码完成注销，不依赖审核员接收公司短信。

## 运营后台与发布

- 新建独立 React/TypeScript 后台和专用管理API，部署至 `ops.readyoufife.com`；工作人员邮箱密码加
  TOTP，管理员/客服使用最小权限，所有高风险操作记录不可由普通后台账号修改的审计。
- App内法律文本、公开HTTPS页面和商店材料从最终代码/SDK/生产数据流统一定稿；公开页面不依赖登录。
- 每一正式产物从干净 `origin/main` 构建并绑定提交、构建号和发布标签；生产迁移先备份、在副本演练
  并保留回滚证据。

## Agent与集成

- 协调Agent负责范围、集成、发布和所有用户提示；代码、材料和只读审计Agent并行，灵活Agent轮换。
- 新Agent统一 `gpt-5.6-sol`、`xhigh`、平台默认速度。写入Agent使用独立短期分支/worktree和不重叠
  文件范围；审计Agent只读。
