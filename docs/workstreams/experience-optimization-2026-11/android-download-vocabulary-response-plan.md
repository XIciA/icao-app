## 独立排查依据

本轮排查基线为干净隔离克隆 `/private/tmp/icao-pdf-testflight` 的 `085536d0`，当时与远端 main 一致。原工程 `/Users/zhouyide/Desktop/icao-app` 为 `1ddd5e50`，落后该主干 12 个提交，已有修改未被覆盖。执行前须重新核对实际状态，不把本快照当作永远有效的基线。

用户说明使用最新 1.3.1。仓库记录对应安卓测试候选 3596173、源码 `8874900f`，iOS 对照候选 3596172；尚未直接读取用户手机构建号。已核对安卓候选至排查基线的相关下载、凭证、词汇和同步源码没有变化。

### 安卓题库下载

题库下载经 `download-manager.native.ts` 调用 `requestContentCredentials`，再由 `content-credential-verifier.native.ts` 调用 `@icao/distribution-environment` 的原生 Ed25519 验签。现有模块只注册 Apple，没有安卓实现；安卓自动链接解析也未包含该模块。

模块缺失导致验签返回无结果，凭证请求抛出 `invalid_content_credential`，被映射成“待验证”，该错误没有自动重试安排。这与用户看到准备后停住的现象一致。iOS 有原生验签实现；单词下载清单的 topics 为空，不经过这条题库凭证链。

### 单词响应

“认识”和“下一词”经 `useSaveAction`、词汇进度存储调用 `mutateVocabularyInCurrentWorkspace`，后者进入 `inCurrentLearningWorkspace`。该入口先 `await running` 等待正在运行的整轮云同步，再开始本地保存；界面又等待保存成功才切换，因此网络延迟进入点击响应链。

故障诊断测试分别保持云端请求不返回，两种词汇保存均未开始本地提交；释放请求后才能完成。近期同步调度增加周期同步、不再被连续操作推迟，会增加遇到上述等待的机会。此处可确认网络阻塞路径，不能据此断言安卓额外耗时的全部来源；仍需双端真机分段测量。

## 拟采用的最小修改原则

### 下载只补齐安卓能力

在现有原生验签模块内补齐安卓实现及自动注册，沿用现有接口和凭证合同，保留 iOS 原生实现。不另建下载流程，不针对 900 句硬编码，不跳过签名、账号、环境、有效期或内容范围校验。密码实现须覆盖项目支持的安卓版本，不以较新系统可用代替全部支持版本可用。

### 单词本地保存不等待云端网络

面向用户的目标流程为：点击 → 手机可靠保存本次单词状态与待同步记录 → 立即显示释义或下一词 → 沿用后台同步发送到云端。

本地保存通常比网络往返短得多；“立即”是用户感受目标，不承诺零毫秒，也不在未测量前承诺已达成。先移除已确认的网络阻塞，再测量必要的本地保存和渲染耗时；本轮不默认增加先切页、稍后才保存的机制。

- 优先将改动限制在词汇保存入口与同步模块中词汇文档的接收、合并分支，继续复用已有存储与待同步队列，不建立第二套词汇数据负责人。
- 不直接删除通用 `inCurrentLearningWorkspace` 的等待，不改变所有调用方的排队行为，不改全局同步频率来掩盖单词卡顿，不改音频或下载调度。
- 单词状态、当前学习位置、收藏等更新与相应待同步记录仍须原子提交；本地保存失败时保留当前操作并可重试，不显示已经保存成功。
- 本地词汇提交与云端词汇回写的互斥只覆盖必要的本地数据处理，网络请求不占用该本地保存过程。实施时核对迟到的推送确认和拉取结果，避免旧响应覆盖刚保存的答案、位置或收藏，同时保留跨设备合法更新。
- 保留账号切换、退出、学习数据清空及代际校验的保护；旧账号、旧学习代际的请求不得写入新工作区。保持原有数据结构和迁移兼容，不清空用户数据。
- 共享文件中可能需要修改词汇专用分支；“只改单词”以实际行为影响范围判断，不能只凭文件名保证。若发现必须改变共享队列的全局语义，先说明必要性及扩大后的影响，不自行扩展本轮范围。

## 追加问题 微信登录与支付及安卓包身份统一

2026-11-04 用户补充：最新安卓测试版没有微信登录入口，而此前使用过的安卓版本有微信登录。当前仅排查原因并记录，恢复方案尚未确认实施。

已核实的原因是独立测试包配置：`app.config.js` 在 `ICAO_APP_VARIANT=android-test` 时使用 `com.readyoufife.app.test`，并主动将微信 App ID 与 Universal Link 清空。安卓原生微信模块没有 App ID 时无法创建 SDK 实例，返回未配置；`auth-service.ts` 要求安卓微信已安装、受支持且已配置，登录页据此隐藏入口。现有微信登录代码仍在，不能将入口缺失解释成安卓系统不支持微信登录。

该构建分支由 `b7ed7c1d` 于 2026-10-17 引入，最新候选沿用它。已核对本机保存的制品清单：1.3.1 / 3596173 和上一独立测试包 1.3.0 / 3593084 都是 `com.readyoufife.app.test`，均没有微信 App ID 元数据与 wxapi 回调 Activity。用户此前可用的安卓包身份和构建号尚未直接核实，不据此否定用户曾经成功微信登录的体验。

最新交付记录也将此列为未解决的测试配置差异，而非系统必需差异。当前证据来自配置、调用链、Git 历史及留存的制品清单；未操作微信开放平台、生产配置或手机登录。

用户随后补充：微信支付也应可用，登录和支付都应与正式版对齐，不能用隐藏入口代替能力。代码确认安卓支付复用同一微信 SDK 实例，缺少 App ID 时也不能调起支付，且支付参数的 App ID 必须与包内配置一致。

用户明确希望新版与正式版都使用同一个包名，不再另装名为“测试版”的 App；只在官网右上角提供提前下载新版的次要入口。以此作为本轮方案方向，替代前面为 `.test` 独立身份另配微信应用的设想；当前仍是方案记录，不启动构建、发布或修改项目长期规则。

用户进一步明确：微信配置直接复用当前安卓正式版已经可用的同一套配置，包括登录与支付，不另行注册测试身份、不隐藏功能。实施时以当前可用正式制品及其实际构建配置为核对基准，不能只凭仓库默认值认定已一致；沿用正式包名、签名、App ID、回调和原有支付对接，不改微信后台、生产 API 或数据库。当前正式版可用来自用户的实际反馈，本轮尚未独立完成手机登录或支付验证；密钥、证书及签名材料不得写入本方案或日志。

- 新候选沿用正式身份 `com.readyoufife.app`、正式签名、应用名称及与正式身份匹配的微信 App ID 和回调配置。包名相同还不够，签名、原生配置及服务端身份也须逐项核对。
- 官网主下载入口继续提供已批准的稳定版本，右上角提供提前体验新版的入口；入口不同不要求包身份不同。提前放到次要入口不等于允许切换主下载、更新正式升级清单或向全部用户推送。
- 同包名、同签名的新构建会覆盖升级手机中的正式 App，不能与它作为两套应用并装。保留数据依赖正确升级和数据兼容，验收须覆盖账号、进度、收藏、记录和下载资源；不要求用户先卸载。
- 构建号在同一包身份下递增。将来稳定版本应能够继续升级提前体验的版本，不把卸载降级作为回退或数据恢复方案。

- 已安装的旧 `com.readyoufife.app.test` 属于另一套应用数据空间，不能通过改包名自动搬入正式 App。迁移前须核对可同步数据及仅存本机的数据；不自动卸载或清空旧测试 App，不声称登录同一账号即可恢复所有本地文件。

外部依据：[Android 更新机制](https://developer.android.com/google/play/app-updates)说明应用身份、签名及版本条件；[微信支付 OpenSDK 接入指南](https://pay.wechatpay.cn/doc/v3/merchant/4013289321)要求实际 Android 包名和签名与微信登记信息匹配。是否称为“测试版”不是能否使用微信的决定条件。

### 代码核对结果与确定性

排查仍基于隔离克隆 `085536d0`，新增 UI 排查未修改其代码。

1. **图标嵌套结构差异已经确认。** `src/components/ui/Button.native.tsx` 用横向 View 放置 `leading` 和 AppText，但把所有 children 都放进 AppText。`QuestionBankStudyScreen.native.tsx` 的上一题通过 `leading` 传左箭头，下一题则把右箭头作为 children 与文字混排进 Text；二者实际并非同一种布局。`HotspotDetailScreen.native.tsx` 同样把 Sparkles 放在文字 children 中，而且没有显式指定白色前景色。这是与截图相符的结构性问题；安卓换行、iOS 视觉基线差异的最终消除仍须原生渲染验证。
2. **单词裁切已找到字体与行框不匹配的明确依据，真机归因待验证。** `VocabularyStudyViews.tsx` 的 studyWord 使用 Noto Serif SC 半粗体，字号 36、固定行高 46，并允许 flexShrink。词标题附近没有定位在字母上方的白色遮罩。读取实际字体文件，unitsPerEm 为 1000，hhea ascent/descent 为 1151/-286，换算 36 号的自然上下度量合计约 51.7；`g/p/q` 下伸约 9.3，`y/j` 约 9.8。仓库当前 React Native Android 的 CustomLineHeightSpan 会将指定行高与字体上下度量之差分摊到基线上下，并收紧首末行边界；按上述度量估算，46 行高可能只剩约 7.4 的下方空间，与字形被截现象一致。实际安卓 Paint 度量、系统字体缩放及布局收缩仍需在设备上核对，不能将计算视为已完成真机复现，也不把提高 zIndex 当成既定修复。

### 最小实施范围

- 优先复用现有 Button 的横向图文布局，给需要右侧图标的按钮增加可选 trailing 槽位，让图标与文字成为同一行的独立元素；下一题使用该槽位。iOS 与 Android 共用 native 实现，不建立两套按钮。保留纯文字按钮及已有 leading 调用的默认行为，并检查共享组件受影响调用方。
- 热点开始学习直接移除该按钮 children 中的 Sparkles，清理因此不再使用的导入；保留原文字、题数、禁用条件和点击回调。不为此增加通用组件能力，也不影响热点 API、题目关联或学习入口。
- 不全局转换所有 children，不重写 Button 的点击、禁用、加载、教学锚点和可访问性逻辑；不改上一题/下一题回调、完成会话逻辑、热点题目筛选或进入学习的路由参数。
- 词标题先验证按字体自然度量提供完整行框、避免纵向收缩的局部修正；须同时检查继承的 pageTitle 行高，不能仅删除局部 lineHeight 后退回更小的全局行高。让文本按实际字体、系统缩放和换行计算所需高度，不针对 landing 或某个字母加偏移、遮罩或特殊判断。仅在该词标题样式内处理，保留 iOS 当前效果，不调整 AppText 或主题的全局行高，不改词汇内容、释义、学习记录和发音链路。
- 不顺带重排其他页面、替换图标体系或修改音频加载提示。截图中的其他界面现象不自动扩展本轮需求。
