# 离线访问与播放统一方案

日期：2026-11-02。状态：代码分析后的讨论草案，未实施、未进行设备复现。用户明确目标已记录；下列设计建议不代表已批准全部细节或发布。

## 目标与范围

已下载范围内的内容，在会员有效期内，无网也能进入和播放，包括连续多日离线及离线重新启动 App。有网时同样优先使用有效本机内容。保留现有账号、环境、内容权限隔离与加密机制。

本轮围绕题库访问和播放统一职责，并纳入共享授权影响到的离线入口检查。下载速度、离开下载页持续下载、全局页面转场另行讨论，不借此全面重做下载系统。

用户最新确认：基本同意保留可用正文、缺失资源就地提示的方向；不采用“提前保存所有题目文字”的方案。继续讨论和整理，不实施。

## 收敛后的最终效果与改动边界

在具有使用权限的前提下，用户只需理解三个结果：内容齐全就正常学习；只有音频不可用就保留正文、播放器内提示；正文也不可用就在原目标页内容区显示简洁空态，保留返回。取消以“前往下载管理”为主操作的整页引导体验，不新增离线专区或路由。没有正文时不伪造完整学习界面，也不显示依赖正文的作答控件。

| 情况 | 最终显示文案 | 交互 |
| --- | --- | --- |
| 正文与音频可用 | 无额外提示 | 正常进入、播放 |
| 没网且音频缺失 | 音频未下载，联网后可播放 | 在既有播放器状态位轻量显示，无无效重试 |
| 没网且正文缺失 | 本题未下载，联网后可查看 | 原页内容区简洁空态，保留返回；有真实可用目录时保留选题能力 |
| 已确认本机音频损坏、没网 | 音频不可用，联网后修复 | 保留正文，提示在播放器内 |
| 有网但实际播放失败 | 播放失败 | 可重试；正常情况下本地优先，必要时尝试在线回退 |
| 本机会员期限已到、没网 | 请联网确认会员状态 | 不断言用户未续费，不引导重复购买 |
| 普通内容更新 | 有更新 | 下载管理原状态位显示，旧完整版本继续可用 |

以上是面向用户的短文案；内部仍保留精确原因供修复与诊断。正常离线未下载不使用红色故障样式；真正的失败沿用既有错误语义。遵循 UI 规范，不在正常内容上方新增横幅或独占行，不因后台检查造成布局跳动。

现有正文与音频分开读取、本地优先、账号隔离和下载校验可以保留。两张截图显示不同结果本身不能证明两套代码逻辑冲突：正文可用程度不同可以合理产生不同显示。但现有整页下载引导、音频未下载却显示红色加载失败和重试，以及已证实的固定 72 小时限制，均与目标体验有差距。

最小完整调整分两部分：

- 展示层：调整现有学习入口空态和共享播放器状态，减少无效跳转、重试与过重文案；不为故事复诵和听力分别打补丁。
- 行为层：在现有正文仓库、缓存/资源解析、授权签发和账号恢复模块内修正范围一致性、授权期限及失效处理。版本更新策略按共享链路调整，不能仅更换提示词；用户设备上的具体异常仍需后续验证。

不需要更换技术栈或重建离线系统。展示改动相对局部；会员有效期内长期离线涉及客户端与服务端以及旧凭证兼容，不能描述成只删一个页面或改一个常量就完成。尚未实施，也没有据此确认具体改动行数或全部设备表现。

## 从用户操作出发的体验方案

以下均为建议行为，不是当前功能完成声明。评审每个场景时同时看：用户能否完成目标、提示是否准确、下一步是否可行、是否影响其他可用内容。正常学习尽量无需额外提示；异常在发生的位置解释，避免一律跳到离线引导页。

### 日常进入与播放

| 用户的行为与条件 | App 应显示和执行什么 | 合理性判断 |
| --- | --- | --- |
| 下载完成后开飞行模式，进入已下载题目并播放 | 正常进入原学习页面，点击即可播本机音频；不要求先去离线专区 | 下载应兑现可离线学习的承诺，入口无需另学一套 |
| 下载后仍然有网，进入同一道题 | 同样使用本地正文和音频；后台检查不挡住学习 | 网络好坏不应改变已下载内容的基本体验 |
| 学习途中断网，随后翻到另一道已下载题 | 保留当前题目和进度，继续进入和播放；不跳页、不清空内容 | 断网本身不是已下载内容的故障 |
| 连续多天没网，关闭并重新打开 App；会员仍在已确认有效期内 | 恢复本地账号与下载目录，正常学习；不因超过三天要求登录或联网验证 | 长期离线承诺必须覆盖重启，不只是一直开着 App |
| 从题库、收藏/标注或其他已支持入口进入同一道已下载题 | 得到一致的内容可用性结果，返回原入口；各功能自身在线能力另行提示 | 可用性不应由入口决定；不借此承诺所有在线功能可离线 |
| 仅下载某个考试范围，进入范围内题目 | 正常学习；下载页准确注明已下载范围 | 用户下载了所需范围，就不应因主题其他题目缺失而被阻断 |

### 下载不全与本机异常

| 用户的行为与条件 | App 应显示和执行什么 | 合理性判断 |
| --- | --- | --- |
| 没网，点进未下载题目 | 在原目标页正文区域显示“本题未下载，联网后可查看”，保留返回与实际可用的目录 | 没网时点击“下载”不能解决当前问题，不应让用户来回跳转 |
| 下载尚未完成就断网，点击已经完整准备好的题目 | 完整题目可学；未完成题目明确提示未下载完整；包状态显示部分下载 | 一个任务未完成不应否定其中已经可用的内容 |
| 题目文字在，但音频未下载 | 允许阅读；离线时播放器显示“音频未下载，联网后可播放”；有网时按原播放操作在线获取 | 能阅读和能播放分开说明，不能整页报错，也不能承诺完整离线可用 |
| 原本已下载的音频损坏，没网时点击播放 | 保留正文，播放器显示“本机音频不可用，联网后可修复”；相应下载状态更新为需修复 | 不归咎于用户未下载，不让用户重复进入同一故障 |
| 上述故障发生时有网 | 尝试在线播放与修复；成功无需用户手工重下整库；失败则显示准确原因和重试 | 修复局部问题，保护正常资源与学习上下文 |
| 网络反复连接与断开，或服务端暂时失败 | 已有效的本机内容继续使用；网络请求有界重试，不反复切换整页状态 | 临时网络失败不等于会员失效或文件被撤销 |

### 更新、会员与账号

| 用户的行为与条件 | App 应显示和执行什么 | 合理性判断 |
| --- | --- | --- |
| 发现题库有更新，但尚未更新或更新中断 | 下载管理显示“有更新”；原完整版本继续可学；新版本校验完成后切换 | “不是最新版”不应等于“无法离线学” |
| 会员已到本机确认的到期时间，离线进入会员题目 | 显示“本机记录的会员有效期已结束；如已续费，请联网同步”，保留返回与免费内容入口 | 离线无法断言用户没续费，避免误导再次购买；不显示未下载 |
| 已在另一设备续费，本设备一直没网 | 旧有效期内照常学习；超过旧期限需联网同步一次，恢复后复用完整下载 | 新增权益必须同步才能获知，但无需重新下载相同内容 |
| 会员到期后联网续费成功 | 更新授权和显示，完整文件直接复用；确实缺损的部分再修复 | 权益变化与文件下载分离，减少重复等待 |
| 主动退出账号、切换账号或换设备 | 不向其他账号暴露原账号会员下载；换设备需在该设备准备内容。原账号文件保留/清理由现有策略决定 | “已下载”属于当前账号和本机，不暗示跨账号或跨设备可用 |
| 联网确认会员已退款撤销 | 停止受保护访问并说明权益状态；普通网络错误不得显示这类提示 | 明确撤销才改变权限，避免误伤；完全离线只能依据最后有效授权 |
| 升级到新方案版本，但旧授权已过期且没网 | 说明“首次使用新版离线功能需联网同步一次”；联网后尽量保留原下载 | 不能伪造旧凭证延期，也不能把迁移提示变成每三天重复发生的要求 |

涉及播放器之外的在线功能（例如需要服务器参与的处理），应在对应操作处单独提示网络需求，不阻断已下载题目的阅读与播放。具体功能边界在后续核对时明确。

## 当前代码事实

- 服务端 `services/api/src/content-access/content-access.service.ts` 的 `issueCredential` 将到期时间设为会员到期与签发后 72 小时的较早值。客户端 `content-credential-verifier.native.ts` 同时拒绝超过 72 小时跨度的凭证。
- `download-manager.native.ts` 的 `compare` 针对已保存下载包检查凭证。`offlineCredentialNeedsRefresh` 在凭证缺失或剩余不足 24 小时时要求刷新；每批最多 24 个主题请求新凭证，验证后存入安全存储，无需重新下载音频。
- 刷新依附于下载更新检查、在线目录读取触发的下载协调、下载过程中的比较；需要先取得下载清单。联网本身不保证立即续期，清单请求失败可能使续期流程未触发。续期失败保留原有效期。
- 在线读取会员正文也可能签发并保存凭证；直接命中本地正文不保证触发此过程。
- 因此连续离线超过已签发凭证期限，会员即使仍有效，本地会员正文与关联音频也会被拒绝使用。
- 账号恢复缓存 `src/features/auth/account-restore-cache.native.ts` 另有 72 小时限制；`AuthProvider.tsx` 使用该缓存恢复本地账号。只改内容凭证期限不足以保证多日离线冷启动。
- 下载完成会校验正文和资源，但展示状态主要依据下载包记录；进入题目另查正文、授权与目录版本，播放另查资源索引、文件与解密，三个阶段没有统一表达当前可用性。
- 正文完整性检查按主题总题数，而下载可以仅覆盖所选范围；目录版本严格匹配也可能拒绝本机仍存在的内容。上述是代码条件，不等同于已确认用户设备上的唯一根因。

## 建议的授权规则

1. 服务端依据当前真实权益签发离线凭证，期限覆盖至已经确认的会员到期时间；取消固定 72 小时上限。客户端验证签名、账号、环境、内容范围与签名到期时间，不信任可修改的页面会员状态或本地自填日期。
2. 到期时间仅覆盖已经取得的权益，不预支未来自动续费。用户续费后，设备需要至少联网同步一次，才能获知新的到期时间；不能在完全离线时推断服务端新增权益。
3. 联网启动、恢复网络、权益变更、下载准备等时机通过现有授权负责人协调刷新，合并重复请求。授权刷新与媒体更新检查解耦，不以下载清单请求成功为前提，不阻塞仍有效的本地学习。
4. 临时网络或服务故障保留有效凭证和下载；明确的账号注销、退出、切换或服务端撤销权限按对应边界处理，不能把普通请求失败当作撤销。
5. 完全离线时无法实时获知退款或提前撤销；按最后签发的有效授权使用至其到期，联网确认撤销后停止受保护访问。这是满足长时间离线目标的必要取舍，列为方案讨论项。
6. 会员到期后显示会员到期状态，不伪装成未下载；建议保留文件供续费后验证复用，存储清理与权限到期分离。免费内容按自身权限判断，不统一施加会员到期限制。
7. 离线账号恢复与内容授权分工：安全恢复本地身份不要求每 72 小时联网，但恢复身份本身不授予会员内容权限。API 登录令牌过期不得直接使有效离线凭证失效；在线 API 仍必须按原登录授权验证。需连同冷启动、会话刷新和会员展示路径检查。
8. 时间判断使用统一实现，保留最近可信服务端时间，防止明显回拨延长授权；设备重启和系统时间异常的具体处理在实施设计时补齐，不能声称离线环境能获得绝对可信时间，也不能重新引入固定几天强制联网。

## 统一读取与状态

“已下载”表示指定范围的正文及必需音频/图片已经完整落盘、校验通过；“当前可离线使用”还须满足当前账号授权与文件可用性。两者在同一处计算和解释，页面不得各自拼接判断。

| 场景 | 建议行为 |
| --- | --- |
| 本地完整、授权有效，有网或没网 | 直接进入并读取本机音频；联网检查在后台进行 |
| 选定范围完整，主题其他题目未下载 | 按选定范围判定完整，不因主题总题数不足强制联网 |
| 只有部分题目可用，没网 | 已完整准备的题目继续可用；其他题目标明未下载或待修复 |
| 正文存在但音频缺失或损坏 | 可以阅读，明确音频缺失原因；不得把该题展示成完整可离线播放 |
| 本地不可用，有网 | 请求在线内容/音频，按现有缓存负责人修复；遇明确权限拒绝不回退绕过 |
| 本地播放失败，有网 | 有界地尝试在线回退，保留题目与播放上下文；不无限重试 |
| 本地不可用，没网 | 明确缺少正文、音频或文件损坏，保留其他可用内容 |
| 会员签名期限已到 | 提示会员到期或联网同步续费结果，不显示下载丢失 |
| 普通内容有新版本 | 已完整下载的旧版本继续使用，后台准备新版本并验证后切换 |
| 服务端明确要求撤销内容或权限 | 按明确撤销状态处理，与普通版本更新区分 |

下载版本的目录、正文与媒体引用组成一致快照。不得用新目录版本直接否定尚可使用的旧下载快照；更新失败保留原完整版本。切换粒度在现有下载包/主题模型中选择最小一致单元，避免再建一套独立存储系统。

## 代码职责建议

结构简洁的目标是每个事实只有一个负责维护的地方，同一种场景只定义一次处理规则。并非把所有逻辑塞进一个大函数，也不为每张场景表新增服务。

保留三个独立事实：授权是否有效、指定范围的文件是否完整、网络是否可用。“有更新”是另一条信息，不直接代表不可用。由现有共享读取层根据这些事实得到统一结果，页面只展示结果和操作。正文可读而音频不可用要能分别表达，不能用一个全局“离线失败”覆盖。

- 服务端权益与凭证签发：唯一决定可授权范围及到期时间。
- 客户端凭证验证与本地缓存：统一判断账号、签名、范围、时间和文件状态，复用现有缓存负责人。
- 正文仓库与资源解析：按统一结果选择本地或网络；正文和媒体维持同一下载版本。
- 下载管理：准备、校验、更新文件和范围清单，将实际失败反馈给可用性状态；不自行创造第二套会员权限判断。
- 页面、下载列表和播放器：展示统一的可用性与原因，不分别实现离线授权。

使用明确的状态类型表达完整、部分、缺失、损坏、到期与撤销；避免以一个 `outdated` 同时表示普通更新、文件损坏和权限失效。沿现有共享模块调整，优先解决共同根因，不逐题库加例外。

后续实现设计必须逐项回答：状态由谁维护、哪些事件更新它、并发请求如何合并、账号切换后旧请求如何失效、修复失败保留什么。读取不应每次全库校验；下载时完整校验，使用时按所需资源检查，并将新发现的损坏反馈给同一份状态。避免额外保存一份容易过时的“可用=true”与真实文件和授权竞争。

## 兼容与后续验证

- 旧 72 小时凭证不能由客户端改日期延期；联网时取得新凭证，尽量复用既有正文和媒体。旧凭证已过期且设备一直离线，无法安全凭空补发长期授权，需要一次联网迁移。
- 新旧客户端并存时，旧客户端会拒绝长于 72 小时的凭证。实施前设计兼容签发或协议版本协商；服务端仍独立验证权益，新策略不能直接破坏旧客户端。
- 旧下载标记失效但文件仍在的情况，需凭有效授权及完整性核验恢复，不能批量删除失效标记或承诺所有旧下载无需修复。
