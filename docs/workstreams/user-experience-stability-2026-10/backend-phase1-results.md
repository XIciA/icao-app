## 实际改动

### 1. 分阶段观测

主／运营 API 使用同一套请求观测：鉴权、会话检查、身份事务、题库元数据／正文／构造、同步事务／锁等待、资源查询／权限／签名和序列化阶段。日志沿用 Fastify 的 reqId 关联，记录路由模板，不记录新增正文、认证信息或签名 URL。

- 普通成功请求默认采样 1%；错误和服务端耗时 ≥1 秒的请求保留阶段统计。
- 每分钟记录事件循环 P95／最大延迟、RSS；现有清理和支付补偿任务增加耗时与 SQL 语句计数，不改变执行周期、锁、重试及返回值。
- 连接打上 `icao-api`／`icao-ops-api` 标识；提供 `services/api/scripts/backend-performance-diagnostics.sql`，按服务汇总 PostgreSQL 连接与锁等待。该文件仅 SELECT 与只读事务，本轮未对生产运行。
- `db.statements` 是 Drizzle 发出的语句计数；阶段耗时可能包含连接等待。**没有把它误称为纯 SQL 执行耗时，也没有声称驱动等待队列已被精确测量。** 连接／锁汇总用于后续定位，未新增自动查询生产数据库的任务。
- `API_PERFORMANCE_ENABLED=false` 可关闭本次请求／后台观测。

### 2. 版本化内容读取

题库摘要只取标题和数量等字段。题库、AppContent 和文章先读取当前版本／checksum，再复用已验证的不可变正文；题库复用目录、主题定位与免费资源索引，AppContent 复用旧／新版热点格式转换。

每个请求仍核实当前 active 版本，运营后台发布或回退后不依赖跨进程内存通知。显式请求旧题库版本仍有效。会员状态／到期时间和 sandbox 授权不放进共享缓存。题库 304 条件、旧热点格式、资源签名期限保持原语义。

协议接受等事务内读取绕过全局缓存，未提交内容不进入共享缓存。已缓存内容递归冻结，用户响应只拼入本请求的访问状态。缓存失败不保留失败 Promise，可重试恢复。

缓存为进程内 LRU：题库预算 64 MiB，AppContent 正文／格式各 16 MiB，文章 16 MiB；每个缓存最多 8 条、最多记录 16 个不同 key 的在途加载。预算按序列化字节乘 4 保守估算，**不是精确堆内存上限**。超预算不缓存；在途记录满时走普通读取，不新增拒绝响应，数据库仍受原有连接池约束。`API_CONTENT_CACHE_ENABLED=false` 可停用缓存。版本正文仍须按已有发布流程更新版本／checksum。

### 3. 索引与反馈查询

新增 `0059_resource_lookup_indexes` 两个非唯一、部分索引，分别覆盖当前 ready 资源和指定 checksum 的 ready／superseded 资源。迁移不改表字段、数据、权限或旧索引；新旧后端均可继续读取，因此启动最低 schema 仍为 0058。

反馈列表先查当前账号本页票据，再一次查这些票据的回复并分组；保留回复顺序、未读语义、分页、公开字段及所有权限制。一页 30 条时 SQL 从最多 32 次变为 3 次；空页 2 次。

## 性能对照

读取原提交中的服务代码作基线，使用相同本地 PostgreSQL、5 个连接、相同数据。合成题库 3,000 张卡片，JSON 1,852,405 字节；每档并发运行 3 轮，报告保留 1／10／30／100 档。下表为 **30 并发、90 个样本的热缓存服务方法 P95**，不含手机网络、HTTP、认证或真实音频下载，不代表线上容量。

| 场景 | 原代码 | 优化后 |
| --- | ---: | ---: |
| 题库目录 | 93.65 ms | 2.27 ms |
| 主题读取 | 90.67 ms | 3.26 ms |
| 题库摘要 | 82.08 ms | 7.66 ms |
| 协议／热点内容 | 12.54 ms | 1.42 ms |
| 文章列表（小样本） | 1.62 ms | 1.67 ms |
| 反馈列表（30 条） | 57.02 ms | 14.87 ms |

冷启动权衡：本次首次目录读取原代码 6.99 ms，新代码 9.93 ms。新代码首次建立索引、缓存和冻结对象有一次性成本，后续请求减少大内容读取；这两个单次数字不是冷启动 P95，也不能宣称首次请求一定更快。很小的文章样本收益有限，见完整报告。

30,000 条合成资源记录下，两种查询均使用新增索引；对照去掉索引的事务在测试后回滚。执行计划与单次 ANALYZE 原始值保存在 JSON，不能直接当成生产预期耗时。

观测开销：交替开／关观测，对固定 2 ms 等待、约 9 KB JSON 的合成 Fastify 路由各测 300 次、并发 30；P95 关闭 4.30 ms，开启 4.37 ms。日志写入内存 sink，因此不覆盖生产日志磁盘开销；上线后仍需观察。

原始结果：[读取与索引基准](backend-performance-benchmark.json)、[观测开销基准](backend-telemetry-benchmark.json)。
