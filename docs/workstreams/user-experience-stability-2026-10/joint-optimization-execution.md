## 方案自查与范围收紧

- 保持既有产品、权限与数据合同。以 main ec6781fc 为未优化对照，整合原 PR #298，而不是使用旧分支覆盖新功能。
- 客户端第一阶段保留模块排队、会员判断、启动恢复和末尾完整校验，仅优化确定的串行资源传输与进度；不重写授权或同步体系。
- 传输与加密分别限流；同资源共享消费者的取消、账号代次、播放优先和旧文件完整性是回归重点。
- 后端缓存只复用不可变内容；资源可以不增加题库版本而改变，因此清单仍读取当前资源元数据。每资源权限仍即时校验，不跨请求缓存授权。
- 批量资源查询优化不改变签名期限、响应顺序及四项签名并发上限；仍逐项权限检查。不引入 Redis 或新的平行服务。
- 2000 人定义为有操作间隔的活跃逻辑用户，主场景 10% 下载并对照 5%/20%；全量同时网络听音频另作带宽敏感性分析。脚本必须报告实际操作速率、排队和测试持续时间，不能把 2000 次瞬时方法调用等同两千人端到端使用。
- 隔离 PostgreSQL/本机负载只能验证覆盖的代码、数据库和环境；不能代表阿里 2 核机器、真实登录、Storage 签名、网络、手机解码。未覆盖项在结果中明确列出，不能宣称生产容量已通过。
- 生产压测、实例购买、带宽调整、数据库迁移、API/Web/TestFlight/Android 发布都不执行。当前开发和本地验证无需额外人工确认；若需收费测试资源或生产验证，先给出具体范围和费用。

## 已完成的确定性优化

1. 后端保留请求阶段观测、不可变内容缓存、反馈回复批量读取和可选资源索引，并重新匹配最新下载清单、中文 scope ID、资源更新时间。题库摘要不再读取整份正文；会员权限、资源变更、发布回退仍实时检查。
2. 离线清单只缓存题目结构、hash 等不可变计算，资源 checksum、大小、状态及 publishedAt 每次查询，避免同路径换音频后清单失真。五题库十范围、三词书与已稳定源码逐项比对。
3. 24 项资源解析由逐项资源定位改为一次数据库查询，保持输入顺序、重复项、ready/superseded 语义，每项权限检查和签名仍保留；最多四个并行签名，签名时限仍为 300 秒。
4. 客户端 PR #304 保留模块队列和完整校验，模块内两个下载 worker；播放与下载共享同资源传输，按消费者取消。传输总名额四个，字节处理串行，播放准备优先；增加实际字节进度。同步已合入的 Web 图标/封面改动后，候选源码版本为 1.4.4（3593082），不等于已构建或发布。

这不是重写后端。共享合同、已有接口路径、会员/购买/积分规则和数据库业务模型未更换。当前主干已具备本机身份优先恢复，本轮通过已有启动回归复测，没有再建另一套启动状态。本轮没有实施同步事务瘦身、AI 策略重构、CDN迁移或网关压缩；这些不能计作已经解决。

## 扩容评估与仍需验证的地方

建议路线是 API/数据库与媒体分开预算：4 核 16 GiB作为同机 API+数据库的第一档云端验证候选；不是经证明的两千人配置。若真实云端 CPU 或数据库等待成为瓶颈，再评估 8 核及数据库拆分。现有 60 GiB磁盘按可用空间、增长及 I/O 决定，不仅按人数购买。

音频与离线下载优先评估私有对象存储+鉴权 CDN。2000 人全员在线听 128kbps，另有 200 人以 256KiB/s 下载，含 25%余量约需 844Mbps媒体承载；按约 1Gbps量级规划，下载比例升到20%则约1.37Gbps。这是需求预算，不是要直接购买相同带宽的 ECS。

API 出网也需单独评估：本轮偏大主题模型，gzip采样后主题约28Mbps、启动清单约44Mbps。后续可用50～100Mbps作为启用并验证压缩后的API网络测试档；集中启动、无缓存或未压缩时可能更高，不能说媒体迁走后10Mbps就足够。本轮没有修改或部署网关压缩。

公开流量单价条件下，月1000/3000/5000GB的CDN+10% OSS回源流量小计约255/765/1275元；不含服务器、存储、请求、备份和API出网。服务器升配须读取成都可选SKU与本账户剩余期限报价，目前没有确认金额，不作总价承诺。
