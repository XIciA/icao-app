# 客户端下载并发与进度优化：审查记录

日期：2026-11-01。基线 `ec6781fc`（TestFlight 1.4.2 / 3593081）。本轮仅候选源码与 PR，不合并、不发布。客户端独占准备版本 **1.4.4 / 3593082**；不代表候选已构建或上传。

## 最小改动与方案自查

- 保留模块排队，模块内每批最多 24 个资源签名，采用 2 个资源 worker。其他模块等待当前模块结束，不并行启动整库。
- 继续由 `member-content-cache.native.ts` 负责授权、加密与资源生命周期；抽出的 `shared-resource-transfers.native.ts` 仅管理原生传输名额、暂存文件和处理队列，不拥有第二套下载清单或权限。
- 同账号、环境及代次、路径、checksum、大小相同的传输可被永久下载与临时播放共享；各调用方仍分别校验自身权限、尺寸、SHA 和输出类型。签名 URL 不作资源身份，也不跨账号共享。
- 原生总上限 4；离线下载最多占 2，音频会话活跃时新派发下载最多占 1。可选缓存不无限排队，非播放预取最多占到第 3 个槽，保留播放准备空间。已开始的合法资源不强行抢占；当前在线播放沿用既有 streaming 回退。
- 名额持有至所有暂存文件消费者完成，防止网络先完成、磁盘后处理导致临时文件堆积。只允许一项下载的读全量字节、SHA、加密、写盘处理同时运行；排队处理仅持有路径，播放准备优先于排队的批量处理。单文件上限沿用 50 MiB、临时播放 16 MiB。没有宣称真机峰值内存已测。
- 任一 worker 失败立即停止派发，并使同批其余 worker 的任务所有权失效；等待所有已开始 worker 收敛后才结束旧任务。暂停、立即继续、删除、换账号与商业环境仍保留 token/代次检查；一位消费者取消不能中断另一位仍有效的播放消费者。
- 并发 URL 过期刷新共用一次请求；新签名批次在释放刷新锁前生效，避免重复刷新竞态。
- 字节进度由原生回调聚合，约 100ms 节流刷新界面；资源完成时才使用既有约 1s 进度持久化。复用文件按各自字节计入，不按文件数量均分。旧持久化记录没有字节字段时仍兼容原数量进度。
- 保留每资源校验、加密，以及末尾逐文件完整解密/SHA 校验。验证完成前最多显示 99%，绿色“已下载”只在完整成功后出现。页面布局、图标、范围、按钮不变。
- 没有改 API、contracts、迁移、授权策略、启动恢复、PDF 或 Web 下载边界；未清空旧缓存、个人学习数据或题库 ID。

## 交叉审查：optional-first 取消回归

审查发现首个调用者为可选播放预取时，后加入的正式下载继承了不可取消的 `File.downloadFileAsync`。两方均取消后可能仍等待网络，使模块队列无法排空。新增测试在修复前稳定失败：600ms 后仍未收敛，只有手动完成旧网络请求才能退出。

现所有传输统一使用 `createDownloadResumable`，保留 required/optional 的名额与排队规则；均具有 120 秒超时、100ms 全消费者失效检查，取消调用幂等。仍有有效消费者时不中止传输；正常/失败完成也清理 Expo 进度订阅。账号变化仍报原账号上下文错误，单纯任务取消不保存迟到文件。

增加 optional-first / required-join 两方取消、分别仅取消一方、超时和后续任务可继续的回归，API VM 也运行同一真实实现。客户端相关 78 项先通过；同步 `c4597b80` 后，全量客户端 267 suites / 1870 tests、API VM 13 tests、类型检查均通过。最后增加“超时后原生仍返回成功”的拒绝与进度屏蔽，传输聚焦 13 tests 通过。相关 ESLint 0 errors，repository 测试保留 2 个既有 import/no-duplicates 警告。

## 本地有界队列 I/O 对照

脚本：`tools/benchmarks/download-resource-workers.ts`，原始 18 次样本：[download-worker-benchmark.json](download-worker-benchmark.json)。

独立运行；Node loopback HTTP，固定每请求 25ms 等待，合成 12 MiB 数据，真实文件读写、SHA、AES-GCM、末尾解密校验。每形态、每并发执行 3 次，并轮换测试顺序。直接使用产品 `runResourceWorkers`，原生传输/Expo bridge 不在该基准里。

| 形态 | 1 worker 中位数（范围） | 2 workers 中位数（范围） | 4 workers 中位数（范围） |
| --- | --- | --- | --- |
| 96 × 128 KiB | 2718ms（2687–2962） | 1388ms（1364–1524） | 703ms（693–705） |
| 3 × 4 MiB | 124ms（124–132） | 94ms（91–96） | 73ms（72–85） |

多小文件的受控对照中，2 worker 中位耗时较串行减少约 49%。4 worker 更快，但本轮默认仍选 2，为播放留名额并控制每设备瞬时流量；不能把 localhost 数字当作手机下载速率、运营商网络、云出口或两千人容量证据。产品共享传输实际 2/4 名额、取消和存储约束另由原生适配器回归测试覆盖。

运行命令：

```sh
pnpm --dir services/api exec tsx ../../tools/benchmarks/download-resource-workers.ts
pnpm exec jest --runInBand
pnpm typecheck
```
