# 五套题库文本质量技术方案

## 审查模型

审查工具按正式 registry 装配五库，只抽取 schema 中真实用户可见字段。每个值携带题库、
分类、话题、卡片、字段、JSON Pointer 和 SHA-256，按稳定顺序分成 250 条一批。

四轮处理为：

1. 确定性 Unicode、编码、格式和结构规则扫描。
2. 结合静态词典疑似词形和航空白名单做全量中英文低级语言复核。
3. 检查听力答案回显、场景呼号、说话人和同卡片跨字段一致性。
4. 二次审查修复账本，幂等应用后重新扫描并封存覆盖指纹。

## 写入边界

`content:text:audit` 只写 `.generated`；`content:text:apply` 只按审定账本修改维护源，原文或
指纹不匹配立即失败；`content:text:check` 验证覆盖、人工决定和全部修复结果。运行时不读取
审查账本或报告。

明确干扰语境中的连续符号替换为英文
`[unintelligible due to radio interference]`、中文 `［无线电干扰，内容不清］`，不猜测
缺失通话。数字、呼号或术语存在多个合理答案时保留人工审核。

## 生成与发布

有正式修复后递增全局内容版本，运行统一内容构建；随后仅同步受题库文本影响的静态词表和
ASR 文本库存。ECS 发布包只含发生变化的题库与空资源清单，Web v12 镜像复用 checksum 完全
一致的正式资源分片。

本任务不修改 Expo API、原生配置、数据库 schema 或 API 代码。
