## 1. 问题登记

当前 React Native App 已完成工程、题库、内容、账户与状态页面的功能承载，但现有验收重点是“可进入、可运行、代表页面无溢出”。它不能证明每个 Web 手机端页面、临时状态和交互结果已经与 React Native 一致。

当前 Web 设计稿是本任务唯一的产品对照基线。其代码只用于理解视觉、信息层级、交互状态与业务规则；React Native 必须使用原生组件重新实现，不复制 DOM、CSS、浏览器 API，也不使用 WebView。

本 workstream 的目标是把“看起来差距较大”的主观判断，转成可采集、可比对、可逐项关闭的视觉与交互差异清单，最终让现有 Web 手机模拟中的全部既有体验在 RN App 中得到 1:1 的原生等价复刻。

## 2. 目标与完成定义

### 2.1 最终目标

在 iOS 与 Android 原生 App 中，复刻当前 Web 手机模拟的：

- 页面结构、信息优先级、文案、图标、图片、颜色、字体角色、间距、圆角、边框、阴影与动效节奏；
- 页面入口、返回关系、Tab 切换、滚动、抽屉、Bottom Sheet、弹窗、选择器、表单与学习流程；
- 正常、选中、按压、禁用、加载、空、失败、权限、录音、播放、完成等用户可见状态；
- Web 当前明确标注为 mock、示例或待接入的能力边界及其提示方式。

### 2.2 “1:1” 的判定

“1:1”指用户在相同前置条件和相同操作步骤下，在 RN 中看到相同的信息、层级、布局、状态结果与后续路径；不是把 Web 技术实现迁入 App。

允许且必须记录的原生差异只有：

- iOS / Android 系统权限弹窗的系统界面；
- 系统状态栏、手势区、安全区、键盘、系统返回与原生音频/录音生命周期；
- 字体栅格化等无法消除的系统级像素差异。

上述差异不允许改变 App 内容区域的视觉布局、控件语义、交互结果或返回路径。

## 3. 对照基线与优先级

1. 执行开始时冻结的 `/Users/zhouyide/Desktop/icao设计稿` 当前 Git 提交、数据与可运行页面，是唯一页面、视觉、交互和状态基线。
2. Web 手机内容画布以 `/?embed=1` 的 **375 × 812** 视口为主基准；`PhoneFrame` 的外部机壳、浏览器装饰和 iframe 容器不属于 RN 还原目标。
3. 设计稿的 `docs/ui-style-guide.md` 约束颜色、字体、组件气质、导航与 360/390/430 宽度检查；现有 Web 实际渲染优先于抽象描述。
4. 如 Web 实际页面、UI 规范、RN 既有实现之间冲突，以冻结的 Web 实际页面为准；如该冲突会改变总战略、架构决策或第一阶段范围，暂停并由用户确认。
5. 设计稿仓库始终只读；截图、索引、差异报告、执行记录与 RN 改动只写入本仓库。

## 4. 范围

### 4.1 纳入范围

以下所有当前 Web 手机端真实页面及其可见状态，均须建立对照项并在 RN 中实现等价体验：

| 页面族 | 最低覆盖内容 |
| --- | --- |
| 主导航 | 题库、发现、我的三个 Tab；Tab 选中态、入口、回退后的状态与悬浮底部导航 |
| 题库与学习 | 五题库入口、目录、模块切换、学习卡、选择题、口语/复述、音频、字幕/原文/译文、答题卡、标签/高亮/笔记、报告、学习记录、我的标注及回跳 |
| 发现与内容 | 单词、随身听、文章、资源、课程、OPI 热点、AI 模考、AI 报告及所有详情、列表、抽屉和示例状态 |
| 认证与账户 | 启动、登录、注册、验证码、忘记密码、资料、编辑、设置、同步演示、安全、凭证变更、注销、退出确认 |
| 信息与系统状态 | 帮助、反馈、关于、协议、隐私、麦克风、通知、无网络、加载失败、维护、全局加载及重试/关闭路径 |
| 通用瞬态界面 | 下拉选择、Popover、Bottom Sheet、Dialog、确认层、表单校验、按压/禁用/加载、空与失败提示 |

每一项以“页面状态 + 前置数据 + 操作轨迹”为最小单位，而不是仅以一个路由或组件为单位。

### 4.2 明确不做

- 不修改、重构或迁移 Web / 设计稿代码；不将 Web 代码作为 RN 代码来源。
- 不迁移 `PhoneFrame` 外壳、iframe、浏览器功能或独立桌面营销页 `/curriculum`。
- 不趁对齐工作新增真实 Supabase Auth、云同步、真实 AI、支付、会员、下载或完整离线学习。
- 不以“功能已经更真实”为理由保留与 Web 设计不一致的页面、文案、状态或交互。
- 不为截图对齐降低已有数据、音频、录音、权限、本地保存与双端可运行能力。
- 不在未完成大流程的方案、盘点和路线图确认前开始 RN 业务代码、截图基线采集或批量页面改造。

对齐过程中发现的 RN 简单逻辑错误不属于新增功能，应在当前页面小闭环内修复，使入口、按钮、状态切换、返回和恢复结果与 Web 一致。

## 5. 需求

### R1：可追溯的对照标准库

在 RN 仓库建立不依赖设计稿仓库写入的对照标准库。每条记录至少包含：

- 稳定状态 ID、所属页面族、优先级与状态名称；
- 冻结的 Web 提交、入口 URL、固定视口、前置数据与截图文件；
- 从初始状态到该画面的可重复操作步骤；
- 对应 RN 路由、页面/组件、前置数据与截图文件；
- 视觉、交互、返回、状态恢复和原生例外的验收结果；
- 未关闭差异、责任模块、证据与关闭日期。

标准库必须能回答“这张 RN 图对应 Web 的哪个状态、经由什么操作到达、还差什么”，不能只存放无说明截图。

### R2：全量截图与状态采集

使用可重复的浏览器自动化或等价脚本，从本地运行的 Web 设计稿采集真实页面截图和状态截图。采集必须：

- 使用冻结数据、固定认证/示例状态和固定 375 × 812 内容画布；
- 覆盖每个真实页面和所有会改变用户所见结果的交互状态；
- 为涉及滚动的长页采集首屏、关键交互区域和必要的滚动终点；
- 为动画/按压/播放等过程保留能证明起点、过程结果和终点的截图或等价操作证据；
- 在 Web 页面不可访问、状态不能稳定复现或数据不确定时，明确记录为基线阻塞项，不得猜测或手工伪造截图。

### R3：RN 原生视觉复刻

RN 必须以标准库截图和 Web 实际效果为准，对齐以下可见结果：

- 375 × 812 主画布的内容位置、模块层级、卡片尺寸、间距、留白与滚动关系；
- 字体角色、字号层级、行高、换行、字重、数字样式和文本截断规则；
- 色彩、透明度、边框、圆角、阴影、图标、插图、图片裁切和状态色；
- 顶部栏、悬浮底部导航、底部操作区、Bottom Sheet、Dialog、Popover 与遮罩层；
- 360、390、430 宽度下的同一结构与内容优先级，不溢出、不遮挡、不异常裁切。

不得把当前 RN 的共享组件或已有样式视为不可改变的约束；只要它们造成对照差异，应在保持原生架构的前提下调整或替换。

### R4：RN 原生交互复刻

每个 Web 操作轨迹在 RN 中必须有等价的：入口、触发、可见反馈、状态变更、关闭/取消、返回与恢复结果。最低包括：

- Tab、页面入口、模块切换与深层页面返回；
- 下拉/选择器、Sheet、Dialog、抽屉、答题卡与外部遮罩关闭；
- 表单输入、校验、错误提示、按钮禁用与成功/演示反馈；
- 音频播放控制、播放列表、字幕、速度、题目切换；
- 录音权限、开始、停止、重录、回放、失败提示；
- 学习作答、标注、高亮、笔记、报告、学习记录与原题回跳；
- 网络、资源、权限、加载与维护状态的重试或退出路径。

Web 的 mock / 示例行为在 RN 中必须保留相同的用户认知，不得被误导性地呈现为已经接入真实服务。

### R5：简单逻辑修复与复杂能力占位

- 如发现 RN 中存在按钮无响应、错误跳转、状态未刷新、返回目标错误、弹层无法关闭、示例内容前后冲突等简单逻辑错误，应随当前页面对齐同步修复并验证。
- 修复只恢复 Web 已有或明显表达的行为，不借机新增产品流程、真实服务或复杂业务规则。
- AI、云同步、支付、会员等本阶段暂不接入的复杂能力，仍须复刻完整入口、页面、加载、成功、失败和返回等必要 UI。
- 暂无真实结果时可以使用稳定的示例内容，但必须明确标注“演示”“示例”或“待接入”，并通过可替换的数据/状态边界承载，后续接入真实功能时不得推翻页面结构。
- 占位 UI 也必须纳入 Web/RN 截图与交互验收，不能只放一个通用“敬请期待”页面替代设计稿中已有流程。

### R6：差异治理

所有发现的差异必须进入差异清单，并使用以下结论之一关闭：

- `已对齐`：截图与操作轨迹均通过；
- `允许原生差异`：属于本文件第 2.2 节范围，记录原因和两端证据；
- `基线待定`：Web 本身无确定或可重复结果，需要用户决策；
- `待修复`：不得在阶段验收时以“路由已存在”或“功能可用”替代关闭。

不得存在未记录的主观视觉差异。

### R7：持续验证与收口

每个小流程闭环至少验证：

1. Web 与 RN 的同状态截图并列/叠加对照；
2. 对应操作轨迹在 RN 可完成，并得到相同的界面状态与返回结果；
3. `pnpm check` 通过；涉及原生能力或原生依赖时，完成相关 iOS / Android Development Build 与冒烟检查；
4. 检查 Git diff，确认未修改只读设计稿、未引入 WebView 或浏览器 API；
5. 更新本 workstream 的状态索引、差异清单与必要阶段记录。

全量收口前，必须完成 iOS 真机逐核心流程检查；Android 保持构建和基础启动门禁，并在当前平台验收策略允许时完成物理 Android 集中回归。

- 不存在未解释的视觉、交互、返回或状态恢复差异；
- 所有允许原生差异均有明确原因和证据；
- RN 的类型、Lint、测试与相关原生构建门禁通过；
- 总战略、架构决策、设计稿只读边界及第一阶段明确不做项仍然成立。

## 7. 风险与暂停条件

以下情况必须停止小流程并回到大流程确认：

- Web 设计稿实际页面与 UI 规范、总战略或架构决策发生无法消解的冲突；
- 为实现对齐需要新增真实服务、账号、付费资源、生产凭证、外部平台或新的产品能力；
- Web 基线存在不可重复、缺失或互相矛盾的页面状态，且会影响用户体验决定；
- 原生平台限制导致不能同时满足 Web 的既有效果与既有 App 能力，需要改变最终体验；
- 当前工作区中其他未完成改动与本 workstream 的目标文件发生实际冲突。
