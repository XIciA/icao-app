# 设备独立使用路线图

状态：阶段 0 至 3 的自动执行已完成，等待 iPhone 人工终验（Android 阶段延期）

更新时间：2026-07-13

## 1. 路线图目标

在不改变当前App功能、UI和主体架构的前提下，完成临时个人域名过渡运行：

- iPhone在Apple Development签名有效期内脱离Mac独立使用。
- Android通过专属Release签名的APK独立运行并小规模受控分发。
- 当前Development Build、SSH隧道和本地调试能力继续保留。

## 2. 阶段总览

| 阶段 | 目标 | 核心产出 | 进入下一阶段标准 |
| --- | --- | --- | --- |
| 0 | 冻结边界与准备回滚 | 域名输入、执行文件集、ECS备份、人工前置检查 | 域名和回滚条件齐备 |
| 1 | 建立HTTPS公网入口 | DNS、Caddy、API与Supabase公开入口 | 手机网络可访问全部代表性端点 |
| 2 | 建立Release配置边界 | 受保护环境配置、双端构建命令、文档 | 产物不含回环或Mac地址 |
| 3 | iPhone独立运行 | Apple Development签名的iOS Release构建 | 停止Mac服务后核心链路通过 |
| 4 | Android Release APK | 专属密钥、签名APK、校验信息 | 干净Android设备安装通过 |
| 5 | Android升级与受控分发 | 覆盖升级证据、最终APK、版本说明 | 数据保留且分发包可核验 |
| 6 | 双端回归与收口 | 全量门禁、独立运行证据、phase-log、closeout | 本需求全部验收效果关闭 |

## 3. 阶段0：边界冻结与回滚准备

### 目标

在修改ECS和签名前，明确临时运行输入、隔离无关工作区改动并建立可回滚基线。

### 主要工作

- 确认临时个人主域名、DNS控制权和计划使用的 `api`、`cloud` 子域名。
- 确认域名备案状态及阿里云安全组80/443开放条件。
- 明确本任务目标提交或经过复核的文件集，不携带题库标注和音频审计等无关改动。
- 记录当前ECS容器、镜像、端口、环境文件和健康状态。
- 备份API源码、镜像、Supabase外部地址配置和拟新增公网网关配置。
- 新建本 workstream 的 `phase-log.md`。

### 允许范围

- 本 workstream 文档、只读检查、备份和运行状态记录。

### 暂不做

- 不修改总战略和架构决策。
- 不开放公网端口，不改Supabase，不生成签名密钥。

### 验收标准

- 临时域名和DNS入口明确。
- 80/443具备开放条件。
- 回滚文件和当前健康基线存在。
- 无关工作区改动不会进入部署或构建。

## 4. 阶段1：HTTPS公网入口

### 目标

让手机不通过Mac即可安全访问现有API、Supabase和音频资源。

### 主要工作

- 为 `api` 和 `cloud` 子域名配置DNS。
- 在ECS建立仓库可追溯的Caddy配置和自动HTTPS证书。
- `api`转发到本机业务API，`cloud`转发到本机Supabase Kong。
- 保持数据库、Studio、Mailpit、API和Supabase内部端口不直接暴露公网。
- 更新Supabase Auth外部URL、Site URL、回调允许列表及API公开Supabase URL。
- 重启受影响服务并验证健康状态。

### 验证

- DNS解析和HTTPS证书链。
- `https://api.<域名>/health/ready`。
- 注册、登录、token鉴权和App深链回调基础。
- 题库接口、资源签名、音频HEAD和Range请求。
- 同步、AI查词和代表性转写请求。

### 暂不做

- 不开放数据库、Studio和Mailpit公网入口。
- 不执行数据库Migration。
- 不修改App UI和业务逻辑。

### 验收标准

- Wi-Fi和蜂窝网络均可访问代表性端点。
- API、数据库、Auth和Storage健康。
- 内部端口仍只绑定本机或Docker网络。
- 原SSH隧道调试链路仍可回退使用。

## 5. 阶段2：Release配置边界

### 目标

建立不会泄露敏感信息、不会混淆开发模式的独立构建入口。

### 主要工作

- 增加不含真实值的Release环境示例。
- 使用Git忽略的本机配置或受保护环境变量注入真实公网地址。
- 增加iOS独立构建和Android Release构建命令。
- 明确Development Build、独立Release和ECS部署三类命令的用途。
- 确认客户端只包含公开地址和Supabase publishable key。
- 扫描产物和源码，确保没有数据库密码、Service Role Key、AI Key、SSH Key或签名密码。

### 验证

- `pnpm check`
- Expo生产Bundle导出。
- Bundle和生成配置中不存在 `127.0.0.1`、Mac局域网IP、3101、8000或8081运行依赖。

### 验收标准

- Release配置可重复生成。
- 开发命令不受影响。
- 真实配置和密钥未进入Git。

## 6. 阶段3：iPhone独立运行

### 目标

在当前Apple Development签名有效期内完成iPhone独立使用验收。

### 主要工作

- 使用Release配置和公网环境构建iOS App。
- 通过当前个人Team签名并安装到 `OOMG`。
- 确认JavaScript Bundle、字体和必要静态资源已进入安装包。
- 停止Mac上的Metro、SSH隧道和本地资源服务。
- 使用Wi-Fi和蜂窝网络分别完成核心链路。

### 核心链路

- 冷启动、登录与会话恢复。
- 五题库入口和代表性学习卡。
- 音频播放、录音、AI查词/转写/反馈。
- 学习记录、标注、笔记和云同步。
- 切后台、重新打开和失败重试。

### 验收标准

- 8081、3101、8000和本地资源服务停止后App仍可使用。
- Mac断开后App可冷启动并完成核心链路。
- 当前功能和UI无明显回归。
- 签名有效期和重新安装方式有记录。

## 7. 阶段4：Android Release APK

### 目标

生成首个可核验、可安装的Android Release APK。

### 主要工作

- 在仓库外生成项目专属Release Keystore并建立加密备份。
- 通过受保护配置接入Gradle签名，不提交密钥和密码。
- 将Release构建从Debug签名切换到专属签名。
- 使用公网Release配置生成APK。
- 输出包名、版本号、签名证书摘要和SHA-256。
- 在真实Android设备执行首次干净安装。

### 暂不做

- 不接入Google Play或国内应用市场。
- 不建设公开下载页面。
- 不更换项目主体架构和业务模块。

### 验收标准

- APK通过签名验证且不使用Debug证书。
- 真机冷启动、登录和核心学习链路通过。
- Mac停止后App仍可运行。
- Release Keystore已有至少一份可恢复的加密备份。

## 8. 阶段5：Android升级与小规模分发

### 目标

证明后续APK可以覆盖升级，并形成受控测试交付物。

### 主要工作

- 递增 `versionCode` 生成升级测试包。
- 在保留账号、本地学习数据、标注和缓存的情况下覆盖安装。
- 使用Wi-Fi和蜂窝网络复测核心链路。
- 生成最终测试APK、SHA-256、版本说明、安装步骤和已知限制。
- 记录测试者、设备、安装版本和反馈入口，不公开扩散下载地址。

### 验收标准

- 覆盖升级成功，无签名冲突。
- 账号和学习数据保留。
- 最终APK、版本信息和校验值一致。
- 测试范围保持小规模受控。

## 9. 阶段6：双端回归与收口

### 目标

确认独立运行改造没有破坏现有产品，并形成可接续和可回滚记录。

### 主要工作

- 运行 `pnpm check`、Expo检查和双端Release构建门禁。
- 复测登录、题库、音频、录音、同步、AI、标注、学习记录和生命周期。
- 检查ECS健康、证书续期、端口暴露、日志和敏感信息。
- 验证Mac全部ICAO进程停止后的双端冷启动。
- 更新 `phase-log.md`，生成 `closeout.md`。
- 记录临时域名、公司域名未来替换点、Apple签名到期和Android密钥保管边界。

### 验收标准

- `requirements.md`中的全部验收效果有证据。
- iPhone和Android均可脱离Mac独立运行。
- Android APK可安装、可升级、可核验。
- 无数据库迁移、UI重做、业务架构重构或秘密泄露。
- ECS和开发隧道均有明确回滚方式。

## 10. 小流程启动与暂停条件

本路线图经用户确认后，Codex可按阶段0至6自动执行，不需要逐项请求普通实现许可。

以下情况必须暂停：

- 用户无法提供临时域名或DNS控制。
- 域名备案、安全组或证书条件阻止HTTPS入口。
- 公网暴露出现安全风险。
- Apple Development无法签署目标Release构建。
- 缺少真实Android设备，无法完成安装和升级终验。
- Android密钥无法安全保存。
- 实现需要数据库迁移、账号体系重建、大规模项目结构调整或修改总战略。

普通构建、配置、兼容性、证书部署和验证失败由小流程先自主诊断修复；只有触发以上边界时返回用户决策。
