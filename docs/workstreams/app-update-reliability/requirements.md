# 应用更新机制：安卓启动检查与共享漏弹修复

记录日期：2026-11-05。状态：用户在同日撤销延期，要求本轮至少完成安卓更新机制；正在准备 1.3.2 / 3596177 独立测试候选。

## 用户决定与接续时机

此前延期决定已被当前要求替代：本轮实现安卓在进入登录／业务页面前检查更新，并修复共享检查机制。苹果已安装 1.3.1 仍有原问题；服务器清单正确不能替代客户端升级。本记录只约束本项任务，不新增长期规则。

1.3.1 已确认 App Store 审核通过且实际可下载，本轮新候选使用 1.3.2；仅递增 Android build 至 3596177，iOS build 不变，本轮不上传 iOS。正式 Android 下载和渠道切换仍需用户明确确认。

## 已核实的现状

- 安卓 1.1.1 / 3533721、1.1.2 / 3533722 未接入当前服务器更新清单，不能依靠该清单自动提示。
- 安卓 1.2.1 / 3578875 与当前正式 1.3.1 / 3596176 的检查和版本比较代码相同；苹果 1.3.1 / 3596174 也共用这套逻辑。安卓正式源码为 `7d6c456f`；苹果来源可由 `release/ios-testflight/v1.3.1-b3596174` 追溯。
- 自动检查要求登录后进入首页、会员状态就绪且无音频占用；会员到期提醒可能优先。24 小时是检查间隔，不是每隔 24 小时主动检查或弹窗。
- 同一个目标“渠道＋版本号＋构建号”被记为已提示后，不再自动提示；不同新版不继承该忽略键。手动检查绕过检查间隔和忽略记录。
- 提示之后仍需用户操作下载／跳转及系统安装确认，不是静默自动安装。

## 本轮修复重点

1. 请求前就记录检查时间，联网失败也会阻止 24 小时内自动重试。区分成功检查与失败重试，避免每次切前台连续请求。
2. 请求期间离开首页，结果可能被丢弃，但检查间隔已经生效。保留待提示结果，在允许的时机展示，保护学习、音频、录音和支付流程。
3. 弹窗实际显示前就持久化“已提示／忽略”，页面或账号、会员状态变化可能导致从未展示却永久抑制该目标版本。区分检测到新版、实际展示和用户关闭，不提前消耗提示机会。

本轮默认采用普通更新可暂缓，已向用户征询强制更新偏好；在用户另行指定前按可暂缓实现：

- Android 每次冷启动在登录／业务页面挂载前读取对应渠道，不依赖登录与会员状态。HTTP 限时 4 秒，启动门额外在 4.5 秒放行；失败后仍可进入 App。不能在用户打开 App 之前显示应用内提示。
- 手动检查与冷启动绕过检查间隔和暂缓记录。普通前台检查成功后缓存 1 小时，失败冷却 1 分钟；首页／登录页处于前台时每分钟调度一次，返回前台也调度。学习、录音、播放和支付中不打断。
- 缓存待提示结果，切页或会员状态变化不会永久消耗它。只有用户明确关闭才记 24 小时暂缓；下次冷启动仍可提示，不再永久忽略同一目标。
- 下载失败／取消可重试；允许安装来源后可继续安装并复用已下载包。沿用原生包名、正式签名、版本、SHA-256 校验及系统确认，不增加静默安装。
- 共享检查修复进入源码后，只有包含该代码的新包才生效。当前 iOS 1.3.1 不会远程获得修复；本轮 Android 启动门不自动引入 iOS。

对齐基准为 iOS 1.3.1 / 3596174（源码 `2bed7706`）以及后续 Android 3596176 的共享主干。保留 Android 安装包与系统安装权限这一必要平台差异，账号、学习、权益、内容、音频合同不变。
