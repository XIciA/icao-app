# Web 三类题库优化与增量迁移需求

状态：已确认，已完成

更新时间：2026-07-15

## 1. 核心问题

Web 题库中的听力、陆空通话和故事复诵，与 App 现有题库存在重复、高相似、格式不一致、分类不一致以及翻译或资源不完整等情况。App 现有题库已经完成多轮文本规范化，不能用 Web 旧数据整库覆盖。

本任务要把 Web 题库作为候选池，只迁移真正新增且质量合格的内容，使新增题目无缝融入 App 当前题库，而不是单纯追求题量增加。

## 2. 目标

- 从 Web 三类题库中筛选具有独立学习价值的净新增内容。
- 排除完全重复和高度相似、考点价值重复的题目。
- 补齐迁移所需的英文、中文、答案和音频资源，使每道新题可以直接学习。
- 按 App 当前分类、字段、标题和展示规则加入现有题库，不形成第二套结构。
- 保留 App 已完成的文本校准、稳定 ID、学习记录兼容性和现有用户体验。

## 3. 范围与权威边界

- Web 候选源：`/Users/zhouyide/Desktop/web题库/` 中于 2026-07-15 收集的听力、陆空通话、故事复诵数据及其关联资源。
- `banks/` 的 2251 条记录和 `quarantine/` 的 37 条记录均进入本轮候选，共 2288 条；听力分区是否集满 20 题不作为单题迁移条件，37 条原隔离记录按单题完整性正常审计。
- 目标题库：当前 `icao-app` 的听力、陆空通话和故事复诵正式题库。
- App 当前正式题库是内容和格式权威基线；Web 数据只提供迁移候选，不能反向覆盖 App 已校准内容。
- Web 源项目在本工作流中只读；筛选、补全和规范化结果只写入 `icao-app`。
- 本任务不处理 900 句、OPI 或其他产品内容。

## 4. 共性要求

### 4.1 候选筛选与去重

- 同时检查 Web 候选内部重复，以及 Web 候选与 App 现有题库之间的重复。
- 完全相同的音频或核心文本不迁移。
- 音频、主要内容、问题或学习考点实质相同的高度相似题不迁移，即使编号、标点、翻译或个别词不同。
- 只在细节相似但学习目标确有区别时保留；无法明确判断的候选标记后保守迁移，并在上线后集中人工复核，不形成中途停点。
- 每个候选都要形成明确结论：迁移、完全重复不迁移、高度相似不迁移、质量不合格暂缓或待人工确认，并记录理由。
- 相似度处于难以可靠判断的中间区间时，采用保守保留策略：先作为 `borderline-kept` 进入迁移，记录最相似对象、相似证据和保留理由，任务不中断，最终集中交由用户人工审核。
- 去重增加关键事实保护：呼号、数字、跑道后缀、高度、航向、频率或单位不同的候选，不得仅因其他文本高度相似而自动判为重复。
- 去重范围补充覆盖故事复诵：完全重复不迁移，高度相似故事需人工确认是否具有独立复述价值。

### 4.2 文本与内容质量

- 所有迁移内容必须符合 `docs/rules/audio-text/audio-text-unified-rules.md` 及对应题型细则。
- 本次只执行既有规范中的确定性展示和格式规则，包括标点、空格、换行、说话人标签、民航代码、进离场代号和 Runway 写法；不重新校对或改写语义内容。
- 不润色、不改写、不概括，不主动修正语法、用词、事实、句序或音频中的实际表达；疑似内容错误只记录为复核项，未确认前不迁移。
- 当前不使用 Whisper 或任何其他 ASR 模型，不新增识别候选，也不使用历史 ASR 结果决定迁移文本。
- 音频事实、数字、呼号、跑道、航向、高度、频率、地点和单位保持原内容，不得猜测修改。
- 删除能够明确判断为正文外的多余内容，例如 `(145 words)`、`(14words)`、独立词数统计、篇号、来源备注和重复首尾标签；无法判断是否属于正文时保留并人工复核。
- Web 原字段中混写的英文、中文或展示标签应拆分到 App 对应字段，但不得在拆分过程中改写原意。
- Web 与 App 内容冲突时，保留 App 已人工确认或已规范化的版本；Web 版本不能造成文本倒退。
- 新增翻译和字段拆分不得制造新的错配或矛盾；源题已经存在且本轮无法无证据修正的疑点保留原值、进入人工审核清单，不阻断其他候选。

### 4.3 翻译补全

- 缺少中文翻译的迁移候选必须补齐后才能进入正式题库。
- 翻译必须符合航空语境，准确表达原文事实和通话意图，不做自由扩写或简化关键数字。
- 已有且完整的翻译不做风格性重译；发现疑似实质错误时只进入人工复核。补译仅用于原字段缺失或明显不完整的候选。
- 呼号、民航代码、跑道号、进离场代号、高度、航向、频率和单位在中英文中保持对应。
- 无法可靠确认的专名或事实不得猜译；保留可追溯原值并进入人工复核。只有客观缺少必需字段或资源、无法独立学习的候选才排除为 `exclude-invalid`。

### 4.4 音频与资源完整性

- 每道迁移题必须有可播放、内容匹配且来源可追溯的音频。
- 缺失、损坏、错配或无法确认内容的音频不得直接迁移。
- 不重复迁移 App 已有的同一音频资源，不为同一资源建立多套长期来源。
- 新增音频必须使用 App 当前资源体系，并能通过现有音频映射和完整性检查。
- 迁移开始前冻结 Web 原始文件清单和逐文件 checksum；执行期间源文件发生变化时不得静默继续使用新内容。

### 4.5 无缝融入现有题库

- 复用 App 当前 `categories → topics → cards` 层级和学习页字段，不新增平行题库或特殊页面。
- 现有卡片 ID、标题、顺序、音频路径和学习记录关联不得因增量迁移失效。
- 新增卡片必须使用不冲突的稳定 ID、连续且符合现有风格的任务标题，并保留 Web 来源追溯关系。
- 必须保存完整映射：`Web 源 ID → App 新 ID → 目标目录 → App 音频路径`。
- 正式源、App 内嵌题库和后续发布内容必须保持一致。

## 5. 听力题要求

- 新题必须归入现有四类：`10s航空英语`、`20s陆空通话`、`20s航空英语`、`10s陆空通话`，不得新增近义分类。
- 分类先看内容形态：存在飞行员与管制员往返、标准陆空通话交互的归“陆空通话”；单人陈述、解释、广播或事故叙述归“航空英语”。不能仅按 Web Stage 机械映射。
- 在内容性质确定后再模糊区分长短：约 18 秒以下优先归 `10s`，约 20 秒以上优先归 `20s`；18–20 秒标记 `duration-borderline`，以 19 秒作为确定性兜底分界并记录实际时长，供上线后集中复核。
- Stage 只用于来源追溯，不直接决定 App 分类。
- 每题必须具备英文原文与问题、中文翻译与问题、四个选项、唯一正确索引、匹配的参考答案和有效音频。
- 问题、四个选项、正确答案和参考答案必须作为完整答题链路核对，不能只迁移原文。
- 完全重复或核心内容、问题和考点高度相似的听力题不迁移。

## 6. 陆空通话要求

- 延续现有按规范三字呼号前缀划分航司分类、按场景组织题组、按呼号自然排序的方式。
- 同一场景中的新增卡片必须归入正确呼号和场景，不得按 Web 旧目录机械照搬。
- 出现现有分类之外的有效三字呼号时，应先确认其真实性和必要性；不能确定时不建立新分类。
- 每张卡必须具备英文任务文本、中文翻译、英文参考答案、中文参考答案和有效音频。
- 同一飞行阶段、指令内容和标准回答实质相同的高度相似卡片不迁移。

## 7. 故事复诵要求

- 故事候选必须先在全局范围去重：同时检查 Web 候选内部，以及与 App 现有四个故事子库中的全部篇目是否完全重复或高度相似。
- 只有确认在全局范围内不重复、且具有独立复述价值的篇目才能迁移；与任何现有目录或本轮其他新增篇目重复的候选都不迁移。
- 所有批准迁移的新故事统一追加到“飞行 ICAO → 基础题库”，不再按内容重新分配到其他三个故事子库，也不新建目录。
- 每题必须具备完整英文故事、航空语境中文翻译和有效音频。
- 文本继续符合单段展示、粘词、标点和正文外标签规则，不把来源编号或重复标签带入正文。
- 完全重复故事不迁移；高度相似但无法可靠证明重复、且可能有独立复述价值的故事标记为 `borderline-kept` 后保守迁移，并进入上线后集中人工审核。

## 8. 明确不做

- 不整库复制 Web JSON，不迁移 App 当前结构不使用的生产字段。
- 不覆盖、还原或批量重写 App 现有已校准题目。
- 不以增加题量为理由保留重复、高相似或资源不完整内容。
- 不使用 Whisper 或其他 ASR 模型重新识别音频。
- 不对 Web 英文原文、现有中文翻译或答案做语义润色、事实修正和自由改写。
- 不修改现有 UI、导航、API、类型或数据库结构。
- 不删除 Web 源数据，也不在本工作流中反向更新 Web 项目。
- 本路线图已经获得内容迁移和 ECS 上线授权；仍必须在本地检查通过、数据库备份完成后才能改动线上活动题库。

## 9. 验收效果

- Web 三类候选全部完成去重、质量和迁移结论，正式迁移前没有未处理候选。
- 实际新增数量与“批准迁移”的唯一候选数量完全一致。
- 最终题库不存在已被确定判定为重复的新增题；保守保留的高相似边界题必须完整进入人工审核清单。
- 所有新增题字段完整、翻译准确、答案链路正确、音频有效且分类正确。
- 新增内容全部符合当前三类文本规则，没有把 Web 旧格式或正文外杂项带回 App。
- 最终正文不包含已确认的词数、篇号、来源备注或重复首尾标签，格式规范化前后实质语义保持不变。
- App 现有题目、稳定 ID、学习记录关系和其他两套题库保持不变。
- 正式题库源与 App 内嵌题库一致，内容构建、音频映射、完整内容检查和项目检查通过。
- 新增题在现有目录页和学习页中自然显示，不需要新增特殊界面或例外逻辑。
- 所有新增故事只存在于“飞行 ICAO → 基础题库”，并且与四个现有故事子库及本轮其他新增故事均不存在已判定的重复或高度相似篇目。
