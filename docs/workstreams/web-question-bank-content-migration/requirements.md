# Web 三类题库优化与增量迁移需求

状态：待确认

更新时间：2026-07-15

## 1. 核心问题

Web 题库中的听力、陆空通话和故事复诵，与 App 现有题库存在重复、高相似、格式不一致、分类不一致以及翻译或资源不完整等情况。App 现有题库已经完成多轮文本规范化，不能用 Web 旧数据整库覆盖。

本任务要把 Web 题库作为候选池，只迁移真正新增且质量合格的内容，使新增题目无缝融入 App 当前题库，而不是单纯追求题量增加。

## 2. 目标

- 从 Web 三类题库中筛选具有独立学习价值的净新增内容。
- 排除完全重复和高度相似、考点价值重复的题目。
- 补齐迁移所需的英文、中文、答案和音频资源，使每道新题可以直接学习。
- 按 App 当前分类、字段、标题和展示规则加入现有题库，不形成第二套结构。
- 保留 App 已完成的文本校准、稳定 ID、学习记录兼容性和现有用户体验。

## 3. 范围与权威边界

- Web 候选源：`/Users/zhouyide/Desktop/icao项目/feizhuicu/public/data/question-bank/mini-v1/` 中的听力、陆空通话和故事复诵数据及其关联资源。
- 目标题库：当前 `icao-app` 的听力、陆空通话和故事复诵正式题库。
- App 当前正式题库是内容和格式权威基线；Web 数据只提供迁移候选，不能反向覆盖 App 已校准内容。
- Web 源项目在本工作流中只读；筛选、补全和规范化结果只写入 `icao-app`。
- 本任务不处理 900 句、OPI 或其他产品内容。

## 4. 共性要求

### 4.1 候选筛选与去重

- 同时检查 Web 候选内部重复，以及 Web 候选与 App 现有题库之间的重复。
- 完全相同的音频或核心文本不迁移。
- 音频、主要内容、问题或学习考点实质相同的高度相似题不迁移，即使编号、标点、翻译或个别词不同。
- 只在细节相似但学习目标确有区别时保留；无法明确判断的候选必须人工复核。
- 每个候选都要形成明确结论：迁移、完全重复不迁移、高度相似不迁移、质量不合格暂缓或待人工确认，并记录理由。
- 去重范围补充覆盖故事复诵：完全重复不迁移，高度相似故事需人工确认是否具有独立复述价值。

### 4.2 文本与内容质量

- 所有迁移内容必须符合 `docs/rules/audio-text/audio-text-unified-rules.md` 及对应题型细则。
- 当前暂停使用 Whisper，不新增 Whisper 识别，也不使用历史 Whisper 结果决定迁移文本。
- 音频事实、数字、呼号、跑道、航向、高度、频率、地点和单位不得猜测修改。
- Web 与 App 内容冲突时，保留 App 已人工确认或已规范化的版本；Web 版本不能造成文本倒退。
- 英文、中文、问题、答案及音频之间必须语义一致，不得出现错配或相互矛盾。

### 4.3 翻译补全

- 缺少中文翻译的迁移候选必须补齐后才能进入正式题库。
- 翻译必须符合航空语境，准确表达原文事实和通话意图，不做自由扩写或简化关键数字。
- 呼号、民航代码、跑道号、进离场代号、高度、航向、频率和单位在中英文中保持对应。
- 无法可靠确认的专名或事实不得猜译；候选应暂缓并进入人工复核。

### 4.4 音频与资源完整性

- 每道迁移题必须有可播放、内容匹配且来源可追溯的音频。
- 缺失、损坏、错配或无法确认内容的音频不得直接迁移。
- 不重复迁移 App 已有的同一音频资源，不为同一资源建立多套长期来源。
- 新增音频必须使用 App 当前资源体系，并能通过现有音频映射和完整性检查。

### 4.5 无缝融入现有题库

- 复用 App 当前 `categories → topics → cards` 层级和学习页字段，不新增平行题库或特殊页面。
- 现有卡片 ID、标题、顺序、音频路径和学习记录关联不得因增量迁移失效。
- 新增卡片必须使用不冲突的稳定 ID、连续且符合现有风格的任务标题，并保留 Web 来源追溯关系。
- 正式源、App 内嵌题库和后续发布内容必须保持一致。

## 5. 听力题要求

- 新题必须归入现有四类：`10s航空英语`、`20s陆空通话`、`20s航空英语`、`10s陆空通话`，不得新增近义分类。
- 分类必须同时符合音频时长性质和内容性质；无法判断时进入人工复核，不强行归类。
- 每题必须具备英文原文与问题、中文翻译与问题、四个选项、唯一正确索引、匹配的参考答案和有效音频。
- 问题、四个选项、正确答案和参考答案必须作为完整答题链路核对，不能只迁移原文。
- 完全重复或核心内容、问题和考点高度相似的听力题不迁移。

## 6. 陆空通话要求

- 延续现有按规范三字呼号前缀划分航司分类、按场景组织题组、按呼号自然排序的方式。
- 同一场景中的新增卡片必须归入正确呼号和场景，不得按 Web 旧目录机械照搬。
- 出现现有分类之外的有效三字呼号时，应先确认其真实性和必要性；不能确定时不建立新分类。
- 每张卡必须具备英文任务文本、中文翻译、英文参考答案、中文参考答案和有效音频。
- 同一飞行阶段、指令内容和标准回答实质相同的高度相似卡片不迁移。

## 7. 故事复诵要求

- 延续现有“飞行 ICAO / 空管 ICAO”两类方向及“必做题库 / 基础题库”四个子库，不另建相近目录。
- 新故事必须按内容性质和现有子库标准归类，不能仅按 Web 文件夹名称迁移。
- 每题必须具备完整英文故事、航空语境中文翻译和有效音频。
- 文本继续符合单段展示、粘词、标点和正文外标签规则，不把来源编号或重复标签带入正文。
- 完全重复故事不迁移；高度相似但可能有独立复述价值的故事必须人工确认。

## 8. 明确不做

- 不整库复制 Web JSON，不迁移 App 当前结构不使用的生产字段。
- 不覆盖、还原或批量重写 App 现有已校准题目。
- 不以增加题量为理由保留重复、高相似或资源不完整内容。
- 不使用 Whisper 重新识别音频。
- 不修改现有 UI、导航、API、类型或数据库结构。
- 不删除 Web 源数据，也不在本工作流中反向更新 Web 项目。
- 未经后续路线图确认，不部署生产环境或改动线上活动题库。

## 9. 验收效果

- Web 三类候选全部完成去重、质量和迁移结论，正式迁移前没有未处理候选。
- 实际新增数量与“批准迁移”的唯一候选数量完全一致。
- 最终题库不存在已判定的完全重复或高度相似新增题。
- 所有新增题字段完整、翻译准确、答案链路正确、音频有效且分类正确。
- 新增内容全部符合当前三类文本规则，没有把 Web 旧格式或旧错误带回 App。
- App 现有题目、稳定 ID、学习记录关系和其他两套题库保持不变。
- 正式题库源与 App 内嵌题库一致，内容构建、音频映射、完整内容检查和项目检查通过。
- 新增题在现有目录页和学习页中自然显示，不需要新增特殊界面或例外逻辑。
