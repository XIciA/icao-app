# Web 专用 Vercel 后端分离需求文档

状态：已确认

更新时间：2026-07-28

工作目录：`docs/workstreams/web-vercel-backend-split/`

## 1. 问题登记

当前 iOS、Android 与 Expo Web 共用页面、组件、业务规则和产品流程。Web 静态前端部署在 Vercel，但运行时仍直接依赖中国大陆 ECS 上的 API、Supabase、题库和资源服务。

在当前域名无法备案的前提下，Web 可能因大陆服务器的未备案接入限制、跨来源请求和多段网络链路出现无法进入、登录失败或功能请求失败。

本 workstream 要保留当前 Expo Web 的页面和组件，不创建 Web V2，只为 Web 建立独立的 Vercel 运行时后端；Web 不再运行于或依赖当前阿里云节点，iOS、Android 及其阿里云运行链路保持不变。

## 2. 目标

- 保留当前 Expo Web 的页面、固定手机画布、导航、视觉、交互和现有功能入口。
- Web 正式运行时不再依赖当前阿里云 ECS、其自托管 Supabase 或其公网资源域名。
- Web 前端、服务端接口、邀请码校验和必要运行状态统一由 Vercel 或其受控集成承载；外部 AI 模型只作为服务供应商，不得让浏览器直接持有模型密钥。
- Web 使用独立邀请码进入，不建设与 App 共用的正式账号体系。
- Web 学习进度和个人操作数据只保存在当前浏览器本机，不提供与 App 的数据同步、云端恢复或跨设备同步。
- iOS、Android 继续调用当前阿里云 API、Supabase 和资源服务，不因 Web 后端分离而改变构建、发布或运行结果。
- Web 与移动端继续共享产品定义、页面组件、内容规则和接口语义，但账号、邀请码、会话和个人运行数据相互隔离。
- Web 定位为 App 的演示/体验型衍生产品，不承担与 App 完全等量的正式功能和用户数据责任。
- Web 后端切换必须可灰度验证、可回滚，不以直接覆盖当前生产链路作为首次验证方式。

## 3. 产品与系统边界

### R1：不创建第二套 Web 页面

- 继续使用当前 Expo Router Web、`src/app`、`src/features`、`src/components` 和 `src/theme`。
- 不创建独立 Next.js/React 页面工程，不重写现有 Web UI。
- 当前 Web 已确认的平台例外继续有效；浏览器系统权限、键盘、后台播放和锁屏能力不要求与原生完全一致。
- 后端分离不得成为修改品牌、页面结构、导航模型或核心学习流程的理由。

### R2：Web 运行时与阿里云解耦

- 用户打开 Web 后，正常使用范围内不得依赖当前 ECS 的 API、Auth、数据库、题库、音频、图片或下载域名。
- ECS 故障、维护、备案拦截或 Web 侧无法连接 ECS 时，不得阻断 Web 的进入、登录和纳入范围的核心功能。
- Web 客户端不得通过隐藏代理、IP、非标准端口或其他方式继续间接依赖当前 ECS。
- Web 所需服务端密钥不得进入浏览器包、公开环境变量、日志或仓库。

### R3：iOS 与 Android 保持原链路

- iOS、Android 继续使用当前 Expo Development Build、原生发布配置和阿里云运行时。
- 当前移动端 API 地址、Supabase、用户数据、题库和资源来源保持不变。
- 不因 Web 分离迁移移动端数据库，不修改移动端账号，不切换移动端 AI 供应链。
- Web 专用实现优先收敛在 `.web.*` 平台文件、Web 构建配置和 Vercel 服务端边界，不进入原生运行路径。
- 不得改变 iOS、Android 的页面效果、交互、音频生命周期、录音、学习数据、认证、接口结果或错误状态。
- 不得为了 Web 增加原生依赖、权限、Expo Plugin、原生配置或 Development Build 重建要求。
- 确需修改共享文件时，修改必须对原生行为保持等价，并通过现有 iOS、Android 自动检查和与风险相匹配的原生构建验证。
- 任一移动端功能或效果出现回归时，本 workstream 不得继续上线，必须先恢复原生基线。

### R4：Web Demo 功能效果

Web 后端切换后，应优先保证能够展示产品价值和核心学习体验的代表性流程，包括：

- 启动、独立邀请码登录、本机会话恢复和退出；
- 邀请码校验、失败提示和暴力尝试限制；
- 现有页面、固定手机画布、主导航和代表性内容入口；
- 最新完整题库文本、全部对应音频、学习卡和学习报告的体验；
- 学习进度、收藏、标注、笔记、学习记录和词汇进度的浏览器本机保存；
- 内容、文章、课程、OPI 热点和随身听前台能力；
- 选定的 AI 查词、语法检查、表达润色或录音转写体验；
- 现有错误、空、加载和本机数据丢失提示。

Web 不要求逐项复制 App 的全部正式能力。未纳入 Demo 的功能可以不接 Web 后端，但必须隐藏入口、显示明确的 Demo 边界或提供可理解的不可用说明，不能出现无响应、假成功或重新调用阿里云。

Web 不提供 App 账号注销、云端学习同步、跨设备恢复、全部设备退出、正式个人资料和长期服务端学习档案；相关页面必须显示符合 Demo 实际能力的说明，不得假装已经云端保存。

### R5：共享来源与允许分叉

- 题库正文、音频映射、时长、字幕、词汇、文章、AI 航空术语、业务规则和接口类型继续使用仓库内既有权威来源。
- App 内容发布链路及其已经确认发布到移动端服务器的版本是题库文本和音频的唯一真实来源；Vercel 只保存该版本的只读镜像，不允许直接编辑 Web 镜像。
- 每次 App 题库或音频正式发布后，开发者必须能通过一个标准命令完成校验、增量上传、预览验证和 Web 当前版本切换；不得人工逐文件复制。
- Web 允许晚于 App 同步，但对外可见版本必须是某个完整、可追溯、已经验证的 App 内容发布版本，不能暴露半次上传或文本与音频版本不一致的状态。
- 不为 Vercel Web 手工维护第二份题库、音频索引、学习规则或 AI 领域资产。
- 允许 Web 在构建或发布过程中生成适合其运行环境的派生产物，但派生产物不得成为新的编辑源。
- Web 与移动端在账号实例、邀请码、会话、个人数据和部署生命周期上明确分离。
- Web 个人学习数据仅保存在浏览器本机；清理浏览器数据、更换浏览器、更换设备或隐私模式结束后允许丢失。
- 产品必须在适当位置明确提示本机保存边界，不承诺云端备份、跨设备恢复或误删找回。
- Web 服务端只保存维持安全运行所需的最小状态，例如邀请码有效性、失败次数、限流和会话撤销状态；不建设完整用户资料和学习档案数据库。

### R6：失败状态与安全

- Web 的登录、题库、资源、AI、录音和本机保存必须提供明确失败、重试或恢复结果。
- 独立邀请码必须具备服务端校验、停用、过期、频率限制和失败次数控制，不能把有效邀请码明文打入浏览器包。
- 首版不做短信验证码、邮箱验证码、手机号或邮箱找回；只有风险评估证明必要时才增加轻量人机验证。
- 用户录音、学习数据、账号数据和 AI 使用记录必须遵守明确的访问、保留和删除边界。
- 浏览器录音只允许为当次转写临时上传；转写成功或失败后均应进入删除流程，并由兜底清理任务处理异常遗留，不建立长期录音库。
- 首版不建设 AI 用量配额、计费或用户额度页面；服务端仍必须具备基础请求频率限制、超时和异常保护，避免单次故障拖垮服务。
- Web 生产环境必须只使用 HTTPS；用户数据和服务端密钥不得通过客户端构建产物泄露。
- Web 上线前必须完成浏览器存储、Cookie、麦克风、录音和外部 AI 数据处理的合规检查。

### R7：发布与回滚

- 新 Web 后端先在独立预览环境完成验证，不直接替换正式入口。
- 正式切换前必须记录当前 Vercel Production 部署；迁移验收完成前，现有 Web/ECS 链路只作为一次性应急回退基线保留。
- 新架构的常规回滚必须回到上一版 Vercel 代码部署或上一版 Vercel 内容指针，不得把“重新请求 ECS”作为长期回滚方案。
- 若首次生产切换失败且尚未完成新架构验收，可以临时恢复旧 Web/ECS 版本；该状态视为迁移未完成，不得宣称已经达到 Web 运行时零 ECS。
- 本 workstream 的发布授权只覆盖 Web 和其专用运行时；不包含 ECS API 发布、关系型数据库迁移或移动端正式发布。

### R8：三端产品关系与功能等级

- iOS、Android 是一级主产品，共用 React Native / Expo 主工程和阿里云业务链路，产品需求、功能完整度、真机体验和正式发布优先保障。
- Web 是二级演示/体验型衍生产品，继续复用同一 Expo 页面和产品定义，但使用独立 Vercel 运行链路。
- Web 不拥有独立于 App 的产品方向，不得先于 App 重新定义导航、页面、题库规则、学习规则、AI 结果语义或品牌视觉。
- App 新增或修改功能时，Web 应优先继承共享页面、组件、内容和纯业务规则；浏览器或后端差异通过 Web 专用边界处理。
- Web 只选择性承载适合演示的 App 能力，可以因产品定位、浏览器能力、轻量账号和本机数据策略少于 App；差异必须明确记录和解释，不能无说明失效。

三端首版关系如下：

| 能力 | iOS | Android | Web |
| --- | --- | --- | --- |
| 产品优先级 | 一级主产品 | 一级主产品 | 二级 Demo 衍生产品 |
| 页面与视觉 | 正式基线 | 与 iOS 共用主工程 | 对标 App，共用页面组件 |
| 运行后端 | 当前阿里云 | 当前阿里云 | Vercel 专用链路 |
| 登录 | 当前 App 邀请账号 | 当前 App 邀请账号 | 独立 Web 邀请码 |
| 学习数据 | 云端同步与本机保护 | 云端同步与本机保护 | 仅当前浏览器本机保存 |
| 跨设备恢复 | 按 App 现有能力 | 按 App 现有能力 | 暂不提供 |
| 题库与内容规则 | App 权威发布链路 | 同一权威来源 | 镜像最新完整已发布版本 |
| AI 能力 | 当前 App 服务链路 | 当前 App 服务链路 | Vercel 服务端调用外部 AI |
| 音频与录音 | 原生完整能力 | 原生完整能力 | 浏览器前台等价能力 |
| 后台/锁屏/系统能力 | 原生支持范围 | 原生支持范围 | 允许明确降级 |
| 发布节奏 | 优先 | 优先 | 独立跟随，允许晚于 App |

### R9：Web 对标 App 与跟随更新

- 产品需求首先以 iOS、Android App 为主线确认和实现，Web 不阻塞 App 的正常路线和正式发布。
- 每项 App 变更先判断是否属于 Web Demo 应跟随范围；纳入后再判断属于“共享即可继承”“需要 Web 适配”“需要 Web 后端实现”或“浏览器不支持”四类之一。
- 共享页面、组件、主题、内容和纯业务规则只修改一个权威来源；Web 通过同仓库构建获得更新，不手工复制。
- 涉及原生设备能力的变更，App 可以先完成；Web 在后续 Web 适配闭环中提供浏览器等价能力或明确降级说明。
- 涉及阿里云 API、认证、同步、资源或 AI 的 App 变更，不得让 Web 重新依赖阿里云；必须评估 Vercel 侧是否需要对应能力。
- App 发布不自动把未经验证的共享改动直接提升为 Web Production。每次相关变更先生成 Web 预览版本，完成构建和代表性流程验证后再独立发布。
- Web Demo 不纳入的 App 功能不构成缺陷；需要跟随但暂未完成的功能必须记录在三端功能矩阵或平台例外中，写明 App 基线、Web 当前结果、缺口原因和后续状态。
- Web 可以晚于 App 发布或不跟随非 Demo 功能，但不得在共享代码变化后保持不可构建、入口失效或与已承载的产品规则冲突。
- 题库正文和全部对应音频更新时，App 内容发布链路先完成；Web 再通过一键同步流程镜像同一版本并发布，不得另开一套人工编辑流程。
- 文章、词汇和 AI 领域资产若纳入 Web Demo，同样从仓库既有权威来源生成，不得在 Vercel 控制台直接维护第二份内容。
- “Web 跟随 App 更新”只表示选定 Demo 范围内的产品、代码、内容和规则对标，不包含 App 与 Web 用户数据同步；两者用户数据始终隔离。

每次 App 功能更新后的 Web 跟随检查至少回答：

1. 本次 App 更新是否属于 Web Demo 应跟随范围。
2. Web 是否自动继承了相关共享页面、组件、文案和规则。
3. 是否新增了浏览器不支持的原生能力。
4. 是否新增或改变了阿里云接口依赖。
5. Vercel Web 后端是否需要增加等价接口或 AI 能力。
6. Web 本机数据结构是否需要兼容升级。
7. Web 预览构建、核心路径和回滚点是否通过。
8. 本次 Web 与 App 的差异是否已记录并可被用户理解。

## 4. 明确不做

- 不新建 Web V2，不重写一套 Web 页面和组件。
- 不封存或删除当前 Expo Web 源码。
- 不把 iOS、Android 改为调用 Vercel 后端。
- 不迁移、删除或覆盖当前 ECS、Supabase 和移动端用户数据。
- 不建设 Web 与 App 的统一账号、统一邀请码或学习数据同步。
- 不在当前或后续本 workstream 中建立 Web 与 App 的用户数据互通。
- 不建设 Web 个人资料库、长期学习档案、云端备份、跨设备恢复或误删找回。
- 不做短信/邮箱验证码、手机号/邮箱登录和密码找回。
- 不为 Web 复制题库、音频映射、字幕、时长、资源解析或学习规则。
- 不建设 Web 侧题库编辑后台，不允许把 Vercel Blob 或 Web manifest 变成内容编辑源。
- 不长期保存用户录音、转写原文件或 AI 对话历史。
- 不要求展示全部 App 账户页；无意义的账户页面保留共享源码但在 Web 隐藏，或以明确的“体验版不提供”状态替代。
- 不新增当前产品尚未确认的支付、会员、下载或完整离线学习能力。
- 不要求 Web 与 iOS、Android 每次同日发布，也不允许 Web 延期反向阻塞 App 主线。
- 不承诺仅靠本 workstream 保证 Vercel 在中国大陆所有地区和运营商 100% 可达。
- 需求阶段不决定具体数据库、认证供应商、Vercel Function 组织、文件存储、队列或迁移脚本；这些属于技术方案。

## 5. 验收效果

1. 当前 Expo Web 的页面、固定手机画布、导航和主要交互没有因后端分离出现明显变化。
2. Web 在不连接当前 `api.feizhuicao.com`、`cloud.feizhuicao.com` 及 ECS 资源域名的条件下，可以完成邀请码进入、题库学习、浏览器本机数据恢复和代表性 AI 流程。
3. Web 的邀请码校验、服务端会话、资源和 AI 请求全部进入已确认的 Web 专用云端链路；个人学习数据只写入当前浏览器本机。
4. ECS 停止提供 Web 访问时，Web 核心流程仍可独立运行；iOS、Android 仍能按原链路使用 ECS。
5. iOS、Android 的 API 地址、认证、数据、原生配置和发布流程未被切换，并通过与共享改动相匹配的检查和构建验证。
6. 浏览器包中不存在数据库管理密钥、AI 密钥、对象存储管理密钥或其他服务端秘密。
7. Web 的录音上传和 AI 转写在浏览器允许的文件大小、超时和生命周期边界内具有明确成功或失败结果。
8. 正式切换前已完成预览验证并保留可验证的 Vercel 代码与内容回滚点；回滚不要求恢复或修改移动端，也不以重新依赖 ECS 作为新架构的常规方案。
9. 实现没有引入第二份可编辑题库、音频映射、字幕、时长、学习规则或资源解析来源。
10. 清理浏览器数据后个人学习记录可以消失，但产品此前已明确提示本机保存边界，不出现“已云端备份”或“可跨设备恢复”的错误承诺。
11. 邀请码停用、过期和连续错误均由服务端拒绝，刷新或篡改浏览器本地数据不能绕过。
12. 纳入 Demo 范围的 App 新功能或改动能够通过共享源码和明确适配流程进入 Web，不要求人工复制页面、题库或规则。
13. Web 未承载或暂未跟随的功能具有清楚边界；不存在页面仍显示可用但实际无响应、调用阿里云或假成功的情况。
14. App 可以优先发布；未经 Web 验证的共享改动不会自动覆盖 Web Production，Web 预览验收通过后独立发布。
15. Web 可访问的题库文本和全部对应音频来自同一个完整 App 内容发布版本，版本号、manifest 和 checksum 可追溯；同步失败不会改变线上当前版本。
16. 开发者可通过一个标准命令完成 Web 内容同步，命令具备检查、增量上传、预览验证、原子切换和回滚能力。
17. Web 页面明确显示“Web 体验版”，并说明“App 是正式学习产品；Web 是独立体验产品”；无意义账户入口不展示，受限入口均有清楚说明。
18. 当次录音完成转写或失败后不进入长期存储；异常中断留下的临时对象可由兜底任务清理。

## 6. 已确认的轻量化决策

1. Web 不新建页面工程，继续使用当前 Expo Web。
2. Web 不再依赖当前阿里云 ECS、Supabase 和资源域名，运行时迁到 Vercel 专用链路。
3. iOS、Android 的功能、效果、构建、服务器和数据链路完全保持不变。
4. Web 使用独立邀请码，能通过邀请码进入和使用即可，不要求与 App 账号互通。
5. Web 不做与 App 的用户数据同步、云端学习数据恢复或跨设备同步，个人学习数据只保存在当前浏览器。
6. Web 暂不建设完整用户数据库，只保留邀请码、限流、安全和会话撤销所需的最小服务端状态。
7. Web 首版不做短信或邮箱验证码，不建设完整找回和账号管理体系。
8. 允许使用 Vercel 受控集成承载最小状态、文件和服务；AI 模型继续由外部供应商提供。
9. iOS、Android 是一级主产品，Web 是二级 Demo 衍生产品；App 开发与发布优先。
10. Web 通过共享源码、对标矩阵和独立预览发布机制选择性跟随 App 的 Demo 范围，不与 App 同步用户数据。
11. Web 必须镜像最新完整题库文本和全部对应音频；唯一真实来源仍是 App 内容发布链路，Web 只做只读跟随。
12. 开发者需要一个一键同步流程，把已发布 App 题库版本安全镜像到 Vercel；Web 允许晚更新，但不能发布半成品版本。
13. 浏览器录音只为当次转写临时保存，之后删除；不保存长期录音和 AI 历史。
14. 首版暂不管理 AI 用量配额，不显示额度页面；仅保留服务稳定性所需的基础限流和超时。
15. 无意义的完整账户页面不必展示，但共享源码不删除；Web 必须明确显示“Web 体验版”及其数据边界。

## 7. 后续方案阶段需要确定

以下内容不改变本需求结果，由后续技术方案比较后确定：

1. 邀请码、限流和会话使用何种最小状态服务。
2. Web 题库、图片、音频和其他资源如何从 App 权威发布版本一键镜像到非 ECS 运行位置。
3. 浏览器本机数据使用何种现有 storage adapter，以及容量、版本升级和清理策略。
4. 录音如何绕开 Vercel 请求体限制并完成临时上传、转写和删除。
5. 正式域名是否继续使用 `feizhuicao.com`，以及停止当前 Web 对 ECS 调用的切换时间。

## 8. 与既有决策的关系

本草稿改变了 `app-web-online-edition` 已确认的“iOS、Android、Web 使用同一云端数据源”边界，也为现有 ECS 单一 MVP 拓扑增加 Web 专用运行时例外。

因此本文确认后，进入技术方案前需要同步评估并更新：

- 项目总战略中的 Web 运行时定位；
- `architecture-decisions.md` 中 ECS 单一拓扑对 Web 的适用范围；
- `app-web-online-edition` 的三端同源维护规则；
- `docs/operations/deployment-and-runtime-rules.md` 的 Web 运行图与回滚边界。
