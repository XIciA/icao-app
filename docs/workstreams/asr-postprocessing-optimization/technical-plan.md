# ASR 后置优化技术方案

## 推荐方案

将现有后置函数升级为确定性规则引擎：

```text
rawTranscript
-> 基础清洗
-> 缩写与固定表达
-> ICAO 字母/数字
-> 航空结构化表达
-> 受限错词修正
-> transcript + 修改追踪
```

引擎只处理航空领域可确定的格式和识别偏差；通用词汇、句法和内容识别保持 ASR 原样。

规则分为：

- `safe`：不改变语义，可直接执行。
- `context-required`：只有明确航空结构时执行。
- `guarded`：来自真实错例，必须有强上下文和负例保护。
- `forbidden`：语法纠错、润色、补全和模糊猜测。

保留现有公开转写字段；后置程序内部增加独立版本和规则修改记录，供评测与排错使用。

## 迭代方法

1. 每轮抽取 900句、听力、陆空通话各 10 个新样本。
2. 每个模块 7 个随机样本、3 个重点航空结构样本。
3. 每段音频只生成并缓存一次 `rawTranscript`。
4. 先检查音频与 `audioText` 是否对应；源错配或明显错误文本单独记录，不参与规则评分。
5. 比较原始结果、后置结果和有效文本，统计严格匹配、内容匹配、WER、改善和变差。
6. 按模型错误、后置错误和源数据错误分类，再修改、增加、收紧或删除规则。
7. 重跑本轮样本和全部累计历史样本；通过后再进入下一轮。
8. 最后运行独立盲测集并完成收口。

## 关键取舍

- 题库文本仅用于测评，不进入运行时后置输入，避免答案补全。
- 规则采用本地确定性代码，保证低成本、低延迟和可解释性。
- 单次偶发错词不直接晋升为全局规则；优先处理重复、明确、可保护的错误。

## 不采用

- 不使用 prompt 或供应商 hotwords：不属于本轮后置范围。
- 不用 LLM 二次纠错：不可控且可能改写用户原话。
- 不只复测最近 30 句：会造成历史回归和过拟合。
