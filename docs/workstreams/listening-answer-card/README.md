## 听力答题卡需求

听力题有标准答案，可以直接判断对错，答题卡不能与其他题库完全统一为已学/未学两种状态。只增加一层结果判断，保留当前答题卡布局、学习状态和标注显示。

| 条件 | 题号显示 | 优先级 |
| --- | --- | --- |
| 已作答，且选择与标准答案一致 | 绿色，答对 | 高于已学/未学 |
| 已作答，且选择与标准答案不同 | 红色，答错 | 高于已学/未学 |
| 未作答，包括只听音频 | 沿用当前已学/未学样式 | 没有作答结果时回退 |

- 当前题仍保留选中轮廓，不覆盖其答对/答错颜色。
- 标签点、高亮标记、题号点击跳转和学习统计保持原有含义。
- 没有可用标准答案或作答数据时，不推断为答错，沿用学习状态。
- 其他题库沿用原有已学/未学逻辑，不把录音、AI反馈或主观练习等同于客观判分。
- 正在进行的模拟考试保持现有不提前透露答案的行为；交卷后的听力回顾可以展示已保存结果。

## 确认后的最小修改范围

1. 复用既有 `selectedChoiceIndex`、`correctChoiceIndex` 和学习状态来源，派生显示结果；不新增另一套持久化状态或判分机制。
2. Native 答题卡消费既有结果参数，按“结果优先，学习状态回退”渲染；复用主题的正确/错误颜色。图例和无障碍说明同步表达答对/答错。
3. 串通学习中、结束页、学习记录回顾的入口，核对 iOS、Android 与正式 Web 的同一语义。实时学习读取当前保存状态，历史回顾读取该记录的作答快照，不被后来练习覆盖。
4. 保留当前题标识、跳题、标签/高亮、统计和考试中的答案隐藏行为，不扩大为答题卡重设计。

## 验收与防回归

- 同一张听力答题卡包含答对、答错、已学未答、未学未答四种题目，颜色和说明分别正确。
- 只播放音频不产生对错；未作答不显示为红色。选择第一个选项（索引0）也能正常判定。
- 改选答案、切题后返回、退出重进及恢复已保存进度时，结果与当前作答一致。
- 结束页答题卡、学习记录和交卷回顾显示一致；旧记录缺字段时稳定回退，不伪造结果。
- 当前题轮廓、题号跳转、标签点、高亮和学习统计保持正常；其他题库不出现听力的对错颜色。
- 模拟考试进行中不通过答题卡泄露判分；交卷后按记录显示。
- 修改共享答题卡或学习状态时，回归上述差异；检查与发布按用户确认后的统一安排执行。

## 补充一：用户协议、隐私政策无法返回

### 用户反馈与现状核对

- 真机截图中返回箭头已进入状态栏区域，用户点击协议后无法返回，需要退出App。这是导航可用性问题，本轮不涉及修改法律文本。
- 登录页的 `LegalLinks` 使用 `AppModal` 包住 `Screen`/`TopBar`；协议更新同意页也通过模态窗口展示正文。`Screen` 已有顶部安全区处理，不能把问题简单归结为完全没有安全区。
- 当前原生 `AppModal` 未建立模态窗口自己的安全区上下文。需要核对模态视口、实际insets和顶部栏位置是否一致；这是优先调查方向，尚未经过修复后的真机验证，不能直接写成已证实的唯一根因。

### 拟定修复与验收

- 优先修正协议阅读容器的安全区来源和导航位置，继续复用现有页面和顶部栏，不给全局顶部栏添加猜测的固定偏移。
- 返回点击区至少44×44，避开状态栏/灵动岛；标题栏固定，正文独立滚动。
- 登录页、协议更新确认页、设置/信息页中的协议与隐私入口均核对。返回关闭当前阅读页，回到原入口，保留手机号、登录表单和原勾选状态；打开链接或返回不自动表示同意。
- 连续打开两份文档、滚到正文底部再返回、重复进出都正常，不需要重启App；检查不同顶部安全区的iPhone，并回归Android和Web的返回行为。

## 补充二：PDF导出的等待提示与取消

### 用户反馈与现状核对

- 用户确认PDF能够生成，主要问题是耗时较长、只有转圈，且缺少主动取消入口；不将其误记为完全无法导出。
- 导出页面已经传入“正在生成PDF”文案，但共享 `Button` 在 `loading` 时仅渲染转圈并隐藏文字，解释了界面只剩转圈的现象。
- 生成任务已有 `AbortController` 和协作取消检查，当前仅在页面卸载时触发；界面没有“取消本次导出”动作，且生成中的返回动作被 `busy` 拦截。

### 拟定修复与验收

- 在现有底部生成区显示转圈及可见文案“正在导出，请稍候…”，同时提供轻量的“取消导出”入口。局部适配，不改变其它按钮默认加载样式，不增加全屏等待页或无依据的百分比/剩余时间。
- 取消后留在导出设置，保留范围和勾选项；可重新发起。取消作为正常用户操作，不显示“生成失败”。
- 复用当前任务的取消机制，覆盖字体读取、排版、序列化、文件落盘及迟到结果的处理；不只把按钮恢复可点，也不能让旧任务的完成或清理回调覆盖新任务。
- 若某阶段无法即时中断，取消请求仍使该任务失效，在可让出执行的位置停止并清理结果；不能先显示已取消，随后又弹出旧PDF。
- 区分两个独立动作：“跳过教学”只退出教学，生成继续；“取消导出”取消实际生成任务。教学期间两个入口都必须可点击，遮罩不能挡住取消。
- 回归小范围和全量、附带高亮/标签/笔记、生成后预览/分享；覆盖生成早期取消、较晚取消、立即重试、离页和换账号，确认无旧结果回填、无学习数据丢失。

## 补充三：教学弹层底部突然变深、闪烁

### 用户反馈与现状核对

- 本聊天的收藏教学和导出设置截图显示：上半部灰色遮罩下方出现一条明显更深的区域；弹层进入过程中会闪一下。截图确认了现象，尚不足以单独证明唯一根因。
- 相关链路为 `GuideOverlay`、`GuideModalScope`、`AppModal` 和 `BottomSheet`。当前Native同时保留根页面遮罩、渲染模态层裁剪遮罩，并对底部弹层执行位移动画。
- 重点核对根层/模态层/普通弹层背景是否在同一区域重复变暗，以及 `measureInWindow` 得到的位置与动画中弹层的实际可见位置是否一致。不能把最终位置的裁剪区域提前画在仍然透明的区域上。

### 拟定修复与验收

- 明确每个可见区域的遮罩归属，在弹层进入、显示、退出全过程保持灰度连续；坐标、裁剪与实际动画一致，避免多层叠加形成深色带。
- 保留已有聚光灯样式、真实目标点击、跳过教学、滚动定位与弹层动效。不给所有步骤统一加延时，也不以取消全部动画或重写整套教学掩盖问题。
- Web使用同页面portal，不能直接套用Native多窗口处理；普通非教学弹层也要回归。
- 重点验收“查词→收藏→关闭→录音”和“900句目录→导出→范围/语言/筛选弹层”，包括快速开关、返回、跳过、重新查看教程。
- 对用户说明基本正常的教学步骤做回归，尤其录音/AI反馈、单词教学和普通底部操作，避免修复局部闪烁后出现白屏、重复变暗、目标错位或按钮不可点。
- Native弹层动画中的视觉结果必须在候选真机上检查；静态组件断言或Web预览不能单独证明这一问题已消失。

## 补充四：频率标签应贴近单词，而非屏幕边缘

### 用户反馈与现状核对

- 真机 `clearance` 截图中单词保持居中，但频率标签出现在屏幕最右侧且被裁切，未达到“单词右上角”的要求。
- 当前 `VocabularyStudyViews.tsx` 的频率标签采用 `left: '100%'`、固定宽度定位，标题容器还保留两侧空间；它依赖布局容器边界，不能保证是文字实际可见边界。需结合Native文字布局测量核实具体偏差，不沿用只在Web看起来正常的结论。

### 拟定修复与验收

- 以单词实际渲染文本的边界为锚点，将蓝色小标签放在其紧邻的右上方；单词文本自身的中心仍与页面内容中心对齐。
- 标签不参与把单词推偏的横向排版；按实际标签宽度及可用屏幕范围约束位置，完整显示，不依赖屏幕右边界或固定60px宽度。
- 短词、长词、长短语换行分别处理。空间不足时在文字块右上方的可见范围内安排标签，不挤偏单词，不遮挡单词、发音或收藏按钮，不擅自大改现有字体与学习页布局。
- 切词、字体加载、系统字号/可用宽度改变后重新对齐，避免沿用上一词的边界产生瞬间错位。
- 回归短词/长词/多行短语、不同频率标签、无频率标签、连续下一词和展开释义；保持发音、熟悉程度、收藏、测评、进度及使用指南定位正常。
- 以原生iPhone上的文本实际位置为主要验收依据，并检查Android与正式Web共享组件的适配。
