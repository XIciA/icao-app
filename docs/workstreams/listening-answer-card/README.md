# 听力答题卡与维护经验文档方案

状态：待用户确认。2026-10-25 用户要求先记录方案，确认后统一修改；本文件入库不表示已确认或已实施。

本轮只记录需求、实现检查结果和拟定方案，不改产品代码、不激活新的长期规则、不构建或发布。

## 用户需求

听力题有标准答案，可以直接判断对错，答题卡不能与其他题库完全统一为已学/未学两种状态。只增加一层结果判断，保留当前答题卡布局、学习状态和标注显示。

| 条件 | 题号显示 | 优先级 |
| --- | --- | --- |
| 已作答，且选择与标准答案一致 | 绿色，答对 | 高于已学/未学 |
| 已作答，且选择与标准答案不同 | 红色，答错 | 高于已学/未学 |
| 未作答，包括只听音频 | 沿用当前已学/未学样式 | 没有作答结果时回退 |

- 当前题仍保留选中轮廓，不覆盖其答对/答错颜色。
- 标签点、高亮标记、题号点击跳转和学习统计保持原有含义。
- 没有可用标准答案或作答数据时，不推断为答错，沿用学习状态。
- 其他题库沿用原有已学/未学逻辑，不把录音、AI反馈或主观练习等同于客观判分。
- 正在进行的模拟考试保持现有不提前透露答案的行为；交卷后的听力回顾可以展示已保存结果。

## 当前实现核对

以下是本次读取代码得到的事实，不是已经完成的修复：

- `src/features/question-bank/components/AnswerCardSheet.native.tsx` 已声明 `results` 参数，但渲染未消费它，只显示学习状态。
- `QuestionBankStudyScreen.native.tsx` 的答题卡入口只传学习状态，未传作答结果。
- `StudyReport.native.tsx` 的结束页/记录答题卡同样未传作答结果，需要覆盖这一入口。
- 通用 `AnswerCardSheet.tsx` 已支持对错颜色；通用学习页面的结果计算仍受旧端判断限制，应核对正式 Web 的实际链路。

## 确认后的最小修改范围

1. 复用既有 `selectedChoiceIndex`、`correctChoiceIndex` 和学习状态来源，派生显示结果；不新增另一套持久化状态或判分机制。
2. Native 答题卡消费既有结果参数，按“结果优先，学习状态回退”渲染；复用主题的正确/错误颜色。图例和无障碍说明同步表达答对/答错。
3. 串通学习中、结束页、学习记录回顾的入口，核对 iOS、Android 与正式 Web 的同一语义。实时学习读取当前保存状态，历史回顾读取该记录的作答快照，不被后来练习覆盖。
4. 保留当前题标识、跳题、标签/高亮、统计和考试中的答案隐藏行为，不扩大为答题卡重设计。

用户明确要求把听力与其他题库的差异保留为长期约束，并建立可持续积累常见错误的文档。待本方案确认后一起落实：

- 在现有 `docs/rules/ui-style-guide.md` 增加听力答题卡的语义约束，并保留为该约束的唯一规则来源；不复制到多份长期规则。
- 新建 `docs/resources/project/maintenance-lessons.md` 作为长期维护的经验资料，通过 `docs/README.md` 导航。它保存容易遗漏的差异、已发生的问题及对应验证方法，不自行增加权限或审批要求。
- 第一条经验记录“听力是可客观判分题型，共享答题卡不能丢失对错结果”，列出现象、根因、适用范围、规则链接、受影响入口和回归清单。
- 未实施前标记为待修复；检查通过、候选交付和用户真机验收分别记录，不能提前把方案写成成功经验。

## 验收与防回归

- 同一张听力答题卡包含答对、答错、已学未答、未学未答四种题目，颜色和说明分别正确。
- 只播放音频不产生对错；未作答不显示为红色。选择第一个选项（索引0）也能正常判定。
- 改选答案、切题后返回、退出重进及恢复已保存进度时，结果与当前作答一致。
- 结束页答题卡、学习记录和交卷回顾显示一致；旧记录缺字段时稳定回退，不伪造结果。
- 当前题轮廓、题号跳转、标签点、高亮和学习统计保持正常；其他题库不出现听力的对错颜色。
- 模拟考试进行中不通过答题卡泄露判分；交卷后按记录显示。
- 修改共享答题卡或学习状态时，回归上述差异；检查与发布按用户确认后的统一安排执行。

后续新增问题继续先记入待确认方案；本轮尚未进行任何产品代码修改。
