# 静态查词替代运行时 AI 查词：技术盘点

状态：已确认，基于 2026-07-22 只读检查

## 结论

改为静态查词在现有结构中可行：当前入口、弹层和题库正文均已具备，本地只需替换结果来源。真正的主要工作是内容生产、词条质量和覆盖校验，而不是 React Native 或服务端改造。静态词条不读取句子，因此不提供词义自动消歧。

## 现有链路

| 位置 | 现状 | 可复用性 |
| --- | --- | --- |
| `src/features/question-bank/components/InteractiveStudyText.tsx` | 文本按空白切分；可按查词交互策略触发。 | 可直接保留；静态查询只使用词，不使用句；原生使用长按，Web 由显式查词模式改为单击。 |
| `src/features/question-bank/components/QuestionBankStudyScreen.tsx` | 管理 Bottom Sheet、查词状态、AI 同意和 `wordLookup` 请求；当前也将 `referenceText` 作为参考内容传入。 | 弹层容器可复用；AI 状态、句子和多余展示内容须移除；听力必须停止展示其遗留答案键。 |
| `src/features/question-bank/components/ChoiceList.tsx` | 听力四个选项以普通 `Pressable` 文本渲染，短按用于作答。 | 在不干扰短按作答的前提下，原生支持词内长按查词；Web 仅在查词模式激活后支持词内单击查词。 |
| `src/features/ai/ai-client.ts` | 客户端内存缓存后调用 `/v1/ai/word-lookup`。 | 不应继续作为静态查词依赖。 |
| `services/api/src/ai/*` | 鉴权、同意、DashScope 调用、30 天用户级缓存、用量日志。 | 可保留给其他 AI 能力；静态查词不应触达。 |
| `src/features/question-bank/data/question-bank.json` | 五个题库的唯一题库正文来源。 | 应作为词条覆盖清单的输入，不能复制为第二份正文。 |

## 数据规模证据

对 `question-bank.json` 的只读统计如下。听力的全部 1,223 张卡当前都含 `referenceText`，其内容形如“正确答案：B. …”；这是遗留答案键，不是听力产品的参考答案模块。后续词表只以音频原文和四个选项文本为准，听力页也不应展示该字段：

| 指标 | 结果 |
| --- | ---:|
| 题库模块 | 5 |
| 学习卡 | 6,844 |
| 纳入静态查词的英文 token | 298,095 |
| 纳入静态查词的去重英文词形 | 8,767 |
| 混合编号/粘连格式等排除 token | 1,237 |
| 题库 JSON 体积 | 约 6.27 MB |

听力共 1,223 张卡，全部拥有四个选项。按“音频原文 + 四个选项”的已确认范围统计，包含 71,546 次英文 token、4,341 个题库内去重英文词形。

这些数字说明：按词形建立静态主词典可管理。由于需求仅显示词条本身，不再需要维护约 23.4 万个“词—句子”语境组合。

## 已有可复用词汇资产的覆盖

`content/vocabulary/dataset.json` 是已有单词学习的独立内容源，包含 838 条词/短语及释义、例句和翻译。它适合继续服务单词学习，但不能直接成为题库静态查词的唯一来源：

- 其中仅 290 条为单词形式。
- 与题库正文的去重词形相交为 207 条。
- 该交集约覆盖题库词形的 2.4%，按出现次数约覆盖 5%。
- 其例句来自词书，不等同于用户当前点选的题库句子。

因此，新增静态查词内容必须有自己的权威边界；可以引用词书内容作为人工编写的候选资料，但不得混用两个模块的数据生命周期。

## 关键缺口与风险

1. 已新增静态查词词表清洗/覆盖校验脚本，并锁定 8,767 个严格英文词形；1,237 个混合编号、粘连格式等异常 token 已单独报告，不作为普通词条生成。美式 IPA 和两类释义仍待当前 Codex 生成。
2. 当前 UI 把每个空白分隔 token 都作为可点对象；它并不支持用户框选短语，且文本变更会改变 token 序号。Web 必须以工具栏的显式查词开关避免默认单击与学习页其他操作冲突。
3. 当前学习页会把听力 `referenceText` 作为参考内容传入，与“听力只有四个选项、没有参考答案模块”的产品规则冲突；本 workstream 必须纠正展示行为，但不需删除遗留答案键数据。
4. 既有结果 UI 和文案含 AI 同意、加载、失败、缓存、题库信息、原句与本句理解；静态方案下均为多余内容。
5. 工作区已有大量未提交的 UI、认证和文档改动，包括 `QuestionBankStudyScreen.tsx`；实施时必须只叠加本 workstream 所需改动，不覆盖这些变化。

## 验证与回滚点

- 数据验证：脚本确定性提取/清洗词表；词形覆盖、字段结构、重复键、美式 IPA 格式、航空释义和常用释义均含词性加中文含义、题库版本/内容指纹一致性。
- 生成边界验证：记录批次、已锁定输入词表与输出文件；审查确认过程未调用外部 API、本机其他本地模型或第三方词典数据。
- 行为验证：离线状态下打开代表性普通词、ICAO 缩写和多义词，均不发起网络请求。
- UI 验证：iOS/Android 渲染确认弹层只显示单词、一个音标、航空释义和常用释义，且不影响高亮与长按手势；Web 确认“查词”开关激活前后单击行为与高亮模式互斥。
- 回滚：在完成静态覆盖和双端验证前保留现有 AI 查词实现；切换需是独立、可逆的客户端改动，不删除其他 AI 服务能力。
