# 通用大流程：决策与阶段管理

大流程用于跨系统、高风险、长周期、复杂迁移、外部发布或需要多人交接的工作。它保护关键
决策与验收，不要求每项任务固定创建四份文档。

## 1. 进入条件

出现以下任一情况时考虑大流程：

- 目标或非目标需要产品决策；
- 改动跨客户端、API、数据库、内容管线或部署系统；
- 涉及不可逆数据、账号、隐私、付费、发布或较大迁移；
- 需要多个独立阶段、持续多轮或明确交接；
- 错误方向会造成显著返工。

其余任务直接使用 `orchestration-loop.md`。

## 2. 决策层

开始前形成最小充分信息：

1. 要解决的问题与用户可感知结果；
2. 明确非目标；
3. 当前事实和唯一来源；
4. 关键方案、取舍和风险；
5. 可验证的完成标准；
6. 需要用户决定的产品、范围、不可逆操作或线上权限。

可以把这些写进一份 task/workstream 文档，也可以在已有 requirements、technical plan 或 ADR
中更新。只有内容确实独立且会持续维护时才拆成多份文件。

## 3. 阶段拆分

- 每个阶段交付一个可独立验证、可回滚或可继续的结果。
- 阶段按风险和依赖拆分，不按目录、文件数或固定模板拆分。
- 先解决未知和边界，再批量迁移或扩展。
- 阶段开始前说明输入、输出、验证和停止条件。

## 4. 阶段内执行

每个阶段调用小循环：

`确认当前事实 → 选择最小闭环 → 实现 → 定向验证 → 审查差异 → 更新必要记录`

Codex 在已确认边界内自主处理可逆实现细节。只有以下情况暂停：

- 缺少会显著改变结果的用户选择；
- 需要新的外部权限、生产发布或不可逆操作；
- 当前证据推翻了已确认范围或架构边界；
- 发现无法安全绕开的用户未提交修改。

## 5. 文档职责

- Requirements：稳定记录做什么、不做什么、验收什么。
- Technical plan/ADR：记录有长期影响的边界与取舍。
- Phase log：仅在长任务中记录当前状态、证据和下一步。
- Closeout：记录完成结果、残余风险和长期文档迁移。

它们是可选职责，不是文件配额。不要把聊天复述、逐行操作或随时可从 Git 得到的信息写成
永久文档。

## 6. 收口

完成时：

1. 用证据核对验收结果；
2. 将长期结论提升到当前战略、架构、设计、指南或运维文档；
3. 将完成的过程材料标记完成或归档；
4. 清除已被替代的现行说法和无效引用；
5. 报告已验证范围、未验证范围和残余风险。

大流程历史完整版本保存在 `docs/archive/workflows/`。
