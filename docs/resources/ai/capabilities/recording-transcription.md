# 录音转写

## 目标

录音转写只做一件事：

```text
用户语音 → 展示给用户的文本
```

最终文本应忠实表达用户说出的内容，并正确呈现民航语音中的数字、字母、缩写、呼号和固定表达。

## 输入与输出

```text
输入：用户录制的语音
输出：展示给用户的最终文本
```

产品结果只需要：

```json
{
  "transcript": "展示给用户的最终文本"
}
```

模型原始结果、模型参数、热词、资产版本、脚本处理和性能数据都属于内部优化过程，不作为用户结果的一部分。

## 结果要求

- 忠实转写用户实际说出的内容。
- 正确保留民航关键内容：高度层、跑道、航向、频率、应答机编码、QNH/QFE、呼号、字母和缩写。
- 可以整理已经明确的民航格式，例如将 `flight level one eight zero` 展示为 `FL180`。
- 不得补写用户没有说出的内容。
- 不得在转写阶段做语法纠错、表达润色、评分或生成标准答案。

## 当前接入方案（2026-09-20）

- 共用 API 的普通转写与转写评价入口统一使用普通英文模型 `16k_en`；旧客户端传入的实验模型偏好仍可解析，但不能改变服务端选定引擎。
- 腾讯凭据仍由服务端唯一配置管理；热词和自学习通过 `TENCENT_ASR_HOTWORD_ID`、`TENCENT_ASR_CUSTOMIZATION_ID` 显式绑定，ID属于对应账号和引擎，不可跨账号复用。
- 音频暂存、超时、清理、用户同意和权益计费链路保留。
- 腾讯识别 → 去除时间戳包装后的 rawTranscript → 保守航空写法 → transcript。原文、版本与转换轨迹随结果保存，可复原；界面继续读取 transcript，不展示内部参数。
- 语法纠错和表达优化仍是后续独立结果，不覆盖转写。禁止否定词修正、猜测数字/导航点或根据参考答案补全。
- 当前材料唯一来源为 `docs/resources/ai/assets/tencent-asr/`（900句原文、热词及依据），被替代的旧优化资产已清理，历史原始证据仅用于追溯。新账号ID、云端训练状态和部署证据见 `docs/records/workstreams/tencent-asr-accuracy-20260920/task.md`。
- 本轮不调用真实音频做测试；离线检查与上线配置核验不能证明准确率达标。实际识别质量待用户使用后验收。

## 后续性能验收资产：900句

900句音频与对应原文是主要回归资产。此前已完成900句原始转写；本轮按用户决定直接配置普通英文模型与三项优化，不重复调用音频。

```text
输入：900句音频
标准答案：对应的 audioText
验收：最终文本尽可能与 audioText 一致
```

验收时：

- 单词内容应一致。
- 民航关键内容必须完全一致。
- 大小写、纯空白和句末标点差异可以单独记录，不作为首要识别错误。
- 漏词、多词、错词，以及数字、字母、缩写识别错误，均视为转写错误。

本轮全部900句文本已用于自学习，因此后续900句复测只能说明这套题库的回归表现，不能当作未见样本的泛化证明。口音、口误和真实用户录音仍需另外验收。

## 优化方向

不把目标放在重新解决“普通英语识别”上。应先选择英语识别能力足够强的基础 ASR，再集中处理民航领域识别和规范写法。

```text
用户语音
→ 基础 ASR 识别英语
→ 民航领域适配
→ 民航规范写法
→ 最终文本
```

民航领域适配可以使用：热词、上下文、领域词表、模型微调或其他模型能力。数字读音、字母读音和高频词等资产用于帮助模型识别民航内容。

民航规范写法可以使用保守的非 AI 脚本，例如将已经明确识别出的高度层、跑道、频率和 QNH 整理为统一文本格式。

## 当前执行边界

基础模型固定为普通英文 `16k_en`。使用225项热词（初始18项来自差异分析，其余来自全题库原文及上下文审查，尚未音频复测）、900句原文自学习以及保守格式脚本；不使用词汇替换表，不调整音频质量策略，不再比较模型。原始结果、优化资产和版本均保留可追溯依据。

## 禁止方式

- 不使用通用大模型在 ASR 后自由润色或猜测文本。
- 不为了让结果“更像标准答案”而补写用户没有说出的词、数值、呼号或程序内容。
- 不把语法纠错、表达润色、评分混入转写流程。
