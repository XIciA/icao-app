## 维护规则

- 不确定的读音、含义或规范形式允许留空，不猜测补齐。
- 修改数字或字母规则时必须检查普通英语误转换风险。
- 只有明确写入并通过校验的 `asr-hotwords.json` 词条才会进入隔离验证；通过定向对照、盲测和发布门槛后才同步给 Fun-ASR。
- 任意正式热词都必须是候选数据库的子集；候选库不因高频自动变成正式热词。
- 空热词版本用于建立从零基线；不能用无意义占位词伪造空词表。

## ASR 热词命令

```bash
pnpm ai:asr:candidates
pnpm ai:asr:assets:check
```

第一个命令读取四个固定文本来源，刷新原始统计、正式候选数据库和开发者总览；不会自动修改正式热词。第二个命令校验候选数据库、正式热词子集、线上验证快照和开发者总览是否一致。

开发者查看 [asr-hotword-inventory.md](./asr-hotword-inventory.md) 即可确认候选总数、仓库已选数、线上已部署数、同步状态和全部候选明细。

非空热词候选必须先创建与生产隔离的供应商评测资源：

```bash
pnpm ai:asr:vocabulary:prepare evaluation .generated/ai-asr/evaluation-vocabulary.json
```

正式发布同样创建全新的隔离生产候选资源，不允许原地修改线上资源。同步后必须部署或重启 API，并执行真实代表性请求。真实热词表 ID、签名地址、音频和供应商响应不得写入仓库或文档。
