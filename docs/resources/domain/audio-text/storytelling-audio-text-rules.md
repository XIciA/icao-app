# 故事复诵文本规则

> 三类题库共性规则及当前暂停 Whisper 的统一策略见 `docs/resources/domain/audio-text/audio-text-unified-rules.md`。

## 1. 文档目的

本文档用于规范故事复诵题库中 `audioText`（英文音频原文）和 `audioTextZh`（中文翻译）的格式清理，以及正文之外首尾标签的识别与删除。

本文档只授权处理文本格式和能够逐卡确认的正文外标签，不授权修改故事正文的事实、语法、用词、句序或表达方式。

## 2. 适用范围

- 题库：故事复诵（`storytelling`）。
- 目标字段：`audioText`、`audioTextZh`。
- 维护源：`content/question-banks/banks/storytelling/topics/`。
- App 内嵌数据：`src/features/question-bank/data/question-bank.json`。
- 规则实现：`tools/storytelling-text-format-normalization.mjs`。
- 审计记录：`docs/records/workstreams/storytelling-text-format-normalization/`。
- 首轮格式清理历史基线：296 张卡片；后续经独立迁移工作流批准的净新增不受该固定总数限制。

以下内容不属于本文档的处理范围：

- 参考答案及参考答案标签页；
- 卡片标题、ID、顺序和分类；
- 音频文件、音频路径和时长数据；
- 故事正文内部的事实、语法、拼写、疑似 OCR 错字或重复内容；
- 其它题库的任何字段。

## 3. 核心原则

1. **只改格式**：允许插入或删除空格、调整换行和标点形式，不得改变正文的字母、数字和汉字序列。
2. **正文优先**：航班号、年份、跑道号、高度层及其它数字只要属于故事正文，就必须保留。
3. **逐卡确认标签**：删除首尾标签必须使用卡片级确认清单，不得依赖宽泛正则猜测。
4. **疑问只报告**：疑似 OCR、语法、用词和内部重复句只进入报告，不直接改写。
5. **源与派生同步**：维护源和 App 内嵌数据必须逐卡一致，不得只改其中一份。
6. **幂等和可追溯**：规则重复执行不得继续产生修改，并应保留修改前快照、前后对照和非目标字段校验。

## 4. 音频原文格式规则

### 4.1 单段展示

- 每张卡的 `audioText` 和 `audioTextZh` 均以一个自然段保存和展示。
- 删除排版造成的换行、空行和制表符。
- 删除首尾空白，连续多个普通空格合并为一个。
- 合并换行时不得删除正文字符，也不得把原本独立的英文单词错误粘连。
- 中文翻译中的排版换行直接并入连续中文；中文中的英文词组仍保留必要的单词间空格。

### 4.2 英文粘词

- 只拆分能够明确判断的粘连词，例如：

| 原写法 | 规范写法 |
| --- | --- |
| `runwayholding` | `runway holding` |
| `B747on` | `B747 on` |
| `thecontroller` | `the controller` |
| `maintenancepersonnel` | `maintenance personnel` |
| `witha` | `with a` |
| `toget` | `to get` |

- 每项粘词拆分必须来自显式确认词表；不得运行不受约束的自动分词并直接写回题库。
- 拆分只允许插入空格，不得增加、删除或替换字母和数字。
- `B747`、`A320`、`36R`、`FL340`、`QFA67` 等航空标识不得因为通用分词规则而拆开。
- `AirAsia`、`Go2Sky` 等品牌或专名，以及 `glideslope`、`windshear` 等既有写法，不得仅因拼写检查器给出建议就自动拆分。
- 无法确定是粘词还是 OCR、拼写或用词问题时，只记录为复核项。

### 4.3 英文标点和间距

- 英文原文中的中文逗号、句号、分号、冒号、感叹号、问号、引号和括号统一为半角英文标点。
- 删除标点前多余空格，在逗号、分号、冒号、问号和感叹号后补充必要空格。
- 相邻句之间补充必要空格，例如 `airport.The` 调整为 `airport. The`。
- 引号与前后正文保持正常间距，例如 `warned"stop!"and` 调整为 `warned "stop!" and`。
- 不得破坏小数、时间、频率、缩写、跑道号或航空代号，例如 `132.1`、`12:00`、`D.C.`、`02L`。
- 中文翻译继续使用中文标点，不为追求英文格式而改写中文标点体系。

### 4.4 明确禁止的正文修改

- 不修正语法、搭配或不自然表达。
- 不修正疑似 OCR 字符，例如大小写异常、字母误识别或已有拼写错误。
- 不删除正文内部的重复句、重复词或看似多余的信息。
- 不依据常识修改事故年份、人数、航班号、地点、机型或其它事实。
- 不根据中文翻译反向改写英文，也不根据英文重新翻译中文。

上述问题可以进入报告，后续只有在用户明确授权文本内容校对时才能修改。

## 5. 正文外首尾标签规则

### 5.1 可删除的标签

只有同时满足以下条件时，首尾内容才可以删除：

1. 位于文本开头或结尾，并与故事正文在排版上相对独立；
2. 能够明确判断为篇号、标题、来源备注、索引、独立航班号或其它内部标记；
3. 已加入包含卡片 ID、位置和原始标签的逐卡确认清单；
4. 删除后不会造成故事正文缺句或事实信息丢失。

当前已确认的典型类型包括：

- 开头英文篇号：`Passage One` 至 `Passage Twelve`；
- 对应中文篇号：`短文一。` 至 `短文十二。`；
- 结尾独立标签：`AFR123`、`QFA67`、独立年份、独立数字和重复人名。

### 5.2 必须保留的内容

- 正文句子内部出现的航班号、年份、人数、跑道号、高度层和编号。
- 虽然位于首句或末句，但属于完整句子语义的一部分的数字或专名。
- 无法确认是正文还是来源备注的内容。
- 与正文连续书写、删除后会改变字母或数字序列的内容。

例如，`story-wing-001` 正文首句中的 `AFR123 crashed ...` 必须保留；只有故事结束后独立出现的第二个 `AFR123` 才能删除。

### 5.3 禁止宽泛匹配

- 不得使用“删除所有结尾年份”“删除所有结尾数字”或“删除所有首尾航班号”之类的全局正则。
- 不得因为某个数字看起来像编号就自动删除。
- 新发现的标签必须先进入候选报告并完成人工确认，再加入逐卡清单。

## 6. 执行和验收流程

1. 读取全部故事复诵维护源并确认卡片数量。
2. 保存目标字段修改前快照和非目标字段哈希。
3. 生成格式变化及首尾标签候选报告，不直接猜测写入。
4. 复核粘词词表和逐卡首尾标签清单。
5. 将批准的规则应用到维护源和 App 内嵌数据。
6. 重建题库发布产物。
7. 重复执行规则，确认结果幂等。
8. 验证正文字符序列、卡片 ID、顺序、标题、音频路径和其它题库未发生越界变化。
9. 运行内容检查、相关行为测试和项目总检查。

当前规则命令：

```bash
node tools/storytelling-text-format-normalization.mjs audit
node tools/storytelling-text-format-normalization.mjs refresh-report
node tools/storytelling-text-format-normalization.mjs apply
node tools/storytelling-text-format-normalization.mjs verify
pnpm content:build
pnpm content:check:full
pnpm check
```

验收至少满足：

- 首轮历史 296 条及后续批准新增的全部 `audioText` 和 `audioTextZh` 均为单段；
- 不存在换行、制表符、首尾空白或连续空格；
- 除逐卡批准删除的首尾标签外，字母、数字和汉字序列不变；
- 已批准首尾标签全部删除，正文内部航空标识和数字保持不变；
- 维护源与 App 内嵌数据逐卡一致；
- 其它题库及故事复诵非目标字段通过哈希保护；
- 规则重复执行不再产生修改。

- 283 张英文原文发生格式调整；
- 181 张中文翻译发生格式调整；
- 使用 625 项显式确认的英文粘词边界；
- 删除 29 项逐卡确认的首尾标签；
- 疑似 OCR、语法、用词及内部重复句保留原文，只进入报告。
