# App 加载等待排查

2026年10月26日。范围为 iOS、Android 和 EdgeOne 产品 Web 的主要用户加载链路：启动登录、题库与刷题、标注、学习记录、电台、模考、词书与收藏、资源文章、热点、音频资源、AI请求，以及相关题库API。

结论：存在可直接从代码确认的串行等待、整批展示门槛和非必要请求。本轮首先修复标注与两个共用加载路径；其余问题按下表保留为后续优化项。这里没有把静态代码审查当作真实设备性能测量，也没有据此判断生产服务器或数据库已经达到性能上限。

## 本轮修复

| 位置 | 原行为 | 本轮行为 |
| --- | --- | --- |
| 我的标注 | 跨题库串行；全部目录和题组完成后才设置页面结果 | 目录与题组共享最多4个并发请求；每个目录或题组完成即发布结果；重复标注仍共用题组请求 |
| 我的标注权限订阅 | 任意会员快照revision变化都重新查题，包括不改变会员权限的刷新 | 使用现有内容权限snapshot，账号、环境或会员访问权限改变才重查；旧请求不能继续发布 |
| Web会员题正文 | 获取已经授权的题组后，还等待原生离线凭证接口，最终浏览器缓存适配器不执行写入 | Web跳过原生离线凭证；在线题组授权、版本及账号检查保留；Native离线凭证流程保留 |
| 资源列表与文章 | 列表等所有封面签名完成；文章等封面签名完成才显示正文 | 文字先显示，封面逐个补齐，列表封面最多4个并发；离开页面后不再启动排队的封面查询 |

实现入口：

- `src/features/question-bank/data/card-references.native.ts`：原题解析、并发上限、逐批结果与所有权检查。
- `src/features/question-bank/annotations/use-card-references.native.ts`：把部分结果提交给页面；离开或换请求后停止发布及排队任务。
- `src/features/question-bank/data/repository.native.ts`：Web不申请Native离线凭证。该共享路径也供刷题、模考、电台和热点使用。
- `src/features/editorial/use-editorial.native.ts`：资源正文与封面分开提交显示状态。

## 后续优化清单

P1表示优先处理的常用链路；P2表示受网络或数据规模影响较大的次级优化。它们是本次排查的排序，不是新增长期规则。

| 优先级 | 用户场景 | 已确认的代码路径与影响 | 建议与约束 |
| --- | --- | --- | --- |
| P1 | 首页、题库、电台同时加载或快速切换 | `useStudyCatalog.native.ts`每次获得焦点加载所有题库，电台`catalog.native.ts`也加载所有题库；`repository.native.ts`缺少目录/题组进行中请求的合并机制。同一账号对同一版本的重叠请求可能重复访问服务端 | 在现有repository内合并进行中的请求，键必须包含账号、环境、访问权限、内容版本；请求完成后清除，不创建第二套持久缓存。用并发调用测试和真实网络记录确认收益 |
| P1 | 弱网打开词书、词书收藏 | `vocabulary/catalog-loader.ts`先读取缓存，但仍等待网络响应，网络失败后才返回缓存；词书正文依赖整个词书目录 | 校验缓存后先展示，在后台检查更新；明确发布撤回、目录版本和学习记录迁移规则；失败时保留已显示内容。不能把45秒请求超时说成每次固定等待45秒 |
| P1 | Native会员题首次打开 | `repository.native.ts`仍按题组正文→离线凭证→校验和缓存写入顺序返回正文 | 评估把离线准备移出在线首屏关键路径；必须保持授权撤销、账号切换、失效凭证和离线有效性边界，不能直接忽略403。Web的无用凭证请求已在本轮去掉 |
| P2 | 电台加载其他题库时当前题库也在等待 | `radio-player/catalog.native.ts`先等所有目录的Promise.all，再发布目录/启动正文补齐；后续题组补齐已经有最多3个worker、优先题库和渐进发布 | 把目录阶段也改为逐题库发布，优先当前选择；保留内容版本、播放归属、已有完整题组的合并保护。不要重复重写已经实现的题组渐进加载 |
| P2 | 开始完整模拟考试 | `mock-exam/build-session.native.ts`的模块构建逐个await；听力多个分类、陆空等级题组也串行等待 | 先固定抽题计划和随机数消费顺序，再对相互独立的题组有界并发加载。直接Promise.all包住共享随机数的模块会改变确定性组卷，不能机械替换 |
| P2 | 大量标签、高亮和笔记 | `MyAnnotationsScreen.native.tsx`使用ScrollView加全量map，且解析当前题库筛选下的所有标注，包括其他分段；高亮行会处理原题全文 | 用虚拟列表和可视区/当前分段优先加载，复用现有内容所有者。影响随标注数量增长，3条截图不能证明这里已经是当次瓶颈 |
| P2 | 弱网播放已有缓存的音频 | `remote-resource-service.native.ts`即便找到离线资源，仍先等待资源授权请求，失败后才回退；电台preferDownloaded还会等待临时下载，最多6秒后回退签名URL | 对在线授权、已验证离线使用和电台队列准备分别设置合理策略与时限。不能直接先返回任何本地路径而绕过现有授权检查；需真实设备首帧测量 |
| P2 | 登录或切换账号时同步正在请求网络 | `AuthProvider.tsx`等待`switchLearningSyncAccount`；`learning-sync.native.ts`切换工作区前等待running同步结束 | 检查旧同步的网络请求能否取消并安全排空，再执行账号工作区切换；账号隔离锁本身必须保留。需要复现“同步请求挂起时登录/切账号”的实测与回归 |
| P2 | 多题组加载造成后端重复大对象处理 | `ContentAccessService.activeRelease`每次读取完整题库payload；目录、题组及凭证scope检查会重复调用。客户端按题组取正文仍可能每次让后端读整库 | 先测接口各阶段和数据库响应大小，再考虑按不可变version/checksum复用题库发布数据；会员与会话授权仍单独校验。本轮没有生产DB耗时或CPU证据，不宣称它是首要瓶颈 |

## 已有合理机制与边界

- 学习记录页已有20条分页与FlatList，并按打开动作读取详情，不属于标注页的全量渲染模式。
- 词书单词列表和单词收藏已有FlatList；静态查词通过本地Map完成，无联网前置。
- App公共内容已有进行中请求合并与8秒请求超时。
- 电台题组补齐已有并发worker、部分结果、优先题库和账号取消保护；待优化的是目录阶段与重复请求。
- AI授权/提交和录音准备中有真实数据依赖，不能只因看到多个await就判定可并行。录音核心与商业化扣费流程本轮未改动。
- 启动时诊断清理、更新提示及录音过期清理没有被列为“已确认首屏瓶颈”，因为当前代码证据不足以支持该结论。
