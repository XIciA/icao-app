# 微信支付检查与网页扫码接入

日期：2026-10-21。本文是本次任务记录，不新增长期规则，不代表已获生产部署或迁移授权。

## 检查结论

- 正式入口为 `readyoufife.com`（EdgeOne Expo Web）与 `api.readyoufife.com`（ECS API）。
- 只读核对生产 `icao-api` 容器：微信支付七项商户配置均存在，现有配置解析器验证通过，通知地址为当前正式 API 的 `/v1/commerce/wechat/notifications`。检查没有输出密钥、证书或完整环境。
- 原服务端仅下单 `/v3/pay/transactions/app`，网页只读共享权益；商户配置存在不能证明网页产品权限已开通，也不等于真实支付已验收。
- 浏览器安全策略阻止访问微信支付商户平台；没有尝试绕过。APP、Native、H5、JSAPI 的实际商户权限均待负责人手动确认。
- 正式公共应用内容接口当前返回第 31 版（检查时）；其中协议 v5.1、隐私政策 v5.3、第三方清单 v5.2，仍按 Android 微信支付描述。

## 本次实现

- APP 下单合同保持兼容，新增显式 `NATIVE` 渠道；只有服务器配置 `WECHAT_PAY_NATIVE_ENABLED=1` 才开放扫码目录与下单，默认关闭。
- 复用现有套餐与计价、认证账号、订单锁、幂等键、回调验签解密、商户查单、权益账本与退款处理。
- 新增迁移 `0055_bumpy_sue_storm`，为支付尝试添加 `trade_type`（旧订单默认 APP）、`code_url` 及渠道约束。结算时交易类型必须匹配持久化渠道。
- 网页通过本地 QR 编码显示微信返回的支付链接，不调用第三方二维码图片服务；恢复未支付订单，轮询查单，支持主动取消，服务端确认到账后刷新共享权益。
- 网络结果不明时先核对原订单，不为重复点击创建新购买意图；所有请求固定到发起账号的会话，账号切换后丢弃旧页面响应。
- 本次仅接入 Native 扫码；手机浏览器 H5 拉起和微信内 JSAPI 仍未实现，扫码提示明确要求另一台设备。
- 内嵌应用内容补充网页支付披露；线上内容需在最新发布的基础上合并本次 legal 变化，并通过现有应用内容发布流程发布新版本，不能把本地第 6 版直接覆盖线上第 31 版或覆盖新热点。
- 显示版本从主线 1.2.1 更新至 1.2.2。主目录其他任务的版本和未提交修改未被改动。

## 商户后台需要核对的项目

1. 超级管理员手动登录商户平台，在产品中心查看 APP、Native、H5、JSAPI 状态。
2. 电脑网页扫码需要 Native 产品权限，以及商户号和当前微信移动应用 APPID 的有效绑定。已有移动应用 APPID 可用于 Native，不需要为电脑扫码另造公众号。
3. 手机微信外浏览器直接拉起需要另行开通 H5，并配置实际支付页面域名 `readyoufife.com`，按平台当时要求提供网站、备案及经营场景材料。
4. 微信内网页直接支付需要 JSAPI 及合适的公众号身份、授权域名与支付目录；现有移动应用登录不能自动替代公众号网页授权。
5. 如页面要求签署协议、实名或验证，由负责人完成；本次没有代签、申请新的金融账户或发起真实资金操作。

## 启用与验收依赖

本地代码通过检查、合入主线和商户权限开通是三件不同的事。生产迁移、API 与 EdgeOne 部署、应用内容发布需要明确授权；此记录不授予授权。

在授权后：从干净主线执行现有备份/迁移与发布流程，保留网页开关关闭；先发布合并最新线上内容的支付说明，再在确认 Native 权限和 APPID 绑定后开启该开关。最后由负责人发起一笔真实购买，核对微信金额、服务端到账、跨端权益同步与商户退款。未完成这些步骤前，不标记“支付已开通”或“真实付款验收通过”。

回退：关闭 `WECHAT_PAY_NATIVE_ENABLED` 可停止新的网页扫码下单；已有订单仍可通过查单与验签回调结算。数据库迁移为加列，不在回退时删除订单或字段。
