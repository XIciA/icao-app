# 微信注销后重新注册修复

用户授权：修复、PR 合入 main 后部署生产 API。现有 TestFlight 继续使用；不修改客户端、数据库结构或 Vercel。

## 问题与修复

微信身份原来派生固定 Auth UUID。注销清除登录映射后，同一微信再次登录会重用该 UUID，命中保留的 deleted 账号，被账号状态检查拒绝。

- 新注册使用随机 UUID，并先在现有微信映射中提交预留。并发和失败重试复用同一预留。
- 已有映射关联 deleted 账号时换用新 UUID；active 账号继续使用原映射。
- 注销 worker 将映射删除延后至最终事务，与账号标记 deleted 一起完成。
- 登录检查身份关联及注销任务中的账号归属，避免 Auth 删除级联清除身份后漏掉仍在注销的绑定账号。
- 登录等待账号锁期间若映射被注销事务删除，重新持久化新预留。
- 不恢复旧账号、学习数据和会员，不重发同一身份终身一次的 AI 体验。沿用现有终身资格账本。

## 验证范围

隔离本地 PostgreSQL，加载全部迁移，调用真实微信身份服务、账号解析与注销 worker；仅模拟外部 Auth 和对象存储。

覆盖正常重复登录、8 个并发登录、连续两轮注销再注册、旧映射指向已注销账号（含残留 Auth 用户）、Auth 创建失败后重试、普通与绑定账号 Auth 清理后对象删除失败、注销最终事务与登录并发。

重点断言账号 ID 不复用、旧账号保持 deleted、新账号无旧会员/记录、终身试用领取数不增长、未完成注销拒绝登录、重试预留不丢失。

验证结果：`pnpm check` 通过，App 1,038 项、API 686 项测试通过；新增真实数据库回归 7 项通过，类型检查和 API 构建通过。

## 发布

部署来源为修复 PR 合入的 origin/main。生产使用独立 API release ID；无需重新构建或安装 App。
部署脚本保存上一个镜像、运行配置及内容激活备份，检查配置、迁移账本、健康状态和 release ID 后完成切换。

最终用户验收：在现有 App 用此前注销的微信再次登录，应进入新账号。
