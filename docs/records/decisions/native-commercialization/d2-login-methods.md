## 决策

- Native 1.0.0 的正式登录入口为：
  1. **Apple 登录**：仅 iOS，首次成功即自动创建账号并进入 App；
  2. **微信登录**：iOS 与 Android 使用微信开放平台移动应用登录，首次成功即自动创建账号并进入 App；
  3. **中国大陆 `+86` 手机号 + 短信验证码**：未注册手机号验证成功后自动注册并进入；
  4. **中国大陆 `+86` 手机号 + 密码**：已绑定手机号且已设置密码的用户使用。
- 微信开放平台账号已经注册，负责人已明确把移动应用微信登录恢复到 1.0.0；正式包应包含经过平台审核
  的微信登录入口、OpenSDK、AppID、URL Scheme/Universal Link、服务端认证路由和真实数据流。
  微信支付仍不属于 1.0.0，不能因为接入微信登录而加入支付 SDK、按钮、回调或商店材料。
- 第三方首次登录采用已确认的**方案 B：先进入、稍后自愿绑定手机号**。1.0.0 同时适用于 Apple 和微信。
  绑定手机号不是进入 App、
  普通学习、AI 使用或购买会员的前置条件；账号安全页持续说明绑定手机号对找回和增加登录方式的价值。
- 敏感操作通过账号**已经绑定的登录身份**重新验证，不要求 Apple 用户为了购买或注销临时
  绑定此前未提供的手机号。手机号绑定、手机号换绑和设置手机号密码时，
  仍必须验证目标手机号；不得强制微信用户新增手机号。
- 手机号是最高可信的账号找回锚点，但**不直接作为数据库主键**。学习记录、会员权益、
  AI 点数和订单归属永久、不可变的内部 `accountId`。
- Supabase Auth 继续负责可复用的正式会话；认证提供方产生的 `auth.users.id` 是登录身份 ID，内部
  `accountId` 是业务账号 ID。一个 `accountId` 可以关联多个已验证身份，业务表不得再假定
  `auth.users.id` 永远等于业务账号 ID。`wechat` 是 1.0.0 正式身份提供方，微信身份、生产认证路由和
  审计必须与手机号、Apple 一样映射到内部 `accountId`。
- 邮箱和邀请码不属于 Native 登录入口。邀请码只保留赠送会员、优惠或渠道归因用途。

## 1.0.0 自动注册与登录规则

- Apple、微信或手机号 OTP 第一次认证成功时自动创建内部账号，不再区分“注册页”和“登录页”；
  同一个已验证身份以后再次登录必须回到同一个 `accountId`。
- Apple 或微信登录前必须完成16周岁确认并同意用户协议与隐私政策；用户取消授权、网络失败、提供方拒绝
  或配置缺失时均失败关闭，不创建半成品账号。
- 16周岁确认采用登录页主动勾选的轻量自我声明，不收集出生日期、身份证、人脸或其他额外年龄证明；
  首发不建设未满16周岁用户的监护人授权与儿童账号流程。
- 手机号 OTP 默认允许自动注册；密码登录和短信重置密码不得为未知手机号创建账号。
- 密码是手机号身份的可选登录方式。用户绑定并验证手机号后可设置密码；未设置密码时仍可使用
  Apple 或手机号验证码登录。
- Apple 使用原生 Sign in with Apple 和 Supabase ID Token 登录/身份关联；首次授权可能返回的姓名只
  保存一次，后续缺失不得覆盖已有资料。
- 手机号普通 OTP（含首次自动注册/登录）和密码找回的发码都只能经自有 API 发起；公网网关阻断
  Supabase `/auth/v1/otp`、`/auth/v1/resend`、`/auth/v1/signup`，避免客户端绕过统一风控。找回流程对
  未知与已知手机号返回同形结果并设置一致的最短响应时间，不泄露账号是否存在。

## 1.0.0 微信登录方案

- 公司银行账户和微信开放平台账号已经具备；1.0.0 仍须完成 iOS/
  Android 移动应用审核、AppID、iOS Universal Link、Android 应用签名/包名及服务端 AppSecret 配置。
- 微信使用微信开放平台移动应用 OpenSDK 获取一次性授权 `code`，由服务端持有 AppSecret 并交换
  微信身份；AppSecret、access token、UnionID/OpenID 和完整授权响应不得进入客户端日志。iOS 与
  Android 必须挂在同一微信开放平台主体并具备一致的 UnionID 归属，才能保证跨端同一身份。
- 微信能力必须通过 SDK 隐私审计、生产路由审计、真机验收和商店材料更新后进入最终候选包；外部平台
  验证、扫码或验证码等待只阻塞微信最终验收，不得阻塞热点、商业、UI 或其他可独立推进的上架工作。

## 手机号绑定与账号隔离

本节在 1.0.0 适用于 Apple、微信与手机号身份。

- 第三方账号绑定一个尚未使用的手机号：验证短信 OTP 后，将手机号身份关联到当前
  `accountId`，当前 `accountId` 保持不变，不创建第二份业务账号；用户随后可设置密码。
- 第三方账号尝试绑定一个已属于其他账号的手机号：短信验证成功后消耗本次验证码，服务端统一返回
  `409 phone_already_registered`；App 保持当前账号登录，只提示“该手机号已有账号，请退出后使用
  手机号登录”。只有用户明确点击退出后，才结束当前会话并进入手机号登录页。
- 1.0.0 不自动归并账号，也不提供人工自助归并入口。手机号已占用时，不转移 Apple 身份、学习记录、
  订单、会员时间、AI 点数、补偿点或其他数据，不返回目标账号会话、账号标识或权益摘要。
- 未占用手机号的绑定在单一事务内锁定当前账号、目标手机号和手机号认证身份；并发抢占、手机号映射
  与认证身份映射不一致，以及当前账号已经并发绑定其他手机号，均统一按已占用冲突处理。
- 已验证的冲突必须在事务回滚边界外保留验证码已消费状态，避免同一验证码重放；冲突或异常时服务端
  注销临时手机号会话，不能影响当前 Apple 会话。
- 旧版 `/v1/account/merge/phone*` 路由仅作为已有 TestFlight 的兼容别名，必须调用同一“仅绑定未占用
  手机号”实现；路由名称不是归并能力，不得写入 `account_merges` 或产生 `merging`/`merged` 状态。
- 既有归并表、历史迁移和无运行时入口的商业纯模型可以暂留，避免在首发前进行无必要的破坏性迁移；
  发布门禁必须证明正式客户端与账号 API 没有可达的账号归并或跨账号数据转移路径。

## 安全与会话规则

微信 grant、code 去重和微信身份冲突处理属于 1.0.0 正式生产能力。

- 业务 API 先验证合法且未撤销的 Supabase token，再将认证身份解析为内部 `accountId`；不得把
  “拥有手机号”或“使用 OTP”写死为访问普通业务 API 的条件。
- 绑定手机号、绑定/解绑第三方、设置/重置密码、全设备退出和注销要求近期认证；敏感操作
  优先使用当前操作所涉及或账号已经绑定的身份重新验证，并使用短时、单用途授权，不能只凭页面参数
  绕过重新验证。已设置密码的手机号账号可通过校验当前密码取得近期认证授权；未设置密码或选择短信
  方式时使用一次性验证码。Apple 绑定只接受当前 Apple 会话中
  `method=oauth` 的 AMR 时间，不能把更新的 TOTP/其他 AMR 误当成 Apple 近期认证；微信 code 交换成功
  后由服务端为对应 `authUserId + sessionId` 签发10分钟、绑定用途且消费即失效的 grant。
- 购买会员不强制绑定手机号；渠道支付凭证、当前有效会话和服务端订单校验承担购买验证。不得因用户
  只绑定 Apple 或微信身份而拒绝正常购买。
- 短信发送、OTP 校验、密码尝试、第三方授权和绑定按账号、号码、设备和 IP 分层风控；验证码验证前
  不泄露某手机号、Apple 或微信身份是否已经存在，验证已占用手机号后仅返回统一冲突，不泄露目标账号。
- 微信 code 交换入口按来源限流，对一次性 code 使用不可逆摘要去重；同一 code 在窗口内只能消费
  一次，重复、超限或上游异常均失败关闭。
- 绑定至少一种可恢复身份后才能解绑当前登录身份；任何操作不得让账号失去全部可用登录方式。
- 手机号密码规则与短信找回沿用已确认的双登录规则：密码10—64位并同时含字母和数字；找回密码
  由自有 API 在服务端使用 `shouldCreateUser=false` 发起 OTP，验证成功后通过受保护账号 API 更新已有
  手机号身份。客户端不得直接修改 Supabase user；公网网关阻断 `PUT/PATCH /auth/v1/user`。

## 注销与重新注册

本节的 1.0.0 注销验收覆盖手机号、Apple 和微信；微信重新授权、映射解除与防重复规则均是提交门禁。

- 用户在已登录状态发起注销后，按账号已有身份重新验证：已设置密码的手机号账号优先校验当前密码，
  未设置密码或用户主动选择短信方式时使用一次性验证码；Apple 账号再次完成 Apple 登录，微信账号
  再次完成微信授权。已绑定手机号可以作为 Apple 或微信账号的备用验证方式，但未绑定手机号不是注销
  阻塞条件。
- Apple 身份对应的账号注销时，服务端同时按 Apple 要求撤销相关授权令牌；微信和手机号身份映射随
  账号注销解除。提供方临时不可用时允许稍后重试；用户确实无法再使用原身份且没有其他已绑定身份时，
  通过公开隐私入口进入人工身份核验，不要求先新增手机号。
- 注销立即放弃内部 `accountId` 对应的学习数据、会员时间和 AI 点数，并解除全部登录身份映射；依法
  必须保留的交易和安全记录隔离保存，不能恢复旧账号。
- 同一手机号、微信或 Apple 身份以后重新授权时，可以按新账号规则创建新的 `accountId`，但同一个
  已验证登录身份只能领取一次100点新用户体验点；注销和重新注册不得重置领取资格。
- 服务端只为防重复领取保留与原账号隔离、不能用于登录或恢复账号的身份摘要，不保留旧账号权益；
  不为此收集身份证、人脸或强设备指纹。彼此独立的登录身份按各自身份判断领取资格。
- 注销只针对当前账号及其全部已绑定身份执行，不影响其他独立账号。

## 分阶段交付顺序

1. 建立永久 `accounts` 与 `account_identities` 映射层，将认证 ID 与业务账号 ID 分离；
2. 把手机号 OTP 改为验证后自动注册/登录，保留密码登录、设密与短信找回；
3. 接入原生 Apple 登录并验证自动注册、会话恢复和手机号绑定；
4. 在 1.0.0 范围内完成手机号/Apple/微信的未占用手机号绑定、占用冲突、风控、注销/解绑、双端回归、
   真机和弱网验收；
5. 接入微信 OpenSDK、服务端 code 交换、Supabase 会话桥接及对应绑定，并完成隐私、生产和真机验收；
   如未来需要账号归并，须重新决策和验收。

## App Store 审核账号

- 只准备一个由公司长期控制的中国大陆手机号，并通过正常手机号验证流程建立一个 Production 审核
  账号；审核员使用“手机号 + 密码”登录，不依赖短信收件或审核员自己的 Apple ID。
- 该账号使用正常新账号100点完成非付费 AI 体验，并通过真实 Apple Sandbox/TestFlight 购买获得
  会员权益；不以 Ops 人工赠送作为1.0.0提交前置条件，不修改商品或真实业务逻辑。
- 审核顺序固定为同一账号先完成免费与会员边界、五档商品、语音转写和文本 AI 等完整体验，再完成
  Sandbox/TestFlight 购买和恢复购买，最后执行账号注销；注销后不可继续安排其他审核步骤。若审核中
  已经注销，下次提交前可用公司控制的同一手机号重新注册并设置密码；同一手机号不会再次获得新用户
  100点，需要时通过正常购买恢复验收状态。
- 审核账号必须已经设置密码，Apple 审核员使用当前密码完成近期身份重新验证后即可独立注销；不要求
  审核员接收公司手机号短信，不使用固定 OTP、隐藏审核模式或人工跳过重新验证。
- 该账号使用正式 App 的真实账号、权限、AI 和订单链路。不得加入隐藏审核模式、硬编码账号、
  跳过支付验签、虚构 AI 结果、关闭注销或其他只对审核员生效的后门。
- 密码、手机号和审核凭据属于受保护配置，只填写在 App Store Connect 审核信息及公司的凭据管理
  位置，不进入仓库、决策文档、构建日志或普通聊天记录；审核期间不得过期、停用或触发无故锁定。

## 验收

- 1.0.0 登录页按已确认方案 A 默认提供手机号验证码，可切换手机号密码，并在第三方快捷登录区提供
  Apple（仅 iOS）与微信；没有邮箱或邀请码登录入口。
- 新用户通过任一入口首次认证后能自动注册并进入 App；第三方用户可以跳过手机号绑定，普通学习、
  AI 使用和购买会员不受阻塞，账号安全页明确提示绑定价值。
- 同一 Apple 或手机号身份跨重装、跨设备再次登录得到同一 `accountId`；手机号 OTP 与密码得到
  同一个账号和权益。
- 第三方账号绑定未占用手机号不产生第二业务账号；绑定已占用手机号时，验证后统一返回冲突并保持
  当前账号，只有用户明确退出后才进入原手机号账号的正常登录流程，双方数据和权益不转移。
- OTP 覆盖倒计时、重发、限流、错误/过期/重复验证码与三网到达；Apple 覆盖取消、拒绝、回调丢失、
  重放、身份已占用和提供方不可用。
- 自动化与发布门禁证明普通/找回发码和密码更新只能走自有 API，公网 Supabase 发码、注册及 user
  修改路径均被阻断；找回未知/已知号码的响应形状一致。
- Production 不存在固定测试 OTP；客户端和日志不含阿里云或 Apple 私密凭证及完整 token。
- 验证仅绑定手机号、仅绑定 Apple 和同时绑定二者的账号都能在 App 内完成注销；注销
  使用已有身份重新验证，不以新增手机号作为前置条件，Apple 注销同时撤销 Apple 授权令牌。
- 最终 1.0.0 归档、安装包、生产配置、公开路由和 App Store 材料必须包含与实际功能一致的微信登录
  OpenSDK、URL Scheme/Universal Link、微信认证生产路由和隐私说明；同时必须证明不存在微信支付
  SDK、支付入口、支付回调或客户端 AppSecret。
