# D8 内部运营后台结构决策

> 历史记录：保留原任务的决定与状态，不是当前长期规则；原文“已确认”不授权或约束新任务。参见 [归档说明](README.md)。

状态：已确认；结构方案保留，但可视化运营后台延后到1.0.0上架后，不是提交、审核或发布门禁
初次确认日期：2026-08-12
最近确认日期：2026-08-29
关联需求：[Native App 正式商业上线总需求](../../../workstreams/app-store-1.0.0/requirements.md)

## 已确认结构

- 建设一个与用户 App 隔离、独立部署的内部运营后台，不把管理能力放入用户 App。
- 后台使用项目现有 React、TypeScript 和服务端技术体系，不引入第二套应用技术栈；建立独立的后台
  Web 应用和发布产物，建议使用 `ops.readyoufife.com`，通过现有 ECS 上的专用管理 API 工作。
- 后台前端、管理 API 和普通用户 App 分别构建与部署；后台不可用不得导致普通用户登录、学习、
  支付验签、权益读取、AI 自动风控、注销编排或数据清理停止。
- 可视化后台首次投产时，工作人员角色只有管理员和客服；二者使用独立工作人员账号登录同一后台，通过角色区分可见
  页面和允许操作，不能复用普通用户手机号账号。
- 后台通过专用服务端管理接口读取和操作现有用户、订单、权益、AI 风控及后续运营数据。
- 后台页面和客户端不得直接连接或修改生产数据库。
- 当前用户 Web 产品及 Vercel 部署继续冻结；内部运营后台不是面向用户的 Web 商业化，也不得复用、
  修改或顺带发布现有 Web/Vercel。

## 上架后首期页面范围

- **总览**：展示正式服务健康状态、用户与订单概况、AI 使用和成本概况、支付通知、自动清理任务、
  待处理反馈、隐私请求和风险事件；不以运营后台轮询代替服务端监控和告警。
- **用户与账号**：按手机号、内部账号 ID 或订单号进行受审计查询，默认只显示脱敏身份信息；查看
  登录身份、设备、账号状态、会员和必要安全信息，并支持强制退出全部设备。
- **会员与 AI 点数**：查看权益来源、有效期和点数账本；通过统一权益服务为审核、补偿等批准场景
  发放有期限的会员或调整点数，不允许直接修改数据库余额。
- **订单与支付**：严格区分 App Store Production、TestFlight/Sandbox 和 Android 渠道；查看验签、
  通知、退款及权益重算状态，并允许重试验签、通知处理和对账。不得把未付款订单手工改成已付款；
  iOS 退款由 Apple 处理，后台只消费经验证的退款结果。
- **AI 与风险**：查看腾讯云 ASR、DeepSeek、点数、成本、请求状态和失败率；支持解除误判风控、
  暂停单个账号及按能力或全局紧急关闭 AI。默认不展示用户回答正文，不展示或保存原始录音。
- **反馈与隐私请求**：处理反馈及必要附件，跟踪数据导出、更正、删除、注销和无法登录时的人工请求；
  不允许绕过身份核验直接删除账号，自动保留和清理任务不依赖人工页面。
- **工作人员与审计**：管理员可以创建、停用工作人员并查看审计；工作人员密码、动态验证码密钥和
  恢复码不得由页面明文回显。审计记录不能由普通后台账号修改或删除。

## 角色权限

- 后台上线时只要求实际创建一个公司负责人控制的管理员账号，同时保留管理员和客服两套权限能力，
  后续增加客服不需要改变权限模型。
- 管理员可以管理工作人员、调整会员和点数、解除 AI 风控、操作服务紧急开关及执行通过身份核验的
  高风险流程；仍不得直接操作生产数据库、伪造支付成功或删除审计记录。
- 客服可以查看完成工单所需的脱敏用户资料、订单状态和反馈，并提交权益调整、风控解除或注销协助
  请求；不能自行执行这些高风险变更，不能查看无关用户内容或完整支付凭证。

## 后台上线安全底线

- 工作人员使用公司控制的邮箱、独立密码和 TOTP 动态验证码登录；支持账号停用、会话撤销、可信
  设备上的可撤销持续会话和最小权限。正式环境不得共享账号，不把凭据写入仓库、日志或普通聊天。
- 客服默认只看完成工单所必需的脱敏数据，不得查看 AI 正文、录音、完整支付凭证或其他无关信息。
- 退款、补偿、赠送、封禁、注销协助和数据导出属于高风险操作，至少记录操作者、对象、原因、前后
  状态和时间；首次投产使用权限校验、原因必填、变更预览和明确二次确认，不建设复杂的多人会签流程。
- 所有查询和变更都通过受鉴权的管理接口完成并留下不可由普通后台账号删除的审计记录。

## 1.0.0 边界与后续

- 可视化 Ops Web、`ops.readyoufife.com` 部署、首个管理员初始化及 TOTP 验收全部延后到 App Store
  1.0.0 上架后，不是 TestFlight、IAP 送审、App Store 提交、审核或发布门禁。
- 现有 Ops 代码、管理 API、数据库表和审计设计保留，不在1.0.0收口中删除或改写。用户 App 不依赖
  可视化后台；登录、学习、支付验签、权益读取、AI 风控、注销和数据清理必须在后台未部署时正常工作。
- 以后重新设计后台通常只需保持既有管理 API 合同，用户 App 无需大规模更新；若改变用户可见接口、
  登录/权益合同或数据结构，再通过独立版本评估 Native 改动。
- 后台首期不建设营销活动、优惠券、内容或题库编辑器、复杂经营报表、自动客服机器人、
  财务记账与发票、多级组织架构、Android 商店渠道管理或多人会签；这些能力以后另行确认。
