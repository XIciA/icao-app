# 随身听播放系统优化需求

状态：已确认

更新时间：2026-07-16

工作目录：`docs/records/workstreams/radio-player-optimization/`

## 1. 核心问题

当前随身听已经能进入听力、900 句和故事复诵，播放真实音频并切换倍速、字幕和曲目，但整体仍是一个页面内的播放器样例：播放列表只取前 50 条，播放顺序没有真正切换，音频结束不会自动续播，字幕缺少“仅英文”，进度不能拖动，离开页面后播放状态也会消失。

本任务要把随身听升级成接近常规音频播放软件的原生播放系统，同时继续复用题库的音频、双语文本、资源解析和内容发布链路，不复制一套随身听专用题库或音频库。

## 2. 目标

- 用户可以在听力、900 句、故事复诵三个模块之间切换，并播放模块内全部可用音频。
- 用户可以切换顺序播放、单曲循环、随机播放三种模式。
- 用户可以切换仅英文、英文和翻译、不显示字幕三种字幕模式。
- 用户可以像使用常规音频软件一样播放、暂停、上一首、下一首、拖动进度、切换倍速、查看播放队列。
- 离开随身听全屏页后，正在播放的内容由迷你播放器承接；切到后台或锁屏后仍可继续播放并使用系统媒体控制。
- 播放状态、时长、字幕、失败与恢复状态真实可信，不再用 `--:--`、固定前 50 条或无动作按钮模拟完整能力。
- UI 必须好看、合理、高级，严格符合当前 UI 设计规范；功能可用但视觉粗糙、信息拥挤或层级混乱不算完成。
- 所有新增能力基于共享题库与音频基础设施扩展，不形成第二数据源或第二套互相竞争的音频生命周期。

## 3. 内容与资源范围

随身听只包含当前题库中明确标记为可用于随身听的三个模块：

- 听力；
- 900 句；
- 故事复诵。

内容规则：

- 曲目身份、标题、所属分类/题组、英文原文、中文译文和音频路径均以当前题库统一发布数据为准。
- 只调用已有音频资源，不重新录制、生成、转码或复制音频。
- 接入音频时长元数据；时长必须由当前内容发布链路统一维护并能与曲目、音频路径对账。
- 题库内容更新后，随身听应自动读取新版本，不在页面或 feature 内长期维护一份静态曲目表。
- 陆空通话和 OPI 当前不进入随身听；未来是否加入必须经过新的产品决策，不能随题库更新自动混入。

## 4. 播放行为

### 4.1 基础播放

- 支持播放、暂停、上一首、下一首和点击队列切歌。
- 支持可拖动的播放进度，并显示当前时间和总时长。
- 支持 0.75×、1×、1.25×、1.5× 倍速；切歌后保持用户选择。
- 手动选择曲目后立即播放；切换模块时停止当前模块并从新模块上次位置或首条开始。
- 播放结束后按当前播放模式自动处理下一首，不要求用户再次点击。

### 4.2 三种播放模式

- 顺序播放：按当前模块的稳定题库顺序播放，末条结束后回到首条继续。
- 单曲循环：当前曲目结束后从头继续播放当前曲目。
- 随机播放：从当前模块内随机选择下一首，避免连续重复同一首；上一首可沿随机历史返回。
- 模式切换后立即生效，并在全屏播放器、迷你播放器和系统媒体控制中保持同一状态。

### 4.3 三种字幕模式

- 仅英文：只显示音频英文原文。
- 英文和翻译：显示英文原文和中文译文。
- 不显示字幕：隐藏正文区域，但保留曲目信息与播放控制。
- 当前字幕是整段原文，不承诺逐词或逐句时间轴同步。
- 长文本必须可以滚动阅读，不得挤压或遮挡播放控制。

## 5. 播放器界面

### 5.1 全屏播放器

- 顶部提供返回、当前模块切换和播放队列入口。
- 主区域明确展示模块、曲目标题、所在分类/题组、字幕和加载状态。
- 底部固定展示可拖动进度、时间、主播放控制、播放模式、倍速和字幕模式。
- 控件层级、颜色、字体、圆角、阴影和安全区继续遵守当前 App 的暖白、墨蓝、钴蓝视觉体系。
- 视觉必须保持精致、干净、轻盈、克制和专业：播放主操作突出，辅助控制安静，不堆叠厚重卡片、强阴影、过量装饰或无意义动效。
- 信息层级、留白、对齐、控件密度和点击热区必须合理；用户一眼能识别当前内容、播放状态和下一步操作。
- 375 × 812 作为视觉定稿基准，并在 360、390、430 宽度下无溢出、遮挡和裁切。

### 5.2 播放队列

- 展示当前模块全部曲目、真实总数、曲目序号、标题、路径和时长。
- 当前曲目有明确选中和播放状态，并能自动定位。
- 支持按标题、英文原文或中文译文搜索，并可按题组/分类缩小范围。
- 大列表使用适合数千条数据的虚拟化渲染，不能一次性创建全部行。
- 加载、空列表、无搜索结果和资源失败均有明确状态和重试入口。

### 5.3 迷你播放器

- 有当前播放内容时，离开全屏播放器后在受保护的 App 页面提供迷你播放器。
- 迷你播放器至少展示曲目标题、播放/暂停、下一首和回到全屏播放器入口。
- 迷你播放器不得遮挡底部导航、学习页关键操作、安全区或系统手势区域。
- 用户主动关闭迷你播放器时停止播放并清除当前播放会话。

## 6. 后台、锁屏与其它音频能力

- 随身听在切到后台或锁屏后继续播放。
- 锁屏、控制中心或 Android 媒体通知展示当前标题、模块和系统媒体控制；必须支持播放/暂停、进度、上一首和下一首。
- 曲目自然结束后，即使 App 在后台或锁屏，也必须按顺序/随机模式自动续播，单曲循环必须持续重播当前曲目。
- 拔出耳机、蓝牙断开、来电或系统音频焦点变化时遵循平台安全行为，不继续从扬声器意外外放。
- 开始题库音频、录音或录音回放时，随身听自动暂停；这些操作结束后不擅自自动恢复。
- App 退出登录、账号失效或用户主动停止时，随身听停止并清除系统媒体控制。
- App 冷启动只恢复上次曲目、进度和偏好，不自动出声播放。

## 7. 状态保存与恢复

- 在当前设备保存上次模块、曲目、播放位置、播放模式、字幕模式和倍速。
- App 重启后恢复为暂停状态；用户点击播放后从保存位置继续。
- 内容版本变化、曲目被删除或资源路径变化时，安全回退到当前模块可用曲目，不崩溃、不引用失效索引。
- 这些偏好属于设备本地播放状态，本轮不做账号云同步。

## 8. 加载、失败与重试

- 明确区分曲目元数据加载、资源地址解析、音频缓冲、可播放、暂停和失败状态。
- 网络失败、签名地址过期、音频超时或文件缺失时暂停自动续播，显示当前曲目的错误和重试入口。
- 重试时复用现有资源解析能力刷新地址，不绕过统一资源服务拼接新的地址规则。
- 单条曲目失败不得导致整个模块或 App 崩溃；用户可以重试或跳到下一首。
- 不以静默跳过掩盖资源缺失；缺失项必须能在内容校验中被发现。

## 9. 共享与复用硬约束

- 题库正式数据是曲目、字幕和音频关系的唯一来源，不为随身听复制一套内容。
- 音频加载、地址刷新和失败重试继续复用 App 已有能力，不另建互不兼容的资源体系。
- 时长进入现有题库内容维护与发布流程，不在 App 内长期并存两份时长数据。
- 随身听、题库音频、录音和录音回放必须服从同一套互斥规则，不允许多个声音同时播放或互相覆盖状态。
- UI 优先复用现有导航、进度、弹层、文字、主题和错误状态，保持当前 App 视觉语言。
- 每个阶段都要说明复用了什么，并检查是否新增了第二数据来源或竞争的播放状态。

## 10. 明确不做

- 不新增或修改题库教学内容，不改写英文原文和中文译文。
- 不重新录制、AI 生成、转码或复制现有音频。
- 不加入陆空通话、OPI 或其它尚未确认的模块。
- 不建设音频下载包、离线播放、离线资源管理或全量音频随安装包分发。
- 不做逐词/逐句时间轴字幕、波形编辑或音频剪辑。
- 不做收藏歌单、睡眠定时、播放统计、会员、支付、AI 推荐或云端播放进度同步。
- 不重做全局导航、题库学习页或录音交互的 UI；仅在音频协调所需范围内接入共享能力。
- 不为了播放器复制题库、字幕、时长或资源解析；播放引擎可以在 Expo SDK 55 的系统媒体控制能力不足时替换，但只能保留一个播放生命周期 owner。

## 11. 验收效果

- 三个模块中正式标记为可用于随身听的全部有音频曲目都能对账进入随身听，无固定 50 条上限。
- 全部曲目都有可用时长元数据；内容检查能阻止缺时长、缺字幕或缺音频映射的发布。
- 三种播放模式、三种字幕模式、倍速、进度拖动、上一首、下一首和队列切歌行为正确。
- 全屏播放器、迷你播放器和系统媒体控制读取同一播放状态，不出现多个音频同时播放或状态互相打架。
- App 内与系统媒体控制的上一首/下一首均切换实际题目；播放过程中上一首同样立即切换，不再被“回到本题开头”规则拦截。
- 随身听当前曲目提供“学习本题”入口，进入对应 bank/category/topic/card；返回操作直接回到随身听并保留原曲目与位置，学习期间随身听保持暂停。
- 离开页面、切后台、锁屏、耳机断开、录音和 App 重启等关键生命周期行为符合本需求。
- 网络、签名地址过期、超时和缺失资源均有可恢复状态。
- iOS 与 Android Development Build 完成真实设备或等价设备验证；375 × 812 及 360–430 宽度完成渲染检查。
- 全屏播放器、队列、迷你播放器及其加载、缓冲、暂停、错误和字幕状态通过真实渲染对照；只通过构建或功能测试不能作为 UI 验收。
- 未修改只读设计仓库，未复制题库或音频资源，未引入第二来源。
