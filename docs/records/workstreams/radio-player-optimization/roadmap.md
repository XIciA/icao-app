# 随身听播放系统优化路线图

状态：已完成

更新时间：2026-07-16

## 1. 路线图定位

本文承接同目录的 `requirements.md`、`technical-plan.md` 和 `technical-audit.md`。用户确认四份大流程文档后，Codex 才按 `docs/rules/bigandsmall-workflows/orchestration-loop.md` 进入小流程，并在授权范围内按阶段连续执行。

当前路线图不授权立即修改随身听代码、原生配置、题库发布物或线上环境。

## 2. 阶段总览

| 阶段 | 目标 | 核心产出 | 进入下一阶段标准 |
| --- | --- | --- | --- |
| 0 | 冻结共享基线与所有权 | 正式曲目清单、时长 contract、文件边界、验收样本 | 与题库迁移无冲突，来源唯一 |
| 1 | 接入共享时长与曲目 repository | 内容 schema、时长补齐、统一曲目 adapter、内容检查 | 全部可用曲目可对账且时长完整 |
| 2 | 建立队列与全局播放核心 | 队列状态机、Provider、资源按需解析、本地恢复 | 三种模式与跨路由播放测试通过 |
| 3 | 收口音频会话 | 共享 audio coordinator、题卡/录音互斥 | 不再有竞争的全局音频 owner |
| 4 | 完成播放器 UI | 全屏播放器、虚拟化队列、三字幕、拖动进度 | 关键状态与多尺寸渲染通过 |
| 5 | 接入迷你播放器、后台与锁屏 | 全局宿主、原生后台配置、系统媒体信息 | 双端真实生命周期无阻塞问题 |
| 6 | 全量验收与收口 | 自动检查、双端真机、视觉证据、phase-log、closeout | 需求逐条有结果且无第二来源 |
| 7 | 锁屏控制修复与学习入口 | 原生短队列、系统上/下一首、单曲循环、精确题卡跳转 | 双端构建和回归通过，待真机锁屏复验 |

## 2.1 阶段 7：缺陷重开

原阶段 5 将 Expo SDK 只提供 seek forward/back 的能力边界记录为限制，但这不满足用户对“上一题/下一题”的明确产品要求，因此 workstream 重开。阶段 7 在不改变共享内容与资源所有权的前提下替换随身听播放引擎，并增加从当前曲目进入精确学习卡片、直接返回随身听的闭环。

## 3. 阶段 0：冻结共享基线与所有权

### 目标

在写实现前，先把当前题库迁移、随身听数据、时长元数据和音频生命周期的所有权冻结，防止并行改动覆盖和重复建设。

### 主要工作

- 复核当前 Git 状态和题库迁移工作流的实际进度。
- 在正式候选发布物上重新统计三个 `radioEligible` 模块、曲目、音频、英文、中文和时长覆盖。
- 冻结时长字段在资源维护 schema、题库运行时 contract 和内容检查中的归属。
- 确认既有 1,827 条索引导入方式和缺失时长补齐方式。
- 列出随身听、题卡音频、录音和回放的现有 owner，冻结共享协调接口。
- 依据 `docs/ui-style-guide.md` 冻结视觉基线、共享组件/配方复用清单和关键渲染状态矩阵。
- 选择代表性验收样本：三个模块首/中/末、长字幕、资源失败、签名过期、随机历史和内容更新恢复。

### 阶段产出

- 已冻结的曲目/时长覆盖报告、文件所有权清单、共享模块与 UI 配方复用清单、视觉状态矩阵和验收样本表。

### 允许范围

- 本 workstream 文档和必要审计脚本/报告。
- 对现有文件做只读盘点。
- 在不与题库迁移冲突的独立测试目录准备纯逻辑样例。

### 禁止范围

- 不覆盖当前未提交的题库迁移文件。
- 不按当前 2,559 条临时数量写死页面或代码。
- 不复制题库、音频、字幕或时长索引。
- 不修改线上资源或部署服务。

### 暂不做

- 暂不修改播放器页面、原生配置、线上内容或音频组件。

### 验收标准

- 正式曲目集合、版本和来源可以复现。
- 共享模块和新模块的所有权清单明确。
- 时长只有一个维护源，运行时字段由构建生成。
- 题库迁移冲突文件已有避让或合并顺序。
- `phase-log.md` 记录阶段证据后自动进入阶段 1。

### 验证

- 当前 Git/工作流文件所有权检查
- 正式候选数据只读统计与时长覆盖脚本
- 四份大流程文档一致性和 `git diff --check`

## 4. 阶段 1：接入共享时长与曲目 repository

### 目标

让所有随身听曲目通过现有题库发布链路获得完整、可校验的时长与元数据。

### 主要工作

- 扩展共享内容 schema 和 contract 以承载音频时长。
- 一次性导入已有 1,827 条时长，补齐正式集合中缺失条目。
- 将时长生成接入现有内容构建，不保留手工运行时副本。
- 扩展内容检查：`radioEligible`、音频、英文、中文、时长、稳定 ID 和唯一资源映射。
- 建立随身听曲目 adapter，通过 `loadQuestionBank` 返回完整元数据队列。
- 验证 remote/cache/embedded 三种来源得到一致曲目结构。

### 阶段产出

- 共享时长 schema、完整时长维护数据、生成后的运行时字段、曲目 adapter、内容校验与测试报告。

### 允许范围

- 现有题库 schema、contracts、内容工具和其测试。
- 共享题库数据层中的曲目 adapter。
- 与时长导入、生成和校验直接有关的内容文件。

### 禁止范围

- 不修改音频文件、英文、中文或题目内容。
- 不新增随身听私有 JSON、私有音频映射或私有资源 resolver。
- 不在本阶段修改播放器 UI、后台配置或导航。
- 不把全部音频打入 App 安装包。

### 暂不做

- 暂不实现播放状态机、播放器 UI、迷你播放器和后台播放。

### 验收标准

- 三个正式模块全部有音频曲目可对账，无 50 条上限。
- 每条曲目都有正数时长，缺失或重复会让内容检查失败。
- 旧索引导入和新增时长补齐有报告与 checksum/版本证据。
- remote/cache/embedded adapter 测试通过。
- 未产生第二内容或时长来源。

### 验证

- `pnpm content:build`
- `pnpm content:check:full`
- contracts 和 repository 相关测试
- `git diff --check`

## 5. 阶段 2：建立队列与全局播放核心

### 目标

实现与 UI 解耦的三模式队列和跨路由长期存在的随身听播放器。

### 主要工作

- 实现顺序、单曲循环、随机历史、上一首与结束事件去重（阶段 7 已将上一首最终语义修订为始终切题）。
- 在受保护根布局挂载随身听 Provider 和唯一 player。
- 按当前曲目解析签名 URL，处理取消、慢响应、过期、超时和重试。
- 实现播放、暂停、seek、切歌、切 bank、倍速和 stop/clear 命令。
- 用本地 KV 保存并恢复曲目、进度和偏好；冷启动保持暂停。
- 在全屏页面先接入临时无样式控制或测试宿主，证明路由离开后 player 不释放。

### 阶段产出

- 可测试队列状态机、全局随身听 Provider、按需资源加载器、设备本地播放快照和集成测试。

### 允许范围

- 随身听 queue、provider、persistence 和相关测试。
- 资源服务中为了共享非 hook 解析所需的最小扩展。
- 根布局中 Provider 的挂载点。

### 禁止范围

- 不在此阶段重做视觉页面。
- 不预解析全部曲目 URL。
- 不接后台原生配置或锁屏控制。
- 不让全屏和迷你播放器各建一个 player。

### 暂不做

- 暂不完成正式 UI、音频会话重构、迷你播放器、后台与锁屏。

### 验收标准

- 三种模式、随机历史、快速切歌和 `didJustFinish` 测试通过。
- 切出 `/content/radio` 后播放状态仍由同一 Provider 保持。
- 资源失败可重试并刷新签名 URL。
- App 重启恢复暂停状态，失效曲目安全回退。
- Provider/资源扩展没有复制现有 repository 或 resolver。

### 验证

- queue/persistence/provider 单元与集成测试
- 资源过期、慢请求和失败注入测试
- `pnpm check`

## 6. 阶段 3：收口音频会话

### 目标

让随身听、题卡音频、录音和录音回放使用同一个全局音频会话协调规则。

### 主要工作

- 建立 audio session coordinator 和明确 role/profile。
- 把随身听、`StudyAudioPlayer`、`SpeakingPracticePanel` 的全局音频模式调用迁入协调层。
- 统一“新 owner 开始前暂停旧 owner”的顺序。
- 定义录音、题卡音频和回放结束后不自动恢复随身听。
- 验证退出登录、账号失效、耳机断开和错误清理。

### 阶段产出

- 共享音频会话协调层、四类 role/profile、现有音频与录音接入以及互斥回归测试。

### 允许范围

- 共享平台音频协调层。
- 现有音频与录音组件的最小接入修改。
- 生命周期和互斥测试。

### 禁止范围

- 不重设计题库播放器或录音 UI。
- 不把不同用途强行合并为一个 player/recorder 实例。
- 不继续保留多个无协调的 `setAudioModeAsync` owner。
- 不在此阶段开启后台录音。

### 暂不做

- 暂不改变题库播放器视觉，不接入后台/锁屏原生能力。

### 验收标准

- 任意顺序启动随身听、题卡音频、录音和回放，都不会同时出声或错误占用录音模式。
- 录音开始前随身听可靠暂停，结束后不意外自动播放。
- 音频模式变更只通过协调层完成。
- 现有题库音频和录音回归测试通过。

### 验证

- 音频互斥和录音生命周期测试
- 题库学习核心回归测试
- 前台 iOS/Android Development Build 冒烟

## 7. 阶段 4：完成播放器 UI

### 目标

把当前页面重构为符合音频软件使用习惯、同时保持 ICAO 学习产品视觉的全屏播放器和完整队列。

### 主要工作

- 重构全屏播放器布局，删除负 margin 和容易挤压的固定字幕高度。
- 接入三种播放模式、三种字幕、倍速、上一首、下一首、播放/暂停和可拖动进度。
- 复用 `AudioTimeline`、TopBar、BottomSheet、AppText、主题和错误状态。
- 用虚拟化列表实现完整队列、真实时长、当前定位、搜索与分类/题组筛选。
- 覆盖加载、缓冲、错误、重试、空列表、无搜索结果和缺译文状态。
- 为可访问性补齐按钮标签、禁用态、点击热区和非颜色状态提示。
- 逐项校准信息层级、留白、对齐、控件密度、轻边框/轻阴影和克制动效，确保页面精致、干净、合理、高级，而不是只把功能控件排到屏幕上。

### 阶段产出

- 全屏随身听、完整虚拟化队列、搜索/筛选、三种模式与字幕 UI、关键状态渲染证据。

### 允许范围

- 随身听全屏页面及其局部展示组件。
- 必要的共享 UI 组件最小扩展。
- 随身听组件和视觉测试。

### 禁止范围

- 不改变品牌色、字体角色、导航结构或其它页面视觉。
- 不复制 Web DOM/CSS，不使用 WebView。
- 不引入新的品牌色、图标体系或娱乐化唱片视觉。
- 不在队列行内解析音频 URL。

### 暂不做

- 暂不启用后台原生配置，不加入收藏、定时、下载或其它模块。

### 验收标准

- 全部用户操作对应真实 Provider 命令，无假按钮。
- 长英文/中文和数千条队列不遮挡、卡死或丢失当前项。
- 375 × 812 与设计基线方向一致；360、390、430 无溢出和遮挡。
- 默认、播放、暂停、缓冲、错误、无字幕、仅英文、双语和队列状态有渲染证据。
- UI 通过设计规范逐项自检和主观视觉复审；功能正确但视觉粗糙、拥挤、层级混乱或不符合品牌气质时不得进入下一阶段。
- 未新增第二套 UI 原子件或播放器状态。

### 验证

- 组件交互测试
- iOS 模拟器真实渲染与截图对照
- 360/375/390/430 布局检查
- `pnpm check`

## 8. 阶段 5：迷你播放器、后台与锁屏

### 目标

完成跨页面承接和原生音频软件必需的后台、锁屏生命周期。

### 主要工作

- 在受保护路由共享宿主接入迷你播放器和统一底部 inset。
- 全屏随身听内隐藏迷你播放器；其它页面按遮挡策略展示、折叠或隐藏。
- 显式启用 `expo-audio` 后台播放 config plugin，保持后台录音关闭。
- 配置随身听 audio profile、锁屏 active player 和实时元数据。
- 在 iOS/Android 验证后台、锁屏、媒体通知/控制中心、长时间续播和恢复。
- 验证耳机/蓝牙断开、来电/焦点变化、录音和退出清理。

### 阶段产出

- 全局迷你播放器宿主、后台播放原生配置、锁屏/媒体元数据接入和双端生命周期证据。

### 允许范围

- 迷你播放器宿主与安全区协调。
- `app.json` 的 `expo-audio` 后台播放配置。
- CNG/Prebuild 生成的必要原生差异和 Development Build。
- 锁屏元数据与生命周期测试。

### 禁止范围

- 不开启后台录音。
- 不新增无关权限、下载服务或离线缓存。
- 不以 Metro 热更新代替 Development Build。
- 不因某一平台差异直接引入第三方播放器；先记录真机证据并返回大流程决策。

### 暂不做

- 暂不做后台录音、下载、离线、云端进度或第三方播放器迁移。

### 验收标准

- 离开全屏页后同一曲目和进度由迷你播放器承接。
- 迷你播放器不遮挡底栏、学习主操作和安全区。
- iOS 后台/锁屏、Android 后台/媒体通知持续播放通过。
- 系统媒体元数据、播放/暂停和进度控制有效；平台不支持的控制有真实记录。
- 耳机断开、音频焦点、录音和退出不会意外外放或保留幽灵媒体状态。

### 验证

- `pnpm prebuild` 或对应平台 Prebuild 后检查生成差异
- iOS Development Build
- Android Development Build
- 双端真机或等价设备生命周期矩阵
- Expo Doctor 与 `pnpm check`

## 9. 阶段 6：全量验收与收口

### 目标

按需求、内容、播放、生命周期、视觉和复用边界完成最终验收，形成可审查记录。

### 主要工作

- 对照需求逐条核验三个模块、三模式、三字幕、进度、队列、迷你播放器、后台和失败恢复。
- 复跑内容数量、时长覆盖、资源映射和正式发布数据验证。
- 完成 iOS/Android 设备矩阵、不同屏宽和关键视觉状态证据。
- 复核代码中题库、音频映射、时长、资源解析、播放状态和音频会话的来源数量。
- 检查 Git diff、生成文件、原生配置和未提交现场，避免带入其它迁移文件。
- 更新 `phase-log.md`、生成 `closeout.md`，纠正旧复刻记录与当前完整能力之间的语义差异。
- 最后更新 App 展示版本。

### 阶段产出

- 最终验收矩阵、自动检查与双端证据、复用/单一来源审计、`phase-log.md`、`closeout.md` 和展示版本。

### 允许范围

- 当前 workstream 的缺陷修复、测试、证据和收口文档。
- 已确认发布流程内的内容/服务发布和回滚记录。

### 禁止范围

- 不在收口阶段追加收藏、睡眠定时、下载、AI 推荐等新功能。
- 不降低后台、双端、内容完整性或复用要求换取“完成”。
- 不部署未复核的 dirty-worktree 差异。

### 暂不做

- 暂不进入收藏、定时、下载、离线、AI 推荐、其它模块或第三方播放器路线。

### 验收标准

- `requirements.md` 每项均有通过结果或经用户确认的真实平台限制。
- `pnpm check`、内容全量检查、Expo Doctor、双端 Development Build 和核心测试通过，或外部限制有证据。
- 三个模块的正式曲目与时长 100% 对账。
- 无第二题库/字幕/音频映射/时长/资源 resolver/播放状态来源。
- `phase-log.md`、`closeout.md`、实际代码、线上内容与 App 展示版本一致。

### 验证

- `pnpm content:check:full`
- `pnpm check`
- `pnpm doctor`
- iOS Development Build 与 Android Development Build
- 双端生命周期矩阵、360/375/390/430 渲染矩阵
- 线上内容代表性请求与资源播放验证（如本任务实际发布远程内容）
- `git diff --check` 和最终文件范围审查

## 11. 小流程启动条件

满足以下条件后才能进入小流程：

- 用户明确确认本目录四份大流程文档；
- 当前题库迁移的文件所有权和合并顺序已能安全执行；
- 不存在与总战略、架构决策、UI 规范或运行部署规则的未解决冲突。

确认后，Codex 默认从阶段 0 开始连续执行；每阶段在 `phase-log.md` 留证并自动进入下一阶段。只有出现范围扩大、数据库迁移、未授权第三方依赖、生产不可逆操作、当前题库迁移无法安全协调，或 Expo 真机能力无法达到确认目标时，才暂停并返回大流程。

## 12. 授权边界

用户确认本路线图后，以下普通操作视为小流程范围内授权：

- 本 workstream 范围内的 React Native、共享音频层、题库 contract/内容工具、测试、文档和必要原生配置修改；
- 使用现有依赖、执行检查、Prebuild 和 Development Build；
- 对明确文件集执行当前内容发布流程，并按运行规则验证。

以下仍需单独返回用户或大流程决策：

- 新增第三方播放器或改变 Expo/React Native 技术路线；
- 数据库 schema/Migration；
- 扩大到下载、离线、会员、支付、AI、其它随身听模块；
- 无法隔离的其它 dirty-worktree 变更；
- 未在路线图中覆盖的生产不可逆操作。

本路线图不自动授权提交、推送或创建 Pull Request；只有用户另行要求时才执行 Git 发布动作。
