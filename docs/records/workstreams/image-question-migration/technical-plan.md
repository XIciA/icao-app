# 图片题功能与资源迁移技术方案

状态：已实施并通过小流程验收

更新时间：2026-07-13

## 1. 方案结论

采用“来源白名单提取 → 当前内容模型最小扩展 → 原生图片卡垂直样例 → 全量发布 → ECS 真实验证”的方案。

```text
feizhuicu 图片题子集
  -> 可审查的 23 图 / 64 题 / 64 音频映射清单
  -> icao-app 自有内容维护结构
  -> 统一发布产物与资源 manifest
  -> 现有题库 API / 私有 Storage / 资源签名
  -> React Native 原生图片卡与现有 OPI 问题卡
```

来源项目只提供经过白名单确认的内容和静态素材；`icao-app` 自己决定运行字段、资源路径、组件结构、错误状态、发布方式和验证方式。

## 2. 来源提取与迁移清单

### 2.1 允许取用

- `feizhuicu` 当前 `图片题` 分类中的 23 个话题标题与图片—问题分组关系。
- 23 张最终水印图片。
- 64 道问题的英文问题、已有中文题意、参考答案和中文参考内容。
- 64 个与问题一一对应的 MP3。

### 2.2 不允许直接迁移

- 不导入来源 `topics.json` 整体结构。
- 不保留来源 `schemaVersion`、`source`、`rawSourceId`、catalog 结构或生产 manifest。
- 不复制来源页面、组件、路由、样式、脚本、原始图、中间图、Word 文档或其它题库。
- 不使用目录级复制；正式迁移必须由 allowlist 和 checksum 清单精确选择 87 个资源文件。

### 2.3 内容转换

- 图片卡使用当前 App 新增的明确卡片类型和稳定图片资源路径，不用空文本或伪造问题绕过校验。
- 问题卡转换成当前 `QuestionBankCard` 语义，拆分英文问题、中文题意、英文参考内容和中文参考内容。
- 来源中两道缺少中文题意的问题先进入缺口报告，补齐后再发布；其它内容只做结构化拆分和必要格式清理，不批量改写。
- 来源追溯、原 ID、checksum 和迁移状态保存在 workstream 清单中；运行数据只保存当前 App 需要的稳定字段。

## 3. 当前 App 数据模型扩展

在保持现有标准卡兼容的前提下，为题库卡片增加最小图片卡语义：

- 标准卡继续要求问题文本，并可包含音频、译文、参考内容和选择题字段。
- 图片卡必须声明图片类型、图片资源路径和可访问性描述；不得带音频、问题文本、录音任务或文字答案。
- 内容 schema 和构建校验按卡片类型执行条件规则，禁止“图片卡塞空字符串”或“标准卡缺少题干”。
- 数据集、分类、话题、学习记录和同步定位仍沿用现有层级与稳定 ID，不为图片题建立第二套 Repository 或进度系统。

图片题增加为 OPI 的第 8 个分类，23 个话题和 87 张卡片进入现有 OPI 发布。普通 OPI 卡片结构和能力不变。

## 4. 内容工程与资源结构

### 4.1 维护层

- 图片题话题写入 `content/question-banks` 的 OPI 维护源，并由 OPI 分类文件显式排序。
- 23 张图片和 64 个音频进入本项目自有资源维护目录；不依赖 `feizhuicu` 绝对路径作为运行时来源。
- 资源源清单记录稳定 object key、App 公共路径、来源相对路径、MIME、大小、checksum 和状态。

### 4.2 发布层

- 扩展统一内容 schema、构建器和全量校验，使其同时验证文本卡、图片卡、音频和图片资源。
- 资源 manifest 从“只支持 MP3”升级为按允许 MIME 管理音频和图片；构建必须检查引用存在、大小和 checksum。
- 提升内容发布版本，生成新的 OPI payload、release manifest、资源 manifest 和变更报告；`dist` 仍只由构建生成，不手工修改。
- 内嵌回退数据与远程发布从同一维护源生成或同步校验，避免手工维护两套互相漂移的图片题数据。

建议公共资源路径保持语义清楚，例如：

```text
/question-bank-assets/images/opi/image-questions/<stable-id>.jpg
/question-bank-assets/audio/opi/image-questions/<stable-id>.mp3
```

路径只表达本项目资源语义，不继承来源项目目录作为架构约束。

### 4.3 云端导入

- 现有数据库 `resource_objects`、私有 Storage bucket 和资源签名接口可以继续使用，不需要新增表。
- 将现有内容导入脚本从音频专用路径读取改为通用资源根目录读取，仍按 checksum 幂等上传。
- 新版本题库以新增 release 方式导入，保留现有可回滚版本，不覆盖旧 payload 和 Storage 对象。
- 任何 `services/api` 变更都按项目运行规则从干净、已复核文件集部署 ECS，保留旧镜像、源码和内容 release 回滚点。

## 5. React Native 原生图片卡

- 复用仓库已经锁定的 `expo-image` 和现有资源解析能力；实施前按项目规则读取 Expo SDK 55 对应文档，不新增图片展示依赖。
- 建立可复用的图片卡视图，使用完整适配方式展示不同宽高比图片，并提供加载、失败、超时和重试状态。
- 图片资源继续经过统一 `QuestionBankAsset`/资源签名链路，页面不拼接 Storage 域名，也不读取 Supabase 私有字段。
- 图片卡沿用当前学习页顶部、题号、答题卡、上一题/下一题、结束和完成流程，但跳过：
  - 音频播放器；
  - 口语录音；
  - AI 查词；
  - 问题/答案文字区；
  - 标签、高亮和笔记等基于文字的工作台。
- 问题卡继续走现有 OPI 文本卡路径；迁移音频存在时播放文件音频，不影响其它 OPI 卡继续保留生成语音方向。
- 图片卡分支应由卡片能力决定，不使用 topic 名称、分类中文或卡片序号等脆弱判断。

## 6. 学习数据兼容

- 图片卡拥有稳定卡片 ID，可记录访问、完成和时间，但不产生录音、选择题或文字标注字段。
- 现有同步 payload 可继续保存卡片状态，不改变用户表或同步协议语义。
- 新卡片只新增新的状态键，不重编号现有 OPI ID，不迁移或覆盖旧用户记录。
- 答题卡、完成统计和学习报告必须能处理“图片观察卡 + OPI 问题卡”的混合话题。

## 7. 验证方案

### 数据与资源

- 23 个话题、23 张图片卡、64 张问题卡，共 87 张卡片。
- OPI 最终为 8 个分类、144 个话题、1356 张卡；全题库为 5034 张卡。
- 23 个图片引用和 64 个音频引用唯一、存在，MIME、大小、checksum 和 object key 一致。
- 图片卡无音频和文本；问题卡字段与音频完整；所有稳定 ID 全局唯一。
- `pnpm content:build`、`pnpm content:check:full` 和任务专用迁移校验通过。

### React Native

- 为内容条件校验、Repository、资源解析、图片卡渲染、错误重试和图片卡工具禁用补充自动化测试。
- 运行 `pnpm check`。
- 使用 iOS Development Build 验证目录进入、图片加载、图片失败重试、问题音频、录音、前后题、答题卡、结束和完成。
- 按当前视觉规范检查 375 基准及 360、390、430 宽度，不裁切关键信息；构建通过不能替代截图和真实渲染检查。

### ECS 与远程链路

- 部署前备份当前 ECS 源码、API 镜像和当前 active 内容 release。
- 从明确文件集部署并重启 API；`/health/ready` 必须通过。
- 验证 OPI 新版本、ETag、分类/话题/卡片数量，以及一个图片资源和一个问题音频的真实签名与读取。
- 使用 App 经安全隧道命中远程 OPI 和 Storage 资源，不能只验证本地内嵌数据。
- 失败时回滚旧镜像、源码和 active release，不删除已上传的旧对象。

## 8. 关键取舍

- 复用现有 OPI 分类和统一学习页，避免建立第二套图片题题库、路由和进度系统。
- 迁移 64 个现成问题音频，而不是把图片题降级为当前“生成语音预留”提示；资源体量小且能直接形成完整学习闭环。
- 图片卡使用明确类型和条件 schema，不用空文本或字段猜测换取短期兼容。
- 图片资源网络优先，不打入安装包；缓存只改善体验，不承诺完整离线学习。
- 来源数据先经过 allowlist、映射和字段拆分，再进入当前维护源，确保“取用资源”而不是复制来源题库。

## 9. 不采用的方案

- **复制来源 OPI JSON 和前台代码**：不采用，会把来源 schema、Web 实现和无关题库带入 App。
- **只复制 23 张图，不迁移问题音频**：不采用，会使图片题问题卡的能力低于已有来源且无法形成完整资源闭环。
- **把图片塞进 `audioText` 或 `referenceText`**：不采用，会破坏类型语义、校验和后续维护。
- **把图片题做成新的一级题库**：不采用，会扩大导航、Repository、同步和报告范围。
- **把 87 个资源打入 App 安装包**：不采用，不符合当前网络优先和对象存储方向。
- **重新生成图片或重新写整套答案**：不采用，本任务是迁移与接入，不是内容再创作。
- **手工上传对象并手改数据库**：不采用，无法重复验证和安全回滚。

## 10. 主要风险与控制

- 图片与问题串组：用 23 组映射清单、ID 和抽样截图双重校验。
- 两道中文题意缺失：形成显式缺口记录，只补缺项并人工抽查。
- 图片宽高比不完全一致：使用完整显示和真实设备检查，禁止统一强裁切。
- 内容维护源、内嵌回退和云端 release 漂移：从同一维护源生成并对比 checksum、版本和数量。
- 资源导入脚本当前音频专用：先用单样本完成通用资源垂直验证，再批量导入。
- 当前工作树存在其它未提交改动：只修改路线图授权文件，部署从明确干净文件集生成，不携带无关变更。
