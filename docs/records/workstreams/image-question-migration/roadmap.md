# 图片题功能与资源迁移路线图

状态：已按小流程完成

更新时间：2026-07-13

## 1. 路线图定位

本文承接同目录 `requirements.md`、`technical-plan.md` 和 `technical-audit.md`。路线图确认后，Codex 才按 `docs/tools/workflows/orchestration-loop.md` 自动进入实施。

实施期间继续遵守：

- 项目 `AGENTS.md`；
- 总战略与架构决策；
- 当前题库云端接入、资源发布和同步 contract；
- `docs/rules/conditional/deployment-and-runtime-rules.md`；
- 设计仓库只读、`feizhuicu` 仅取用图片题所需资源的边界。

## 3. 阶段 0：来源与执行边界冻结

### 阶段目标

把允许取用的来源子集、当前本地/云端基线和并行改动边界固定为可审查记录。

### 主要工作

- 生成 23 个话题的图片、问题、音频一一对应清单。
- 记录来源文件 checksum、大小、标题、问题数量和迁移目标 ID。
- 明确两道缺失中文题意并给出待补内容。
- 读取当前本地内容 release、ECS active OPI release 和资源统计。
- 记录当前脏工作树中相关文件的归属，避免覆盖其它 workstream。

### 阶段产出

- 来源 allowlist 和映射报告。
- 本地/ECS 基线对账记录。
- 目标文件范围和回滚点。

### 允许修改范围

- `docs/records/workstreams/image-question-migration/`
- 与本任务有关的只读审计脚本或 `.generated` 临时结果。

### 禁止范围

- 不修改正式题库维护源、RN 代码、API、Storage 或数据库。
- 不复制资源，不进入 `feizhuicu` 其它题库。

### 验收与检查

- 清单严格为 23 图、64 题、64 音频，且文件全部存在。
- 每张图片与问题分组可解释，目标 ID 无冲突。
- 当前 local/ECS 版本、资源数量和回滚方式记录清楚。

## 4. 阶段 1：图片卡与通用资源合同

### 阶段目标

先建立适合当前 App 的图片卡数据语义和可发布图片资源框架，不直接批量写入 23 个话题。

### 主要工作

- 扩展题库类型和 schema，使标准卡与图片卡按条件校验。
- 扩展内容构建器，收集和校验图片、音频两类引用。
- 扩展资源 manifest 的 MIME 与来源路径规则。
- 将内容导入脚本升级为通用资源根目录，保持 checksum 幂等和旧音频兼容。
- 用一个任务内样本验证构建、manifest 和导入逻辑。

### 阶段产出

- 图片卡 contract。
- 通用资源构建与导入能力。
- 条件校验和回归测试。

### 允许修改范围

- `content/question-banks/schema/`
- `tools/question-bank-content.mjs`
- 题库共享类型或 contract。
- `services/api/scripts/import-content.mjs`
- 本任务测试和样本文件。

### 禁止范围

- 不批量导入 23 个话题。
- 不修改数据库 Schema，不上传生产资源。
- 不改变普通题库卡片的既有必填规则和资源引用。

### 验收与验证

- 标准卡旧数据全量校验继续通过。
- 合法图片卡通过；缺图、图片带音频、标准卡缺题干等无效数据被拒绝。
- 单张 JPG 和单个 MP3 能生成正确 MIME、checksum、公共路径和 object key。
- API 相关类型、lint、测试和构建通过。

## 5. 阶段 2：原生图片题垂直样例

### 阶段目标

用一个真实图片话题证明从目录、图片资源、问题音频到完成记录的闭环成立。

### 主要工作

- 接入一个真实图片题话题作为垂直样例。
- 建立原生图片卡组件和加载/失败/超时/重试状态。
- 图片卡跳过音频、录音、查词和文字工作台。
- 问题卡复用当前 OPI 音频、录音、参考答案和笔记路径。
- 验证答题卡、前后题、结束、完成、进度和同步状态。

### 阶段产出

- 一个可完整学习的图片题话题。
- 图片卡组件与相关自动化测试。
- iOS 真实渲染和交互证据。

### 允许修改范围

- `src/features/question-bank/` 相关类型、组件、hook 和测试。
- 当前 OPI 维护源中的垂直样例。
- 本任务所需的 1 张图片和对应问题音频资源。

### 禁止范围

- 不重做学习页、目录页或普通 OPI 卡片。
- 不新增 Expo/原生依赖，不使用 WebView。
- 不把来源页面样式当作 UI 基线。

### 验收与验证

- 图片完整显示、AI 标识可见，加载失败可重试。
- 图片卡没有无意义工具；问题卡现有能力正常。
- 375 基准及 360、390、430 宽度无关键裁切或横向溢出。
- 垂直样例的类型、测试、内容校验和 iOS Development Build 通过。

## 6. 阶段 3：全量迁移与发布产物

### 阶段目标

把经过垂直验证的结构扩展到全部 23 个图片题话题。

### 主要工作

- 按 allowlist 复制 23 张最终 JPG 和 64 个 MP3 到本项目资源维护层。
- 生成 23 个话题、23 张图片卡和 64 张问题卡。
- 补齐并复查 2 道缺失中文题意；保留内容变更报告。
- 更新 OPI 分类顺序、声明数量、发布版本和资源版本。
- 构建新的远程 release 与内嵌回退数据，生成变更和校验报告。

### 阶段产出

- 图片题完整维护源和资源。
- 新题库发布产物、资源 manifest 和迁移报告。
- 可重复执行的校验结果。

### 允许修改范围

- `content/question-banks/banks/opi/`
- `content/question-banks/resources/`
- 内容版本和生成的 `dist/question-bank-release/`
- 内嵌回退产物及任务校验/报告。

### 禁止范围

- 不复制来源完整 OPI JSON、脚本或中间图。
- 不重编号现有 OPI ID，不改写现有普通题目。
- 不手工修改生成产物代替维护源构建。

### 验收与验证

- OPI 为 8 分类、144 话题、1356 卡；全题库为 5034 卡。
- 图片题严格为 23 图卡、64 问题卡、23 JPG、64 MP3。
- ID、声明数量、字段、MIME、路径、checksum 和引用全量通过。
- `pnpm content:build` 与 `pnpm content:check:full` 通过且可重复。

## 7. 阶段 4：本地与 iOS 全量验收

### 阶段目标

证明全部图片题在当前原生学习体验中可用，且没有破坏普通题库和同步能力。

### 主要工作

- 运行内容、客户端、contract 和 API 全量检查。
- 抽查全部 23 个话题的首图与问题分组，重点检查长文本和不同图片比例。
- 验证图片加载、超时、失败、重试、音频失败和网络失败状态。
- 验证目录进度、答题卡、录音、笔记、学习记录、结束/完成和账号同步。
- 使用 iOS Development Build 和模拟器完成真实渲染、截图与核心链路。

### 阶段产出

- 自动化验证结果。
- 图片题页面/状态截图与抽查清单。
- 本地阶段审查结论。

### 允许修改范围

- 本任务相关 RN、测试、内容、资源和文档。

### 禁止范围

- 不以构建通过代替视觉验收。
- 不把 Android 标记为已验证；当前内部题库云端切片的验收环境仍为 iOS。
- 不顺手处理其它 UI、音频或题库问题。

### 验收与验证

- `pnpm check` 通过。
- `pnpm content:check:full` 通过。
- 相关 iOS Development Build 通过并成功运行。
- 图片题核心链路和代表性异常状态真实渲染通过。
- 现有普通 OPI 和至少一个其它题库回归抽查通过。

## 8. 阶段 5：ECS 发布与远程验收

### 阶段目标

让模拟器和集成环境真正使用新的云端 OPI release 与图片/音频资源，而不是停留在本地代码和内嵌数据。

### 主要工作

- 确认部署仅包含本任务已复核文件集，不携带脏工作树无关改动。
- 备份当前数据库、active OPI release、ECS 源码和 API 镜像。
- 部署通用资源导入脚本和必要 API 文件，重启 `icao-api`。
- 幂等导入新题库 release、23 张图片和 64 个音频。
- 验证健康、题库、资源签名、文件读取和 App 远程链路。

### 阶段产出

- ECS 新 active OPI release。
- 87 个新增资源对象与元数据。
- 部署、验证和回滚证据。

### 允许修改范围

- 路线图已确认的 ECS API 部署文件、题库 release 和 Storage 对象。

### 禁止范围

- 不部署其它未提交改动。
- 不执行数据库 Schema Migration。
- 不删除旧 release、旧 Storage 对象、备份或回滚镜像。
- 不公开发布或改变公网/域名边界。

### 验收与验证

- `/health/ready` 的 API 和数据库均为 `ok`。
- 远程 OPI 返回新版本及 8/144/1356 数量，ETag/304 正常。
- 代表性 JPG 和 MP3 均能经资源接口获得签名地址并成功读取。
- App 经安全隧道实际命中远程题库和资源，图片题完整学习链路通过。
- 重复导入不重复上传或产生重复 release；回滚步骤可执行。

## 9. 阶段 6：收口

### 阶段目标

形成可审查、可接续、可回滚的最终结果。

### 主要工作与产出

- 更新 `phase-log.md`，记录每阶段实际文件、验证和判断。
- 生成 `closeout.md`，逐项对应需求、数量、资源、渲染和 ECS 证据。
- 检查最终 Git diff、生成文件、未跟踪文件和来源边界。
- 记录明确未做、剩余内容质量问题和 Android 未验收边界。
- 最后刷新 `APP_DISPLAY_VERSION`。

### 验收标准

- 四份决策文档与真实实现一致。
- 需求中的每个验收效果都有验证证据。
- 未修改设计仓库、独立单词模块、来源代码或其它题库。
- 当前远程运行版本、回滚点和剩余风险清楚。

## 10. 小流程启动条件

只有同时满足以下条件才进入小流程：

- 用户确认 `requirements.md`、`technical-plan.md`、`technical-audit.md` 和本路线图。
- 确认只迁移图片题，不包含独立单词资源。
- 确认路线图中的 ECS 内容发布和 API 部署属于本任务最终验收范围。
- 当前工作区相关并行改动的归属已检查，可在不覆盖其它改动的前提下执行。

确认后 Codex 从阶段 0 自动推进；只有触碰硬约束、不可逆数据风险、外部权限/密钥变化或真实路线失效时才回到大流程。
