# 图片题功能与资源迁移技术盘点

状态：只读盘点与后续实施均已完成

盘点日期：2026-07-13

## 1. 盘点范围与结论

本次只读检查了：

- `icao-app` 当前题库维护层、发布层、Repository、资源解析、学习页和 ECS 导入链路；
- `feizhuicu` 图片题正式数据、最终图片、问题音频和既有 workstream 记录；
- 图片题与当前 OPI 数据、资源和学习行为的兼容缺口。

结论：可以在不复制来源代码和完整题库的前提下迁移。当前 App 已有统一 OPI 目录、远程题库、私有资源、缓存、进度和同步框架；缺口集中在图片卡类型、图片资源发布、图片卡原生渲染以及内容导入脚本的通用资源支持，不需要重建题库或修改数据库 Schema。

## 3. `icao-app` 当前题库与内容工程

### 3.1 当前数量

| 项目 | 当前数量 | 图片题加入后 |
| --- | ---: | ---: |
| 全部分类 | 27 | 28 |
| 全部话题 | 239 | 262 |
| 全部卡片 | 4947 | 5034 |
| OPI 分类 | 7 | 8 |
| OPI 话题 | 121 | 144 |
| OPI 卡片 | 1269 | 1356 |

OPI 分类和话题由数据驱动的 `QuestionBankCatalog` 渲染，不存在来源项目中“分类数组硬编码”的限制；增加分类不需要新增路由。

### 3.2 三层内容工程

当前已具备：

- 维护层：`content/question-banks/`，按题库、分类、话题拆分。
- 发布层：`tools/question-bank-content.mjs` 生成版本、checksum、manifest、变更报告和 bank payload。
- 运行层：RN `QuestionBankRepository`、API release、SQLite 缓存和内嵌回退使用同一数据形状。

现有约束和缺口：

- `QuestionBankCard` 只有文本、音频、选择题和参考内容字段，没有图片卡类型或图片资源字段。
- topic schema 强制每张卡都有非空 `audioText`，不能正确表达纯图片卡。
- 构建工具只收集 `card.audio` 引用，没有检查图片引用。
- 资源 schema 的 MIME 被固定为 `audio/mpeg`。
- 当前内嵌快照和内容维护源是两个物理产物；新增图片题时需要明确同源生成或一致性校验，避免远程与回退内容漂移。

## 4. React Native 学习页现状

当前 `QuestionBankStudyScreen` 和相关组件已经具备：

- 题目导航、上一题/下一题、答题卡、结束和完成；
- OPI 问题音频、录音、参考答案、笔记、标签、高亮、AI 查词；
- 资源签名、缓存、加载超时和重试；
- 本地进度、学习记录和账号同步。

缺口：

- 学习页当前默认给每张 OPI 卡挂载音频区、口语录音和文字工作台。
- `StudyCardStack` 接受通用 React 内容，但没有图片卡专用的加载、完整显示和错误状态。
- 页面没有按卡片能力跳过音频、录音、查词和文字工具的分支。
- 当前没有图片卡真实渲染测试或图片资源失败测试。

有利条件：

- `expo-image` 已在仓库锁定依赖中，无需为图片展示新增生产依赖。
- `useQuestionBankAsset` 和底层资源服务实际按路径工作，不限定音频，可复用签名 URL、缓存和重试思路。
- 问题卡提供 `audio` 时，现有学习页会播放文件音频；只有无文件时才显示 OPI 生成语音预留，因此 64 个来源 MP3 可以增量接入而不改变其它 OPI。

## 5. API、Storage 与部署现状

### 已具备

- `resource_objects` 已保存 object key、模块、source path、checksum、大小、MIME 和状态，字段可以容纳图片。
- 私有 `question-bank-assets` bucket、短期签名 URL 和 `/v1/resources/resolve` 可处理统一资源前缀。
- 题库 release 支持版本、checksum、active 状态、ETag 和 RN 缓存。
- 当前数据库无需为图片题新增表或字段。

### 缺口

- `services/api/scripts/import-content.mjs` 目前以 `AUDIO_ROOT` 和 `/question-bank-assets/audio/` 为前提读取文件，不能直接导入图片。
- 资源构建和导入需要升级为通用资源根目录与 MIME 白名单，同时保持相同 checksum 的幂等跳过。
- 本地当前发布清单已显示 3895 个资源，而第二阶段 A 收口时 ECS 证据是 3894 个资源；实施前必须重新核对当前本地目标 release 与 ECS active release，不能从旧收口数字推断实时一致。
- 修改 `services/api` 后，按仓库规则必须部署干净文件集、重启容器、通过 `/health/ready` 并验证真实接口。

## 6. 学习数据兼容性

- 当前学习状态按 `bankId/topicId/cardId` 定位，新增稳定 ID 不会要求迁移现有卡片状态。
- 图片卡可沿用访问、完成和同步字段；不需要新增数据库 Schema。
- 现有答题卡和完成统计按 topic 卡片数组工作，理论上支持混合卡片，但仍需自动化和真实流程验证。
- 图片卡不应生成空录音、空答案、无意义文字标注或 AI 查询记录，否则会污染同步数据和报告。

## 7. 主要缺口与风险分级

### P0：实施前必须关闭

- 明确定义图片卡条件 schema 和运行类型，不能使用空 `audioText` 绕过。
- 建立精确 allowlist，证明只取用 23 张图、64 个音频和对应内容。
- 补齐并复查 2 道缺失中文题意。
- 确认本地目标 release 与 ECS 当前 active release、资源数量和回滚点。

### P1：垂直样例必须验证

- 图片完整显示、AI 标识可见、不同尺寸不被裁切。
- 图片加载、超时、失败和重试可用。
- 图片卡跳过音频、录音、查词和文字工作台；问题卡行为不回归。
- 图片和 MP3 能通过 manifest、Storage、签名接口和 App 远程读取。

### P2：全量阶段持续检查

- 23 组图片—问题对应关系、标题和顺序。
- 87 张新卡对答题卡、学习记录、完成统计和同步的影响。
- 当前脏工作树与其它 workstream 的并行改动，尤其共享题库组件、内容工具、API 导入脚本和展示版本文件。

## 8. 回滚点

- 保留当前 OPI release 和内嵌快照，不覆盖旧稳定 ID。
- 新资源使用新 object key；不删除或覆盖现有 Storage 对象。
- 导入前保留 ECS 数据库备份、旧 API 镜像和源码备份。
- 新 OPI release 验证失败时可重新激活旧 release，并回滚 API 镜像/源码；资源对象可保留为未引用对象，不执行破坏性删除。

## 9. 总体判断

推荐方案与当前架构一致，可以进入路线图确认。任务不需要新一级模块、数据库 Migration、Web 代码迁移、完整题库复制或新图片生成；正确顺序是先收口来源清单和通用资源合同，再完成单个图片话题垂直样例，随后批量迁移、真实渲染、ECS 发布和远程链路验收。
