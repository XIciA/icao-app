## 1. 使用方式

负责人已授权 Codex 按小流程连续执行当前内部 TestFlight 里程碑。代码、测试、配置、构建排错、
材料草稿和文档更新默认由 Codex 完成，不再拆成逐项人工确认。

当前路线只有六类情况需要负责人介入：

1. Apple 账号登录、账号所有者确认或双重认证；
2. 测试员接受邀请以及必须在真实设备上完成的安装、信任或系统权限动作；
3. Apple、微信开放平台、阿里云或其他受保护平台临时要求输入的验证码；
4. 阿里云后续充值、扩容、三网真机验证或受保护 Secret 重新输入；
5. 微信开放平台的企业认证、移动应用审核、协议/认证费和 AppSecret 输入；
6. Production 数据库迁移开始前，确认备份、评审、演练证据和执行窗口。

阿里云实名认证、签名“云启航科成都”、通用验证码模板、真实发送链路和一个代表号码收件已经完成。
用户尚无“听你五个”注册商标；阿里云当前签名页面只允许企事业单位名或已注册商标来源，因此不得
用不实材料提交“听你五个”。该品牌签名延期到商标注册完成或具备平台认可材料后，不阻塞内部
TestFlight 或当前登录。
Apple App ID 的 Sign in with Apple 已启用，但发布描述文件需重建、Supabase provider 仍需配置；微信
开放平台配置仍待人工平台动作。生产 API/网关更新和新内部 TestFlight 上传已经授权，当前尚未执行；
新账号数据库迁移仍必须在备份/评审完成后，于临执行前请求负责人明确确认。

除此之外，真实支付、Android 分发、运营后台、异机备份/长期恢复、法律和客服均不是当前阻塞项；
Production 账号迁移所需的本机可恢复备份属于 M-TF04，不能延期。现有
Expo Web/Vercel 完全冻结；当前不要求负责人进入 Vercel 做任何操作，Codex 也不得修改、构建或部署
该网站。

不要把密码、完整验证码、身份证、营业执照、银行卡、私钥、证书或支付凭证粘贴到仓库或聊天。需要
验证码时，由负责人直接在对应可信界面输入；Codex 只确认操作是否完成。

## 3. 当前已经确定、无需再次人工决策

| 项目 | 当前执行答案 |
| --- | --- |
| TestFlight 范围 | iOS 内部 TestFlight 优先，不开启外部测试，不提交 App Store 正式审核 |
| App/Web 边界 | 只修改 Native App、必要 App 后端与 Auth 公网网关；Expo Web/Vercel 零修改、零构建、零部署 |
| Native 登录 | 微信/Apple/手机号多入口；第三方首次自动注册并先进入、稍后绑定；手机号为最高可信归并锚点，永久 `accountId` 承载权益；邮箱和邀请码不登录 |
| Auth 公网边界 | 普通/找回发码只走自有 API；公网 Supabase `/otp`、`/resend`、`/signup` 阻断；密码更新走受保护 API，公网 `PUT/PATCH /user` 阻断；找回未知/已知号码同形 |
| 第三方近期认证 | Apple 只认 method-specific OAuth AMR；微信 code 交换限流/去重并签发10分钟、当前会话绑定、消费一次即失效的服务端 grant |
| 手机号绑定 | 未占用手机号保留源 `accountId`；已占用才归并到手机号账号；两条事务直接返回最终账号摘要 |
| 短信供应商 | 首发锁定阿里云国内短信，不再需要二选一 |
| 短信资质与签名 | 资质主体“云启航科（成都）科技有限公司”；“云启航科成都”已审核并完成真实发送；“听你五个”因尚无注册商标且当前不满足平台来源要求而延期，不阻塞登录 |
| 短信模板 | 注册、验证码登录和找回密码共用通用身份验证码模板；推荐正文“您的验证码为${code}，5分钟内有效，请勿泄露。如非本人操作请忽略。” |
| 短信风控初值 | 全局200条/日、2000条/月；同一脱敏号码5条/小时、10条/日；正式多实例前改为持久共享计数并补齐设备/IP维度 |
| 支付 | 当前只做稳定合同、禁用提供方和默认关闭开关；不接 StoreKit、支付宝或微信 SDK |
| AI 点数 | 采用可配置的推荐测试策略，不公开承诺具体点数；未来整体替换正式策略 |
| Android 下载 | 主机和域名暂缓，不阻塞当前 TestFlight |
| 内部运营 | 后台及其托管、管理员/客服账号和联系方式暂缓 |
| 备份 | Production 账号迁移前先生成并验证本机可恢复备份；异机方案暂缓 |
| 法律与客服 | 法律文本终稿、客服流程和客服人员暂缓 |

这些答案是当前里程碑的范围选择，不改变 D1—D9 对未来正式商业上线的终局要求。

## 5. Codex 当前可无阻塞完成的工作

在不触及第2节人工闸门的情况下，Codex 继续完成：

- 盘点并保护已有工作区改动，建立 Native/Web 所有权和冻结检查；
- 在既有手机号验证码/密码基础上，建立永久账号与多身份映射，新增微信/Apple 自动注册、第三方
  先进入后绑定、手机号绑定和冲突归并；API Guard 只解析合法身份与活跃 `accountId`；
- 将普通/找回发码和密码更新统一收口到自有 API，部署公网 Supabase 写入口门禁；完成 Apple OAuth
  AMR、微信 code 限流/去重与10分钟单用途 grant，以及保持源 `accountId` 的未占用号码绑定；
- 已建立阿里云短信适配、Supabase Hook 验签、严格隔离的非生产测试实现、格式校验、基础限流和失败
  关闭测试；维持“云启航科成都”真实发送并配合完成三网验证；“听你五个”在商标/材料合规前不提交；
- 建立支付纯合同、禁用提供方、功能开关及“无 SDK、无网络、无订单、无权益”的自动证明；
- 建立可配置的 AI 推荐测试策略和替换接口，不发布正式点数承诺；
- 运行与影响范围相符的类型、单元、API、Native、Release/Archive 和包检查；
- 在本地完成候选后，按当前授权更新生产 API/网关并上传内部 TestFlight；当前尚未部署或上传，执行到
  Apple 登录/2FA、数据库迁移确认或测试员设备动作时再请求负责人；
- 记录真机验证结果、修复缺陷并更新阶段日志和商业差距清单。

当前授权包含生产 API/网关更新和 iOS 内部 TestFlight 上传，不包含：修改/构建/部署 Web/Vercel、
未经临执行确认的 Production 数据库迁移、真实支付、外部 TestFlight、App Store 正式提交、Git push、
Android 对外发布或任何资金操作。阿里云现有真实短信链路可继续用于登录验收，但充值/扩容仍属资金
闸门。

## 6. 当前联络规则

Codex 不因普通技术选型、测试失败、模拟配置或可自行修复的问题暂停。只有出现下列真实阻塞时才联系
负责人：

- Apple 官方界面要求账号登录、2FA、账号所有者确认或缺少公司 Team 权限；
- 内部构建已就绪，需要测试员接受邀请、安装或在设备上完成系统动作；
- 可信平台明确要求负责人输入一次性验证码；
- Production 数据库迁移已到临执行点，需要确认备份、评审和执行窗口；
- 继续执行会涉及真实资金、外部/正式发布、Git push、Android 对外发布或 Web/Vercel。

当前没有“协调冻结”要求 Codex 停在本地边界；生产 API/网关更新和内部 TestFlight 上传可按路线继续。
截至本次文档更新仍未部署或上传，不能把本地 adapter、网关文件或测试通过写成线上已生效。

若没有这些情况，Codex 在每个人工闸门之间按路线连续执行，不再要求负责人逐条回复；遇到数据库迁移
临执行确认、阿里云付费/Secret、Apple/微信受保护操作或真机动作时必须停下。
