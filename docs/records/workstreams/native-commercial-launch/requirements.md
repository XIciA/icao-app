# Native App 正式商业上线总需求

状态：商业终局需求基线已锁定；当前执行“内部 TestFlight 技术预览”里程碑
更新时间：2026-08-13

## 1. 目标

在 App 备案和公司 Apple Developer Program 审核期间，完成所有不依赖审核结果的产品决策、
技术设计、开发、测试、运维和商店准备。

目标状态：审核通过后不再进行核心架构设计或大规模开发，只需绑定正式资质、签名和商品，完成
最终真机验收并提交商店。

本文是 Native App 正式上线的总需求。登录、同步、会员、AI 等复杂工作包后续分别讨论方案，
本文只定义范围、决策点和上线标准。

### 1.1 当前执行里程碑：内部 TestFlight 技术预览

当前授权只覆盖一个可安装、可验证的 iOS **内部 TestFlight** 版本，不等同于正式商业上线，也不
改写 D1—D9 的商业终局决定。当前里程碑遵循以下硬边界：

- 只修改 iOS/Android Native App 以及其确有必要的 App 后端；现有 Expo Web/Vercel 完全冻结，
  不修改、不构建、不预览、不部署，也不以内部后台、法律页或下载页为由复用该项目；
- Native 取消邀请码登录入口和认证依赖；正式终局提供微信、Apple（iOS）、中国大陆 `+86` 手机号
  验证码和手机号密码四种入口。第三方首次登录自动注册并可先进入，稍后绑定手机号；当前已上线的
  TestFlight 仍只具备手机号验证码/密码基础，社交登录与账号归并属于本次新增实现；
- 真实短信供应商已锁定为阿里云国内短信。资质主体为“云启航科（成都）科技有限公司”；
  签名“云启航科成都”和通用验证码模板已经审核，现有 TestFlight 已完成真实发送与代表号码收件。
  用户尚未注册“听你五个”商标，阿里云当前页面只允许企事业单位名或已注册商标来源，因此不得用
  不实来源提交该品牌签名；它延期到商标注册完成或具备平台认可材料后，不阻塞当前登录。仓库已完成
  Supabase Send SMS Hook、阿里云发送适配、签名校验、基础限流和生产式配置覆盖层；三网实测、设备/IP
  风控与多实例共享计数仍待完成；
- 仅限非生产 TestFlight 的测试 OTP 仍须由非生产配置、显式开关和受控测试号码共同启用，在
  Production 配置和正式包中强制失败关闭；测试 OTP 覆盖层不得与阿里云真实短信覆盖层同时使用；
- 当前不接入真实支付，不安装或编译 StoreKit、支付宝、微信支付 SDK，不创建渠道商品，也不产生
  真实订单或权益；只交付稳定支付合同、禁用提供方和默认关闭的功能开关，购买入口不得形成可用
  支付承诺；
- AI 点数先使用可配置、可替换的推荐测试策略，只用于内部验证接口、余额与扣点流程，不写入公开
  商品文案，不构成正式额度承诺；
- Android APK 下载主机/域名、内部运营后台及托管、常规异机备份/长期恢复、工作人员和告警联系人、
  法律文本终稿、客服运营以及所有真实支付工作均延期到后续商业化阶段；但本轮 Production 账号迁移
  前必须生成并验证本机可恢复备份，异机目标仍另行决定；
- 当前代码和配置仍处于本地候选状态，尚未部署生产 API/网关，也尚未上传新 TestFlight。负责人已
  授权把生产 API/网关更新和内部 TestFlight 上传纳入当前目标；Production 数据库迁移仍必须先完成
  备份、评审、隔离演练，并在临执行前取得明确确认。正式支付、外部测试、App Store 提交和任何其他
  对外发布仍不在本次授权内。

当前已发布 TestFlight 的手机号验证码/密码基础和阿里云真实短信可用；本地小步已完成 D2 多入口候选
的客户端、账号层与服务端适配，但 Apple/微信、账号归并和新构建尚未完成生产迁移、外部平台配置及
真机验收。移动/联通/电信三网覆盖也未收口，因此不能把四种入口全部描述为已经上线；第3、7节的

## 2. 已确认边界

- Native 用户可使用微信、Apple（iOS）、中国大陆 `+86` 手机号验证码或手机号密码登录。首次第三方
  登录自动注册并允许先进入、稍后绑定手机号；手机号是最高可信的找回与冲突归并锚点，永久内部
  `accountId` 才是学习数据、会员、订单和 AI 点数的唯一业务主键。
- 邀请码不再登录，只用于赠送会员、优惠或渠道归因。
- 资源模块和非 AI 基础学习工具全部免费；900句完整免费；听力4个模块各前10题、陆空通话前3套、
  OPI前3个话题和故事复诵前3篇免费。
- 会员解锁其余题库内容并获得用户可见的 AI 点数；免费新账号获得一次性少量 AI 体验点数。
- 首发平台为中国大陆 iOS 和国内 Android；两端共用正式账号、会员时间和 AI 点数。
- 现有 Web/Vercel 整体冻结，不接入本轮正式账号、会员、支付或内容授权，也不因本轮改动其运行时。
- 真人小班价格、微信咨询和购买导向退出本轮范围，后续作为独立专题重新决策。

## 3. 上线工作包

### A. 正式账号与登录

- **已确认**：iOS 支持微信、Apple、手机号验证码和手机号密码；Android 支持微信、手机号验证码和
  手机号密码。微信/Apple 首次登录自动注册并直接进入，手机号可稍后绑定；邮箱和邀请码不登录。
- **必须交付**：永久内部 `accountId` 与多身份映射；真实短信供应商与公司名签名/模板；手机号 OTP
  自动注册/登录、设密/修改、密码登录和短信找回；原生 Apple/微信授权；手机号绑定、身份解绑、
  已占用手机号的双凭证安全归并、会话/换号/注销；短信、密码与第三方滥用风控；双端真机与异常
  场景验证。任何入口不得产生两份业务权益。
- **认证边界**：普通 OTP/自动注册和密码找回发码只从自有 API 发起，公网 Supabase `/otp`、`/resend`、
  `/signup` 由网关阻断；找回未知/已知手机号返回同形结果。手机号密码设置/修改走受保护账号 API，
  公网 `PUT/PATCH /user` 阻断。Apple 近期认证只认对应 OAuth AMR；微信 code 交换入口限流并去重，
  成功后签发绑定当前会话、10分钟有效且只能消费一次的服务端 grant。
- **绑定与归并**：未占用手机号绑定后保留第三方源 `accountId`；只有手机号已属于其他账号时才归并到
  手机号账号。绑定/归并事务直接返回最终账号摘要，避免提交成功后因额外查询失败而误报失败。

### B. 多设备数据同步

- **已确认**：未来用于商业验收或公开测试的 TestFlight、官网正式 APK、App Store 及未来 Android
  商店版本共用 Production 账号与数据；结构化学习数据和 AI 文字结果同步，原始录音、资源缓存和
  设备设置仅保留本机。当前内部 TestFlight 技术预览使用非生产配置，不因此取得 Production 权限。
- **必须交付**：账号级数据隔离、服务端版本、增量同步、幂等写入、离线重试、冲突和删除传播；
  清除学习数据后拒绝旧设备回灌；冲突自动处理，并通过双设备并发、离线恢复、换机、重装、切换
  账号、清除学习数据和注销验收。

### C. 会员、订单与权益

- **已确认**：首发提供7天、15天、1个月、2个月和3个月会员；1个权益月固定为31天，因此后三档
  分别为31、62和93天。基准价格分别为 ¥68、¥108、¥168、¥298 和 ¥398。所有套餐均为用户主动
  购买的非自动续期商品，可重复购买并从当前最终到期时间继续顺延，权益跨 iOS/Android 共享。
- **已确认**：iOS 使用 App Store 非自动续期内购；国内 Android 首发同时支持支付宝和微信支付。
- **必须交付**：商品、订单、支付交易和权益分离；服务端授权；渠道合规支付、验单/通知、恢复购买和
  订单管理；覆盖重复购买、跨端恢复、退款、撤销和重复通知。

### D. AI 成本与防滥用

- **已确认**：用户以 AI 点数理解和使用权益，不看到供应商人民币成本。长期套餐每31天分批发放
  点数，未用点数可以累计到会员最终到期；重复购买延长最终到期时间，也延长已发放未使用点数的
  有效期。具体点数表在成本审计后由负责人最终确认。
- **已确认**：AI 不设置每日或每月总调用次数停止线；服务端另以真实人民币成本、极短时高频窗口、
  单任务执行、日/周期金额上限和全局预算防止异常消耗。点数规则、模型、供应商价格和风控阈值
  分开版本化。
- **必须交付**：服务端权益与额度校验；用户/设备/IP 限流和并发控制；真实用量与成本记账；异常
  识别、预算告警、单用户上限、全局熔断和紧急关闭；AI 辅助结果标识、模型备案/登记信息核验及
  适用的生成合成内容标识要求。

### E. 内容与资源保护

- **已确认**：资源模块和900句全部免费；听力4个模块各前10题、陆空通话前3套、OPI前3个话题、
  故事复诵前3篇免费。免费范围使用版本化内容 ID；会员内容不进入正式包，按内容单元授权下载，
  使用最长72小时且不越过会员到期时间的离线凭证。
- **必须交付**：按已确认边界统一划分免费与会员内容；正式包不携带可直接提取的完整会员内容；
  API、音频/文件、页面和缓存采用同一授权规则，切号或失去权益后不能继续访问。

### F. 隐私、合规与账号安全

- **已确认**：学习成果在账号存续期间保留，临时录音与敏感原文最短保存；安全日志6个月、AI成本
  明细12个月、原始分析事件90天、反馈图片180天、交易记录至少3年、备份7天。提供分层删除、
  数据导出、AI同意撤回和无反悔期注销；只允许14周岁及以上用户注册；首发不接广告或第三方行为
  分析 SDK。
- **已确认**：注销立即放弃账号、学习数据、会员时间和 AI 点数；同一手机号再次注册获得新的
  `accountId`，视为新账号并可重新获得免费 AI 体验点数。依法保留的交易和安全记录只隔离保存，不能
  用于恢复旧账号。
- **必须交付**：实际数据流和第三方 SDK 清单；协议同意、年龄声明、权限说明、账号注销和订单管理；官网、
  备案和商店隐私披露保持一致；自动保留期清理、跨设备删除传播、密钥和敏感数据保护。

### G. 稳定性、安全与运营

- **必须交付**：崩溃、API、数据库、支付、同步和 AI 成本监控；异机备份与恢复演练；鉴权、限流、
  依赖/密钥扫描、审计、负载测试；用户自助隐私入口；独立内部运营后台基础；功能开关、降级和
  回滚能力。
- **最小数据分析**：观察注册/登录、学习激活、会员页、购买、AI 成本和错误漏斗，不采集不必要的
  作答、录音、Token、手机号等敏感内容。
- **已确认**：后台首发只有管理员和客服两个角色，以独立工作人员账号登录；用户 App 无管理入口，
  后台不复用或修改现有用户 Web/Vercel，只通过专用服务端接口操作，不直接操作数据库。

### H. 构建、商店与发布

- **已确认**：iOS 先通过 TestFlight 测试，验证完成后发布中国大陆 App Store；Android 首批通过
  公司官网提供正式 APK，国内 Android 应用商店后续另行决定。两端独立达到发布门槛，哪一端先
  准备完成即可先上线，不互相等待。
- **必须交付**：可重复的 CI 和双端 Release 构建；正式环境配置；真机、弱网、后台、音频、权限和
  升级测试；截图、文案、审核账号、隐私材料、非自动续期商品说明和审核备注；完整发布演练。

## 5. 推进规则

1. D1—D9 已作为商业终局锁定；D8 只锁定后台结构，具体设计留到后台建设阶段。
2. 决策锁定后，形成对应技术方案、数据变更、测试和回滚计划。
3. 当前按内部 TestFlight 路线连续完成本地实现、测试、生产 API/网关更新、候选构建、上传和真机
   收口；这些动作已获当前授权，但不得把本地检查写成已部署或已上传。用户 Web/Vercel 始终冻结。
4. 当前路线完成后，商业终局的支付、内容、运营、合规和正式发布阶段仍保持暂停，需新的明确授权。
5. 后续审核期间使用开发/沙盒配置完成构建和端到端演练，审核完成后再绑定正式团队、备案号和
   商品，最终验收后提交。

真实价格和商品发布、生产数据库迁移、当前登录目标以外的生产部署、正式商店提交、法律文本终稿及

上传已在第1.1节单独授权。

## 6. 当前主要差距

- Native 当前界面、会话服务和账号界面已完成中国大陆手机号验证码/密码基础、设密/修改和短信找回；
  邀请码可执行路径已关闭。新 D2 的本地候选已加入永久账号映射、OTP 自动注册、Apple/微信入口、
  手机号绑定与冲突归并；普通/找回发码及密码更新已收口到自有 API，公网 Supabase 写入口由网关门禁
  保护，但这些新增能力尚未生产部署、上传新 TestFlight、完成外部微信平台配置或真机验收。
- API 已形成 Supabase Send SMS Hook 与阿里云适配、签名校验、基础号码/总量限流、Secret 边界和生产式
  Supabase 覆盖层；严格隔离的非生产测试 OTP 仍保持失败关闭。“云启航科成都”签名和通用模板已审核，
  现有 TestFlight 已完成真实发送与代表号码收件；尚未完成三网端到端验证、设备/IP 风控和多实例共享
  计数。“听你五个”因未注册商标且当前不满足平台签名来源要求而延期，不是当前登录阻塞项。
- 当前短信预算和幂等记录是单 API 进程内实现，重启会重置，多实例不会共享；正式扩容前须迁移到
  Redis 或数据库，并在验证码请求入口补齐设备/IP 维度风控和持续告警。
- 已有会话和同步基础；D3 已确认，但完整多设备场景尚未实现及验收。
- 已形成独立的稳定支付合同、禁用提供方和默认关闭测试；尚未接入 App 交互或任何真实渠道，正式
  订单、非自动续期商品、跨端权益和渠道通知系统属于后续商业化差距。

## 7. 上线验收标准

只有以下条件全部满足，才进入最终商店提交：

1. D1—D9 已锁定，需求、实现、隐私披露和商店材料一致。
2. 正式账号和多设备同步在双端、离线、换机、切号和注销场景通过验收。
3. 免费、会员、AI 和内容资源均由服务端授权，客户端不能简单绕过。
4. iOS 非自动续期内购、Android 支付宝/微信支付及跨端权益全生命周期已完成沙盒验证。
5. AI 配额、成本控制、防滥用和熔断真实生效。
6. 监控、告警、备份恢复、用户自助隐私流程、最小运营后台、降级和回滚均有演练证据。
7. 自动化检查、双端真机、代表性负载和 Release 构建通过，无 P0/P1 问题。
8. 商店和备案材料除审核结果产生的正式字段外均已完成。
9. 审核完成后不再需要新架构、核心功能开发或高风险数据改造。
