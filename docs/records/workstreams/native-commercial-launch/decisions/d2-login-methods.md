# D2 正式登录与账号归并方案决策

状态：已确认；2026-08-12 覆盖更新为方案 B（第三方先进入、稍后绑定手机号）
确认日期：2026-08-12；外部配置状态更新：2026-08-13
关联需求：[Native App 正式商业上线总需求](../requirements.md)

## 决策

- Native iOS 与国内 Android 最终支持四种入口：
  1. **微信登录**：首次成功即自动创建账号并进入 App；
  2. **Apple 登录**：iOS 首次成功即自动创建账号并进入 App；
  3. **中国大陆 `+86` 手机号 + 短信验证码**：未注册手机号验证成功后自动注册并进入；
  4. **中国大陆 `+86` 手机号 + 密码**：已绑定手机号且已设置密码的用户使用。
- 第三方首次登录采用已确认的**方案 B：先进入、稍后绑定手机号**。不把绑定手机号设为进入 App 的
  前置条件，但在账号安全页持续提供清晰提示；支付、注销、换绑、账号归并等高风险动作可要求先绑定
  手机号并重新验证。
- 手机号是最高可信的账号找回和冲突归并锚点，但**不直接作为数据库主键**。学习记录、会员权益、
  AI 点数和订单归属永久、不可变的内部 `accountId`。
- Supabase Auth 继续负责可复用的正式会话；认证提供方产生的 `auth.users.id` 是登录身份 ID，内部
  `accountId` 是业务账号 ID。一个 `accountId` 可以关联手机号、Apple、微信等多个已验证身份，业务
  表不得再假定 `auth.users.id` 永远等于业务账号 ID。
- 邮箱和邀请码不属于 Native 登录入口。邀请码只保留赠送会员、优惠或渠道归因用途。

## 自动注册与登录规则

- 微信、Apple 或手机号 OTP 第一次认证成功时自动创建内部账号，不再区分“注册页”和“登录页”；
  同一个已验证身份以后再次登录必须回到同一个 `accountId`。
- 第三方登录前必须完成14周岁确认并同意用户协议与隐私政策；用户取消授权、未安装微信、网络失败、
  提供方拒绝或配置缺失时均失败关闭，不创建半成品账号。
- 手机号 OTP 默认允许自动注册；密码登录和短信重置密码不得为未知手机号创建账号。
- 密码是手机号身份的可选登录方式。用户绑定并验证手机号后可设置密码；未设置密码时仍可使用微信、
  Apple 或手机号验证码登录。
- Apple 使用原生 Sign in with Apple 和 Supabase ID Token 登录/身份关联；首次授权可能返回的姓名只
  保存一次，后续缺失不得覆盖已有资料。
- 微信使用微信开放平台移动应用 OpenSDK 获取一次性授权 `code`，由服务端持有 AppSecret 并交换
  微信身份；AppSecret、access token、UnionID/OpenID 和完整授权响应不得进入客户端日志。iOS 与
  Android 必须挂在同一微信开放平台主体并具备一致的 UnionID 归属，才能保证跨端同一身份。
- 手机号普通 OTP（含首次自动注册/登录）和密码找回的发码都只能经自有 API 发起；公网网关阻断
  Supabase `/auth/v1/otp`、`/auth/v1/resend`、`/auth/v1/signup`，避免客户端绕过统一风控。找回流程对
  未知与已知手机号返回同形结果并设置一致的最短响应时间，不泄露账号是否存在。

## 手机号绑定与账号归并

- 第三方账号绑定一个尚未使用的手机号：验证短信 OTP 后，将手机号身份关联到当前**源
  `accountId`**，源 `accountId` 保持不变，不创建第二份业务账号；用户随后可设置密码。
- 第三方账号绑定一个已属于其他账号的手机号：必须先验证该手机号；验证成功后以手机号原有账号为
  主账号，将当前第三方身份和可合并数据归并到主账号。不得只凭用户输入手机号自动合并。
- 已占用手机号的验证码由服务端在当前第三方会话下校验；只有事务归并成功后才把手机号主账号会话
  返回 App，禁止 App 先切换账号再异步归并，以免弱网或中断造成身份与权益状态分裂。未占用绑定和
  已占用归并都在事务内生成并返回最终账号摘要，事务提交后不再依赖额外摘要查询决定成功与否。
- 归并后的学习记录、会员有效期、AI 点数、订单和其他权益只能保留一份权威归属；第三方身份以后
  登录直接进入归并后的主账号。源账号进入不可恢复的 `merged` 状态，不得继续产生业务数据。
- 同一账号已绑定另一个微信或 Apple 身份、存在不可自动处理的订单/实名冲突，或任一身份无法重新
  验证时，不自动覆盖；返回中性错误并进入人工核验流程。
- 不得通过昵称、头像、设备 ID、支付渠道昵称或其他弱信息合并账号。

## 安全与会话规则

- 业务 API 先验证合法且未撤销的 Supabase token，再将认证身份解析为内部 `accountId`；不得把
  “拥有手机号”或“使用 OTP”写死为访问普通业务 API 的条件。
- 绑定手机号、绑定/解绑第三方、设置/重置密码、归并账号、全设备退出和注销要求近期认证；敏感操作
  使用短时、单用途授权，不能只凭页面参数绕过重新验证。Apple 绑定只接受当前 Apple 会话中
  `method=oauth` 的 AMR 时间，不能把更新的 TOTP/其他 AMR 误当成 Apple 近期认证；微信 code 交换成功
  后由服务端为对应 `authUserId + sessionId` 签发10分钟、绑定用途且消费即失效的 grant。
- 短信发送、OTP 校验、密码尝试、第三方授权和绑定按账号、号码、设备和 IP 分层风控；界面与 API
  不泄露某手机号、Apple 或微信身份是否已经存在。
- 微信 code 交换入口按来源限流，对一次性 code 使用不可逆摘要去重；同一 code 在窗口内只能消费
  一次，重复、超限或上游异常均失败关闭。
- 绑定至少一种可恢复身份后才能解绑当前登录身份；任何操作不得让账号失去全部可用登录方式。
- 手机号密码规则与短信找回沿用已确认的双登录规则：密码10—64位并同时含字母和数字；找回密码
  由自有 API 在服务端使用 `shouldCreateUser=false` 发起 OTP，验证成功后通过受保护账号 API 更新已有
  手机号身份。客户端不得直接修改 Supabase user；公网网关阻断 `PUT/PATCH /auth/v1/user`。

## 注销与重新注册

- 注销立即放弃内部 `accountId` 对应的学习数据、会员时间和 AI 点数，并解除全部登录身份映射；依法
  必须保留的交易和安全记录隔离保存，不能恢复旧账号。
- 同一手机号、微信或 Apple 身份以后重新授权时，按新用户规则创建新的 `accountId`；同一手机号可
  重新获得免费 AI 体验点数。
- 已归并的源账号不能单独恢复；注销针对当前主账号及其全部已绑定身份执行。

## 分阶段交付顺序

1. 建立永久 `accounts` 与 `account_identities` 映射层，将认证 ID 与业务账号 ID 分离；
2. 把手机号 OTP 改为验证后自动注册/登录，保留密码登录、设密与短信找回；
3. 接入原生 Apple 登录并验证自动注册、会话恢复和手机号绑定；
4. 接入微信 OpenSDK、服务端 code 交换与 Supabase 会话桥接；
5. 实现未占用手机号的直接绑定，以及已占用手机号的双凭证账号归并；
6. 完成风控、注销/解绑、双端回归、真机和弱网验收。

## 验收

- 登录页清晰提供微信、Apple（仅 iOS）、手机号验证码和手机号密码；没有邮箱或邀请码登录入口。
- 新用户通过任一入口首次认证后能自动注册并进入 App；第三方用户可以跳过手机号绑定，普通学习
  不受阻塞，账号安全页明确提示绑定价值。
- 同一微信、Apple 或手机号身份跨重装、跨设备再次登录得到同一 `accountId`；手机号 OTP 与密码得到
  同一个账号和权益。
- 第三方账号绑定未占用手机号不产生第二业务账号；绑定已占用手机号时，必须验证手机号并将第三方
  身份、学习数据和权益安全归并到原手机号账号。
- OTP 覆盖倒计时、重发、限流、错误/过期/重复验证码与三网到达；第三方覆盖取消、拒绝、未安装、
  回调丢失、重放、身份已占用和提供方不可用。
- 自动化与发布门禁证明普通/找回发码和密码更新只能走自有 API，公网 Supabase 发码、注册及 user
  修改路径均被阻断；找回未知/已知号码的响应形状一致。
- Production 不存在固定测试 OTP；客户端和日志不含阿里云、微信或 Apple 私密凭证及完整 token。

## 外部依赖

- 阿里云短信真实发送沿用已确认的企业资质、签名“云启航科成都”、通用验证码模板和最小权限 RAM
  配置；该链路已经完成真实发送与代表号码收件。用户尚无“听你五个”注册商标，且阿里云当前只接受
  企事业单位名或已注册商标来源，因此不得以不实材料提交该品牌签名；等商标注册完成或具备平台认可
  材料后再单独申请，当前登录上线不等待它。
- 公司 App ID `com.readyoufife.ios` 已开启 Sign in with Apple；启用 capability 后需要重建发布描述文件，
  并在 Supabase Auth 启用对应 Client ID。Native ID Token 路线不需要客户端保存 Apple 私钥。
- 微信需要微信开放平台企业开发者资质、iOS/Android 移动应用审核、AppID、iOS Universal Link、
  Android 应用签名/包名配置，以及服务器侧 AppSecret；这些外部配置尚未完成。当前自动化浏览器的
  安全策略不能代办微信开放平台，因此平台登录、认证、协议/费用和受保护凭证输入需要负责人在官方
  界面完成。没有这些外部条件时，代码必须明确显示渠道尚未可用，不能伪造已接入。
- 数据库迁移必须先评审、备份、在副本执行和校验，再单独获批用于 Production。
