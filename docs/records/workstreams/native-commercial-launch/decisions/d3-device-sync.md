# D3 多设备数据同步决策

状态：已确认
确认日期：2026-08-12
关联需求：[Native App 正式商业上线总需求](../requirements.md)

## 决策

- 正式账号的结构化用户数据采用“本机工作副本 + 云端权威数据”的同步模式。
- 面向真实用户的 TestFlight、官网正式签名 APK、App Store 和国内 Android 商店版本，共用同一
  Production 账号体系、API 和数据库。
- 开发包和内部测试使用 Staging；其测试数据不进入 Production。
- 安装渠道和设备 ID 不决定数据归属，唯一归属依据是正式 `userId`。

## 同步范围

云端同步：

- 题目学习状态、学习记录和模考结果；
- 收藏、标注、笔记、高亮、标签和单词学习状态；
- AI 转写文字、分析结果和学习报告；
- 经确认属于账号级的学习偏好。

仅保存在本机：

- 原始录音、下载内容和资源缓存；
- 未提交的临时草稿；
- 权限、音量和播放设备等设备级设置。

订单、会员权益、AI 点数和账号安全状态不走普通学习数据同步，以服务端实时结果为准。

## 同步规则

- 本机先保存并进入待同步队列，联网后通过 API 增量推送和拉取。
- 服务端版本和变更游标是冲突判断依据，不依赖设备时间。
- 学习记录、模考和 AI 报告追加保存；完成状态只前进不倒退。
- 收藏、笔记和单词状态按单条版本合并；删除操作通过删除标记传播。
- “清除全部学习数据”和账号注销使用服务端数据代次或等效失效边界；清除前的离线队列、旧游标和
  旧设备副本恢复联网后不得把已删除数据重新写回。
- 冲突自动处理，不要求普通用户选择本机或云端版本。
- 切换或退出账号必须隔离本机数据，不能串号。

## 渠道衔接约束

- iOS TestFlight 与 App Store 保持同一 Bundle ID 和 App Store Connect App 记录。
- 官网第一版 APK 即使用长期正式签名；未来 Android 商店包保持相同包名和签名，并递增
  `versionCode`。
- 不依赖覆盖安装保留本机文件；换机、重装或必须卸载时，登录后仍可恢复全部应同步数据。
- TestFlight/Sandbox 交易与正式交易隔离，不得产生永久正式会员权益。

## 验收

- 同一账号在 iOS 与 Android 可以读取一致的应同步数据。
- 离线产生的数据在恢复联网后同步，重复请求不会产生重复记录。
- 双设备同时修改、删除、换机、重装和切换账号场景不丢失或串用数据。
- 清除全部学习数据后，长期离线旧设备重新联网也不会恢复清除前的数据。
- 原始录音和资源缓存不会上传为跨设备用户数据。
