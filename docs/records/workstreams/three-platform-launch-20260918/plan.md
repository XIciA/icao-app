# 三端正式交付计划

用户于 2026-09-18 授权实施、检查、部署。此记录描述本轮范围，不是长期规则。

## 目标与边界

- 以已上线 iOS 的功能和视觉为基准，补齐 Android 与正式 Expo Web（readyoufife.com），共用账号、学习记录和服务端权益。
- Android 正式签名 APK 下载发布，微信支付套餐为 7 天 68 元、31 天 158 元、93 天 358 元；不增加本轮应用商店申请范围。
- Android 不展示 Apple 登录；优先完成微信登录，按安装状态和返回前台动态更新入口；若确有外部阻塞，保留手机号登录继续交付。
- 正式 Web 仅手机号登录，提供学习及会员功能，不提供购买。用户在 APP 购买，同账号网页刷新权益。
- 正式 Web 资源维持 OPI 热点、资源分享；右上角提供下载 APP，复用已有下载页布局。
- Vercel 宣传项目冻结，仅在正式 APK 可用后更新安卓下载链接。
- 不承诺浏览器具备系统后台音频、原生录音持久性等操作系统专有能力。

## 实施结构

复用正式客户端的账号、同步、题库、AI、权益协议；浏览器保留存储、录音、资源访问适配。通过明确的构建运行时区分正式网页与旧宣传网站，避免新旧业务并行竞争。付款以服务端验签、查单和幂等权益账本为准。

## 里程碑与验收

1. 核对代码、凭据存在性和基础设施；敏感内容不进入记录、日志或仓库。
2. 完成正式 Web 适配、Android 支付异常恢复、下载入口及价格核验。
3. 聚焦自动测试、完整检查、正式 Web 构建与浏览器检查；审查账号隔离、退出与切换、网络失败、重复支付和会员同步。
4. 代码通过 PR 进入 origin/main 后，从干净主线生成正式制品、部署 API 与 EdgeOne，发布 APK；最后只激活 Vercel 安卓下载。
5. 检查生产健康、页面与下载制品，记录实际完成与尚不能独立验证的真机支付事实，不以构建通过代替真实付款验收。

## 初始事实

- 基线 origin/main 为 2dda94d；本机有用户无关 output/，保留。
- ECS SSH 可用，当前 API 容器健康；本机已有正式 Android 签名材料及 Java 17。
- 服务端套餐已为 6800、15800、35800 分，需验证客户端与正式配置一致。
- 正式 Web 存在旧 AuthProvider、旧同步以及空权益 Provider，必须一并补齐，不能只发布下载入口。
- 商户证书与私钥匹配；微信支付公钥可解析，APIv3 密钥用户已设置。需进一步验证正式部署与接口。

遇到外部人工验证时继续其他工作，不绕过验证，不伪造验收结果。

## APK 存储发布

正式 APK 使用现有 Supabase Storage 的独立公开 bucket `app-releases`，路径包含版本和 build number，不覆盖旧包；不新增可写匿名策略。仅接受 Android APK MIME，bucket 上限 512 MiB。既有私有 bucket 的 50 MiB / 8 MiB / 5 MiB / 10 MiB 限制保留。

若正式包超过原全局 50 MiB 限制，使用 `infra/supabase/docker-compose.app-releases.yml` 作为现有生产 Compose 的附加覆盖文件，只重建 storage 服务；先备份并核对原 Compose 文件，不覆盖生产的其他配置。上线后验证公开下载、文件大小和 SHA-256，并验证现有私有资源仍需授权。

依据：https://supabase.com/docs/guides/self-hosting/storage/config 与 https://supabase.com/docs/guides/storage/uploads/file-limits 。
