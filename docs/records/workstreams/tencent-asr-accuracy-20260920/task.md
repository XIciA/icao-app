## 航空写法层边界

- 用户最新要求：尽量保守，只做高确定性的等价写法规范化；不确定就保留原文，不为提高参考匹配率扩大替换。
- 保留 rawTranscript；另外输出 formattedTranscript 与命中规则/版本。脚本只接收转写内容，不依赖题号、参考答案或最相似题目。
- 可纳入规则的示例：上下文明确的 `flight level 310 → FL310`、明确拼读的 `Q N H → QNH`。每条规则须有明确触发边界、正例与不应替换的反例；不把示例当作无限制的字符串全局替换。
- 用户口述示例出现 `flight label`：当前采用保守解释，只有明确的 `flight level` 才可规范成 FL；`flight label → flight level/FL` 涉及猜测听辨错误，不纳入自动改写。`will go → wilco`、`enable → unable`、全局 `tree → 3` 同样禁止。
- 数字、频率、跑道、导航点的规则必须保持数值、前导零、左右方向与语义；仅凭航空语境不足以补数字、猜导航点或补词。有歧义不转换；用户说错、漏说和语法错误照实保留。
- 当前格式候选v2只是实验资产，不能视为已满足最新保守边界；接入前逐条审查并收窄不合格规则。后续语法建议独立展示，不覆盖原始转写。
