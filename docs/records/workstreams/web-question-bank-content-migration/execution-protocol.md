# Web 三类题库迁移专用小流程

状态：已授权，已完成

更新时间：2026-07-15

## 1. 目的

本文件只补充本任务的长时间执行和恢复规则。通用执行循环仍以 `docs/tools/workflows/orchestration-loop.md` 为准；本文件不改变已经确认的需求、技术方案和路线图。

## 2. 输入冻结

- 输入固定为 `/Users/zhouyide/Desktop/web题库/` 当前批次的 `banks/`、`quarantine/`、`resources/audio/`、`manifests/units/` 和 `manifests/extraction-state.json`。
- 开始处理前建立仓库外或 `.generated` 下的只读快照，不向 Git 提交约 465 MB 音频副本。
- 对每个文件记录相对路径、字节数、修改时间和 SHA-256；对排序后的清单计算根 checksum。该根 checksum 即只读快照的内容归档 checksum，不额外生成 465 MB 的单体压缩归档。
- 后续所有批次只读取冻结快照。桌面源目录发生变化不影响当前批次，也不得静默混入。

## 3. 连续批处理

- 总候选固定为 2288 条：听力 777、陆空通话 1367、故事复诵 144。
- 不做试审，不设置等待用户确认的中间停点。
- 固定每 225 条为一个可恢复检查点；2288 条候选为 10 个完整检查点和最后 38 条尾批。每批保存输入范围、规则版本、候选结果、校验状态和输出 checksum。
- 每批完成结构、字段、事实签名和样本检查后自动进入下一批。发现系统性问题时只重跑受影响批次，不丢弃已通过批次。
- 临时候选、批次缓存和中间翻译写入 `.generated/web-question-bank-content-migration/`，不得边处理边修改正式题库。

## 4. 去重与关键事实保护

- 每题生成仅用于比较的规范文本、题型专属字段相似度和关键事实签名。
- 关键事实覆盖呼号、所有数字、跑道及 `L/R/C` 后缀、高度、航向、频率、单位，并额外保护 `left/right`、`climb/descend`、`cleared/cancel/hold`、`affirm/negative/unable` 等高影响词。
- 事实等价只允许确定性书面转换，例如 `Qantas 4 3 2 = QFA 432`、`runway zero three right = Runway 03R`；不跨单位换算。
- 关键事实不同或无法可靠解析时，不得仅凭文本相似自动排除。
- 不使用模糊相似关系做传递删除；每个排除候选都必须独立匹配一个最终保留代表题。

## 5. 决定状态

- `migrate-unique`：明确新增，迁移。
- `borderline-kept`：相似度处于不好判断区间，保守迁移并进入最终人工审核。
- `exclude-exact`：确定完全重复。
- `exclude-high-confidence`：在关键事实一致前提下满足题型专属严格门槛的高相似重复。
- `exclude-invalid`：客观缺少必要字段、音频损坏或音频缺失。

上述状态均不形成中间人工停点。只有需要改变需求、数据结构、生产架构或发生无法安全回滚的风险时，才按通用小流程暂停。

## 6. 听力分类

- 先去除问题段，仅用音频正文判断性质。
- 飞行员与管制员往返，或明确的标准陆空通话片段，归“陆空通话”。
- 单人陈述、技术说明、事故叙述、新闻、广播，以及飞行员与机务、签派、地服或乘务的普通对话，归“航空英语”。
- 呼号、角色标签和航空术语只能作为线索，Stage 只保留为来源信息。
- 性质确定后再判断长短：约 18 秒以下优先 `10s`，约 20 秒以上优先 `20s`；18–20 秒标记 `duration-borderline`，使用 19 秒作为确定性兜底并保存实际时长，供最终人工审核。

## 7. 暂存、全局复检与正式写入

- 所有批次完成后，再对 Web 内部、跨批次、App 现有题库和准备迁移集合执行一次全局复检。
- 故事复诵在四个现有子库和 Web 内部全局去重；保留故事统一写入 `story-flight-basic`。
- 正式写入前生成完整映射：`Web 源 ID → App 新 ID → 目标目录 → App 音频路径`，同时记录源文件、音频 checksum、决定、相似对象、事实差异、快照根 checksum 和人工审核标记。
- 映射必须绑定最终去重 `ruleVersion` 与 checksum；最终排除项不得保留正式 App ID、目标目录或音频路径，最终保留项映射必须完整。
- 候选区按听力、陆空通话、故事复诵三库分别生成并验证；三库全部通过后，正式源、App 内嵌题库、资源清单和版本元数据作为一个可回滚原子写入统一落盘，避免产生半同步状态，最后再逐库复验。
- 任一步失败时恢复写入前快照，不让部分写入进入发布包。

## 8. 验证与发布

- 本次迁移工具负责新增 ID、动态数量、音频路径、源与内嵌同步、映射、冻结输入和幂等验证。
- 现有 `content:audio:verify` 固定了旧数量和 ID，只用于旧基线，不作为新增内容验收器。
- 本地依次运行迁移 `verify`、`pnpm content:build`、`pnpm content:check:full` 和 `pnpm check`。
- 发布包只包含实际变化的听力、陆空通话、故事复诵三库和必要新资源，不导入五库全量包。
- 新资源使用新发布版本命名空间下唯一的 `publicPath` 和 `objectKey`。
- ECS 导入前备份 PostgreSQL、校验备份可读、保存原三库活动版本并复算发布文件 checksum。
- 使用现有 `icao-api:phase2a` 镜像导入内容，不部署或重启 API 代码。
- 失败回滚时删除本次新版本行并重新激活原三库版本；数据库 dump 作为灾难恢复。
- 仓库最终编辑后刷新共享 `APP_DISPLAY_VERSION`，并在发布前审查 Git diff 与生成文件范围。

## 9. 最终人工审核

- 上线不等待逐题人工审核。
- 上线后集中提供固定路径的 `reports/migrate-review.json` 与 `reports/migrate-review.md`；记录规则版本和 checksum。
- 清单必须覆盖全部最终保留的 `borderline-kept`，并额外收录 `duration-borderline`、翻译或事实疑点、`source-section-incomplete`；按目录/题号展示新增题、最相似旧题、各字段相似度、关键事实差异、实际时长、音频路径和保留理由。
- 若人工审核决定删除某题，后续内容版本删除该题，不复用已经发布过的 App ID。
