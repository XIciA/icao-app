# 技术方案
选择：服务端与题库更新，保持现有App同步合同，不发新版App。

## 冻结去重清单
执行开始时从最新main维护源重算未经四舍五入的相似度，算法保持NFKC、casefold、非词字符规范化，SequenceMatcher(autojunk=False)，严格>0.92。冻结输入checksum、题目ID、题组、保留ID、原始分值及删除理由。预计107题；若真实数据变化导致范围明显变化，停止删除并说明差异。
每个被删题必须与其实际保留题直接超过阈值，不仅依赖A≈B≈C的传递关系。优先保留固定免费清单ID，再按内容完整性、音频可用性和稳定ID确定代表，完整保留代表题的原文、选项与答案，不拼接不同题目的字段。相似原文但不同考法亦按用户确认范围去重；答案冲突题不凭相似度改写正确答案。执行时固定清单，重复运行不继续扩张范围。
退役ID不重编号、不复用。在现有内容维护/发布体系中携带唯一版本化退役清单，API及运维清理工具共用，不建立平行题库或客户端数据所有者。

## 数据和同步
1. 生产执行前在受保护位置保存相关内容版本、部署产物及受影响数据的最小必要备份；不把用户原文、密钥或备份放入Git/聊天。先dry-run统计影响账号数、状态条数、标注条数、历史条数，逐条限定在冻结清单内。
2. 服务端先部署拦截逻辑：card_state写入退役ID时返回高于请求/已有版本的权威空状态（visited/completed=false，清除作答、笔记、标记等）；不要走“完成状态只前进”的普通合并。收到旧annotations或混合历史时先清理再合并，响应现有客户端支持的权威payload并正常消耗outbox，避免401/404或无限重试。
3. 清理user_card_states中退役题有效负载；使用兼容旧协议的最小空状态/删除控制信息，保留防止复活所需版本信息。annotations仅移除相关entries，不删除全局定义。
4. 普通练习：依据bank/topic/cardId定位快照items，移除对应states/answers及关联AI详情，重算可确定的题数、完成数、正确数等摘要；保留未关联删除题的有效部分。原会话总时长不伪造分摊。若快照缺失、无法准确分离，按已确认删除范围采取保守处理并记录数量，不批量删除无证据关联的历史。
5. 受影响模考及无有效题目的历史：写现有删除标记，删除详情及直接关联记录；保留其他会话。
6. 清理sync_changes、sync_mutations回执内旧负载，追加版本更高的空状态、清理后文档/历史或删除事件。pull路径和mutation幂等回放均应用退役清单，旧客户端更高版本写入也不能恢复被删数据。不得提升全账号learningDataGeneration来清空无关离线学习成果。
7. 分账号事务、沿用现有锁和写队列，支持分批、断点恢复、幂等重跑；上线切换期间并发写入必须继续过滤。

## 内容发布与媒体
从维护源删除冻结ID，通过既有content构建更新总量、分类/题组数量、索引、scope清单、公开目录、checksum和发布版本。保护既有40个免费题ID及会员访问边界。先清理用户数据及发布兼容API，再切换题库版本；验证旧目录请求的现有版本处理路径，不删除旧请求仍需访问的资源以免出现播放404。
媒体二进制不做本次物理删除，只从当前引用/授权清单退出无引用项；共享资源继续保留。历史Vercel快照冻结。
正式生产产物必须来自合入origin/main的干净提交；更新题库发布版本及必要产品内容版本，不递增安装包build或触发原生构建。无需改变EdgeOne前端代码；若现有内容分发需要更新其内容镜像，限制为同一正式题库产物，不扩大为网页改版。

## 回滚与限制
异常时停止分批作业，恢复验证过的API/题库产物，保留退役拦截以免旧数据复活。用户记录不因代码回滚自动重导入；必要的数据恢复仅限本次错误清理范围并经过核实。
现有协议保留本机空状态条目，无法触达未登录或离线副本；用户已接受。不能承诺发布瞬间所有设备都清理完成。生产数据清理前需确认线上App兼容现有合同，失败不强行上线、不自动新增App更新范围。
