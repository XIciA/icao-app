# RN 与 Web 手机端 1:1 对照复刻技术方案

状态：已确认，进入小流程执行
更新时间：2026-07-11  
前置文档：`requirements.md`

## 1. 方案结论

采用“冻结 Web 基线 → 建立页面状态清单 → 采用既有 Web 金标准 → 校准 RN 原子组件 → 按用户流程逐状态复刻 → 截图并列与操作轨迹双验收”的路线。

Web 代码只用于定位状态、数据、交互与精确样式依据；RN 保持 Expo Router、React Native 原生组件、原生音频/录音与本地数据边界。视觉复刻不改变客户端技术路线，不引入 WebView，不让业务页面直接依赖浏览器实现。

## 3. 状态模型

### 3.1 最小验收单位

每个对照项使用稳定 `stateId`，推荐格式：

```text
<page-family>.<screen>.<state>
```

示例：

```text
home.default
home.course-picker.open
study.choice.unanswered
study.choice.answer-card-open
study.speaking.recording
account.settings.logout-dialog
state.network.offline
```

同一路由出现不同可见结果时，必须拆为不同状态，不得用一张“页面截图”概括整个流程。

### 3.2 Manifest 字段

每条状态至少保存：

- `stateId`、页面族、优先级、状态说明；
- Web 提交、入口预览路由、iframe 路径、375 × 812 视口；
- 前置数据、浏览器本地状态、操作步骤、滚动位置；
- Web 截图、RN iOS 截图和差异图路径；
- RN 路由及相关组件；
- 视觉结果、交互结果、返回结果、恢复结果；
- `aligned`、`native-exception`、`baseline-pending`、`needs-fix` 四类结论。

Manifest 只保存确定、可重放的数据；一次性坐标或依赖当前窗口位置的操作不得作为长期标准。

## 4. Web 基线使用方案

### 4.1 冻结与启动

采集前记录：

- 设计稿 Git 提交、分支、工作树状态；
- Node、pnpm、Next.js 版本；
- 题库与关键资源数据散列；
- 采集日期、基准视口和浏览器环境。

使用设计稿已锁定的依赖运行本地 Next.js。默认入口包括 `/`、`/auth`、`/account`、`/info`、`/state`。`/curriculum` 是桌面营销页，明确排除。

### 4.2 截图库

Web 金标准直接使用 `docs/records/evidence/ui-screenshots/2026-07-11/`。这些图片已经按 `?embed=1&capture=1` 生成 375 × 812 App 内容画布，不包含 PhoneFrame 外壳。

采集规则：

- 不重复生成或复制 Web 截图；
- RN 对照图直接引用相同页面族和状态文件名；
- 交互含义不明确时只读检查 Web 代码与原始截图清单；
- 现有图片缺口进入矩阵，不阻塞已覆盖页面的 RN 对齐。

### 4.3 状态发现

先从 Web 代码生成候选清单，再用真实页面逐项验证：

1. 路由和 AppShell 入口；
2. Flow 中的联合类型、`useState` 与条件渲染；
3. 用户可点击控件、表单校验、弹层和返回路径；
4. 数据驱动的题库交互差异；
5. 加载、失败、空、权限与 mock 状态。

代码扫描只负责理解候选状态与交互；视觉标准以现有截图文件为准。

## 5. RN 复刻方案

### 5.1 保留边界

继续保留：

- React Native + Expo + TypeScript；
- Expo Router 原生导航；
- 现有 repository、resource resolver、learning store 边界；
- Expo 原生音频、录音、权限、SQLite 与 Development Build；
- iOS / Android 的原生安全区、键盘和系统返回能力。

允许调整：

- `src/theme/` 的视觉令牌与字体映射；
- `src/components/ui/`、`navigation/`、`states/` 的共享组件；
- 各 feature 的视图结构、样式、局部状态与导航编排；
- 为稳定截图和交互验证增加的开发期测试入口、fixture 或脚本。

### 5.2 对齐顺序

先校准共享原子件，再修改页面：

1. 画布、背景、字体与安全区；
2. 顶部栏、悬浮底部导航、页面滚动容器；
3. 卡片、列表行、按钮、标签、输入与状态文案；
4. Bottom Sheet、Dialog、Popover、遮罩和固定底部操作区；
5. 音频、录音、题库工具条等领域组件；
6. 页面族和完整操作轨迹。

页面不复制 Web DOM 层级。实现目标是相同的布局结果、信息层级与状态转换。

### 5.3 状态可重复性

截图和交互验收不能依赖随机数据或人工提前操作。执行阶段应为开发/测试环境建立受控入口，使 RN 能稳定进入指定：

- 登录/未登录演示状态；
- 题库、卡片与学习进度样本；
- 播放、录音前后、保存失败等可见状态；
- 空、错误、权限和维护状态。

这些入口不得进入生产用户路径，不得绕过真实生产安全边界。

### 5.4 简单逻辑修复与复杂功能占位

页面对齐时同步检查当前 RN 的入口、按钮、状态切换、关闭、返回和恢复逻辑。能在当前页面范围内确定、修复和验证的简单错误，直接纳入同一个小闭环，不单独扩大为新功能阶段。

AI、云同步、支付、会员等复杂能力不接真实服务，但采用“完整 UI + 稳定示例状态 + 可替换数据边界”的承载方式：

- 按 Web 基线保留入口、流程、加载、成功、失败和返回 UI；
- 示例数据固定、可重放，并明确显示为演示或待接入；
- 页面只依赖本地 mock/adapter 接口，不直接依赖未来供应商 SDK；
- 后续接入真实能力时替换数据和动作实现，不重做页面结构；
- 不用一个通用占位页替代 Web 已经设计出的复杂功能页面。

如果 Web 本身出现明显矛盾，设计稿仓库仍保持只读；该状态进入 `baseline-pending`，记录相邻页面、代码意图和建议结果，在大流程确认后再确定验收标准。

## 6. 视觉比对方案

### 6.1 比对层次

每个状态依次检查：

1. **结构完整性**：元素、文案、图标和层级不得缺失或新增；
2. **几何对齐**：关键边界、留白、卡片、导航、弹层和滚动位置对齐；
3. **视觉令牌**：颜色、字体角色、字号、行高、字重、圆角、边框、阴影和透明度对齐；
4. **内容表现**：换行、截断、图片裁切、数字与状态提示对齐；
5. **动态结果**：按压、打开、关闭、切换、失败和返回后的画面对齐。

### 6.2 截图处理

- Web 金标准保留 375 × 812 原始 PNG；
- RN 基准优先使用 375 逻辑宽度环境，并统一裁出 App 内容区；
- 当前 iOS 26.3 只有 402 宽的已创建设备，执行阶段可创建系统支持的 iPhone 11 Pro（375 × 812）模拟器作为几何对照设备；
- 本 workstream 不启动或使用 Android 模拟器；多宽度视觉检查在 Web 与 iOS 可用画布完成；
- 差异图使用并列图和 50% 透明叠加图，必要时增加标注框；
- 不用跨浏览器/原生的原始像素相等作为单一门禁，因为字体栅格化和系统合成不同；任何肉眼可见、未记录的布局或视觉偏差仍视为失败。

### 6.3 关闭规则

以下任一情况不得标记 `aligned`：

- 缺少页面状态或交互步骤；
- 文案、图标、信息优先级或操作结果不同；
- 关键布局、换行、滚动、弹层或导航存在可见偏差；
- 仅有 RN 截图，没有对应 Web 标准；
- 仅通过构建或测试，没有真实渲染证据。

## 7. 交互验证方案

每个页面族建立操作轨迹，格式为：

```text
前置状态 -> 用户动作 -> 可见反馈 -> 状态结果 -> 返回/关闭 -> 恢复结果
```

操作轨迹必须同时验证 Web 与 RN。触控目标、系统返回和键盘采用原生等价方式；外部系统权限弹窗只验收弹窗前说明页、用户选择后的 App 状态与恢复路径。

高优先级轨迹至少包括：

- 题库首页 → 模块 → 目录 → 学习卡 → 音频/录音/作答 → 报告；
- 学习卡 → 标注/笔记 → 我的标注 → 原题回跳；
- 发现 → 单词/随身听/内容详情/模考；
- 我的 → 资料/设置/帮助/退出；
- 启动 → 登录/注册/找回/协议；
- 权限、无网络、失败、维护与重试。

## 8. 工程验证

每个 RN 小闭环至少运行：

- `pnpm check`；
- 与当前修改相关的路由/组件测试；
- 涉及 Expo 或原生能力时执行相关 Development Build 和模拟器/真机冒烟；
- Web 只读状态检查，确认没有文件变化；
- `git diff --check` 与目标文件 diff 审查。

正式引入或改变 Expo API 前，必须先读取 Expo SDK 55 对应版本文档。新增依赖只允许作为技术方案内必要的开发/测试依赖，并在实施前确认与当前 Expo/Node/pnpm 锁定版本兼容。

## 9. 未采用方案

| 方案 | 不采用原因 |
| --- | --- |
| WebView 包装 Web | 违反原生 App、Web 只读参考与架构边界 |
| 直接复制 JSX/Tailwind/CSS | Web 与 RN 布局、事件和平台能力模型不同，产生长期维护风险 |
| 只按路由截图 | 一个路由包含多个关键状态，无法覆盖弹层、校验、录音、失败和返回 |
| 只靠人工目测改页面 | 无稳定基线、不可复查，容易反复回归 |
| 只做全局像素差百分比 | 浏览器与原生字体/系统合成不同，会误报；仍需结构、操作轨迹和人工视觉门 |
| 先继续开发第二阶段功能 | 会扩大差异面并增加返工，当前应先关闭第一阶段视觉与交互差异 |
