# 单词学习功能与资源迁移技术方案

状态：已确认并授权连续执行

更新时间：2026-07-13

## 1. 方案结论

在现有 React Native 页面和账号体系内原生重建单词学习模块，只提取 `feizhuicu` 当前启用的 838 条词书资源与已验证行为。

词书作为独立、版本化、需登录访问的内容发布物由现有 TypeScript API 提供；App 使用远程 repository、ETag 和本地缓存读取。学习状态、收藏和最近测评结果复用现有 `document` 云同步能力，不新增数据库表。发音使用 Expo SDK 55 对应版本的 `expo-speech`。

## 2. 内容资源方案

- 建立单词内容工程，只保留 App 使用的稳定 ID、词书/等级、词或短语、释义、例句、译文和来源追溯信息。
- 将三本词书合并为一个带 schema、版本和 checksum 的发布物；导入与校验脚本负责数量、重复 ID、字段完整度和来源对账。
- API 提供受鉴权的单词内容端点和 ETag，不把 Web 运行代码或题库数据带入 App。
- App 优先读取远程版本，远程失败时使用最近一次有效缓存；无缓存时显示失败和重试，不承诺首次离线可用。
- 不迁移词汇测评插图、备份 JSON、例句替换稿、空音标和空音频字段。

## 3. 学习状态与同步方案

- 本地使用 Expo SQLite KV 保存一个版本化单词学习文档，包含稀疏的单词状态、收藏和最近一次测评结果。
- 每次状态变化先落本地，再进入现有同步 outbox；同步失败不阻断学习，恢复网络后自动重试。
- 服务端继续使用已有 `user_documents` 表和 `document` mutation，不新增 Migration。
- 单词文档按每个词条的 `updatedAt` 合并；最近测评按完成时间合并，显式重置也作为带新时间的状态更新，防止旧设备覆盖新数据。
- 首次登录的数据合并/归档、账号隔离、退出和注销清理沿用现有账号规则，并把单词文档纳入相同范围。

## 4. React Native 功能方案

- 保留现有 `/content/vocab` 入口和 `icao-app` 的 TopBar、Screen、Card、Button、字体与颜色令牌。
- 把当前单文件演示实现拆成独立的 repository、持久化、发音、测评引擎和原生页面组件。
- 学习队列支持多词书、筛选结果、再来一轮和错词复习；页面离开时停止正在播放的语音。
- 发音通过 `expo-speech` 使用英文语言、适合词与例句的语速，并用完成/失败回调串联“单词 → 例句”。
- iOS 静音模式可能导致系统语音无声；界面提供可重试反馈，不把发音失败变成学习阻塞。

## 5. 词汇测评方案

- 测评逻辑实现为可测试的纯函数：30 题、10 秒、校准/自适应/验证三阶段、弱/正常/强三种模式、同轮不重复。
- 题目来源只使用三本已迁移词书，预习/4级/5级分别映射到测评 3/4/5 级。
- 随机选择器可注入，使单元测试可以稳定覆盖难度升降、超时、纠错和结果分类。
- 最近一次结果进入单词学习文档并同步；结果页面明确“学习诊断，不是官方等级”。

## 6. 验证与部署

- 内容：校验 360 / 372 / 106、合计 838，必需文本字段完整且 ID 无重复。
- App：类型、Lint、单元测试、repository/cache、持久化、同步、学习与测评交互测试。
- API：类型、Lint、单元/集成测试、鉴权、ETag 和 838 条线上响应验证。
- 原生：安装 `expo-speech` 后执行 Prebuild/Development Build，并在 iOS 模拟器与可用物理 iPhone 验证朗读和核心流程。
- UI：真实渲染检查词书选择、列表、学习揭示、完成页、测评作答和结果页。
- API 改动使用明确文件集部署 ECS，保留源码和镜像回滚点，重启后验证 `/health/ready` 与代表性单词接口。

## 7. 不采用的方案

- 不把 `feizhuicu` 页面、组件、CSS、localStorage 或 Web Speech 代码翻译进 RN。
- 不把 838 条词书继续硬编码在页面组件中。
- 不只提供 App 内置数据而绕过当前登录和真实资源边界。
- 不为单词状态新建数据库表或迁移；现有版本化文档同步已足够承载本轮需求。
- 不新增真人音频、AI 音标生成、官方等级评分或完整离线下载。
