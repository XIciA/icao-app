# 执行路线与阶段验收

用户已授权整体流程和自主实现细节，2026-09-09开始。产品要求以README十五项及对应模块为准，当前执行状态见phase-log；本路线不是新增人工选稿/逐阶段审批门槛。

| 阶段 | 目标与主要产出 | 验证和进入后续标准 |
| --- | --- | --- |
| 0 基线与盘点 | 最新main任务分支、真实差异、冻结边界、统一合同设计 | 工作树及原修改保留；盘点定位到真实源文件；关键跨模块风险可落实 |
| 1 共同数据与账户 | 四目标/资料/入口；本次作答历史身份和删除同步；周额度规则/订单环境；反馈权限接口 | 聚焦状态/权限/删除/幂等测试；合同类型一致；不触碰Vercel。独立切片可并行，依赖方等合同稳定 |
| 2 用户主流程 | 普通/热点学习和历史回看，完整模考限制与收尾，购买解锁/额度卡，微信登录绑定 | 同题跨来源注释共享、独立答案；20题成绩；三档购买和恢复；权限/失败返回；真实既有视觉组件 |
| 3 内容与运营 | 兼容内容独立更新、反馈完整后台、AI规则表单、Android微信支付 | 发布与缓存版本校验；全文图片分页鉴权；规则生效和既购保护；支付验签/查单/取消/退款 |
| 4 联动审查与修复 | 十五项逐项证据、账号/环境/同步/到期/删除/导航、Logo统一 | 独立审查重点高风险链路；修复后受影响测试通过；保留App视觉；外部未验证不冒充通过 |
| 5 主线与交付 | 必要版本准备、PR/main、API/内容/ops配套发布、Release上传TestFlight | pnpm check:ci及本地pnpm check、冻结校验；干净HEAD=origin/main；签名/环境/包身份正确；Apple处理后用户可在TestFlight验收 |

每个实施切片先运行直接相关测试及类型检查，最终再汇总全项目必要门禁。React Native UI按真实页面或等价渲染核对；不默认增加模拟器/Development Build流程。生产动作先确认已具明确授权，准备具体迁移、发布范围及回滚；不得以计划文档自行扩张权限。

不提前进行：Vercel修改/构建/预览/发布；App Store上架；暂缓的全面其他功能重设计和销售材料专题。Android支付功能仍在范围内，其他平台正式分发安排仍暂缓。

完成判据：所有十五项有实现和相应检查证据，后台与配套服务真实可用，候选包上传并可交用户验收。候选包交付不冒充用户已验收；平台依赖未解决时如实保持未完成。
