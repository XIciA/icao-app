# 学习使用流｜最终产品方案

更新日期：2026-09-09。范围：普通题库学习、模拟考试、OPI 热点、学习记录及四者联动。

**功能决策已完成。本文件及所链接的四个模块共同组成最终方案。用户已停止继续制作与选择视觉参考稿，后续依据既有App组件和视觉MD实现；本次只整理文档，应用尚未按本方案实施或验收。**

## 1. 用户最终会怎样使用

用户登录后，按照自己的备考目标进入题库学习，也可以选择模拟考试或某一期 OPI 热点。题目始终来自同一题库，各入口只改变题目的组织方式和允许的操作。一次学习结束后自动形成一条记录，用户能够回看自己的那次回答、对应反馈及同题共享学习资料。

用户无需手动同步、命名题包或寻找不同的历史中心。历史恢复原题包与当时回答，直接使用普通学习功能；只浏览不新增记录，实际重新练习另存新记录，原作答与成绩不被覆盖。

## 3. 四个模块各自负责什么

| 模块 | 职责与最终效果 | 完整规则 |
| --- | --- | --- |
| 普通题库 | 题目统一来源；保持完整刷题体验，接入本次独立作答与结束保存 | [普通题库学习](modules/03-question-bank-learning.md) |
| 模拟考试 | 按考试类型及所选板块组卷，限制操作，听力20题提交后揭晓成绩 | [模拟考试](modules/03-mock-exam.md) |
| OPI 热点 | 按资讯期次组织固定同源题包，体验与普通 OPI 学习一致 | [OPI 热点](modules/03-opi-hotspots.md) |
| 学习记录 | 统一保存三种来源、列表、题包学习、删除和保留策略 | [学习记录](modules/03-practice-and-history.md) |

共同的数据归属、保存和权限语义只在学习记录 HIS-01—18 详细定义。考试特有限制只在模拟考试文档定义；热点和普通题库引用共同规则。此总览负责展示关系，不建立另一套决定。

## 4. 同一道题的三种操作模式

| 操作 | 普通学习／OPI 热点 | 模拟考试 | 历史回看 |
| --- | --- | --- | --- |
| 题目显示 | 现有完整学习页面 | 同一页面的收起状态，仅保留必要题目及作答内容 | 同一普通学习页面，恢复原回答，可重新作答 |
| 参考答案与解析 | 可按现有方式查看 | 作答阶段不显示、不允许展开 | 有权限时可查看 |
| 选择／文字回答 | 沿用题型现有能力 | 顺序作答，当前提交前可更正；未答也能前进 | 仅查看该次回答 |
| 录音 | 沿用现有学习能力 | 当前题可重录，不可回听；前进后锁定 | 不录音，不回放个人历史录音 |
| 原题音频 | 沿用现有题型播放操作 | 新题自动播，禁止主动重播、暂停、拖动及倍速；来电例外见模考规则 | 有权限且资源可用时可听 |
| 前后翻题／目录 | 沿用现有学习导航 | 只能顺序前进，不能回前题或任意跳题 | 可翻题及目录选题 |
| AI 辅助 | 可按现有权益使用 | 不提供 AI 辅助或即时 AI 评判 | 可查看原反馈、主动调用AI，遵循原权限与额度 |
| 笔记／标签／标注／查词等工具 | 保留该题型已有完整能力 | 隐藏学习辅助入口 | 与普通题库一样查看、编辑同题共享资料 |
| 学习记录 | 保存本次实际学习范围 | 保存本场所选试卷与实际作答状态 | 只浏览不新增；实际重新练习另存新记录 |

不适用的操作隐藏，不堆置灰按钮；实际需要等待输入的按钮禁用属于必要状态，例如未选择考试板块时不能开始。复用页面不等于保留所有交互，按钮、手势及自动行为都要遵守当前模式。

## 5. 同题共享与每次作答独立

用一道 OPI 题说明最终效果：

1. 用户在普通题库给它写下笔记和标签，并完成一次回答及 AI 分析。
2. 在某期热点再次遇见它，仍读取同一份笔记和标签；本次回答不会覆盖上次回答。
3. 模考抽到它时，仍是同一道题，但隐藏笔记、答案和 AI 工具，旧回答不能被当成本场已作答。
4. 从模考历史回看，可以看到本场回答与当前共享笔记；之前普通学习的 AI 反馈不得冒充本场考试评价。回看普通学习那条记录，仍能看到那次回答与对应反馈。
5. 后来修改共享笔记，各历史入口显示最新笔记；历史作答和成绩保持原样。若题面或选项更新，历史仍要与当时回答正确对应。

2026-09-10用户已取消“只读打印纸”：历史入口直接使用普通学习页；原记录保持不变，新练习与AI归新场次，笔记标签继续同题共享。详见学习记录 HIS-12—15。

## 6. 入口与页面保持精简

- 历史管理统一从“我的 → 学习记录”进入。结束状态的“查看本次记录”只是当前结果的直接回看，不新增另一处管理中心。
- 普通题库、热点及考试使用同一题目展示能力；记录列表点击后直接回看，不加独立题包概览。
- 模考听力成绩页不插入逐题解析；只选听力时它同时作为结束页，不叠加另一页。
- 结束页只保留来源、状态、作答数量、用时、已有听力成绩及必要的查看／返回入口，不加总评、排名、分享或导出。
- 历史列表不增加搜索、筛选、统计卡片、批量工具栏、手动同步或手动刷新；读取失败仍有必要重试。
- 热点详情简短显示期次、话题及题量，统一开始本期学习，不建设每话题单独历史。

## 7. 保留、权限与异常边界

历史永久保留、不设数量上限、不自动过期；用户删除、清空学习数据、注销账号仍按各自范围生效。不保存个人历史录音、不为历史自动转写，不复制整套音频资源。会员到期仍可看自己的回答、笔记及已有 AI 反馈，付费题面、参考答案和原题音频依当前会员权限开放。完整定义见 HIS-03—07、HIS-11、HIS-16—17。

优先把正常学习、考试和保存做完整。中断、重试等少见情况复用现有能力，必要时以准确提示、继续未答或结束保存处理；不扩建复杂版本管理、编辑历史或无损恢复系统。保留可靠内容、不串账号和回答、不虚报成功是基本要求。

## 8. 必须通过的跨模块验收

以下为将来的验收场景，不是已通过结果。各模块自身验收仍需同时满足。

| 场景 | 应达到的结果 | 规则位置 |
| --- | --- | --- |
| 普通学习后结束 | 一次形成一条记录，范围只含本次实际学过的题 | 普通题库；HIS-01、09 |
| 同题出现在普通题库和热点 | 身份不分裂，共享资料一致，本次回答各自独立 | HOT-01—04；HIS-12—15 |
| 有旧回答的题进入新考试 | 不能带入旧作答状态，不能展开答案或调用AI | 模考操作；HIS-13 |
| 听力20题包含未答 | 提交后计分，未答不得分，不返回改答案 | 模考计分 |
| 听力未完成即提前结束 | 显示未完成及已答数量，不给完整成绩或等级 | 模考提前结束 |
| 听力完成后继续其他模块 | 同一场记录，后来提前结束不抹去已获听力成绩 | 模考页面收尾 |
| 仅听力／无听力／全取消 | 成绩与按钮符合所选范围，全取消不能开始 | 模考页面收尾 |
| 来电、重录、未答前进 | 按已定播放与录音限制执行，不借恢复绕过考试约束 | 模考恢复边界 |
| 两个入口查看历史并返回 | 列表返回原位置；结束状态返回结束状态，不重开考试 | HIS-18 |
| 修改笔记后查看旧记录 | 共享笔记更新，旧回答与对应AI不变；回看不写数据 | HIS-12—15 |
| 会员到期再续费 | 自己的内容始终可看，付费内容随权限变化，记录不丢失 | HIS-17 |
| 删除、重启、换账号、自动同步 | 不串账号、不重复记录、不复活已删除记录；不静默截断历史 | HIS-07、11、16 |
| AI稍后返回或保存失败 | 反馈仍归正确回答，失败如实提示；不串入下一场或伪报成功 | HIS-13—14；审查证据 |

## 9. 视觉实施边界与本轮不做的内容

视觉稿及后续代码实现均严格遵循 [共同原则中的视觉延续要求](requirements.md)。用户认可现有App及视觉规范，整体风格保持简洁、高端、大气；本轮只按新功能调整内容、布局和必要状态，不做大规模风格调整。设计与实施前同时核对视觉MD、当前真实页面、主题及组件；生成参考图不能替代这些基线。

功能不再待决，也不再要求继续逐张选稿。Asset页面稿仅参考排版、布局、信息层级和文字内容，颜色、字体及其他视觉元素直接沿用现有组件、主题和视觉MD；未选或被否定稿不得默认为实现目标。下表作为后续真实页面检查范围，不是新的选稿任务：

| 视觉对象 | 处理方式 |
| --- | --- |
| 学习记录列表 | 在现有学习记录视觉语言内适配新内容与布局，同时查看有记录和空状态；v1平面列表已否定，v2卡片稿未选定，已停止继续选稿 |
| 模考入口 | 现有页面适配目标、默认全选及自选状态 |
| 听力成绩／整场结束 | 确认必要信息层级和按钮，覆盖只听力和提前结束 |
| 题目考试态／历史态 | 用既有学习页做代表样例，确认隐藏操作、普通学习交互及付费内容受限状态，其余题型沿用规则 |
| OPI 热点列表／详情 | 沿用风格，确认简短期次信息和进入学习入口；不另设计刷题页 |

异常使用必要的现有页面状态或简短弹窗，不为每个少见错误单独设计页面。

本轮学习流不加入：历史录音云保存、报告导出、复杂统计、排名、自动总评、独立AI历史中心、另一套同步系统或全新题库学习视觉。内容独立更新已纳入本轮十五项中的第11项，详细定义见[07内容更新边界](modules/07-content-update-boundary.md)；该专题单独维护，并与题库、模考、热点及历史的题目身份、资源版本和会话保护联动实施，不是排除在本轮总任务之外。

## 10. 接下来如何落地

结合实际代码准备最短可行的实施与验收安排，不再以继续生成或逐张确认参考稿为前置条件。用户统一授权后按依赖推进：确保原题身份和本次作答关系正确，再打通普通学习与热点、考试限制与成绩、统一记录，最后验收整条用户流程。实现时按已确认布局内容复用现有App组件，并用真实页面核对视觉MD。此顺序是准备方向，不是本次代码执行授权。

代码现状和故障线索单独见 [四者联动决策审查](learning-flow-decision-audit.md)，不混入用户操作规则。热点不可用的根因仍待定位，不能以方案完成代替修复完成。后续讨论若改变已定效果，同步修改规则所属模块及受影响引用，不另造相互竞争的“最终版本”。
