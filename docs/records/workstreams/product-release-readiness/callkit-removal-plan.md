# CallKit 删除与普通音频中断方案

日期：2026-09-13。状态：用户已确定删除方向，本轮完善方案；未实施、未构建或发布。

## 目标及依据

用户要求直接删除 CallKit，不按国家、账号或审核环境动态隐藏。应用无通话业务，不再识别来电身份或为考试建立来电专用重播额度。普通学习与考试采用一致的基础中断处理，随身听仍支持后台音频。

2026-09-12 用户提供的 Apple 审核信针对 1.0.0（3519587）明确要求中国区不启用 CallKit，这是本项直接整改依据；[指南 5](https://developer.apple.com/app-store/review/guidelines/#legal)是一般地区合规原则，不冒称通用指南逐字列出了这封信的地区限制。

## 当前事实

- `modules/icao-audio-interruption/ios/IcaoAudioInterruptionModule.swift` 导入 CallKit、创建 CXCallObserver，并结合 AVAudioSession 中断发送 isCall。
- 对应 podspec 链接 CallKit；`src/features/question-bank/components/ExamQuestionAudio.native.tsx` 使用来电状态决定是否允许重播一次。
- 删除 import 一行不足以解决：必须同步清理观察器、桥接类型、考试分支、依赖声明及最终构建产物。

## 用户体验决策

| 场景 | 最终行为 |
| --- | --- |
| 正常考试音频 | 新题自动播放；其余既定考试规则继续保留，不因本项全面开放暂停、拖动、倍速或返回上一题 |
| 实际音频中断 | 停止当前播放，不判断是否电话，不丢答案、不自动切下一题；恢复可操作后允许用户重播当前题 |
| 中断后重播 | 不计来电次数、不保留“来电只能一次”的专用额度。只有当前曲目实际中断才进入恢复状态，普通已播完曲目不因此解锁任意重播 |
| 切题/返回/主动停止 | 旧中断事件不能让旧题再次出声；用户的最新操作优先，不抢占正在进行的录音或其他音频 |
| 普通题库 | 保留现有播放操作；中断后可正常继续/重播，不新增一套来电页面 |
| 随身听 | 保留锁屏后台能力；中断结束按系统恢复条件及用户最新播放意图处理，用户已暂停则不自动恢复 |
| 耳机断开 | 不突然从扬声器恢复播放；与普通播放器的音频路由处理统一 |

本项覆盖旧方案的“来电专属一次重播”，不改变考试评分、作答记录、未作答可下一题等规则。共享的是播放器及中断职责，不是把普通学习的所有控件放进考试。

## 技术路线（待执行授权）

1. 盘点所有直接/间接 CallKit 引用、原生桥、测试和生成配置；删除 CXCallObserver/代理、isCall 及来电专用状态、额度和分支。
2. 复用播放器与音频会话已有的普通中断机制。确有必要时仅保留基于 AVAudioSession 的最小通用通知桥，不新增来电监听替代品；参照[Apple 音频中断文档](https://developer.apple.com/documentation/avfaudio/handling-audio-interruptions)。
3. 中断由唯一责任方处理；避免原生自动恢复与 React 回调重复播放。校验曲目、请求代次和用户播放意图；录音中断走现有录音结束/保存及重录逻辑，不损坏已有录音。
4. 清理 podspec 和可再生构建配置，按项目 CNG 流程重新生成；不得只手改生成文件。保留 AVFoundation、后台 audio 与随身听锁屏控制。
5. 聚焦测试后检查新归档的可执行文件、内嵌框架和依赖，不再链接/调用 CallKit 或保留活跃通话观察器；如发现第三方间接依赖，查明并处理，不能仅凭源码搜索宣称删除完成。

## 验收与审核材料

- [ ] 源码、podspec、原生桥类型与最终产物检查一致；没有用地区开关或审核特判隐藏功能。
- [ ] 普通题库与模拟考试的播放中断、恢复重播、切题、返回、主动暂停、录音互斥无卡死/串音；多次真实中断仍可恢复。

- [ ] UIBackgroundModes audio 保留；不新增 voip 或以录音权限换取后台播放。
- [ ] 新版本证据记录实际构建、源码和依赖检查结果；完成后才向审核员说明 CallKit 已移除，不能把当前方案当已修复事实。
