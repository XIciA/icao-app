# 07 内容独立更新与 App 发版边界

更新日期：2026-09-09。

## 目标与决策状态

用户已确认本文的目标分类：日常学习内容和兼容现有功能的后台更新不重新构建、发布手机 App；客户端功能、交互和原生能力变更通过正式 App 发版，iOS 经过苹果审核。

这是最终预期能力，不是全部已实现的声明。当前仅授权文档记录与只读评估，未修改应用或服务端代码，未发布内容、执行迁移、构建或部署。本任务不引入 JavaScript OTA 代码热更新，不通过远程页面定义或任意脚本改变应用功能。

## 用户核心体验

用户无需重新下载安装包，也无需点击手动同步，就可以在下一次正常进入相关内容时获取新题、新热点和新文章。“无感”不要求在线用户的当前页面瞬间切换，更不能打断录音、播放或正在进行的考试。

## 已确认分类：无需重新构建、发布 App

| 范围 | 可更新内容与边界 |
| --- | --- |
| 题库内容 | 在已有题型中新增、修改、下架题目，修改答案、解析、参考文本 |
| 题库分类与话题 | 在现有模块内调整分类、话题、排序与题目归属；不能因此引入客户端不认识的新模块或题型 |
| 题目资源 | 更新现有功能支持的音频、图片和学习素材 |
| OPI 热点 | 新增或下架期次，修改日期、考点、介绍与所引用题目；继续引用原题，不另造重复题库 |
| 资源分享 | 新增、修改、下架文章，修改封面、正文、排序；限已有文章展示能力 |
| 帮助中心 | 更新 Q&A 问题与回答 |
| 用户协议、隐私政策正文 | 更新文档版本；重要变化按需要提示及重新取得同意，不能用正文变更替代新数据处理能力的授权 |
| 已有 AI 功能的服务端优化 | 优化提示词、纠错、润色质量，保持接口与结果格式兼容；变更服务商或数据用途须另核对隐私、同意和客户端披露 |
| 后台维护 | 兼容现有客户端的接口修复、性能、稳定性及安全优化 |
| 用户数据 | 账号资料、笔记、标签、收藏、学习记录与权益状态自动同步；这是现有数据同步，不另建内容更新同步系统 |

无需 App 发版不代表无需内容审核、测试、后台发布或生产授权。Apple 现有商品调价可能无需新版 App，但仍通过 App Store Connect 管理；新增内购商品可能涉及单独审核。商业化决定以 02、04 为准，不归为任意可静默更改的普通内容。

## 已确认分类：重新构建、发布 App，iOS 经过审核

| 范围 | 变更举例 |
| --- | --- |
| 新功能、新模块、新题型 | 客户端尚不支持的展示或功能能力 |
| 页面与交互 | 页面、按钮、导航、动效、操作流程变更 |
| 登录与账号流程 | 登录、绑定、退出、注销的客户端行为变化 |
| 学习与模拟考试逻辑 | 作答限制、组卷规则、计分规则、成绩页行为变化 |
| 学习记录机制 | 保存、回看、删除或恢复逻辑变化 |
| 客户端故障修复 | 客户端页面崩溃、按钮、播放、录音、缓存等问题修复 |
| 支付功能 | 新支付方式、购买或恢复购买客户端流程变化 |
| 原生能力 | SDK、系统权限、录音、后台播放等原生能力变化 |
| 应用身份及内置资源 | 当前未内置的桌面图标、启动资源、原生配置等变化 |
| 数据处理能力 | 增加数据收集、上传或需要新增授权的功能 |

## 实施保护边界与验收建议

以下是支撑已确认效果的实施及验收建议，具体技术方案在统一实施前确定：

- 复用题库、文章、资源解析、账号与自动同步的既有唯一来源，不重写录音引擎或建立平行播放器。
- 内容发布携带版本，题目、音频和图片配套生效；媒体不能仅覆盖同一旧路径却继续复用旧缓存。
- 已开始的学习与考试固定本次题包和资源版本；新内容在下一次进入或新会话生效，避免录音中组件被卸载、播放中音源被替换。
- 内容身份与内容版本分开管理。分类迁移、题目改名或下架不能让笔记、标签、分次作答错误关联到另一题。
- 历史回看、同题当前资料和本次独立作答语义继续以 03 学习记录为准，付费题面及音频仍按既有权益策略判断；不因远程缓存或回退绕过权限。
- 异常网络或下载失败不应用半套内容；保留可用版本，发布错误可回退，旧客户端只接收能理解的内容格式。
- 不新增手动更新、同步按钮；必要的失败反馈复用现有异常入口。

核心验收：同一安装包完成题目修订、新增热点、发布文章后，用户再次进入能自动获得新内容；旧缓存不覆盖新媒体；正在录音或播放时发布内容不会中断本次操作；恢复会话、历史回看及同题笔记正常；网络失败、账号切换及会员变化不串数据、不绕过权益；新客户端能力通过 App 发版后再开放相应内容。

## 只读技术盘点与难度评估

依据：2026-09-09 本地 `icao-app-release-main` 源码。未核实当前已安装包与生产内容发布状态，未运行改造后的验证。总体判断为**中等规模、可分阶段的内容层改造**，不是替换 React Native/Expo 架构。以下复杂度为相对判断，不是工期承诺。

| 工作 | 当前依据 | 相对复杂度 |
| --- | --- | --- |
| 题库内容更新完善 | repository.native.ts 已远程读取目录、题组，支持校验和缓存 | 中：主要补齐版本一致性、旧客户端兼容、刷新与发布验收 |
| OPI 期次远程化 | hotspot/repository.ts 静态导入 opi-hotspots.json | 中：新增远程期次加载与发布，沿用题库学习能力 |
| 资源分享完善 | editorial/repository.ts 已远程加载列表正文封面，后台读取活动发布版本 | 小至中：补刷新时机及发布闭环验收 |
| Q&A 及协议远程化 | InfoScreen.tsx、legal-release-surface.ts 内置文案 | 小至中；协议还需版本、同意及离线回退衔接 |
| 媒体缓存与会话稳定 | member-content-cache.native.ts 按 publicPath 哈希定位文件，文件存在则不重下载 | 中、重点风险：须解决同路径内容更新旧文件仍命中的问题 |
| 历史及题目身份联动 | 内容会被题库、热点、模考、历史共同使用 | 中、重点风险：与已确认 03 方案一起设计，避免重复迁移或互相覆盖 |

录音控制器通过 RecordingEngine、sessionId/cardId 和统一音频会话管理；StudyAudioPlayer 接收 uri/playbackKey 并复用平台播放器。因此内容更新不要求重做录音或播放底层。但若刷新错误地改变当前题、播放器 key 或卸载录音组件，仍可能中断操作；不可承诺“完全不会影响”，必须以会话隔离和针对性回归证明。

建议顺序：先确定发布版本和会话不被中途替换的共同边界，再完善已有题库/文章链路，接入 OPI 期次，最后纳入 Q&A/协议。与 03 功能升级分别验收，同一来源与身份规则一次定义。无需新增可视化 CMS 或泛化远程 UI 引擎来满足首版目标。
