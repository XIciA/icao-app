# 08 意见反馈与题目纠错

更新日期：2026-09-09。决策状态：最终极简方案已确认。实施状态：已只读检查，未修改应用或后台功能、未部署及运行验收。

## 用户核心体验与流程

保留用户提供的现有视觉。用户可以可靠提交反馈，开发者有固定渠道完整查看；用户填写联系方式时，由开发者自行人工联系。不开发在线客服、自动回复或工单处理系统。用户进一步确认：反馈查看与 AI 额度调整整合为同一后台的两个业务入口，详见 [统一管理后台](../admin-console.md)。

```text
我的 → 意见反馈 ─────────┐
题目 → 纠错（自动关联题目）┼→ 同一个反馈表单 → 提交成功及反馈编号
                         └→ 失败保留内容，允许重试
提交成功 → 返回来源（原题或我的）
反馈进入既有运营后台 → 开发者查看全文、图片、联系方式及题目关联
                    → 如需联系，开发者自行使用对方提供的联系方式
```

“闭环”指提交确实收件、开发者能方便查看，并可人工联系；不承诺每条建议都会采纳，也不承诺未留联系方式的用户能收到个别回复。

## 已确认范围

### App 端

- 视觉沿用下方截图，不重新设计页面。我的中的意见反馈与题目纠错复用同一表单、同一提交与后台接收链路；题目纠错是带上下文的快捷入口，不是另建反馈系统。帮助中心仍只提供 Q&A。
- 保留三种类型：功能建议、内容纠错、其他。从我的进入默认功能建议；从题目进入默认内容纠错并关联当前题目。
- 描述按现有规则提交（去除空白后 5—500 字）；图片选填，最多 3 张、每张不超过 5 MB；联系方式选填。不强制用户留电话或邮箱。
- 自动携带必要的题目身份、来源与版本诊断信息，用户不用自行查编号；不额外上传用户录音、密码或完整私人学习资料。
- 图片可选择、移除；取消选择或拒绝相册权限不妨碍文字反馈。所选图片失败时不静默丢掉图片后声称完整提交成功。
- 提交中防重复点击；成功必须以服务端确认保存为准，返回反馈编号。失败保留当前文字、联系方式和图片供重试；同一次重试不重复生成反馈。
- 已输入内容时返回，沿用放弃确认，避免误丢草稿；不新增复杂的跨设备草稿同步。
- 成功后能返回原入口。从题目纠错进入，应回到原题并保留本次学习，不结束或重开题包；从我的进入返回我的。复用现有成功呈现，保留必要的功能反馈即可。

### 开发者查看渠道

- 优先完善既有运营后台中的反馈入口，与 AI 额度调整共用同一地址、同一登录并方便切换；后台只展示这两个业务功能，不新建独立后台，不要求日常手动查数据库。
- 最小能力：按时间查看反馈列表，打开后看到编号、提交时间、类型、完整描述、所附图片、选填联系方式、关联题目及必要的版本信息。
- 可复用已有账号关联与诊断信息，不将摘要当全文、不仅显示最近部分数据而让其余有效反馈无法查看。按现有有效保留期处理，不新增永久保留承诺。
- 图片与联系方式仅通过有权限的管理入口读取，不暴露公开图片地址。
- 交付时给用户一个明确、可登录的实际查看地址及简短进入方式；地址、管理访问和图片存储现状需实施时核实，不能把代码里的页面路径当成已上线渠道。
- 人工回复完全在后台系统之外完成：用户留邮箱、手机号或其他联系方式时，开发者自行联系。联系方式缺失、错误或无法联系，不妨碍接收反馈，不作送达承诺。

## 明确不做

- 不开发自动邮件、短信、微信回复或自动通知。
- 不开发 App 内消息中心、我的反馈历史、在线对话或回复进度页。
- 不开发待处理/处理中/已结案等可操作状态流转，不增加回复记录、联系记录、处理备注、分派、结案或统计系统。已有存储状态等必要内部字段可保留，不因此新增管理功能或做无关清理。
- 不要求本轮确定官方回复邮箱或通讯账号；因为无需接入发送功能，该信息不阻塞实现。
- 不改变已确认的模考限制，也不为本任务在所有页面增加纠错入口；只核对现有或已确认允许反馈的入口。

以上替代助手初稿中的三阶段处理状态、后台联系记录及结案建议。用户最终要求是“查看即可，人工联系”，不能在执行时按旧建议扩展功能。

后续最小验收：同一测试反馈从手机提交后，在实际管理入口可看到完整文字、全部所选图片和填写的联系方式；题目纠错能准确定位来源；没有联系方式也能成功；失败保留内容、重复重试不重复收件；成功及取消返回不丢原题学习状态。管理端仅有必要查看能力，不出现本轮明确排除的处理与回复系统。
