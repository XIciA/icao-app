正常卡片示例：`AI 每周使用限额`、`剩余84%`、剩余进度条、`重置时间：9月15日12:15`。样式沿用本 App 蓝白风格，不照搬截图横向桌面比例。加载或读取失败不得伪造0%或100%；会员到期、免费一次性体验按真实状态显示，不展示虚假的每周重置承诺。免费一次性体验已确认；补充边界建议另列，不混入已确认范围。

- 系统失败或未交付完整有效结果不扣额度；内部重试同一任务只结算一次。跨周任务归发起时预占的周期，不在新周重复扣减。断网/关闭页面的已完成任务仍按实际交付状态恢复，不能以关闭页面绕过计量。

## 内部规则初值（按用户授权采用，不在用户页面展示）

用户要求“先大概帮我写一个，然后就使用这个方案”，并明确以后能灵活调整总量和各功能消耗，无需重新发布 App。本轮采用：所有时长会员每周500内部单位，免费新账号一次性100单位；各功能消耗初值如下。内部单位只作计量，非用户购买或可兑换的货币。不是已实测成本结论，也不是当前生产已切换的配置。

| 能力 | 内部单位 |
| --- | ---: |
| 本地查词、录音、播放、查看已有结果 | 0 |
| 转写，单段不超过3分钟 | 5 |
| 语法纠错 | 3 |
| 表达优化 | 5 |
| 转写与纠错组合 | 8 |
| 转写与表达优化组合 | 10 |

500单位相当于每周50次完整转写与优化，或100次单独转写；这是预算说明，不作为前台固定次数承诺。上线前用真实音频和 Token 账单核对能否覆盖目标练习量。未来模拟考试不提前纳入已可用额度承诺。

- 每周额度500时，转写5单位约消耗1%，语法纠错3单位约消耗0.6%，表达优化5单位约消耗1%；这些换算仅供管理者理解，不展示给用户。
- 组合费用为总费用，不在已收取的单项费用之外再收一次组合费。仅查看已有结果不收费；用户主动对新内容发起新的处理才按对应能力计量，同一次请求的重试不重复扣。
- 初值适用于当前支持的单题音频和文本范围；不因采用固定费用就默许无限长录音或文本，现有输入限制继续保留。

- 用户额度账本、供应商成本账本分离；百分比来源于真实剩余额度。内部成本高预警不能在界面仍显示有余额时偷偷阻止正常调用；故障/风控使用真实原因。
- 可调整规则应显示生效时间和影响范围，并保留历史版本与恢复能力；具体发布选项见下节。调整不追溯重算已经完成或正在处理的请求，不暗中减少已购买承诺。
- 历史旧点数与新周期额度不是简单改名：前者长期累计，后者周期服务容量。执行前核查有无真实付费旧权益；用户此前允许清理测试旧数据，不用于推导可以抹掉真实付款、退款依据。新旧商品语义及说明需与 Apple 实际商品类型核对，避免把单独购买的可累计点数改为过期额度。

## 服务端调整总量与单次消耗（已确认，接入统一管理后台）

- 用户已确认：[统一管理后台](../admin-console.md)采用同一地址、同一登录，仅有反馈查看与 AI 额度调整两个业务入口。AI 页面仅管理总额度与各功能消耗规则，要求简洁、清晰；不新增用户管理、订单、数据看板或会员定价页面。此决定替代此前不做后台及只有一个业务入口的方案，不自行修改长期规则。
- 会员周总量、免费一次性体验总量及上表既有功能的消耗保留唯一的服务端配置来源，由这一后台管理。用户无需亲自修改 App 或操作数据库。普通用户 App 不出现管理项、内部单位或扣费明细；未来修改正式配置仍是需要明确授权的真实操作，设计确认不等于本轮已经发布配置。
- 调整数值无需改 App 代码、重新打包或商店审核；优先支持直接发布配置，不把数字写死在客户端。具体配置落点与操作方式在实施盘点时确定，不宣称目前已可热更新。新增此前没有的 AI 功能或新交互另行实现，不能靠配置自动产生。
- 服务端统一决定可用量与实际消耗，App 读取真实剩余百分比及重置时间，不在客户端写死500、100或功能消耗量。所有套餐继续共享同一规则，不增加按价格档区分周额度的选项。
- 免费体验总量变更默认只影响之后获得体验的新账号，不给已有账号重新发一份体验额度；历史已消耗记录保留。
- 已确认生效方式：增加额度或降低消耗可选择立即对后续请求生效；减少额度或提高消耗对后续新购生效，已有有效会员保留原承诺。支持指定生效时间、保留历史版本与恢复配置；随时调整不等于追溯修改已消费的用量。管理者通过统一后台的 AI 额度调整页完成这些操作。
- 立即提高总量时保留本周期已经消耗的内部单位，用新总量重新计算剩余量；不把已用量清零，不改变重置时间。规则恢复也不回滚已完成的消费记录；发布前展示预期影响。
- 一次已经开始的处理使用开始时的规则直至完成；修改规则后重试同一请求仍可恢复原结果，不因为价格改变重复扣费或报冲突。规则读取失败时使用已发布的有效规则，不伪造用户0%或100%。

现状只读证据：本机主干 `services/api/src/commerce/commerce-domain.ts` 的 `AI_POINT_COSTS` 为代码常量，正式持久化扣费在 `persistent-commerce-benefits.service.ts` 直接引用；新周额度和可视化动态规则管理本轮尚未实现。因此本轮确认的是后续建设目标，不能宣称现在已可在后台直接改数字。实施时扩展现有唯一计量来源，不再建另一套并行扣费系统。

### AI 规则页设计（操作细节已确认）

[AI 用量规则后台视觉稿 v1](../assets/02-membership-purchase/ai-usage-rules-admin-concept-v1.png)。沿用项目暖白、蓝色主按钮和清晰排版，桌面使用一个居中表单，顶部可切换反馈查看与 AI 额度调整，不增加多级侧栏或仪表盘。参考稿仅指导布局与内容，样式复用项目既有组件和视觉规范。仅授权管理员可使用；登录与退出为必要访问能力，复用现有身份和规则来源，不为此引入第二套运营系统。

1. **总额度**：并排输入会员每周500单位、新用户一次性100单位。不按7/31/93天分档设置。
2. **每次使用消耗**：五行可编辑数值，转写5、语法纠错3、表达优化5、转写与纠错8、转写与优化10。组合是完整总价，不和单项叠加扣费。新增页面不扩展实际 AI 功能范围。
3. **理解与预览**：旁边自动计算该功能占会员周额度的百分比；下方显示仅用于管理者参考的大致完整练习次数。修改周总量或消耗时同步更新。金额、成本、用户回答和录音不进入此页。
4. **生效方式**：系统根据变更判断增加/减少权益，按已确认原则显示影响范围。可立即生效的增加额度/降低消耗允许改为指定时间；减少额度/提高消耗保留已购承诺，对后续新购生效；免费体验修改只影响以后获得体验的账号。不让管理员手工判断或误选破坏旧权益的范围。混合变更的各项影响在预览中分别说明。
5. **保存流程**：读取当前有效规则 → 修改数值 → 预览并保存 → 弹窗列出旧值、新值、生效时间与影响范围 → 确认保存 → 留在原页短暂提示“已保存”。未修改时主按钮禁用；非法数值明确定位字段；保存失败保留输入，不能假报成功。可放弃未保存修改，离开有未保存内容的页面时提示。
6. **历史版本**：仅保留一个轻量入口，打开抽屉查看时间、操作者和变更数值。恢复旧配置仍需经过同一预览并作为新版本发布，不回滚已经发生的用户消耗，也不能绕过已购权益保护。无独立历史管理模块。

后台保存成功后应明确何时生效，App 在后续额度读取和请求中采用适用规则。后续验收包含数值换算、发布后的真实计量、重复保存/请求、历史恢复以及已购权益保护，不能只验证输入框能保存。
