## 判断边界

截图对应 Provider 的 PlaybackError 通用错误路径；无法从文案还原原生错误码、HTTP 状态或准确触发时间。未取得此次设备日志，未复现同一次故障，因此不将下列风险宣称为唯一已确认现场根因。当前代码事实也不替代对用户安装包来源的核对。

最吻合的方向是下一首资源的实际加载失败：原生队列已有下一首 URL，但 URL 入队不代表音频已下载完成。无间隔单曲循环采用 RepeatMode.Track，复用当前资源，绕过了换资源过程；因此单曲正常不能证明下一首资源链路可靠。缓存、网络、链接年龄和请求时序不同都能导致偶发，具体因素尚待原生错误证据。

| 高 | appendUpcoming、replaceWaitingUpcoming、replacePreparedUpcoming 的异步资源解析缺少统一 generation 校验/串行提交；prepareTrack 在部分 await 后也无失效检查 | 快速选题、改模式、停止或退出账号期间，旧请求存在追加旧曲目、覆盖新队列的执行路径风险；未证明已发生跨账号播放 |
| 中 | prepareTrack 初始下一首直接 chooseUpcoming，跨主题加载只在 appendUpcoming/手动 next 中处理 | 从主题最后一首起播时，可能预排到已加载目录的第一首，跳过尚未加载的下一主题 |
| 中 | chooseUpcoming 的随机选择不复用 nextManualTrack 的 shuffle 历史前进逻辑 | 随机模式返回上一首再点击下一首，可能与原生自动下一首选择不一致 |

| 中 | 播放间隔通过静音轨道及事件后 seek 实现，服务与 Provider 都可能处理间隔错误；多个 void Promise 无最终 catch | 需要验证间隔错误是否重复 skip、快速切歌后旧 seek/setRate 是否作用于新轨道，以及远程操作失败恢复 |
| 中 | 恢复进度时仅 findTrack(embeddedCatalogs)，远程补全曲目可能不在其中 | 已保存的某些会员曲目可能无法恢复到上次位置 |

## 已确认的产品原则

2026-09-13 三项联合复核：中断职责与[CallKit 删除方案](callkit-removal-plan.md)共同落实，联合审核核对见[整改总览](app-review-remediation-plan.md)。两项音频整改不分别建立恢复逻辑。

- 目标是可靠、易理解的连续播放体验，并为苹果后台音频审核提供真实可复现的功能与证据。优先消除软件自身造成的下载阻塞、操作相互干扰、状态错乱和无声停止；不能把内部错误一概归咎于用户网络。
- 用清晰、统一的结构解决整条播放链路，不针对每个现象无限叠加补丁。复用现有播放器、题库资源服务、音频会话与视觉组件，不重做随身听界面，不建立相互竞争的下载器、队列或错误恢复实现。
- 尽可能让短暂波动自动恢复；确实无法继续时，用户应能看懂当前状态和下一步操作。产品目标是尽量不出问题，不承诺外部网络永远正常，也不以一次成功或测试全绿宣称无 bug。

## 已确认的修复结构

| 职责 | 处理方案 | 必须守住的边界 |
| --- | --- | --- |
| 资源准备 | 复用资源服务，提前准备少量后续音频，优先完成受控本地缓存；当前请求优先，同资源请求去重，下载并发与缓存容量有上限 | 入队 URL 不算下载成功；核验文件完成及可用性，部分文件不作为成功缓存。慢速预取不能阻塞用户主动播放/切歌；停止或换曲后取消不再需要的工作，无法取消的结果也须失效 |
| 权限与有效期 | 加载前校验链接时效，确认签名失效后重新解析；可用缓存复用并遵守现有内容权限和账号边界 | 不无限延长签名，不绕过会员/离线授权，不把缓存变成新增永久离线下载产品；缓存按资源版本识别，退出账号按现有权限策略处理 |
| 播放队列 | 播放运行层统一维护连续播放，向原生播放器提供有界的已准备队列；页面负责展示状态和发送命令 | 不依赖页面临时状态补队列；自动/手动切歌共用选曲规则；清理已播轨道，长时间播放不无限增长 |
| 操作协调 | 队列变更串行提交，资源获取按有界并发执行；统一请求与账号代次检查 | 用户最后一次操作生效。停止、暂停、换曲、换账号后，旧请求/迟到错误不能重新启动或覆盖当前播放；网络恢复不能推翻用户主动暂停 |
| 错误恢复 | 对可恢复网络及资源链接错误有限重试，使用统一恢复入口；初始化失败可重新初始化 | 重试有次数与等待上限，具体值实施时按实测确定；权限拒绝、内容不存在等不盲目重试；失败不静默跳过当前学习内容 |
| 模式与进度 | 一并修复跨主题、随机历史、间隔切换、远程曲目进度恢复，统一锁屏和 App 内控制行为 | 不为修复改变既定顺序/单曲/随机产品含义；保留当前曲目与合理可恢复进度，恢复失败明确说明 |

## 用户可见状态与异常处理

复核补充：资源预取只占有界窗口并让位于当前播放；缓存空间不足时可清理可重建缓存或回退现有流式加载，不能为了下一首下载让当前音频不能启动。未就绪时显示加载状态，不能在音频实际未开始时假显示正在播放。网络恢复不得覆盖用户已暂停、切题或停止的意图。

后台仅用于真实听音会话；间隔静音不得无限循环用作保活。停止/退出后结束相关后台任务，不新增 voip 或后台录音。实现要验证系统对间隔及资源下载的实际限制，不能把 JavaScript 服务函数本身当作后台永不挂起的保证。耳机断开避免自动外放；中断恢复服从系统条件和用户意图。播放不请求麦克风权限。以上以[Apple 2.5.4 与 2.5.14](https://developer.apple.com/app-store/review/guidelines/#software-requirements)及本次实际审核反馈为核对依据。

不新增堆叠说明或技术错误弹窗；沿用现有页面，显示简短、真实的状态。以下为语义要求，文案可按现有视觉规范微调。

| 场景 | 用户应看到/得到的结果 |
| --- | --- |
| 正常播放、预取成功 | 自然连续播放；不显示无意义的下载提示 |
| 正在等待音频 | 显示“正在加载音频…”及加载状态；可返回、暂停或切换，不能无限转圈 |
| 可判断为网络中断 | 显示“网络连接中断，正在尝试恢复”；有限自动重试后提供重试与切换操作 |
| 加载较慢但无法判断原因 | 显示“音频加载较慢，请稍候”；等待达到上限后给出可操作提示，不能未经证据断言网络错误 |
| 链接失效 | 内部刷新并恢复，通常无需暴露签名等技术概念；失败后按真实原因提示 |
| 音频缺失/无法解码 | 明确“这条音频暂时无法播放”，提供重试或手动下一首；保留曲目，不静默跳过 |
| 权限或登录已失效 | 使用已有登录/权益提示和操作入口；不显示成网络故障或反复下载 |
| 无法分类的内部错误 | 明确“播放遇到问题，请重试”，记录脱敏诊断；不编造原因，不困在不可退出页面 |
| 锁屏后出错再回 App | 页面曲目、进度、播放/暂停/等待状态与实际播放器一致，能清楚看到原因类别及恢复操作 |

## 执行路线与完成标准（等待实施授权）

1. **诊断与结构盘点：**补足脱敏错误证据，核对真实候选代码；确认现有资源缓存可复用的入口，统一队列及恢复职责。不将推测直接当作现场根因。
2. **完成主链路修复：**资源准备、签名刷新、有界队列、操作失效与有限恢复一起形成闭环，再处理模式/进度等关联缺陷；代码审查关注是否引入第二个所有者、无限重试或新的竞态。
3. **聚焦回归与返修：**覆盖签名过期、慢下载、下一首失败、旧请求晚返回、连续操作、停止/退出账号、跨主题和恢复进度；失败则在上述结构内修正，避免针对测试增加旁路。
4. **真机候选验收：**按后续授权构建新版本，在真实 iPhone/iPad 测试顺序/单曲/随机、有无间隔、跨主题连续锁屏、暂停超过 5 分钟恢复、弱网与断网恢复、耳机/来电中断及前后台切换。对本次偶发场景重复验证；记录设备、系统、构建、场景、结果及剩余限制，不以单次成功收口。
5. **审核材料：**保留 `UIBackgroundModes audio`，录制真实设备随身听连续播放多首、返回主屏并锁屏后继续播放的过程；审核说明明确入口和步骤，在 App Review Information 中提供可访问的录屏及说明。不能用单曲循环录屏替代顺序切歌验收，不能把自动化测试当作后台播放证明。
