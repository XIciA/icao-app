# 统一实施方案

2026-09-10增补：本轮用户实测后的最新修正及验证边界见[十二项反馈修复](testflight-feedback-fixes.md)，相应旧描述以该增补为准。学习记录已改为普通可编辑题包，实际再练另存新记录；Logo内页必须显示圆角，准备学习空间不显示Logo。

2026-09-09：用户已明确授权按“基线→盘点→技术路线→实现/审查/验证循环→联动检查→TestFlight”连续执行，普通实现细节无需再次人工确认。本文件承接该授权，不改变[十五项产品定义](README.md)。生产部署/迁移仍遵守仓库的明确授权及main来源要求；不包含App Store正式上架。

## 唯一来源与模块衔接

1. **账户**继续使用AuthProvider、账户API、账号隔离存储和现有自动同步。四种目标统一为稳定值，资料、首页题库与模考默认共同读取；微信身份加入现有账户体系，禁止自动合并。
2. **学习**复用原题仓库与同一展示能力。原题身份和当前注释共享；会话ID/itemID保存本次作答与分析。普通学习/热点、考试、只读历史各有明确能力限制，在操作方法层也验证，不能只隐藏按钮。
3. **记录**继续用learning-record-storage与learning-sync；详情按需读取，无100条截断。保存必要题面、选项、答案和已产生文字，个人录音URI不写历史。不另建AI历史中心；内部关联AI可复用，但会话列表不混列。清AI/清学习/单删历史同时适配删除代际。
4. **商业化**继续订单、会员段、预占、账本和服务端内容授权。增加账号/环境周锚点与规则版本；订单保留承诺，请求固定费用及周归属；重复请求读取原预占。旧交易可恢复来源与当前三档销售目录分开。微信支付确认后进入同一订单体系。
5. **内容**在现有发布/缓存体系补兼容版本、固定题包及不可变资源。热点仍为原题引用，不与资讯文章混同；Q&A和法律文本采用固定结构正文，不引入CMS或远程UI。
6. **后台**沿用ops应用、同一登录、现有审计，仅反馈和AI额度两个业务入口。反馈图片通过授权私有读取；AI表单调用计量服务唯一规则源，不另算额度。
7. **视觉与导航**沿用主题、字体和组件；Asset只提供布局内容参考。用已有导航/弹层组织新流程，处理可预见失败出口；不建通用复杂恢复系统。

## 实施边界与并行

- Native变体承接正式App变化，保持Vercel冻结文件及行为。提取可复用小模块优先于复制整套业务；不引入WebView/第二技术栈。
- 主线程维护账户、主合同导出、模块注册、导航、Logo和发布整合；学习、商业化、反馈分别负责不重叠实现。跨边界接口先通知主线程；迁移编号统一预留。
- 分阶段做聚焦测试，遇新失败先定位再修改。不为重复报错盲目重跑，不把静态测试当真实平台验收。
- 不为旧测试数据增加大规模迁移；不擅自删除真实订单/权益/身份或生产数据。需要的迁移先本地可审查、演练，再按授权从main发布。
- 外部凭证只用既有安全位置，文档/日志不写值；阻塞的外部节点记状态并继续其他工作。

## 不采用

不另造同步系统、独立AI历史中心、热点学习器、后台账号系统或远程页面引擎；不整体换肤；不以减少十五项范围换取局部测试容易通过；不将依赖未就绪的假按钮作为完成。
