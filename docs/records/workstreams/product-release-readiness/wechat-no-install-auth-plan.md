## 用户规则

- 已安装微信：显示微信登录入口，点击调起微信客户端授权。
- 未安装微信：隐藏微信入口，不弹免安装授权窗口，不引导安装微信；手机号/密码和 Apple 登录保持可用。
- 登录页面首次进入，以及 App 从后台回到前台时，重新检测安装状态；安装、卸载微信后返回无需重启 App 即更新。
- 本轮沿用原方案 iOS/iPadOS 范围；不扩展 Android、Web、Vercel、微信支付或账号体系改造。

## 实现与体验边界

1. 复用现有 `wechat-native-auth.ts` / `IcaoWechatAuthModule.swift` 的安装状态查询，统一由现有认证层提供状态，不新增平行检测服务。
2. 首次检测未完成时不展示微信按钮，其他登录入口正常可用；结果返回后稳定更新布局，避免按钮先出现再消失、留下空占位或阻塞整个登录页。重新激活时重查，拒绝过期请求结果，避免闪烁和多重订阅。
3. 点击时再次校验安装状态，处理检测后微信被卸载的竞态；已卸载则更新入口并简短提示“微信未安装，请使用其他方式登录”，不进入旧的免安装流程。
4. 已安装但 SDK 不支持或配置异常，不误判为未安装；给出明确、可退出的失败提示并保留其他方式，不能空转或显示空白授权容器。正常取消直接回到可操作的登录页，不作为严重错误。
5. 前后台安装状态刷新不取消正在进行的有效微信授权；重复点击共用现有单次授权锁。保留 challenge/state 校验、超时、取消、迟到及冷启动回调保护。
6. 删除仅为免安装授权使用的窗口、控制器及兜底分支；使用现有 SDK 的客户端授权入口。清理不再适用的测试与说明，不能连带移除已安装微信登录所需的回调、Universal Link 或安全检查。
7. 保留服务端 code 交换、身份映射、注销后新建账号及 AI 体验防重复领取修复。不新增强制绑定，不自动合并 Apple/手机号和微信账号，不转移旧权益。

## 账号与审核说明边界

“仅绑定微信的账号在无微信设备上可能无法访问”是已说明的产品风险，不是审核信明确要求新增账号绑定的条款；本轮不因此扩大为绑定/合并工程。其他登录方式不保证进入同一微信账号。
重新送审如实说明：微信是可选登录方式，仅在已安装时提供；未安装设备可使用手机号/密码或 Apple 登录。不得沿用“支持微信免安装授权”或“使用 Safari View Controller”的旧回复。同类 App 的做法是参考，不是本 App 审核结果的保证；审核账号须有真实可用的独立登录路径。

## 验收与后续实施

- 有微信：入口显示，授权成功；取消/拒绝/超时后可重试，不能串号或重复建号。
- 无微信：首次进入及冷启动无微信入口、无闪现、无安装要求；其他登录方式可操作。
- 安装或卸载后返回：无需重启即更新；短时间反复前后台、迟到检测结果不覆盖最新状态。
- 授权过程中返回 App 不被状态刷新打断；检测后卸载、SDK 不支持、配置或查询失败均有合理处理。
- iPhone/iPad 布局无空位、遮挡；原注销、身份映射和 AI 防重复领取不回退。
