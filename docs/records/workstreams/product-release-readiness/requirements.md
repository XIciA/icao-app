# 整体目标与共同原则

更新日期：2026-09-09。性质：本轮用户确认的产品目标与讨论约定；不是新增长期规则。

## 目标

使“听你五个”成为真实用户可使用、可购买、可持续维护并具备正式交付条件的航空英语学习产品。先完成产品决策，再统一组织代码落地与验收。功能完整、逻辑一致、稳定健壮优先于追加局部补丁。

## 已确认的核心原则

| 编号 | 原则 | 对实现与验收的含义 |
| --- | --- | --- |
| P01 | 逻辑清晰且闭环 | 每项操作有明确入口、结果、取消、失败和返回路径；用户不会被困在页面或不确定下一步 |
| P02 | 简洁，只展示必要功能 | 不要求保留当前全部按钮；删除无必要、未形成实际价值的入口和展示项，不能保留假功能占位 |
| P03 | 管理入口归属明确 | 相应功能集中在固定位置，不在多个页面散落重复管理入口 |
| P04 | 复用同一页面和业务能力 | 必要的多场景访问复用同一目的页面与能力，不为相同功能建立平行实现 |
| P05 | 统一账户体系 | 登录、绑定、资料、会员、学习数据、退出与注销围绕同一账号协同；不得自动合并独立账号或串用数据 |
| P06 | 全局联动一致 | 资料与状态变化在相关页面正确反映；不得每个页面各有一份相互竞争的状态 |
| P07 | 减少阅读和操作负担 | 删除冗余小字、重复保存和“我知道了”；危险操作与真实限制仍须简短说明清楚 |
| P08 | 保持品牌与视觉连续 | 以现有App和视觉规范为基线，保持简洁、高端、大气；按新功能调整内容、布局及必要状态，不大幅调整整体风格。视觉稿与代码实现同样受此约束；品牌资产只按已确认的专项决定调整 |
| P09 | 自动化不伪造结果 | 学习数据自动同步，正常过程无感；失败不能假装成功，必要时提供简短可操作反馈 |
| P10 | 决策与实现分离 | 明确用户可见效果与验收，不提前指定具体技术；结合实际代码复用能力，避免堆叠补丁 |
| P11 | 有证据才算完成 | 用户报告、截图现象、代码静态能力、运行验证、平台状态分别标明；计划与历史测试不是当前交付证据 |
| P12 | 逐项讨论，统一推进 | 未定方向不擅自扩张；已明确的决定不在执行时反复询问；跨模块修改同步维护相关文档 |
| P13 | 核心流程优先，控制复杂度 | 少见异常尽量由现有主流程顺带处理，可用简单可靠的提示与退出路径，不为小概率事件增加大量代码、独立系统或页面；不牺牲账号隔离、作答归属和真实保存反馈 |

入口统一不等于同一份协议只能从一个地方阅读。登录与隐私页查看同一协议、不同场景进入同一身份验证能力属于必要复用；不能以此新增重复的账号管理入口。

## 视觉延续要求：设计稿、实现与验收共同适用

用户明确认可既有视觉设计文档和当前App的整体风格，认为已经基本满足“简洁、高端、大气”的要求。本轮工作是在该基础上适配新功能，不是整体视觉改版。

1. **先读规范，再看真实页面。** 制作视觉稿及后续实现前，读取 [UI风格与实现规范](../../../rules/ui-style-guide.md)，核对当前App对应页面、相邻页面、主题令牌和已有组件。实际页面用于理解现有视觉效果，规范及主题用于保持一致；不能只参考聊天生成图或旧截图就重画一套界面。
2. **保持既有视觉语言。** 延续品牌色、页面底色、字体角色、字号层级、圆角体系、卡片气质、图标、边框、阴影、留白及导航动效语义。不能为了某一页“更高级”另设整套风格，也不能把所有页面机械改成同一种平面列表或大卡片。
3. **允许按功能调整。** 内容、文案、信息分组、布局、按钮位置及必要状态可依据已确认需求调整；删除冗余入口和说明。使用现有视觉体系组织新内容，既不保留旧功能错误，也不扩大为全局换肤。
4. **Asset稿只作内容与布局参考。** 本专题assets中的页面设计稿主要用于排版、布局、信息层级及文字内容参考，不是颜色、字体、字号、圆角、阴影、图标或动效的取值来源。即使布局稿被选中，也不能按其像素取色、临摹字体或另造组件；直接复用现有App组件和主题令牌，并严格遵循视觉MD。稿中文字若与最新功能方案冲突，以最新决定为准；被否定或未选定的稿子不自动成为布局依据。用户另行明确确认的正式Logo等品牌素材按对应专项决定处理，不与页面参考稿混同。
5. **代码落地同样严格。** 实施时优先复用既有样式和组件，不逐页拼出相近但不同的配色、字体、圆角和间距。不得因功能可用而忽略视觉一致性；必要布局调整不等于授权修改全局主题。若确实必须改变已确认的整体风格，先说明具体影响，再由用户决定。
6. **验收检查真实效果。** 将修改后的页面与当前App代表页面并排比较，检查字体、卡片、留白、图标和导航是否协调，并覆盖长内容、空态、加载/错误及必要交互。不能仅以生成稿好看、代码编译通过或功能通畅宣称视觉完成。

上述为本专题用户要求的补充记录，承接已有长期视觉规则，不修改或新增 `docs/rules/` 下的规则。用户已停止本轮继续制作与选择视觉稿，转入其他任务；不再将逐张选稿作为继续推进的前置条件。学习记录v1已否定、v2未选定，后续生成的模考A/B稿因风格偏移不作为执行依据；这些状态不因停止选稿而变成已批准。实际实现以已确认功能布局要求、现有App组件和视觉MD为基础。

## 已确认：全局导航、返回与转场（总任务第15项）

用户已确认此项纳入本轮，由Codex自行检查相关页面的导航、动画、返回及异常退出，并按既有视觉规范与合理交互完善；不再要求用户逐页决定动效和返回细节。当前只记录决策，代码留统一执行。

- 检查正常前进、后退、Tab切换、弹层打开关闭的语义与方向是否一致；复用现有导航和动效，不为统一而强行使用同一种动画，不增加新的动效系统。
- 检查加载失败、无权限、内容不存在、空导航栈、深链接进入、重复跳转和异常页面等可预见状态。用户应能返回有效上一页、关闭弹层或回到有权限的稳定入口，不能只能反复重试或强制重启App。
- 有正常返回栈时优先原路返回；无有效上一页时提供合理的关闭或返回入口。不在每页重复堆放退出按钮；已有可用导航即复用。
- 首次强制登录失败仍留在登录范围内，保留重试和必要帮助，不通过异常出口绕过登录。会员限制也不得借退出路径绕过。
- 学习或考试中的退出接入已确认的结束、保存流程；模拟考试不得借返回手势、导航或异常恢复回到上一题改答。支付、录音、提交中的退出遵循各模块既有规则，不伪造完成或丢失已保存结果。
- 以主流程和可预见异常为重点，采取简单可靠的处理，不承诺所有未知故障均可恢复，不为小概率事件显著增加代码复杂性。
- 验收覆盖真实页面正常返回、弹层关闭、无返回栈和主要错误状态，确认不会困住用户、绕过权限或破坏作答归属；这是导航专项，不扩大为暂缓的其他功能完整体验重设计。

## 讨论与实现边界

- 当前已讨论账户、会员及学习使用流等模块；具体确认范围以各模块最新决定为准，尚未决定的内容不当作完整已批准方案。用户已授权统一实施，实际进度另记phase-log。
- 用户同意旧用户数据可以清除，不要求为本轮旧资料设计复杂兼容迁移。真正清除前必须明确环境、数据对象与范围，不把这句话扩大成生产订单、交易或未知数据的无差别删除授权。
- 删除导出等用户功能时，删除专用实现；共用读取、自动同步、系统备份等基础能力不因名称相关而误删。
- 参考主流学习软件的熟悉交互，不照搬其所有入口、社交功能或功能数量。强制登录、帮助与反馈分开等已经确认的自身选择可保留。
- 视觉效果不能仅用文字“高级、流畅”验收。当前不再继续生成参考稿；实施后用真实页面检查与原App的风格一致性，以及输入、键盘、返回和状态变化，不把生成稿确认当作必需门槛。

## 交付与安全边界的承接

本任务遵守仓库已有规则，不在这里另立技术规范：Native/Expo Web 的技术边界、pnpm、唯一状态来源、main 正式交付来源、生产部署与数据库迁移授权、Vercel 冻结、保留无关未提交改动、密钥不得进入记录等，执行时读取对应 docs/rules/。

账号、支付和删除数据等高风险实现需要独立审查具体权限、异常路径与回归证据。验证选择最短有效路径；同一失败没有新证据或修正不反复重跑，不用提交次数冒充进度。

## 总体验收目标

十五项已确认任务以整体完成为交付目标。正式实施后由Codex完成修改、必要验证、审查和修复，全部完成后提交TestFlight，用户最后打开App检查功能与视觉；不要求用户逐阶段参与测试。不能因最终使用TestFlight就缩减后台、内容更新或其他已确认功能，也不能用上传成功代替功能完成。具体交付与当前实施的授权边界见[总清单](README.md)。

1. 逐个检查本次保留的按钮：有真实作用、状态反馈与合理退出路径。
2. 删除清单内的入口不可见，明确要求删除的专用功能不再通过残留入口继续存在。
3. 正常使用无需理解会话存储、同步队列等内部概念。
4. 同一账号的资料、权益与学习状态一致；切换账号不会串数据。
5. 所有已确认需求可关联到验收场景；未完成和未验证项如实列出。
6. 新页面及调整后的页面保持当前App的整体视觉语言，变化主要服务新功能的内容、布局和状态；视觉稿与真实实现均按上述视觉延续要求检查。
