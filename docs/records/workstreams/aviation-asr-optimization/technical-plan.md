# 民航语音 ASR 系统性优化技术方案

状态：已执行并完成首个五轮活动（2026-07-22）

对应需求：[requirements.md](./requirements.md)

## 1. 方案结论

保留现有 Fun-ASR、服务端转写链路和唯一规范化器，建立一个以版本化样本、逐条人工分类、开发集回归和新样本盲测为核心的迭代系统。

每轮采用以下闭环：

```text
冻结样本与版本
→ 运行当前基线
→ Codex 逐条核对音频、原文、原始识别和最终文本
→ 分类并提出最小候选改动
→ 分别验证热词影响与规范化影响
→ 定向复听热词相关样本，并用缓存回归规范化
→ 候选冻结后运行本轮新随机盲测
→ 高风险或生产发布前才运行完整 ASR 回归
→ 固化正式版本和证据
→ 收口
```

首个活动以空热词 v2 和规范化 v2 为起点完成五轮。旧 50 条热词没有自动迁入，三批新热词候选也都因缺乏稳定收益或触发关键退化而撤销；最终发布空热词 v2 和规范化 v7。

### 已实现结果

- 候选生成、人工审核、正式子集校验和开发者总览已确定性脚本化。
- 五轮 30+30+3 开发集和 10+10+1 盲测均使用固定种子、无放回且互不重复。
- 原始识别缓存绑定模型、音频与热词身份；规范化候选直接复用缓存。
- 非完全匹配样本均由主线程逐条分类，累计 420/420 完成。
- 热词评测使用隔离供应商资源；无候选通过时生产明确使用无热词模式。
- 最终累计报告、部署快照和逐轮证据位于 `evidence/campaign-01/`。

## 2. 资产与职责边界

继续复用现有唯一来源：

- 题库、音频引用和原文：现有共享题库数据与音频索引；
- 热词候选数据库：新增的机器可读、版本化候选资产；
- 正式热词资产：`docs/resources/ai/assets/asr-hotwords.json`；
- 规范化规则：`services/api/src/ai/aviation-transcript-normalization.ts`；
- 数字与字母依据：现有数字读音和 ICAO 字母文档；
- 录音、临时存储、Fun-ASR 调用和错误处理：现有服务端链路。

候选数据库与正式热词表职责不同：前者保存已审核、值得后续验证的候选，后者只保存实际提交给 ASR 的词条。不得创建第二份正式热词表、第二个规范化器、第二套题库文本或音频映射。评测清单和结果属于版本化证据，不是新的业务数据源。

## 3. 热词候选数据库

### 3.1 形式与唯一入口

新增 `docs/resources/ai/assets/asr-hotword-candidates.json` 作为正式候选数据库。它是版本化 JSON 资产，不是数据库表，不需要数据库迁移，也不参与运行时 ASR 请求。

同时生成 `docs/resources/ai/assets/asr-hotword-inventory.md` 作为开发者总览。总览由候选数据库、`asr-hotwords.json` 和最近一次已验证的线上部署清单确定性合并生成，顶部显示候选总数、仓库已选数、线上已部署数和同步状态，正文按类别列出全部候选，并清晰标记“仅候选”“仓库已选”“线上已部署”。

开发者无需手工比对资产。总览只负责展示，不是新的运行时来源；仓库选择状态以 `asr-hotwords.json` 为准，线上实际使用状态以最近一次部署后查询验证的非敏感清单为准。仓库与线上不一致时必须显式显示“未同步”。

每个候选至少记录：规范形式、类别、来源题库与字段、跨题目数量、总出现次数、代表性样本 ID、领域性判断、预计识别难度、歧义风险、语义重要性和收录理由。数据中不复制完整题库原文，只保留统计和少量可追溯样本 ID。

候选 JSON 不人工保存 `active` 布尔值，避免与正式热词资产产生双重状态。生成总览时，根据规范形式匹配正式热词和已验证线上清单并计算三种状态；校验命令同时检查总览是否为当前输入的最新结果。

### 3.2 固定数据范围

脚本只读取共享题库的以下字段：

| 题库 | 字段 | 用途 |
| --- | --- | --- |
| 900句 | `audioText` | 音频原文 |
| 陆空通话 | `referenceText` | 参考答案 |
| OPI | `referenceText` | 参考答案 |
| 故事复诵 | `audioText` | 音频原文 |

不读取选项、中文文本、题目提示、陆空通话音频原文或 OPI 问题音频原文作为本候选库输入，避免把非目标表达混入统计。

### 3.3 生成与审核

候选建设分成两层：

1. 确定性脚本完成文本归一化、分词、缩写/单词/短语/专名候选提取、跨题目统计、去重、来源追踪和稳定排序。
2. Codex 基于领域性、基础 ASR 识别难度、语义重要性、复用价值、歧义和来源可靠性进行批量审核，形成正式候选数据库。

脚本负责所有无需语义判断的批量劳动。候选数量较大时，可以让多个子 agent 按互不重叠的批次分析或审查；主线程负责统一标准、抽查边界样本、处理冲突和最终合并。高频只是一项统计，不能替代语义审核。

通用英语、语法词、普通动词和基础 ASR 通常稳定识别的词默认排除。民航领域性强但频率较低的缩写、固定短语或专名可以保留；频率很高但无领域识别价值的 `have` 等词必须排除。

### 3.4 与正式热词的子集约束

资产校验同时读取候选数据库和 `asr-hotwords.json`，忽略大小写后验证每个仓库正式热词都能在候选数据库中找到唯一规范项，并验证开发者总览中的数量、词条、仓库选择状态和已记录线上状态没有过期。

后续有两种合法入口：

- 从候选数据库中选择已有候选加入正式热词；
- 从本轮真实差异直接提出新词，并在同一次变更中先补充候选数据库，再加入正式热词。

任何只修改正式热词、却未满足候选子集约束的变更都必须被检查拒绝。候选或正式热词变化后由脚本重新生成开发者总览；总览未更新或状态不一致时检查失败。候选数据库的存在不代表词条自动生效；正式热词仍需经过本轮差异证据和候选前后 ASR 验证。

## 4. 样本设计

### 4.1 开发集

每轮固定抽取：900句 30 条、听力 30 条、故事复诵 3 条。抽样使用可记录的随机种子，在各题库当前有效且同时具备音频和原文的样本池中无放回选择。

同一轮内清单不可变。已进入以往开发集或盲测集的样本默认不再次作为新盲测样本；样本池不足前不重复抽取。

### 4.2 盲测集

第一版默认每轮新抽取 900句 10 条、听力 10 条、故事复诵 1 条作为盲测。盲测样本在候选改动冻结后才运行和查看，不参与本轮修改；查看后从下一轮开始进入累计回归集。

这个规模用于低成本泛化检查，不作为全量统计结论。若盲测暴露严重退化，本轮候选不得发布；回到开发集收紧或撤销改动后，必须重新抽取未见样本验收，不能反复针对已经暴露的盲测样本调优。

### 4.3 故事复诵

故事复诵按完整音频调用 ASR，同时按整篇、句段和民航关键实体三层分析。总体报告分别展示三个题库结果；不把长故事的词数直接与短句合并成唯一结论。

## 5. 版本与可复现性

每次转写证据绑定以下身份：

- 样本 ID、音频路径和音频摘要；
- 参考文本摘要和题库发布版本；
- 基础模型；
- 热词资产版本和摘要；
- 热词候选数据库版本和摘要；
- 规范化规则版本；
- 运行时间与结果状态。

原始 ASR 输出只能在模型、音频和热词版本完全一致时复用。规范化调整可以在同一原始输出上快速重跑；热词变化属于上游变化，必须重新调用 ASR，不能沿用旧原始输出。

热词变化后不默认重新识别完整开发集。先只重新识别与候选有关的目标错例、相似发音反例和历史保护样本；候选冻结后再运行新盲测。完整开发集和累计回归集只在高风险或正式上线门槛触发时重新识别。

## 6. 空热词基线

仓库正式资产使用 `aviation-hotwords:v2` 表示空热词起点，保留 `aviation-hotwords:v1` 的历史交付记录，不覆盖历史证据。

供应商热词资源可能不接受零词条，因此执行阶段不把空数组同步为伪造词表，而是让评测链路明确支持“不提交热词资源”的基线模式。候选热词在隔离的评测资源中验证，通过后才同步为新的正式热词版本。

首个活动执行期间始终明确区分线上 v1 与隔离评测 v2。活动收口时生产已切换到明确的无热词模式，线上版本与仓库空热词 v2 同步；后续未完成同步、部署和线上验证的候选仍不得声称对用户生效。

## 7. 差异分析方法

每个有效样本保存四层只读对照：

1. 音频及其听感；
2. 题库参考原文；
3. 模型原始识别；
4. 规范化后的最终文本。

分类至少包括：

- `ASR_DOMAIN`：领域词、缩写、呼号或专名识别错误；
- `ASR_GENERAL`：普通英语、漏词、多词、口音或噪声问题；
- `NORMALIZATION_MISSING`：内容听对但未转为目标民航格式；
- `NORMALIZATION_REGRESSION`：规则改变了正确内容；
- `REFERENCE_MISMATCH`：音频和参考文本明显不一致；
- `REFERENCE_VARIANT`：原文与音频存在可接受等价表达；
- `NO_SPEECH_OR_INPUT`：无语音或输入无效；
- `UNCERTAIN`：证据不足，暂不形成资产。

自动脚本可以计算差异和提出候选，子 agent 可以辅助逐项整理，但主线程必须亲自查看每个非完全匹配样本、复核分类并决定是否修改。子 agent 不直接写正式热词或规范化规则，也不作最终泛化判断。

## 8. 从个例抽象为共性

候选改动必须回答四个问题：

1. 当前差异的真正原因是什么？
2. 哪些其他表达共享同一结构或发音模式？
3. 最小且可靠的触发上下文是什么？
4. 哪些相似表达必须明确排除？

只有能构造至少一个独立正例和一个高风险反例，并且规则边界能够解释时，个例才晋升为公共热词或规范化规则。无法回答时保留为观察项。

热词优先解决上游领域识别问题；规范化优先解决已经听对的确定性写法。不得用规范化规则猜回模型漏掉的内容，也不得用高权重热词掩盖普通英语识别问题。

## 9. 变更与归因顺序

每轮先冻结基线，再按错误分类形成少量候选。候选验证分层进行：

1. 组成定向复听集：包含全部目标错例、候选词相关样本、相似发音普通英语反例和已有相关保护样本。
2. 比较定向复听集在旧热词与候选热词下的原始 ASR 输出，判断热词是否真正改善上游识别且没有明显误吸附。
3. 在冻结的原始输出上比较旧规范化与候选规范化，判断规则是否正确改变写法；规范化回归复用缓存，不增加 ASR 调用。
4. 使用候选热词与候选规范化组合检查定向复听集，候选冻结后运行新盲测。
5. 只有触发高风险门槛或准备正式上线时，才使用候选热词完整重跑开发集和累计 ASR 回归集。

同一批次可以同时包含热词和规范化变更，但证据必须能分别归因。一次变更多而无法判断来源时，应拆成更小候选批次。

定向复听集不固定机械数量，由候选风险决定，普通小批候选预计约 8–20 条。低风险轮次调用量约为 63 条基线、8–20 条定向复听和 21 条盲测，即约 92–104 次。

触发高风险或正式发布门槛时，完整 63 条第二遍开发集替代定向复听，不再先额外运行 8–20 条定向集，因此单轮上限为 `63 + 63 + 21 = 147` 次。预计需要更多 ASR 调用时暂停并说明原因。调用次数是文件任务数，真实成本仍按供应商计费音频时长统计。

以下情况触发完整开发集或累计 ASR 回归：

- 候选是短词、常见词、同音词或与普通英语高度相似；
- 使用较高热词权重；
- 一次新增多个类别或较多词条；
- 定向复听或盲测出现误吸附、退化或无法解释的变化；
- 准备把候选版本同步并部署到生产环境。

## 10. 指标与人工判断

报告至少提供：

- 严格完全匹配和忽略大小写、空白、句末标点后的内容匹配；
- 表面 WER 和允许已确认等价写法后的等价差异；
- 改善、不变、退化样本数量；
- 民航关键实体正确、错误和新增退化数量；
- 按 900句、听力、故事复诵分别统计的结果；
- 源数据问题、输入问题和不确定样本数量。

指标用于发现问题，最终判断以语义忠实、关键实体和逐条证据为准。不得为了降低 WER 把合理口语形式强制改成参考答案写法。

任何候选引入新的错误数字、字母、呼号、跑道、航向、频率或应答机编码，都属于发布阻塞。普通非关键差异可以结合语义、来源噪点和分模块指标判断，不机械要求字符完全一致。

## 11. 测试与回归

每条规范化规则必须包含正例、反例和幂等性测试。每个正式热词至少保留触发样本、相似普通英语保护样本和候选前后原始识别对照。

累计回归集包含：

- 所有已用于正式规则或热词决策的开发样本；
- 已完成轮次的盲测样本；
- 既有规范化单元测试；
- 曾经出现退化的保护样本。

一轮允许没有资产变化；不允许为了产出数量而接受证据不足的词条或规则。

规范化规则变更可以在全部缓存原始转写上运行累计回归，不产生新的 ASR 调用。热词变更的日常回归采用定向复听与新盲测；完整 ASR 累计回归按风险门槛和生产发布门槛执行。

## 12. 外部调用、部署与安全

- 批量 ASR 分批运行，缓存每个完整版本身份的结果，失败可续跑，避免重复计费。
- 评测音频只使用现有授权题库资产，不记录密钥、签名地址或完整供应商响应。
- 候选热词使用隔离的评测资源，正式通过后再同步生产资源。
- 准备把服务端实现或正式热词变化发布给用户时，必须先通过完整发布回归，再按项目部署规则从审查后的文件集部署 ECS，保留回滚，验证健康检查和代表性线上请求。
- 生产发布不是每个内部优化轮次的前置条件。每轮必须说明仓库候选版本、线上版本及同步状态；未完成完整发布回归、同步和部署的版本不能标为用户当前版本。

## 13. 不采用的方案

- 直接恢复旧 50 条热词：无法证明每条对当前模型和样本仍有价值。
- 题库高频词自动进入正式资产：频率不能证明识别困难或低歧义。
- 把所有脚本提取结果直接写入候选数据库：原始统计仍包含大量普通英语和上下文碎片，必须经过领域与风险审核。
- 同一批样本边看盲测边修改：会使盲测失去泛化验证意义。
- 只以 WER 决定规则：会误罚等价写法，也可能掩盖关键数字和呼号错误。
- 用大模型二次自由纠错：可能改变用户原意并补写内容。
- 每个个例建立专用替换：会过拟合并形成不可维护的题库答案映射。

## 14. 脚本与 Agent 使用原则

抽样、字段读取、文本归一化、去重、统计、差异计算、缓存、报告、格式校验、子集检查和累计回归等确定性批量任务必须优先脚本化，保留可复跑输入输出，不让主线程逐项手工消耗上下文。

领域判断、差异归因、问题族抽象、热词价值判断、规则边界设计和退化审查属于关键语义任务。主线程对最终结论负责；当样本或候选数量较大时，可以让子 agent 按明确批次专门分析或交叉审查，再由主线程复核、处理冲突并写入正式资产。

首个活动已完成一个试点轮次和四个后续轮次，并证明定向复听、缓存规范化回归、盲测和发布边界可执行。后续活动沿用同一方法；若数据结构、模型或供应商接口改变，才重新审计阶段 0–1。
