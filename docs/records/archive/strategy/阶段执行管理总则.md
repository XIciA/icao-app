# 阶段执行管理原则

状态：当前管理基线
更新时间：2026-07-30

## 用途

阶段管理用于控制跨多个验证闭环的复杂工作，不是所有任务的文档配额。大小流程的完整方法见：

- `docs/rules/bigandsmall-workflows/document-driven-development-workflow.md`
- `docs/rules/bigandsmall-workflows/orchestration-loop.md`

## 原则

1. 先确定目标、非目标、事实来源和验收结果，再决定是否需要阶段化。
2. 每个阶段交付一个可独立验证的结果；不要按文件数量或人造里程碑拆分。
3. 只有产品取舍、架构边界、不可逆数据操作、线上权限或范围扩大需要用户决策。
4. 实现细节、局部修复和可逆选择由 Codex在既定边界内自主完成。
5. 文档只记录后续真正需要的决策、状态与证据；已有合适文档时直接更新，不复制一套。
6. 阶段结束时将长期结论提升到稳定规范，将过程材料标记完成或归档。

## 何时使用完整阶段资料

同时具备跨系统、高风险、持续多轮、多人交接、外部发布或复杂迁移之一时，可以建立
requirements、technical plan、phase log 和 closeout；简单任务不要求创建这些文件。

## 状态词

- `计划中`：范围尚未开始实现。
- `进行中`：存在未完成的当前闭环。
- `已阻塞`：有明确外部条件阻止继续。
- `已完成`：验收目标已有证据且没有剩余必做项。
- `已归档/已替代`：保留历史，但不再代表当前方向。
