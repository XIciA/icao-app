## 3. A0：前置条件与边界冻结

### 目标

把第二阶段 A 的环境、外部依赖和延期边界固定清楚，不解决范围外的微信 P0。

### 主要工作与产出

- 确认四份大流程文档，固定“只使用现有 ECS”的执行范围。
- 明确 SMTP、微信、短信、域名备案、AI、OSS/CDN 和商店能力全部延期。
- 固定 ECS、目录、端口、密钥、客户端公开配置和服务端私密配置清单。
- 固定现有未提交改动的文件级基线和禁止覆盖范围。
- 形成 A0 phase-log；原微信 Auth 风险继续保留在完整第二阶段。

### 允许范围

- 文档、只读检查、环境模板、无密钥预检脚本。

### 禁止与暂不做

- 不部署服务，不改 RN 页面，不导入数据，不解决微信 Auth。

### 验收

- 第二阶段 A 的范围、延期项和接口预留均有明确结论。
- 密钥不进入 Git/RN，工作区现有改动归属清楚。
- 验证：Markdown 链接、环境清单、`git diff --check`。

## 4. A1：后端与 Supabase 基础

### 目标

建立可从空环境重复部署的真实后端、Auth、PostgreSQL 和 Storage 基础。

### 主要工作与产出

- 建立后端 workspace、共享 contract、类型/lint/测试命令。
- 固定官方 Supabase Docker 版本，生成密钥并部署必要组件。
- 建立 Drizzle schema、SQL Migration、RLS/权限补充 SQL。
- 完成健康检查、JWT 校验、错误 envelope、配置门禁和基础日志。
- 建立备份脚本、空库迁移与隔离恢复测试。

### 允许范围

- 后端、contract、infra、Migration、部署和测试文件；RN 仅允许新增不接页面的 API/Auth adapter 骨架。

### 禁止与暂不做

- 不接真实业务页面，不开放数据库/Studio 公网端口，不使用公网 HTTP 传密码。
- 不接手机号、微信、AI 或支付。

### 验收

- Supabase 必要容器健康，API 可通过本机/SSH 隧道访问。
- 空库 Migration 可重复执行；鉴权失败、配置缺失和健康检查返回稳定。
- 后端测试通过，服务器密钥不出现在 Git diff。

## 5. A2：真实题库与资源

### 目标

把题库和规范资源迁移为云端权威发布，同时保留本地回退。

### 主要工作与产出

- 先完成 A2.0 内容工程基线：按题库/话题拆分维护源，建立统一 schema、ID 规则、资源命名和验证命令。
- 由维护源生成统一版本化发布产物、资源 manifest、checksum 和变更报告；禁止手工编辑生成产物。
- 建立版本化题库发布表、资源清单表和私有 Storage bucket。
- 编写可重复导入、上传、checksum、manifest 和对账脚本。
- 导入 5 库、27 分类、239 话题、4947 卡片和 3894 个音频文件。
- 实现题库 API、资源短期地址、远程 repository、版本缓存和内嵌回退。

### 允许范围

- 数据脚本、Migration、后端题库/资源模块、RN repository/resource adapter 和相关测试。

### 禁止与暂不做

- 不改题目内容或稳定 ID，不删除内嵌 JSON，不提供完整离线下载。
- 不迁移旧音频目录，不接账号同步。

### 验收

- 维护层、发布层、运行层边界通过审查；新增题库不需要复制页面、Repository 或后端模块。
- 维护源可重复生成相同发布产物；schema、稳定 ID、数量、资源引用和命名检查通过。
- 导入重复执行不重复数据，checksum、数量和引用一致。
- 五套题库可通过真实 API 读取；资源成功、缺失、过期和重试状态通过。
- iOS 模拟器经安全隧道完成“题库 → 目录 → 学习卡 → 音频”，远程失败可回退。

### A2 小流程顺序

| 小流程 | 目标 | 完成标准 |
| --- | --- | --- |
| A2.0 | 内容工程基线 | 维护源拆分、schema、稳定 ID 规则、命名兼容和验证命令通过 |
| A2.1 | 统一发布产物 | 版本、checksum、manifest、变更报告可重复生成且不可手改 |
| A2.2 | 云端导入与资源上传 | 五库与资源幂等导入、数量和引用对账通过 |
| A2.3 | 远程运行链路 | 统一 API、Repository、缓存、资源地址和内嵌回退通过 |

## 6. A3：邮箱密码账号

### 目标

完成数据同步所需的最小邮箱密码用户归属和真实会话闭环。

### 主要工作与产出

- 接入 Supabase client、统一 `AuthService` 和 `expo-secure-store`。
- 把登录/注册改为邮箱密码真实流程，补齐加载、失败、重复邮箱、弱密码和失效状态。
- 实现会话恢复、刷新、当前设备退出；禁用或明确标记范围外登录入口。
- 保留手机号、微信、Apple、匿名 Auth adapter 接口但不实现。

### 允许范围

- Auth adapter、会话存储、认证页面必要逻辑和文案、测试、Expo 配置。

### 禁止与暂不做

- 不接 SMTP、验证邮件、找回密码、换绑邮箱、账号注销或其他登录方式；不扩展账号功能。
- 不重做认证页面视觉或导航。

### 验收

- 邮箱注册、登录、重复邮箱、错误密码、弱密码、会话恢复、失效和退出均通过。
- token 只进入 SecureStore，客户端没有 service key。
- `pnpm check`、Expo Doctor、iOS Development Build 和模拟器流程通过。

## 7. A4：学习数据同步与收口

### 目标

把现有本地学习数据安全升级为邮箱账号可恢复的在线优先同步。

### 主要工作与产出

- 建立用户学习状态、记录、幂等 mutation 和同步 cursor 数据结构。
- 升级本地存储版本，增加账号归属、稳定 ID、outbox、确认和重试。
- 实现首次本地归属、push/pull、去重、版本冲突和同步状态展示。
- 完成同账号退出重登、第二受控 iOS 会话、弱网和重复提交验证。
- 完成数据库备份、隔离恢复、phase-log、closeout 和完整第二阶段剩余边界清单。

### 允许范围

- 同步后端、Migration、learning store、同步 adapter、账户同步状态和测试。

### 禁止与暂不做

- 不清空 v1/v2 本地数据，不做跨账号自动合并、完整离线系统或复杂冲突 UI。
- 不声称微信、手机号、游客升级、Android 或完整第二阶段已验收。

### 验收

- 首次归属可重试且不重复；旧版本不能覆盖新版本；失败不删除本地数据。
- 同账号可恢复进度、作答、标注、高亮、笔记、记录和报告。
- 空库升级、备份恢复、后端测试、`pnpm check` 和 iOS 验证通过。
- 无公网 HTTP 密码传输、service key 泄漏或静默数据丢失。
