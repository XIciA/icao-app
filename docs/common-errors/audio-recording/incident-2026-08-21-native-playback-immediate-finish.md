# 录音回放立即结束

状态：代码修复完成，等待同一候选 TestFlight 真机验收。

## 现象

iPhone 可以进入录音、停止并显示录音资产，但点击回放后立即结束。

## 根因

- Native Adapter 使用 Expo 包装层 `getStatus().isRecording` 确认启动；SDK 55 的 iOS 实现会在调用底层 `record()` 后先更新包装状态，不能单独证明 `AVAudioRecorder` 正在采集。
- Engine 把单调时钟的操作时长写回 Raw，掩盖原生录音器和文件音轨的时长异常。
- Repository 只检查 M4A 顶层容器，未确认存在有时长的音频轨道，也未用平台解码器验证可读性。

因此“操作持续数秒、实际音轨接近零”的文件可能被误发布，播放器只能正常开始后立即完成。

## 长期修复

- Native 启动只以公开的 `recorder.isRecording` 底层事实确认。
- 操作时长、录音器时长和媒体时长分离，资产采用已验证的媒体时长。
- M4A/WAV 容器解析真实音轨时长；Repository 在发布前使用非播放媒体探针确认平台解码器可以读取。
- 回放完成事件绑定当前 source 和播放尝试；未观察到播放进度时忽略迟到的完成事件。
- 保持 iOS 官方 M4A/AAC preset；WAV 只作为证据明确时的受控对照，不做运行时自动回退。

## 自动门禁

- 包装状态为 recording、底层 recorder 未启动时不得进入 recording。
- 3 秒操作但约 0.091 秒媒体必须拒绝提交。
- M4A 必须包含 `soun` 音轨和有效时长，并通过平台解码器加载。
- 旧 source 的完成事件不能结束新回放。

最终结论以 `v2026.08.20.0016` 对应 commit 的 TestFlight 真机结果为准。
