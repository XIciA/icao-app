# App 双端商业化人工事项清单

状态：项目级人工前置清单

更新时间：2026-07-11

## 1. 使用原则

本文只记录必须由项目负责人亲自决定、实名、付费、签约、提交审核或持有的事项。代码、部署、数据迁移、测试和材料草稿由 Codex 执行。

- 不要一次性购买全部服务；到对应阶段前完成即可。
- 密钥、证书和密码不得发到聊天或提交 Git，只放入本机/服务器安全环境。
- 主体名称、域名、开发者账号、收款账户和应用标识应尽量归属同一主体。

## 2. P0：现在必须处理

不完成会阻塞第二阶段的阶段 0 或阶段 1。

| 人工事项 | 需要完成什么 | 不完成的影响 |
| --- | --- | --- |
| 确认第二阶段方案 | 确认 `technical-plan.md` 和 `roadmap.md` | 不能进入小流程阶段 0 |
| 确定长期运营主体 | 确定个人或企业主体；商业化双端 App 建议优先使用稳定企业主体 | 后续备案、微信、短信、商店和收款信息可能反复迁移 |
| 冻结基础身份 | 确定 App 中文/英文名、品牌归属、正式域名、客服邮箱、iOS Bundle ID、Android Package Name | 微信回调、证书、备案和商店应用无法稳定创建 |
| 准备阿里云账号 | 完成实名认证、付款方式和安全设置；允许创建 RAM 子账号或最小权限凭证 | 无法购买、部署或维护中国内地服务 |
| 准备域名 | 购买域名并完成持有人实名认证，主体信息与备案主体保持一致 | HTTPS、Auth 回调、微信登录和备案无法完成 |
| 准备微信开放平台 | 完成主体认证，申请移动应用、AppID/Secret、Universal Link/回调及测试账号 | 微信登录可行性无法验证 |
| 准备 Apple Developer | 注册或确认 Apple Developer 账号；企业账号准备 D-U-N-S 和签约权限 | 正式 Bundle ID、微信 iOS 回调、TestFlight 和 App Store 无法推进 |
| 确认初始预算 | 确认 ECS、域名、短信、邮件、AI、备份和开发者账号的预算上限 | 无法确定可执行资源规格 |

### 阶段 0 后再购买

以下项目先由 Codex 给出规格和费用清单，再由项目负责人确认付款：

- 中国内地 ECS、公网 IP、带宽和云盘；当前候选从 4 核 8 GB、约 100 GB ESSD 起评估。
- 快照/备份存储、日志和监控资源。
- SSL 可优先使用受信任的自动化免费证书，不要求预先购买商业证书。
- 本阶段使用自托管 Supabase Storage，暂不要求先购买 OSS/CDN；流量或稳定性需要时再启用。

## 3. P1：真实账号、AI 和内部测试前完成

不完成会阻塞第二阶段阶段 1–8。

| 人工事项 | 需要完成什么 | 阻塞阶段 |
| --- | --- | --- |
| 购买并授权 ECS | 按阶段 0 确认的规格购买，提供可管理但不过度授权的访问方式 | 后端与 Supabase 部署 |
| 域名解析与 ICP 备案 | 中国内地 ECS 对外提供 API 前完成域名解析规划和 ICP 备案 | HTTPS、Auth 回调、内测公网服务 |
| 短信服务 | 选择供应商，完成主体认证、短信签名、模板审核、充值和测试号码 | 手机号登录 |
| 邮件服务 | 选择 SMTP/邮件供应商，验证发件域名，准备登录/验证/找回密码模板 | 邮箱登录 |
| 微信配置 | 完成应用审核，提供 AppID/Secret、Bundle ID、Universal Link 和回调白名单 | 微信登录 |
| 阿里百炼 | 开通服务、充值、创建受限 API Key，确认模型及中国内地处理范围 | 全部真实 AI |
| AI 数据处理确认 | 接受录音/文本发送范围、同意文案、供应商保存期限、禁止训练和删除保证 | AI 同意与真实调用 |
| 内测人员 | 提供测试人员名单、手机号/邮箱/微信及至少一台物理 iPhone | 账号、同步和 AI 内测验收 |
| 内容授权确认 | 确认题库、音频、图片、字体、文章和课程内容可用于内部测试 | 真实资源发布 |

人工只负责开通、审核和授权。Docker、Supabase、数据库、HTTPS、备份脚本、短信/邮件接口和 AI Gateway 配置由 Codex 完成。

## 4. P2：双端正式上架前完成

不完成会阻塞总战略第 3 阶段“正式上架准备”。

### 主体与中国大陆合规

- 完成 APP 备案并取得备案编号，在 App 显著位置展示。
- 服务正式开放后，按要求完成公安联网备案。
- 确认是否需要 ICP 许可证、等保、算法备案或安全评估；涉及收费、AI 或特定经营范围时由专业合规人员判断。
- 核对所用生成式 AI 模型的备案/登记状态，并按要求展示模型名称及备案号。
- 确定产品目标年龄、未成年人边界和监护规则。

### 用户与数据规则

- 定稿隐私政策、用户协议、AI 数据说明、第三方 SDK 清单、权限说明和数据保存期限。
- 建立用户查询、更正、撤回同意、注销账号和删除数据的正式流程。
- 第二阶段“不允许自行注销”只能用于内部测试；正式上架前必须在 App 内提供账号删除入口。
- 确定客服邮箱、反馈渠道、服务时间和安全/隐私联系人。

### iOS 上架

- 确认开发者主体、正式 Bundle ID、证书、签名权限和 App Store Connect 角色。
- 因存在微信登录，正式上架前增加满足 Apple 要求的等价隐私登录方式；通常预留 Sign in with Apple。
- 准备 App 名称、图标、截图、简介、关键词、年龄分级、隐私标签、审核说明和可用测试账号。
- 保证审核期间后端、短信、邮件、微信和 AI 服务持续可用。

### Android 上架

- 恢复物理 Android 真机与完整兼容性验收；第二阶段 iOS-only 结果不能代替。
- 决定首发渠道：Google Play，以及华为、小米、OPPO、vivo、荣耀、应用宝等中国大陆市场中的实际范围。
- 分别注册并认证所选市场的开发者主体，接受协议并配置团队权限。
- 冻结 Android Package Name、签名方案和更新密钥；签名密钥必须离线备份。
- 为各渠道准备截图、文案、隐私/数据安全申报、权限说明、测试账号及渠道要求的合规材料。

### 内容与品牌

- 取得题库、音频、图片、字体、文章、课程和品牌标识的正式商业使用权或书面授权。
- 完成商标、App 名称和域名冲突检查。
- 确定公开版本中哪些 AI 输出需要显著标识和免责声明。

## 5. P3：正式收费前完成

不完成会阻塞总战略第 4 阶段“商业化收费运营”。

| 人工事项 | 需要完成什么 |
| --- | --- |
| 定价与权益 | 确定免费范围、会员/订阅周期、AI 额度、题库权益、试用、续费和到期规则 |
| 退款与恢复 | 确定退款、取消订阅、恢复购买、换设备和账号迁移规则 |
| Apple 收款 | 签署 Paid Apps Agreement，提交税务和银行信息，创建订阅/IAP 商品 |
| Google 收款 | 如使用 Google Play，配置商户资料、付款方式、税务/银行信息和 Play Billing 商品 |
| 国内 Android 渠道 | 确认各首发市场的支付规则、分成协议、商品和结算账户 |
| 财税处理 | 确认开票、收入入账、税务申报、退款核算和平台对账负责人 |
| 客服与争议 | 建立收费咨询、退款、账号申诉和内容纠错处理流程 |
| 商业合规复核 | 确认收费模式是否需要新增许可、备案、合同或消费者权益说明 |

支付、订阅和权益代码由 Codex 实现；价格、合同、银行、税务和最终规则必须由项目负责人确认。

## 6. P4：上线后持续执行

这些事项不会阻塞第一次发布，但不持续执行会影响稳定运营或后续版本。

- 续费域名、ECS、开发者账号、短信、邮件、AI 和证书相关服务。
- 定期查看云资源、AI、短信、带宽和商店账单，调整预算与告警。
- 检查自动备份并定期参与恢复演练确认。
- 处理用户反馈、退款、账号注销、数据删除和隐私请求。
- 处理商店审核消息、版本发布审批、合规整改和安全事件。
- 保管开发者账号、签名密钥、恢复码和应急联系人，并定期审查团队权限。
- 复核题库、音频、图片和 AI 内容的版权、准确性与安全问题。
- 跟踪 Apple、Google、中国 Android 市场及中国大陆备案/AI 规则变化。

## 7. 项目负责人最终持有物

以下内容必须长期由项目负责人或正式主体控制，不能只存在于开发人员电脑：

- 阿里云、微信开放平台、Apple Developer、Google Play 及中国 Android 市场主账号。
- 域名、ICP备案/APP备案资料、商标和内容授权文件。
- iOS 证书权限、Android 签名密钥及离线备份。
- 收款银行、税务、合同、发票和平台结算资料。
- 短信、邮件、AI 服务主账号与账单权限。
- 隐私政策、用户协议、退款规则、数据删除规则和客服渠道的最终版本。

## 8. 当前最近一步

1. 确认第二阶段 `technical-plan.md` 和 `roadmap.md`。
2. 确定长期运营主体、正式域名、Bundle ID 和 Package Name。
3. 进入阶段 0，由 Codex 先完成微信 Auth 可行性验证和 ECS 购买清单。
4. 收到购买清单后再完成 ECS、域名备案及外部服务开通。
