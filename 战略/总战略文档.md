# 飞猪 ICAO 产品与平台总战略

状态：当前战略基线
更新时间：2026-07-30

## 1. 目标

围绕 ICAO 英语学习构建稳定、可信、可持续演进的产品。优先保证学习闭环、内容质量、
音频体验、反馈质量和跨版本可维护性；商业化能力应建立在这些核心资产之上。

## 2. 已建立的产品基线

- iOS 与 Android 是正式 Native 产品，使用 React Native、Expo 与 TypeScript。
- Native 已进入真实账号、云端学习数据、题库资源、录音/转写、AI 辅助与真实反馈阶段。
- Web 是同一品牌下的独立在线体验，使用 Vercel 同源运行时和浏览器本地数据，不依赖
  Native 的 ECS/Supabase 身份与同步链路。
- 设计令牌、共享 UI、题库数据、音频映射、录音生命周期和运行时配置各有既定唯一来源。

具体当前事实见 `docs/current/product-state.md` 与 `docs/current/runtime-topology.md`。

## 3. 平台角色

### Native

- 承载完整学习、账号、云端记录、音频、录音、AI 与正式反馈能力。
- 对原生权限、生命周期、离线/弱网、设备差异和发布质量负责。

### Web

- 提供低门槛浏览与学习体验，并复用品牌、内容语义和核心交互意图。
- 后端身份、会话与数据生命周期保持独立，避免对 Native 生产后端形成隐式耦合。

### 共享资产

- 可以共享稳定的视觉令牌、内容源、业务语义、类型与纯逻辑。
- 不为了表面复用而共享平台特有的身份、存储、音频或部署生命周期。

## 4. 当前优先级

1. 保持正式学习闭环可靠，优先修复影响学习、音频、账号、数据和反馈的真实问题。
2. 继续提升题库、航空英语文本、音频映射、AI 输出和编辑内容的质量。
3. 在不破坏平台边界的前提下提升 Native 与 Web 的体验一致性。
4. 收敛重复实现、过期文档和不可验证规则，降低长期维护成本。
5. 商业化、会员、支付或大规模离线能力按明确需求和独立方案推进，不从旧阶段文档自动继承。

## 5. 长期保护项

- 不偏离已批准的品牌色、字体角色、组件气质、导航模型和核心学习流程。
- 不建立题库、音频、录音、账号或配置的第二来源。
- 不把密钥、签名材料或受保护运行时配置放进客户端、仓库或文档。
- 不以历史阶段的限制否定已经落地的新能力。
- 不让 Web 与 Native 在未决策的情况下重新共享后端身份或同步生命周期。

## 6. 战略变更方式

长期方向改变时，先更新 `战略/architecture-decisions.md` 中对应决策，再调整本文和相关稳定
规范。短期实现细节记录在 active workstream，不应膨胀为永久全局规则。
