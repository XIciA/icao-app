# 阶段执行管理总则

状态：项目级管理基线

更新时间：2026-07-11

## 1. 用途

本文只规定每个项目阶段开始、执行和收口时必须查阅的文档及冲突处理规则，不重复大流程和小流程的具体内容。

## 2. 每个阶段必须先查阅

开始任何阶段的需求讨论、技术方案或代码执行前，Codex 必须读取并检查：

1. `战略/总战略文档.md`
2. `战略/architecture-decisions.md`
3. 当前阶段已有的需求文档、技术方案、技术盘点和路线图
4. 仓库级 `AGENTS.md`

其中：

- `战略/总战略文档.md` 决定产品方向、阶段划分和阶段目标。
- `战略/architecture-decisions.md` 决定宏观技术方向、系统边界和已确认技术选择。

当前阶段的文档和实现不得与以上两份高层文档冲突。

## 3. 大流程与小流程查阅位置

每个阶段统一按照“大流程负责决策、小流程负责执行”的方式推进。具体规则直接查阅：

- 大流程：`docs/bigandsmall-workflows/document-driven-development-workflow.md`
- 小流程：`docs/bigandsmall-workflows/orchestration-loop.md`
- 新阶段启动模板：`docs/bigandsmall-workflows/workflow-start-prompt-template.md`

Codex 应直接遵循这些流程文档，不在阶段文档中重复抄写通用规则。

## 4. 冲突处理

出现以下情况时，Codex 必须暂停当前阶段并交由用户确认：

- 阶段需求与总战略冲突。
- 技术方案或实现与架构决策冲突。
- 新要求需要改变产品方向、阶段边界或宏观技术方向。
- 两份高层文档之间出现冲突。

确认后应先更新对应高层文档，再更新阶段文档或继续执行。阶段文档不能自行覆盖高层决策。

## 5. Codex 执行原则

- 用户负责提出需求、确认最终效果、范围和宏观方向。
- Codex 负责方案整理、真实项目盘点、技术实现、验证、问题修复和阶段收口。
- 高层文档只确定大方向；具体库、版本、目录、数据结构和算法由 Codex 根据实际兼容性、验证结果和最终效果决定。
- 当前阶段暂不实现的后续能力，可以只保留接入边界，但不得采用与最终架构冲突的临时路线。
- 阶段结束前必须再次确认实现结果没有违反 `战略/总战略文档.md` 和 `战略/architecture-decisions.md`。
